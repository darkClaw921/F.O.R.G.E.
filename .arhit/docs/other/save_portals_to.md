# save_portals_to

plugins/bitrix/src/config.rs — ЕДИНСТВЕННАЯ функция, которая кладёт секреты Bitrix24 в файл. save_webhook_to, add_portal_to и remove_portal_from — обёртки над ней.

Атомарно записывает ВЕСЬ список порталов в TOML-файл с правами 0600. Четыре инварианта (ради них функция и существует отдельно от serde):
1. read-modify-write — чужие ключи bitrix.toml (интервалы, лимиты, любые незнакомые) переживают запись;
2. права 0600 выставляются В МОМЕНТ создания файла (write_secret_file: OpenOptions::mode + явный chmod ДО первого write_all, потому что для существующего файла mode() не применяется);
3. атомарность — временный файл В ТОМ ЖЕ каталоге (tmp_path_for: .<имя>.<pid>.tmp), fsync, затем rename поверх целевого;
4. при ЛЮБОЙ ошибке временный файл удаляется, а целевой остаётся прежним.
Плюс tighten_perms_if_needed на КАЖДОЙ загрузке (BitrixRootConfig::load_from_file).

Следствия: каталог ~/.config/forge создаётся при необходимости; массив [[portals]] перезаписывается ЦЕЛИКОМ (вызывающий всегда работает от свежепрочитанного списка); верхнеуровневый legacy-ключ webhook СНИМАЕТСЯ — иначе тот же секрет остался бы в файле в двух экземплярах; в лог уходят только id и WebhookUrl::fingerprint. Пустой вебхук у любой записи — ошибка ДО чтения файла, чтобы отказ не оставлял ни каталога, ни пустого конфига.

Обёртки:
- save_webhook_to(path, webhook) — совместимость: список заменяется РОВНО одним порталом. Повторный вход по другому вебхуку заменяет подключение, а не добавляет второе (иначе старая кнопка 'подключить' тихо плодила бы порталы).
- add_portal_to(path, webhook, title) -> PortalConfig — добавляет портал, не трогая секреты остальных. Идемпотентна по вебхуку: тот же URL лишь обновляет title. Новый id выводится из хоста и при коллизии получает суффикс; существующие id не меняются. Возвращает записанный портал с окончательным id.
- remove_portal_from(path, id) -> bool — убирает один портал; отсутствующий портал и отсутствующий файл не ошибка (удаление обязано быть идемпотентным). На портал не ходим: отозвать входящий вебхук через REST невозможно.
- clear_webhook_to(path) — logout старого экрана: снимает ОБА представления (legacy-ключ и весь массив portals).
- portals_for_write(path) — читает список для записи, мигрируя legacy-ключ; общие настройки не разбираются вовсе, чтобы обновление секрета не падало из-за опечатки в poll_active_secs.
