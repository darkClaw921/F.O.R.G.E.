# bitrix-tasks

МОДЕЛЬ ЗАДАЧ Bitrix24 — plugins/bitrix/src/tasks.rs (Ф10).

Что здесь живёт: TaskDto (карточка-шапка над лентой), таблицы статусов и приоритетов, ActionMatrix (матрица прав портала), TaskIndex (индекс task_id <-> chat_id), TaskCountersDto, замороженные константы ловушек.

ГЛАВНЫЙ ФАКТ. Чат задачи — обычный IM-чат с entity_type="TASKS_TASK", entity_id=<task_id>. Комментарии задачи и сообщения чата — ОДИН поток (task.commentitem.add возвращает id сообщения ЧАТА). task.commentitem.getlist возвращает [] всегда — legacy-форум на «новых задачах» мёртв (forumTopicId/forumId у задачи null). Читать комментарии можно ТОЛЬКО через im.dialog.messages.get.

КОНСТАНТЫ-ЛОВУШКИ:
* ENTITY_TASK = "TASKS_TASK" (реэкспорт dto::ENTITY_TASK) — значение "TASKS" молча даёт {"result":null} при HTTP 200;
* LIST_SELECT: [&str; 14] — поля списка, ВСЕ UPPERCASE. camelCase в select портал молча игнорирует, и поле приезжает null, неотличимо от настоящего null. У карточки select нет вовсе;
* FILTER_STATUS_KEY = "STATUS" — ЗАПРЕЩЁННЫЙ ключ фильтра (0 записей молча), FILTER_REAL_STATUS_KEY = "REAL_STATUS" — рабочий;
* PAGE_SIZE = 50 — страница tasks.task.list ФИКСИРОВАНА платформой, LIMIT у метода нет.

СТАТУСЫ (числовые коды v1, приходят строкой): 1 Новая, 2 Ждёт выполнения, 3 Выполняется, 4 Ожидает контроля, 5 Завершена, 6 Отложена, 7 Отклонена. status_label() даёт подпись, status_key() — имя CSS-класса статус-точки (подпись переводима, ключ нет). is_closed(s) = s >= 5.

ПРИОРИТЕТЫ: 0 низкий, 1 средний (дефолт портала), 2 высокий. Неизвестное значение — «средний», а не «неизвестный».

ПРОСРОЧКА — вычисляемый признак, отдельного поля у портала НЕТ: deadline < now && status < 5. Правило живёт только здесь; фронт читает готовый TaskDto::overdue. parse_atom_unix() на неразобранной дате даёт None — «считать нечем», а не «просрочено».

ActionMatrix — матрица прав портала. from_raw() читает PhpMap<Value> (значения как Value, а не bool: одно неожиданное значение не должно ронять разбор всей карточки; всё, что не true — запрет). allows() отвечает «можно сейчас», knows() — «портал знает про такое действие» (это РАЗНЫЕ вопросы). allowed() даёт ОТСОРТИРОВАННЫЙ список разрешённых действий из числа выполнимых панелью — ровно он уезжает в DTO и превращается в ряд кнопок. Сортировка не косметика: порядок обхода HashMap случаен, и без неё кнопки прыгали бы местами.

МАТРИЦА ДИНАМИЧНА: после tasks.task.start становится start:false, pause:true, defer:false; после pause возвращается. Захардкоженный набор кнопок дал бы вызов, который портал молча проигнорирует.

ACTION_METHODS — таблица «действие -> семантический метод портала» (start/pause/complete/defer/renew/approve/disapprove). Это ответ на вопрос «умеет ли панель», а не «можно ли сейчас»: второе решает матрица. Намеренно НЕ включены edit/changeDeadline (нужна форма), delegate (нужен выбор сотрудника, scope user вебхуку не выдают), remove (безвозвратен), rate/checklist.*/favorite.* (сущностей в панели нет). is_action_key() валидирует :action из URL — составные ключи с точкой законны (edit.originator, dayplan.timer.toggle).

TaskDto — проводная форма карточки, одна на три источника: GET /api/bitrix/tasks/:id, страница GET /api/bitrix/tasks и WS-кадр task_update. Ключевые поля: chat_id/dialog_id (None = задача без чата, Р20), actions (разрешённые ПРЯМО СЕЙЧАС), url (абсолютный адрес в портале из WebhookUrl::portal_origin — хост есть, кода вебхука нет никогда), new_comments_count, overdue.

task_from_raw(raw, portal_origin, now) — чистая проекция: ни сети, ни состояния, now параметром ради детерминированного теста просрочки. chatId ПОЛИМОРФЕН (число в tasks.task.get, строка в tasks.task.list) — отсюда StrOrNum.

TaskIndex — кэш в памяти (B24State::task_index), ёмкость INDEX_CAPACITY=512 с вытеснением самой старой записи. Существует ради ОДНОГО требования: действие, запрещённое матрицей, обязано отвергаться БЕЗ обращения к порталу. remember() НЕ затирает известную матрицу пустой — строка tasks.task.list приходит без action вовсе. task_of_chat() отвечает на обратный вопрос ленты: «открыт chat9 — какую карточку показать».

TaskCountersDto (expired/new_comments/mentioned) — ВТОРОЕ семейство счётчиков, отдельное от CountersDto: то считает непрочитанные СООБЩЕНИЯ чатов задач и обнуляется чтением ленты, это — состояние самих задач и обнуляется действием. Сложенный бейдж не обнулить ничем.

Тесты: 19 юнитов в самом модуле + plugins/bitrix/tests/tasks.rs (18) + plugins/bitrix/tests/tasks_traps.rs (10 стражей). Страница: bitrix-tasks-model.
