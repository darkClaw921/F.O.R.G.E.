# openLightbox

tmux-web/static/js/telegram/media.js — просмотр принятого медиа: лайтбокс, сохранение, плееры (Фаза 4, задача Ф4.8).

openMedia(ctl) — диспетчер OPEN по виду вложения: фото/стикер -> openLightbox; видео/голосовое/аудио -> playInCard; документ/прочее -> blob в новой вкладке (window.open с noopener), заблокировали popup -> падаем на saveMedia. Клик по превью равнозначен OPEN, но ТОЛЬКО когда там реально превью или воспроизводимое вложение: по generic-иконке попадают случайно чаще, чем осознанно.

withFull(ctl, done, onFail) — единственная точка запуска 'тяжёлой' загрузки: лайтбокс, плеер и SAVE ходят через неё, поэтому прогресс ('NET n%') и обработка ошибок везде одинаковы, а сама загрузка идёт ТОЛЬКО по явному действию пользователя (автозагрузки полноразмерных файлов нет). onFail нужен вызывающим со своим индикатором: лайтбокс показывает 'loading…' в подписи и без этого колбэка остался бы 'загружающимся' навсегда (дефект найден на рантайм-прогоне и исправлен).

openLightbox(ctl): #tg-lightbox поверх панели, подпись '<имя> · loading…' -> после загрузки '<имя> · 1280×720 · 1.2 MB', при ошибке '<имя> · >> NO MEDIA'. Превью растянутым НЕ подставляется — это было бы обманом ('уже загрузилось'). Закрытие: Esc (слушатель на document, а не на самом лайтбоксе — иначе работало бы лишь пока фокус внутри), клик по фону (e.target === сам оверлей, по картинке не закрывает), кнопка ✕. Доступность: фокус переводится на ✕, Tab заперт между ✕ и картинкой (trapFocus), при закрытии возвращается на элемент, с которого открыли. Гонка 'пока грузили, лайтбокс закрыли или открыли другой файл' отсекается сравнением local.lightbox.ctl.

saveMedia(ctl): полный файл -> <a download> -> click -> remove. Имя проходит sanitizeDownloadName (убираются разделители пути, спецсимволы ФС, ведущие точки): 'download' браузеры трактуют как подсказку пути, и '../../.bashrc' недопустим. objectURL НЕ revoke'ается — он лежит в tgState.mediaCache и будет переиспользован (лайтбоксом, повторным SAVE), а освободится при смене диалога.

playInCard(ctl): <video controls> / <audio controls> с src = objectURL полного файла, монтируется в .tg-media-player внутри карточки, превью/иконка/оверлей/длительность скрываются и восстанавливаются при остановке. Одновременно играет РОВНО ОДИН: stopPlayer() гасит предыдущий (иначе голосовое и видео перекрикивают друг друга). Отказ автовоспроизведения по политике браузера — не ошибка: у элемента есть controls.

initMedia() — идемпотентная привязка обработчиков лайтбокса, вызывается из chat.initChat. teardownMedia() — закрыть лайтбокс, снять карточки и наблюдателя, revoke всех URL; вызывается из main.js::teardownTelegram. _debugMediaState() — снимок для e2e.

РАНТАЙМ-ПРОВЕРКА (браузер, изолированный инстанс): лайтбокс открывается кликом по превью, картинка приходит blob:, подпись 'photo_1.jpg · 1280×720 · 1.2 MB', фокус на #tg-lightbox-close, Esc закрывает и очищает src, повторное открытие не перезапрашивает файл, SAVE отдаёт download='report _2026_.pdf' (санитизация сработала) с blob-href, <video> и <audio> монтируются с blob-src, одновременно в DOM ровно один плеер, превью восстанавливается после остановки, ошибка загрузки видна и в подписи лайтбокса.
