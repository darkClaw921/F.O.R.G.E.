# B24Frame

Конверт WS-кадра Bitrix24 на проводе (plugins/bitrix/src/ws/protocol.rs, Ф5): B24Frame<'a>{ portal_id: &'a str, #[serde(flatten)] msg: &'a B24ServerMsg }.

ЗАЧЕМ. Сокет /ws/bitrix один на все порталы, и по portal_id фронт решает, рисовать кадр в открытой ленте или поднять бейдж соседней вкладки. Поле обязано быть в КАЖДОМ кадре, включая будущие: разложи его по двум десяткам вариантов enum'а — и первый же новый вариант приехал бы без него молча, то есть чужая переписка утекла бы в активную ленту. Конверт делает это невозможным по типам: единственная точка отправки (ws::send_server_msg) собирает только его.

FLATTEN, а не вложенный объект: {"type":"message_new","portal_id":"acme",...} — форма всех существующих кадров не изменилась, старый фронт продолжает читать msg.dialog_id. Заимствует, а не владеет: кадры бывают тяжёлыми (message_new с полным текстом).

ЗАРЕЗЕРВИРОВАННЫЕ ЗНАЧЕНИЯ (ws/mod.rs): VACANT_PORTAL_ID='_vacant' — кадры слота, который ещё не портал (экран подключения); SOCKET_PORTAL_ID='_socket' — служебные кадры сокета (ping, portals). Подчёркивание невозможно у настоящего id: normalize_portal_id оставляет только [a-z0-9-]. Пустым portal_id не бывает никогда — это проверяет тест every_frame_on_the_wire_carries_a_portal_id.
