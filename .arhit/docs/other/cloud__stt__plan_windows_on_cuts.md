# cloud::stt::plan_windows_on_cuts

Нарезка вырезанного речевого файла на окна ПО ГРАНИЦАМ КУСКОВ РЕЧИ (Ф18.3, plugins/meet/src/cloud/stt.rs).

ЗАЧЕМ. plan_windows режет запись арифметически по 90 с, и реплика на границе страдает. Измерено живьём на приёмке Ф17: встреча 21d7274d, граница 180 с — пропало 7 секунд речи; встреча 877d1dc7, та же граница — задвоился фрагмент 'базы данных'. Арифметика при этом верна (окна встык, ничего не наложилось): ломается именно реплика на стыке, потому что модель ДОГОВАРИВАЕТ оборванную фразу по контексту, а следующее окно расшифровывает её настоящий хвост.

КАК. После write_speech_only_wav файл состоит из кусков речи (CutPlan.pieces), между которыми в записи была тишина. Окно набирается как группа ЦЕЛЫХ кусков суммарно не длиннее window_ms; кусок между окнами не разрезается никогда. Куски лежат в файле подряд, поэтому окна идут встык и покрывают файл целиком.

КРАЕВОЙ СЛУЧАЙ. Кусок сам длиннее окна (человек говорит без пауз полторы минуты) в запрос не влезает: предел облака по СТЕНЕ, обойти нечем. Такой кусок режется арифметически, но это единственный разрез внутри речи за прогон, и он попадает в CutWindows.forced_cuts, оттуда — в ForcedCut с именем дорожки и в журнал встречи событием cloud_stt_forced_cuts.

ВОЗВРАТ CutWindows { windows (в координатах ВЫРЕЗАННОГО файла), forced_cuts }.

Миксовый близнец — plan_windows_at_silence.
