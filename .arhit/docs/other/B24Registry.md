# B24Registry

plugins/bitrix/src/registry.rs — упорядоченный список порталов и их жизненный цикл. Состояние axum-роутера плагина (Router<Arc<B24Registry>>): состав меняется на живом процессе, поэтому портал выбирает каждый запрос экстрактором Portal, а не момент сборки роутера.

Чтение: list / connected / get(id) / primary / len / ids / shared / config_path. Изменение: add(webhook,title) / remove(id,purge_cache) / rename(id,title) / reorder(ids). Жизненный цикл: spawn_all / shutdown_all. Фикстуры: from_states / single.

СПИСОК НИКОГДА НЕ ПУСТ. На свежей установке и после отвязки последнего портала в нём стоит слот с ПУСТЫМ вебхуком и ПУСТЫМ id — место для портала, а не портал. Именно он показывает экран подключения. Потребителям (например GET /api/bitrix/portals) такие слоты фильтровать обязательно, иначе фронт нарисует вкладку-призрак.

add: пишет секрет в файл -> занимает пустой слот либо поднимает новое состояние -> воркеры -> публикует. Идемпотентна по URL секрета (тот же URL обновляет только title: два состояния на один вебхук дали бы два троттлера на общий бюджет 2 rps, а портал на превышение рвёт TCP, а не отвечает ошибкой). Ошибка подъёма откатывает запись в конфиге. Автомат подключения add НЕ трогает — его двигает проверка, которую делает вызывающий роут: set_login рассылает кадр login_state, и выставленный здесь disconnected давал бы на живом экране подключения вспышку «нет связи» перед «проверяем».

remove: снять со списка -> shutdown_portal (cancel + shutdown_workers с двухсекундным грейсом + analysis.shutdown) -> стереть секрет -> опционально кэш. Удаление последнего портала ставит на его место пустой слот, причём БЕЗУСЛОВНО: если общие настройки невалидны и build_state не проходит, слот поднимается напрямую через B24State::new. Пустой реестр недопустим настолько, что невалидность настроек его не оправдывает — без слота экстрактор отвечает 503 на каждый запрос, включая /status, и панель не может показать даже экран подключения.

purge_cache сносит каталог, ОТЛИЧНЫЙ от общего cache_dir и лежащий внутри него. До Ф6 пер-портальных подкаталогов нет, все порталы делят один каталог, и снести его значило бы стереть кэш соседей.
