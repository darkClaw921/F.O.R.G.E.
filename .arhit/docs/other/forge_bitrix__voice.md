# forge_bitrix::voice

Файл `plugins/bitrix/src/voice.rs` (580 строк) — адаптер голосовых панели Битрикс24
плюс расчёт огибающей (у портала её нет вовсе).

# ЗАЧЕМ

Тонкий адаптер между лексикой плагина и общим ядром `forge-voice`. Ядро не знает ни про
`CacheKey`, ни про `MediaMeta`, ни про `ApiError` панели — перевод живёт здесь.

# ОБЩИЕ ЭЛЕМЕНТЫ

- `KIND_VOICE = "voice"` — вид вложения в лексике панели.
- `voice_key(key)` — `CacheKey` панели → `forge_voice::VoiceKey` (адрес в сторе).
- `cache_stem(key)` — имя файла в медиа-кэше (`<stem>.bin`, `<stem>.meta.json`,
  `<stem>.wave.json`).
- `kind_of(meta)` — вид вложения по метаданным; сверяется с
  `forge_voice::gate::VOICE_KINDS`.
- `map_voice_error(e)` — `VoiceError` → `ApiError` панели: код отказа переживает
  перевод целиком, потому что фронт печатает человеку текст ПО КОДУ
  (`ERROR_TEXT` в `messenger/voice-transcript-core.js`), а не по сообщению. В сообщении
  движка бывают пути до бинарей и хвост stderr — показывать их человеку вредно.

# ОГИБАЮЩАЯ СЧИТАЕТСЯ ВСЕГДА

У Битрикса нет ни массива волны, ни упакованного атрибута — только файл. Поэтому
`ensure_waveform` идёт в ffmpeg для КАЖДОГО голосового, а `spawn_waveform(state, key,
meta)` запускает расчёт фоном при `commit` докачки, чтобы лента не ждала.
`cached_waveform(cfg, key)` и `attach_waveforms(cfg, dialog, messages)` дописывают
результат в DTO; второй берёт диалог отдельным параметром, потому что подкаталог кэша у
Битрикса выводится из диалога.

# КЛЮЧ МОЖЕТ НЕ СОБРАТЬСЯ

`voice_key(key)` и `cache_stem(key)` возвращают `Option` — единственные из трёх панелей.
Вызывающий обязан обработать `None`, а не разворачивать.

# ЛОВУШКА РАЗМЕТКИ (для фронта этой же панели)

Разметку карточек вложения строит `js/bitrix/attachments.js`, а НЕ `media.js`, и ему
нужен параметр `doc` — модуль гоняют в голом Node без глобального `document`.
