# auto_approve::run

Фоновый воркер авто-апрува (tmux-web/src/auto_approve.rs), тик 2с, спавнится в main.rs рядом с attention::watcher_loop. Принимает AppState целиком — нужен user_settings (тумблер читается каждый тик, переключение в UI действует сразу).

Цикл тика:
1. settings.auto_approve_enabled == false → continue ДО любых tmux-вызовов (opt-in инвариант: выключенная фича стоит ноль).
2. list_sessions, затем по каждой сессии list_claude_pane_targets → capture_pane_target по КАЖДОЙ панели.
3. classify_prompt → decide.
4. Гард стабильности (тот же hash_pane два тика подряд) + анти-луп (≤2 нажатий за серию «prompt непрерывно распознан»).
5. send_key_target в ТУ ЖЕ панель + tracing::info (session, pane, kind, choice, attempt) для аудита.
6. Prune карты состояний по ключам, встреченным в этом тике.

ВСЕ ОКНА (фикс tw-8jo): состояние ключуется парой сессия+панель ('<session>\0<win.pane>'), обход идёт по всем панелям всех окон, нажатие уходит в панель, где найден prompt. Раньше использовался capture_pane (активная панель активного окна) + send_key (автоподбор Claude-панели) — prompt в фоновом окне не подтверждался, а нажатие могло уйти в другое окно. Проверено вживую: сессия с активным окном 0 (zsh) и фоновым окном 1 с prompt'ом → в логе pane=1.0, нажатие в окне 1, окно 0 нетронуто.

Ключ состояния — панель, а не сессия: у окон независимые prompt'ы, и счётчик попыток одного не должен глушить другой.
