# forge-meet-routes

plugins/meet/src/routes/mod.rs — HTTP-поверхность плагина встреч.

В ШАПКЕ ФАЙЛА ЛЕЖИТ ТАБЛИЦА-КОНТРАКТ на 19 строк: сразу все пути всех фаз. Она источник истины для tmux-web/static/js/meet/api.js, и обе стороны обязаны совпадать дословно — расхождение даёт молчаливый 404, а не ошибку сборки. Все пути перечислены заранее именно затем, чтобы имена не расползлись, когда роуты начнут добавляться по одному.

/ws/meet/ingest НЕ СОЗДАЁТСЯ. НИКОГДА. Звук идёт через CDP-биндинг (Runtime.addBinding → window.__forge_<rand32> → Runtime.bindingCalled), а не через наш HTTP-сервер. Между инжектированным скриптом и сервером стоят четыре барьера: auth::csrf_guard отвергает апгрейд /ws/* с чужим Origin, дальше Bearer-auth, жёсткий connect-src в CSP у Meet и Private Network Access для запроса из публичного origin в loopback. Биндинг убирает все четыре разом, потому что убирает сеть. ВАРИАНТ «исключение в csrf_guard по одноразовому токену» НЕ ДЕЛАТЬ НИКОГДА: токен физически лежит в памяти страницы, которую контролирует третья сторона и которой мы ещё и CSP отключили ради инжекта, поэтому скрипт сайта прочитает его и откроет WS к главному серверу, где живёт /ws/attach, то есть терминал. Это превратило бы плагин записи встреч в drive-by RCE.

GET /api/meet/status — ЕДИНСТВЕННЫЙ РОУТ, КОТОРЫЙ НИКОГДА НЕ ПАДАЕТ. 200 отдаётся даже когда нет ни одного внешнего бинаря, нет моделей и нет базы: именно этим ответом пользователь узнаёт, ЧЕГО не хватает. Роут, отказывающий при неполном окружении, оставил бы человека без единственного источника диагностики. Ошибка базы не превращается в 500 — список активных встреч просто пуст. Отдаёт deps (бинари + gpu_metal), limits, РЕЕСТР ПЛАТФОРМ С РЕГУЛЯРКАМИ, активные встречи и настройки. 404 на этом пути означает «плагин выключен» и является КОНТРАКТОМ фронтового гейта.

GET /api/meet/badges?plugin=&chat_id=&min_id=&max_id= — батч состояний для ленты. GET с ДИАПАЗОНОМ, а не POST со списком id: это чистое чтение, id сообщений монотонны внутри чата, и диапазон это один индексный скан по префиксу PK, тогда как список из пятидесяти чисел дал бы пятьдесят точечных поисков. Обслуживается ТЁПЛЫМ ИНДЕКСОМ В ПАМЯТИ, без единого запроса к SQLite. Потолок диапазона MAX_BADGE_RANGE = 1000 сообщений.

QUERY РАЗБИРАЕТСЯ ВРУЧНУЮ (RawQuery + url::form_urlencoded), а не экстрактором Query: экстрактор отработал бы ДО тела хендлера и отдал 400 раньше, чем мы успели сказать «whisper не установлен», и пользователь чинил бы не то. Незнакомые параметры игнорируются — новый фронт может дописать версию клиента в URL.

ЛЕСТНИЦА ОШИБОК вынесена в check_ladder(Preconditions) — переиспользуемую Фазой 3 функцию, возвращающую ПЕРВУЮ сработавшую ошибку в порядке: готовность бинарей (409 *_unavailable) → слот (409 busy) → резолв встречи (404) → допустимость перехода (409 invalid_state) → разбор параметров (400). Порядок не стиль: проверь мы параметры раньше зависимостей, пользователь с неустановленным whisper получал бы 400 «плохой параметр»; проверь мы резолв раньше слота — неподключённый клиент мог бы прощупывать существование чужих записей.
