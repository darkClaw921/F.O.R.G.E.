# telegram-presence-and-read

Присутствие, индикатор набора и отметка о прочтении во вкладке Telegram (Фаза 5).

## Typing — ОТПРАВКА (js/telegram/chat.js)
Слушатель input на #tg-input -> noteTyping(): троттлинг 4с через чистую typingAllowed(lastAt, now, sameDialog) из format.js. Смена диалога сбрасывает окно — собеседник в новом чате обязан увидеть индикатор сразу, а не через остаток чужого окна. Telegram сам держит статус ~6с, поэтому чаще слать нечего и рискованно по FLOOD_WAIT.
cancelTyping() шлёт action=cancel при: отправке сообщения (submitPrompt), очистке поля до пустоты, переключении диалога (chat.openDialog), уходе текста подписью к файлу (upload.js). Идемпотентна: без активного статуса в сеть не ходит.
Ошибки typing глотаются молча (включая 429): из-за индикатора набора UI ломаться не должен.

## Typing — ПРИЁМ (js/telegram/main.js)
Состояние: Map 'dialogId|userId' -> {dialogId, label, timer}. У каждого печатающего СВОЙ таймер сброса TYPING_RESET_MS=6с — Telegram не присылает «перестал печатать», он просто перестаёт слать typing. action=cancel снимает запись сразу.
typingLabel(dialogId, userId): в личном чате dialog_id === user_id, поэтому title диалога берётся ТОЛЬКО при совпадении id — иначе любой участник группы получал бы имя самого диалога («Sofia, Sofia are typing…», реальный дефект, найденный рантайм-прогоном). Для участника группы: свой диалог с этим человеком, если он есть в списке, иначе id (тянуть профиль ради индикатора значит делать RPC на каждое нажатие клавиши собеседником).
Строка собирается чистой typingLine(names): один — 'is typing…', несколько — 'are typing…', свыше трёх имён — '+N'. В DOM попадает только активный диалог; события остальных запоминаются.
clearTypingIndicator() снимает ВСЕ таймеры и зовётся при смене диалога, уходе страницы в фон и logout'е — иначе быстрый перебор диалогов копит setTimeout'ы со ссылками на DOM.

## Mark-read (js/telegram/main.js)
scheduleRead(dialogId, maxId) — единственная точка решения. Триггеры: открытие диалога и докрутка ленты до низа (chat.js -> колбэк onRead из initChat), приход нового сообщения в открытый диалог.
Гейт видимости — чистая readAllowed(document.visibilityState, #telegram.hidden): скрытая вкладка браузера ИЛИ закрытая панель НЕ отмечают прочитанным. Иначе сообщения «читаются» в фоне: пользователь ушёл в терминал, а собеседник видит галочки и ждёт ответа.
Коалесценция: Map dialog_id -> max(message_id) + один таймер READ_DEBOUNCE_MS=800мс -> flushRead шлёт ОДИН POST /read с максимальным id на диалог. Открыть чат с 20 непрочитанными обязано стоить один запрос.
После успеха локально dialogs.setUnread(id, 0) + recomputeUnread() — бейдж гаснет, не дожидаясь эха read/in от сервера.
local.readSent (dialog_id -> уже отмеченный max_id) не даёт прокрутке плодить одинаковые запросы; WS read/in с другого устройства через noteReadFromServer поднимает ту же границу и снимает pending, поэтому своя вкладка следом не дублирует запрос (бейдж при этом гасит dialogs.onRead без сети).
read/out (собеседник прочитал наши) уходит в chat.onRead — структура готова под галочки '✓✓', в объём v1 они не входят.

## Online (js/telegram/dialogs.js)
onOnline(evt) правит ОДИН текстовый узел строки списка — никакой перерисовки: она сбрасывала бы позицию скролла, а статусы меняются постоянно и без участия пользователя. Присутствие user_id, которого нет в списке (контакт без переписки, участник группы), всё равно запоминается и всплывёт, когда диалог появится.
Формат даёт dialogStatusLine: [ONLINE] / [IDLE] last 3h / [OFFLINE]; у групп и каналов — [GROUP]/[CHANNEL] (присутствия там не бывает). Начальных значений в DialogDto нет (сервер их не отдаёт) — до первого апдейта честный [OFFLINE]; Telegram шлёт UserStatus только по контактам и только при изменении, поэтому пустое присутствие — норма, а не ошибка.
presenceOf(dialogId) отдаёт копию — шапка сессии (chat.updateHead -> sessionHeadText(dialog, count, presence)) читает статус, но карта присутствия остаётся единственной, в dialogs.js. chat.refreshHead() дёргается из main.js на WS online для открытого диалога.
renderOnlineCounter() -> #tg-status-right через onlineCounterText(online, known): пустая строка, пока статусов нет вовсе ('0 ONLINE' на свежей вкладке означало бы 'никого нет', а не 'мы ещё не знаем'); группы и каналы в счёт не идут.
clearPresence() при logout — статусы прошлого аккаунта после входа в другой это дезинформация.
