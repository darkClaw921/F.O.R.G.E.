# parse_token_input

Чистая функция plugins/vk/src/login.rs: разбирает то, что пользователь вставил в поле логина VK.

Сигнатура: pub fn parse_token_input(raw: &str) -> Result<ParsedTokenInput, LoginError>.

Принимает ТРИ формы: полный redirect-URL (https://oauth.vk.ru/blank.html#access_token=...&expires_in=0&user_id=...&email=...), голый фрагмент (access_token=...&...), просто токен. Дополнительно переживает URL с ? вместо # (VK так отвечает при code flow). Фрагмент важнее query: в blank.html?foo=1#access_token=... токен лежит после #.

Правила:
- пробелы и переносы вырезаются ОТОВСЮДУ, а не только по краям: адресная строка из терминала или письма приезжает разорванной по 80 колонок, и trim() не помогает; в самом токене пробелов не бывает;
- email не читается ВООБЩЕ — поля под него в ParsedTokenInput нет: адрес не нужен ни для одного вызова VK, а чего нет в структуре, то не утечёт ни в лог, ни в файл;
- user_id — ПОДСКАЗКА, источник истины users.get: токен мог быть выдан другому аккаунту, чем тот, чей URL скопировали;
- expires_in=0 (и отсутствие поля) = бессрочный токен, scope offline; ненулевой даёт expires_at(now);
- мусор в user_id/expires_in игнорируется, а не роняет разбор: без токена жить нельзя, без user_id можно;
- кандидат проверяется на длину (MIN_TOKEN_LEN=8, MAX_TOKEN_LEN=4096) и на алфавит [A-Za-z0-9._-]: это же отвергает вставленный URL без фрагмента (в нём : и /);
- функция ЧИСТАЯ: не паникует, не ходит в сеть и НЕ ПИШЕТ НИ ОДНОЙ СТРОКИ В ЛОГ — входная строка целиком является секретом. Тест parse_token_input_writes_nothing_to_the_log это фиксирует (мутация с tracing::warn! краснит его).

Разбор живёт ТОЛЬКО на бэкенде: вторая копия парсера на фронте была бы вторым местом, где можно ошибиться в обращении с секретом.
