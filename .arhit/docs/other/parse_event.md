# parse_event

plugins/vk/src/longpoll.rs::parse_event(raw: &[Value]) -> Option<LpEvent> —
разбор ОДНОГО события LongPoll.

СОБЫТИЕ — ЭТО МАССИВ, а не объект: [4, 7010, 17, 2000000001, …]. Первый элемент
— код, остальные позиционны и зависят от кода. Отсюда все ловушки разбора:
- события 51 и 62 несут НОМЕР беседы, а не peer_id (нужен + CHAT_PEER_BASE);
- у событий 8/9 (online/offline) id друга приходит СО ЗНАКОМ МИНУС;
- у 63/64 порядок from_ids/peer_id в разных версиях документации VK описан
  по-разному, поэтому разбор идёт по ТИПУ элемента, а не по позиции.

None означает «это не событие» (пустой массив, код не числом, не хватает
обязательных полей) — такой вход пропускается: уронить пачку из-за одного
испорченного элемента было бы худшим из решений.

Неизвестный код становится LpEvent::Unknown(code) — forward-compat: VK добавляет
коды без предупреждения, и отказ разбирать всю пачку означал бы, что новая фича
VK ломает realtime целиком. То же правило, что у битого WS-кадра во фронте:
warn и игнор.
