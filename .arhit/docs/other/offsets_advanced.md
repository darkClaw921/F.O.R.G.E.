# offsets_advanced

plugins/telegram/src/routes/dialogs.rs — страховка постраничной догрузки диалогов от вечного цикла.

Сигнатура: offsets_advanced(prev: (i32, i32), next: (i32, i32)) -> bool — «сдвинулась ли граница
пагинации вперёд».

Зачем: если сервер перестал двигать offset_date/offset_id, следующий запрос вернёт ТУ ЖЕ страницу.
Без обрыва это лишние RPC по кругу и прямой путь к FLOOD_WAIT на ровном месте.

Это ОДНА ИЗ ТРЁХ независимых страховок цикла folder_dialogs (все нужны, каждая ловит свой сценарий):
1. MAX_FOLDER_PAGES — жёсткий потолок числа RPC (MAX_DIALOGS / FOLDER_PAGE + 2, FOLDER_PAGE = 100);
2. offsets_advanced — сервер перестал двигать границу;
3. дедуп по dialog_id — закреплённые диалоги приходят в начале КАЖДОЙ страницы, а exclude_pinned
   включается только со второй; без дедупа дубликаты «набивали» бы limit вместо реальных чатов.
Плюс: страница без единого пригодного сообщения (только MessageEmpty) тоже обрывает цикл —
границы для следующего запроса из неё не получить.

Смежное: folder_dialogs_request(folder_id: i32) -> tl::functions::messages::GetDialogs — стартовый
запрос страницы конкретной peer-папки, вынесен отдельно ради unit-проверки folder_id.
