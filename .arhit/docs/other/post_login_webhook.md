# post_login_webhook

POST /api/bitrix/login/webhook (plugins/bitrix/src/routes/login.rs) — экран подключения. Работает с АДРЕСУЕМЫМ порталом (экстрактор Portal).

Порядок: разобрать (parse_webhook_input, три формы ввода, мусор отвергается 400 invalid_input ДО диска и сети) -> записать и применить (persist_webhook) -> проверить сетью (verify_webhook: profile -> scope).

persist_webhook — ключевое изменение Ф4 мультипортальности. Историческая реализация звала config::save_webhook_to, а та ЗАМЕНЯЕТ весь список порталов одной записью: со строкой вкладок подключение на одной вкладке стирало бы секреты всех остальных. Развилок ровно две, различает их ХОСТ вебхука:
1. Пустой слот свежей установки либо ДРУГОЙ хост — подключение нового портала через B24Registry::add (занимает пустой слот или заводит вкладку рядом). Старая вкладка остаётся: вставить чужой вебхук в чужую вкладку не значит потребовать удалить её портал.
2. Тот же хост, другой код — вебхук отозвали на портале и выпустили заново, то есть это ТА ЖЕ вкладка: секрет меняется в её записи через config::replace_portal_webhook_in, id, title и позиция сохраняются.

Тело содержит СЕКРЕТ целиком и не логируется ни целиком, ни по полям; в лог уходит только отпечаток и только из примитивов записи config.
