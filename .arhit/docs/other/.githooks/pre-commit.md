# .githooks/pre-commit

Bash pre-commit hook enabled through core.hooksPath=.githooks. It examines staged Rust/manifest files, runs the full Cargo workspace test gate when relevant, aborts the commit on failures, then increments only devforge patch version in tmux-web/Cargo.toml and the matching root Cargo.lock package and stages those two version changes. No hook arguments are consumed. The hook resolves REPO_ROOT from Git before testing. Inside the cargo-test subshell only, it enumerates repository-local variable names through git rev-parse --local-env-vars and unsets each using a quoted read loop. Git exports GIT_DIR, GIT_WORK_TREE, GIT_INDEX_FILE and related values into hooks; inheriting them would redirect temporary-repository fixture commands to the release worktree. Clearing them lets child Git commands discover their own repositories from cwd. The parent hook retains its original repository and index environment, so later version staging still addresses the release snapshot rather than a test fixture. Nonrepository settings such as GIT_EDITOR are intentionally retained. This follows the official Git githooks recommendation for foreign-repository operations without bypassing the normal test gate. Verified with bash -n, targeted diff checks and both real worktree::tests::repo_toplevel fixtures under a simulated linked-worktree hook environment; parent repository/index values remain unchanged after the subshell. Reference: https://git-scm.com/docs/githooks.
