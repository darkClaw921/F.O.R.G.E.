# forge_voice::gate

Модуль `plugins/voice/src/gate.rs` (381 строка) — ЛЕСТНИЦА ПРОВЕРОК «можно ли расшифровать
это прямо сейчас», выполняемая ДО единого байта работы.

# ЗАЧЕМ ОТДЕЛЬНЫМ МОДУЛЕМ

Проверок пять, они одинаковы для трёх мессенджеров и для двух движков, и каждая обязана
давать СВОЙ код отказа: фронт показывает человеку разный текст для «нет ffmpeg» и «слишком
длинное». Разложенные по роутам, они разошлись бы за первый же месяц. Здесь — чистая
функция, у которой на входе конфиг и запрос, на выходе план либо `VoiceError`.

# КЛЮЧЕВЫЕ ЭЛЕМЕНТЫ

- `VOICE_KINDS = ["voice", "audio", "voice_message", "audio_message", "music"]` и
  `is_voice_kind(kind)` — общая лексика трёх панелей. Вид вложения у трёх плагинов
  называется по-разному, и без общего словаря одна из панелей молча считала бы своё
  голосовое «не голосовым».
- `VoiceRequest` — вид вложения, длительность (если платформа её знает), запрошенный
  движок, признак `force`.
- `EnginePlan` — что делать: `Local` (с путями до бинаря и весов) либо `Cloud`.
- `check(cfg, req) -> Result<EnginePlan, VoiceError>` — сама лестница:
  1. вложение вообще звуковое? иначе `not_voice`;
  2. длительность в пределах потолка? иначе `too_long`;
  3. ffmpeg найден? иначе `no_ffmpeg`;
  4. для локального движка — бинарь whisper и файл весов на месте? иначе `no_whisper` /
     `no_model`;
  5. для облачного — ключ задан? иначе `no_cloud_key`.

# БИЗНЕС-ЛОГИКА

Порядок ступеней не случаен: сначала бесплатные проверки, потом обращения к файловой
системе. `force` пропускает кэш готовой расшифровки, но НЕ пропускает ни одну ступень —
принудительный запуск без GPU обязан дать `metal_unavailable`, а не тихий CPU.

# СВЯЗИ

Зовётся из `begin(...)` в `routes/voice.rs` каждого из трёх плагинов — той самой общей
функции, к которой сведены и кнопка «Расшифровать», и авторазбор. Значит лестница,
реестр `VoiceHub` и потолок параллелизма у ручного и автоматического режимов ОБЩИЕ.
