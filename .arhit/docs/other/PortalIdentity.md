# PortalIdentity

plugins/bitrix/src/state.rs. Личность портала для интерфейса: стабильный id и человеческое имя title. Живёт в B24State::portal под std::sync::RwLock — отдельной ячейкой от config, потому что обе части меняются в рантайме без рестарта: title переименовывает вкладку (B24Registry::rename), а id появляется у слота, который стартовал ПУСТЫМ (свежая установка) и получил вебхук из UI — до этого момента выводить идентификатор не из чего. std::sync, а не tokio: внутри нет ни одного await, зато спрашивает эту ячейку каждый HTTP-запрос (экстрактор портала, Ф3), каждый пер-портальный путь на диске (Ф6) и каждый WS-кадр (Ф5). Секрета не содержит — id выводится из ХОСТА вебхука, поэтому структура сериализуема и уезжает во фронт как есть. Доступ: B24State::portal_id(), portal_title(), portal_identity(), portal_display_name() (title, иначе хост портала, иначе id), set_portal_identity(), set_portal_title(). Источник истины именно эта ячейка, а не config.portal_id: последний знает только про старт процесса.
