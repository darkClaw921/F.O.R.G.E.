# voice_user_settings

НОВЫЕ ПОЛЯ `user_settings.json` (файл хоста `tmux-web`, `~/.forge/user_settings.json`),
добавленные фичей голосовых сообщений в Ф4.

# ПОЛЯ — ПО ОДНОМУ НА ПАНЕЛЬ

| поле | панель | смысл |
|---|---|---|
| `vk_voice_autotranscribe` | VK | разбирать новые голосовые сами |
| `telegram_voice_autotranscribe` | Telegram | то же |
| `bitrix_voice_autotranscribe` | Битрикс24 | то же |

Дефолт у всех трёх — ВЫКЛЮЧЕНО, и читаются они строго как `=== true` (фронт) /
`Some(true)` (бэкенд). Настройка тратит GPU либо деньги в облаке, поэтому включаться
сама она права не имеет, а любая порча файла обязана трактоваться как «выключено».

# ПОЧЕМУ ТРИ ПОЛЯ, А НЕ ОДНО ОБЩЕЕ

Потому что мессенджеры используются по-разному: рабочий Битрикс разбирать хочется, а
личный Telegram — не обязательно. Общее поле не дало бы этого выбора. А вот ДВИЖОК
расшифровки, наоборот, ОДИН на всех — он живёт не здесь, а в `voice.toml` рядом с ключом
polza.ai, и потому под селектом движка во вкладке стоит подпись `SHARED_HINT`.

# ЧУЖИЕ ПОЛЯ, КОТОРЫЕ ЧИТАЕТ АВТОРАЗБОР

`forge_voice::prefs::PrefsKeys` берёт из этого же файла белый список видимости бесед —
`*_filter_enabled` плюс пара списков, у каждой панели со СВОИМИ именами:
VK — `vk_visible_kinds` / `vk_visible_peers`, Telegram — `telegram_visible_folders` /
`telegram_visible_dialogs`, Битрикс — свои. Имена заданы таблицей, а не собираются из
префикса: собранное имя разошлось бы с хостом МОЛЧА, и тумблер просто перестал бы
действовать без единой ошибки.

# КТО ЧИТАЕТ

Пишет фронт (`settings/voice-tab.js` → `updateUserSettings`, PATCH хосту). Читает
плагин САМ, модулем `forge_voice::prefs`, на каждое входящее голосовое: канала настроек
от хоста к VK/Telegram/Bitrix не существует (у них нет своего `*-host-api`), и заводить
его ради двух булевых значений значило бы сломать границу плагина. Путь к файлу лежит
полем `user_settings_path` в конфиге плагина (`#[serde(skip, default = "…")]`), тесты
подставляют tempdir — никаких переменных окружения.
