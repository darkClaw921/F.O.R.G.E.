# voice_user_settings

ПОЛЯ user_settings.json (файл хоста tmux-web, ~/.forge/user_settings.json), добавленные фичей голосовых сообщений: тумблеры авторазбора (Ф4 фичи голосовых) и белый список бесед авторазбора (фаза forge-cvscope-f1).

# ТУМБЛЕРЫ — ПО ОДНОМУ НА ПАНЕЛЬ

| поле | панель | смысл |
|---|---|---|
| vk_voice_autotranscribe | VK | разбирать новые голосовые сами |
| telegram_voice_autotranscribe | Telegram | то же |
| bitrix_voice_autotranscribe | Битрикс24 | то же |

Дефолт у всех трёх — ВЫКЛЮЧЕНО, читаются строго как === true (фронт) / Some(true) (бэкенд). Настройка тратит GPU либо деньги в облаке, поэтому включаться сама она права не имеет, а любая порча файла обязана трактоваться как «выключено».

Три поля, а не одно общее: мессенджеры используются по-разному — рабочий Битрикс разбирать хочется, а личный Telegram не обязательно. А вот ДВИЖОК расшифровки, наоборот, ОДИН на всех: он живёт не здесь, а в voice.toml рядом с ключом polza.ai, и потому под селектом движка стоит подпись SHARED_HINT.

# СКОУП АВТОРАЗБОРА — ШЕСТЬ СПИСКОВ, ПО ДВА НА ПАНЕЛЬ

| поля | панель | гранулярность |
|---|---|---|
| vk_voice_scope_kinds / vk_voice_scope_peers | VK | типы бесед (user/chat/community) + peer_id |
| telegram_voice_scope_folders / telegram_voice_scope_dialogs | Telegram | папки аккаунта (inbox, archive, folder:N) + id чатов |
| bitrix_voice_scope_kinds / bitrix_voice_scope_peers | Битрикс24 | виды диалогов (user/chat/task) + DIALOG_ID |

Все Vec<String>, default пустой, семантика PATCH — ПОЛНАЯ ЗАМЕНА списка (снять галочку в merge-семантике было бы нечем). Гранулярность ровно та же, что у настройки видимости.

ПУСТОЙ СПИСОК = РАЗБИРАТЬ ВЕЗДЕ, и отдельного тумблера включения у скоупа НЕТ. Это решение, а не недоделка: скоуп добавлен к уже работающей фиче, и любое другое прочтение пустоты («ничего не разбирать») молча выключило бы авторазбор у всех, кто его уже включил. Тумблер же был бы третьим состоянием поверх двух списков — ровно та двусмысленность, из-за которой у видимости пришлось вводить filter_active() («включён, но пуст» = не фильтр).

Скоуп НЕ заменяет видимость и НЕ подчиняет её: видимость — вышестоящий фильтр, скрытая беседа не разбирается, даже если попала в скоуп (порядок ступеней — forge_voice::auto::decide, ступень OutOfScope стоит ПОСЛЕ Hidden). Списки намеренно отдельные: «не показывай мне этот чат» и «не трать GPU на этот чат» — разные просьбы.

Санитайзер и лимиты — ОБЩИЕ с видимостью: sanitize_visible_list, MAX_TELEGRAM_VISIBLE = 512, MAX_VISIBLE_ENTRY_LEN = 64. Записи там и там одной природы (короткие id и ключи групп), а второй санитайзер разошёлся бы с первым при первой же правке.

# ЧУЖИЕ ПОЛЯ, КОТОРЫЕ ЧИТАЕТ АВТОРАЗБОР

forge_voice::prefs::PrefsKeys берёт из этого же файла белый список ВИДИМОСТИ бесед — *_filter_enabled плюс пара списков, у каждой панели со СВОИМИ именами: VK — vk_visible_kinds / vk_visible_peers, Telegram — telegram_visible_folders / telegram_visible_dialogs, Битрикс — свои. Имена заданы таблицей, а не собираются из префикса: собранное имя разошлось бы с хостом МОЛЧА, и тумблер просто перестал бы действовать без единой ошибки. Тем же способом читаются и шесть полей скоупа (поля таблицы scope_kinds / scope_peers).

# КТО ЧИТАЕТ

Пишет фронт (settings/voice-tab.js → updateUserSettings, PATCH хосту; блок выбора бесед — своей кнопкой «Сохранить выбор», ровно двумя своими полями). Читает плагин САМ, модулем forge_voice::prefs, на каждое входящее голосовое: канала настроек от хоста к VK/Telegram/Bitrix не существует (у них нет своего *-host-api). Путь к файлу лежит полем user_settings_path в конфиге плагина, тесты подставляют tempdir — никаких переменных окружения.
