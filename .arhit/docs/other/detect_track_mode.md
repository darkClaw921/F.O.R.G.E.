# detect_track_mode

Определяет, можно ли считать трек человеком (plugins/meet/src/bot/mode.rs). ЧИСТАЯ функция; вся логика перечислена построчно табличным тестом the_mode_table_holds.

Порядок проверок: не прогрелись -> Unknown; несколько CSRC -> Mixed (прямое доказательство микса, а не косвенный признак); дорожек нет -> Unknown; один трек при более чем двух собеседниках -> Mixed; дорожек мало и они не растут за участниками -> Slots; иначе PerParticipant.

vcc.airlabs.pro (Ф13) даёт PerParticipant БЕЗ единой правки функции, и причина стоит понимания. LiveKit держит про запас ЛИШНИЙ удалённый аудиотрансивер: при двух собеседниках приходят три дорожки, у третьей нет потока (streams пуст, msid не приезжает) и track.muted остаётся true всю встречу. Догадка, что этот слот утащит вердикт в Slots при SLOT_TRACKS_MAX = 4, неверна: слот тянет число дорожек ВВЕРХ, а ветка Slots требует ОБРАТНОГО — собеседников должно быть больше дорожек. Тест a_deaf_spare_slot_never_turns_per_participant_into_slots гоняет пару «с лишней дорожкой / без» на 2..6 участниках.

Замер там же: getContributingSources() пуст на всех дорожках, а getSynchronizationSources() возвращает записи БЕЗ поля audioLevel — то есть дешёвого уровня от отправителя у площадки нет, и VAD строится только на собственном RMS.
