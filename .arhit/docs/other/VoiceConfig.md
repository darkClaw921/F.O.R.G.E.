# VoiceConfig

Конфиг расшифровки голосовых в чатах (~/.config/forge/voice.toml), крейт forge-voice, plugins/voice/src/config.rs.

Поля: engine (Engine::Cloud | Engine::Local), language, polza_api_key (SecretKey — не печатается ни в Debug, ни в логах), cloud_base_url, cloud_stt_model, max_duration_secs, max_parallel, local_timeout_secs, cloud_timeout_secs, path.

ЛЕСТНИЦА РАЗРЕШЕНИЯ ПОЛЕЙ: voice.toml (если поле есть и непусто) -> meet.toml -> встроенный дефолт. Наследование из meet.toml сделано ради человека: ключ polza.ai уже введён в настройках встреч, требовать его второй раз значит гарантированно получить два разошедшихся ключа и вторую копию секрета на диске.

СТАНДАРТ ЧАТОВ — ОБЛАКО. Дефолт engine = Engine::Cloud, и это ЕДИНСТВЕННОЕ поле, которое из meet.toml НЕ наследуется: stt_backend = "local" в настройках встреч не уводит чаты на локальный whisper. Причина: у встреч и чатов разные задачи. Час записи встречи локально и бесплатно — осмысленный выбор, ждать её всё равно никто не будет. Голосовое в чате живёт секунды, приходит в любой момент и читается сразу, поэтому не должно ни стоять в очереди к GPU, ни требовать 574 МБ весов на машине. Наследуй мы stt_backend, настройка одной вкладки молча меняла бы поведение другой, и заметить это можно было бы только по времени ответа. Закреплено тестом the_meet_toml_backend_never_switches_chats_to_the_local_engine.

Локальный движок включается ЯВНЫМ engine = "local" в voice.toml — его же пишет селект движка в настройках (settings::set_engine, toml_edit + forge-atomic, комментарии файла сохраняются). Селект показывает облако первым с подписью «по умолчанию» (tmux-web/static/js/settings/voice-tab.js::ENGINES).

Прочее: пустая строка в voice.toml — это не «выключить», а «не заполнил», поэтому проваливается на следующую ступень лестницы; битый файл даёт именованную ошибку VoiceError::Config с указанием, КАКОЙ из двух файлов чинить, а не панику; файл пишется с правами 0600, потому что в нём секрет; cloud_ready() — признак наличия ключа, наружу через роут …/voice/settings уходит только cloud_key_set: true.
