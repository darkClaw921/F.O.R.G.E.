# migrate_legacy_layout

Перенос legacy-раскладки диска в подкаталог единственного портала (Ф6.4 мультипортальности Битрикса). Живёт в plugins/bitrix/src/migrate.rs, зовётся из B24Registry::new ДО поднятия состояний портала.

ЗАЧЕМ. До Ф6 у плагина был один портал, и всё лежало в корне кэша: <cache_dir>/media/, <cache_dir>/uploads/, <cache_dir>/events.json, <cache_dir>/voice/, плюс ~/.forge/bitrix-chat-prompts.json. С Ф6 каждый портал адресует своё подкаталогом <cache_dir>/<portal_id>/ и файлом bitrix-chat-prompts-<portal_id>.json. Без переноса обновление выглядело бы как потеря данных: пустой кэш, забытые разборы и — дороже всего — поток событий с нуля (у im.v2.Event.* ретроспективы нет).

КОНСТРУКЦИЯ. Перенос идёт через std::fs::rename, а не копирование. Отсюда сразу три свойства: (1) гигабайтный медиа-кэш не удваивает диск, (2) каждая запись атомарна, (3) идемпотентность и устойчивость к прерыванию следуют из самого механизма, а не из флага «мигрировано» — источник после переноса просто не существует. Прерывание процесса возможно только НА ГРАНИЦЕ между записями, поэтому следующий запуск доделывает оставшиеся.

Медленный путь (слияние) включается, когда цель уже существует или когда rename невозможен (кэш и конфиг на разных ФС — cache_dir задают руками). Тогда записи переносятся по одной вглубь, и побеждает та, что уже лежит у портала: её написала более поздняя сборка.

ОГРАНИЧЕНИЯ. Переносится ЗАКРЫТЫЙ список имён LEGACY_ENTRIES (media, uploads, events.json, voice) — перенос «всего, что в корне» утащил бы подкаталоги других порталов и зарезервированный _vacant. Запускается только при РОВНО ОДНОМ портале в конфиге: увидев legacy-данные рядом с двумя порталами, владельца не угадать. Портал с id, совпавшим с именем из списка (media.bitrix24.ru => media), не съедает сам себя — src == target проверяется явно.

Ошибки наружу не всплывают: перенос это удобство, а не условие работоспособности. Всё уходит в лог. Тесты: 7 юнитов в migrate.rs + registry::tests::a_legacy_install_is_already_migrated_when_the_registry_is_up.
