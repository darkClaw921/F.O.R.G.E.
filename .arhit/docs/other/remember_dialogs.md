# remember_dialogs

plugins/telegram/src/state.rs — TelegramState::remember_dialogs(&self, dialogs: &[DialogDto]).

Засев серверных кэшей notify_overrides и archived_ids свежим листингом диалогов. Вызывается ОБОИМИ
путями GET /api/telegram/dialogs (iter_dialogs и сырой folder_dialogs) сразу после сборки DTO.

ПОЧЕМУ ЭТО ЗАКРЫВАЕТ D1: WS вещает new_message по ВСЕМУ аккаунту, а страница /dialogs — это
верхняя сотня (или триста при ?folder=). Чат вне страницы фронту неотличим от незаглушённого,
поэтому решение перенесено на сервер: кадр new_message несёт готовые muted/archived, взятые
из этих кэшей. Всё, что сервер когда-либо перечислял, он помнит.

ИНВАРИАНТ: записи ДОПОЛНЯЮТСЯ, существующие ключи перезаписываются, чужие НЕ УДАЛЯЮТСЯ. Полная
пересевка стирала бы знание о чатах из соседних страниц (основной список / архив / папки) и
возвращала бы дефект. Битые id (не разбирается dialog_key) молча пропускаются.

Оба замка (notify_overrides и archived_ids) берутся на запись один раз на весь вызов, а не на
каждый диалог — 300-500 диалогов иначе дали бы столько же пар lock/unlock.
