# TranscriptStore

JSON-стор готовых расшифровок голосовых (plugins/voice/src/store.rs). Раскладка <cache_dir>/voice/<peer>/<message_id>.<index>.json повторяет координаты медиа-кэша плагинов; корень передаётся ПАРАМЕТРОМ конструктора, потому что у VK, Telegram и Bitrix он в трёх разных местах. get() НЕ ПАДАЕТ НИКОГДА: битый JSON, обрезанный файл и чужая версия схемы (SCHEMA_VERSION) отвечают None — расшифровка это кэш, её всегда можно посчитать заново, а отказ на чтении означал бы, что один испорченный файл навсегда ломает кнопку у конкретного сообщения. Ошибка остаётся на записи: там она означает переполненный диск. put() пишет атомарно через forge-atomic под ПРОЦЕССНЫМ замком (write_lock): forge_atomic::tmp_path_for называет временный файл по PID, поэтому два ПОТОКА одного процесса, пишущие один путь, ломают друг другу rename — это не теория, ровно так падал тест параллельной записи. peer и message_id просеиваются (sanitise): ../ в чужом идентификаторе не уводит запись из каталога стора.
