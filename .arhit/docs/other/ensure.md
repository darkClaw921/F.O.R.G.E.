# ensure

forge_voice::waveform::ensure(bin, ffmpeg) -> Result<Vec<i32>, VoiceError> — идемпотентный расчёт звуковой огибающей файла из медиа-кэша плагина.

Читает сайдкар <stem>.wave.json рядом с байтами (read_cached); если его нет — считает compute_default (ffmpeg → PCM 8 кГц моно → RMS по 200 бакетам) и кладёт сайдкар атомарно (write_cached). Повторный вызов ffmpeg НЕ запускает — ради этого кэш и существует: повторных скачиваний одного вложения бывает сколько угодно, а форма записи не меняется никогда.

ПОЧЕМУ ОТДЕЛЬНЫЙ ФАЙЛ, А НЕ ПОЛЕ В .meta.json: мету пишет commit медиа-кэша РАНЬШЕ, чем появляется огибающая (расчёт идёт после коммита и не задерживает выдачу файла). Дописать поле означало бы read-modify-write чужого файла из фоновой задачи — гонку с get, который в этот момент мету читает, и риск потерять неизвестные задаче поля. Сайдкар пишется один раз и целиком, его отсутствие означает ровно «ещё не посчитали».

Формат: WaveformCache {schema: CACHE_SCHEMA_VERSION=1, waveform: Vec<i32>, computed_at}. Чтение НЕ ПАДАЕТ НИКОГДА (нет файла / битый JSON / чужая схема / пустой массив = «огибающей нет»), ошибка остаётся только на записи. Запись под глобальным замком: forge_atomic::tmp_path_for именует tmp по PID, и два потока одного процесса иначе рвут друг другу rename (та же причина, что в store.rs).

Потребители: plugins/bitrix/src/voice.rs и plugins/telegram/src/voice.rs (ensure_waveform / spawn_waveform после commit медиа-кэша), cached_waveform / attach_waveforms при выдаче ленты. Sweeper LRU обоих плагинов считает сайдкар в вес записи и удаляет вместе с ней; invalidate забирает его по префиксу имени.
