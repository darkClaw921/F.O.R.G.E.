# VkServerMsg

Кадры сервер->клиент WS-протокола плагина VK (/ws/vk, plugins/vk/src/ws/protocol.rs). Внешний тег type в snake_case; dialog_id и user_id — СТРОКИ (peer_id беседы = 2_000_000_000 + chat_id, точность JS-числа теряется), message_id — i32. АЧ-Ф3 добавил четыре кадра анализа чата, строго между DialogChanged и Resync (порядок заморожен и зеркалится в js/vk/ws.js, на это есть тест): analysis_started{run_id,dialog_id,kind,messages_used,truncated} — эмитится ПОСЛЕ сборки транскрипта, поэтому уже несёт его размеры, и отдельного кадра 'читаю историю' нет; analysis_delta{run_id,dialog_id,text} — КОАЛЕСЦИРОВАН на сервере (не чаще 120 мс либо по 400 символов), иначе сотни сырых дельт в секунду переполнили бы broadcast и дали Lagged -> resync -> цикл перезагрузок панели; analysis_done{run_id,dialog_id,ok,reason,input_tokens,output_tokens} (reason: cancelled|timeout|error, при успехе null и это часть контракта); analysis_error{run_id,dialog_id,message} — текст раннера ЦЕЛИКОМ, вместе с приклеенным хвостом stderr. Thinking-события Claude не вещаются вовсе. ВАЖНЫЙ ИНВАРИАНТ ПРИВАТНОСТИ: broadcast идёт без фильтрации (как у new_message), поэтому текст анализа виден во ВСЕХ вкладках пользователя, включая remote-сессию; это осознанное следствие модели, а фильтрация — обязанность фронта по паре (dialog_id, run_id).
