# attention::prompt_at_bottom

Гейт против «процитированного prompt'а»: настоящий prompt Claude Code рисуется В САМОМ НИЗУ панели, поле ввода и статус-бар на это время скрыты, а текст с теми же маркерами (diff тест-фикстур, cat исходника, лог) стоит ВЫШЕ поля ввода. Без гейта воркер авто-апрува однажды принял diff собственных тестов за AllowBroad-prompt и напечатал «2» в поле ввода чужой сессии.

СИГНАТУРА. pub(crate) fn prompt_at_bottom(pane: &str) -> bool.

АЛГОРИТМ.
1. Панель разбивается на строки, пустые отбрасываются (capture-pane дорисовывает панель до полной высоты окна).
2. С конца срезаются хвостовые виджеты — attention::trim_bottom_widgets: TODO-список задач и полоса фоновых агентов ('⏺ main' / '◯ run-phase (+6) …'). Оба рисуются ПОД prompt'ом и иначе выталкивают footer за окно проверки.
3. Берутся последние 4 непустые строки оставшегося блока и склеиваются через normalize_ws: в узком терминале footer переносится по словам, и 'Esc to cancel' может уехать со своей строки на соседнюю.
4. Совпадение с любым из BOTTOM_FOOTER_MARKERS ('Esc to cancel' — permission/plan/question; 'to edit in Vim' и 'shift+tab to approve' — plan-prompt редакции 2.1.x, у которого прежнего footer'а больше нет) → true.
5. Иначе Chrome-форма: prompt'ы Claude in Chrome отдельного footer'а не рисуют и заканчиваются самим меню (esc указан прямо в пункте Deny). Проверяются две последние строки на префикс вида '<цифра>. ' (с необязательным '❯') — при переносе по словам номер остаётся на предпоследней строке.

СВЯЗИ. Вызывается из attention::detect_claude_prompt (оранжевое свечение сессии) и auto_approve::classify_prompt (авто-апрув). Ложный false здесь означает, что и свечение, и авто-апрув молчат при висящем на экране prompt'е — исторически это самый частый класс багов фичи (перенос footer'а, TODO-виджет, полоса фоновых агентов).

ОГРАНИЧЕНИЕ. Гейт работает только по тому, что НАРИСОВАНО в панели. Prompt свёрнутого backgrounded-агента Claude Code на экран не выводит вовсе — его не видит ни этот гейт, ни tmux capture-pane.
