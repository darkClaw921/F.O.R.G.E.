# bitrix-bbcode

Парсер BB-кодов Битрикс24 (plugins/bitrix/src/bbcode.rs, Ф4, решение Р11).

ЗАЧЕМ. Портал хранит разметку прямо в поле text и добавляет её САМ: URL_PREVIEW:'Y' (значение по умолчанию у im.message.add) оборачивает голые ссылки в [URL]...[/URL], а системные сообщения целиком состоят из [USER=15 REPLACE]Имя[/USER]. Показать такой текст как есть нельзя — пользователь увидит квадратные скобки вместо имён.

ДВА ВЫХОДА. to_plain(text) -> String — чистый текст для превью в списке диалогов и для поля text в MessageDto (Ф5). to_segments(text) -> Vec<Segment> — дерево структурных сегментов для ленты, где каждый сегмент рисуется своим createElement.

HTML НЕ ГЕНЕРИРУЕТСЯ ВООБЩЕ. На фронте innerHTML запрещён (XSS-инвариант панели), поэтому единственная безопасная форма передачи разметки — структура, которую браузер соберёт узлами через textContent. Функция вида to_html в этом модуле появиться не может: она означала бы, что где-то во фронте есть присваивание innerHTML. Рендер узлами делает format.js::renderSegments.

ОБЪЁМ — ЗАКРЫТЫЙ СПИСОК (Р11): [B] [I] [U] [S] [URL] [USER] [CHAT] [DISK] [TIMESTAMP] [CODE] [QUOTE] [BR]. Расширять без правки Р11 нельзя: каждый новый тег — это новая ветка рендера во фронте и новый способ подсунуть туда чужие данные. Список заморожен тестом the_tag_table_is_frozen.

НЕЗНАКОМЫЙ ТЕГ — ТЕКСТ КАК ЕСТЬ, вместе со скобками. Это требование безопасности, а не снисходительность: молча выбрасывать неизвестную разметку значит незаметно менять смысл сообщения ([SPOILER]пароль[/SPOILER] превратился бы в 'пароль').

СЕГМЕНТ: {kind, text, value, children}. kind — 'text' | 'b' | 'i' | 'u' | 's' | 'url' | 'user' | 'chat' | 'disk' | 'timestamp' | 'code' | 'quote' | 'br' (строчные: значения уезжают в JSON и в data-атрибуты). value — адрес у url, идентификатор у user/chat/disk, время у timestamp. [USER=15 REPLACE]Максим[/USER] несёт И идентификатор (value='15'), И имя на момент отправки (children): имя может устареть, и фронт подставит свежее из peers, а по идентификатору строится клик. REPLACE — служебный флаг портала, значением считается ПЕРВЫЙ токен атрибута.

УСТОЙЧИВОСТЬ К БИТОЙ РАЗМЕТКЕ. Незакрытый тег не съедает остаток сообщения из to_plain (содержимое остаётся вложенными сегментами и участвует в тексте). Перекрёстная вложенность ([B]x[I]y[/B]z[/I]) разбирается без паники: закрывающий тег ищется по СТЕКУ открытых, а принудительно закрытый тег запоминается (orphans), чтобы его собственный закрывающий не вылез мусором в тексте. Глубина ограничена MAX_DEPTH=8 — тысяча вложенных [QUOTE] не роняет стек, а становится текстом. Содержимое скобок длиннее MAX_TAG_LEN=512 тегом не считается. Одиночные '[', ']' и '[/B]' без пары — просто символы. Есть fuzz-подобный тест на 2000 случайных строк из опасного алфавита (xorshift на фиксированном семени, без крейта rand).

ПРАВИЛО ТЕКСТА. У любого тега-контейнера plain = текст вложенных, а если их нет — value. Благодаря этому ни один символ исходного сообщения не пропадает даже у битой разметки. Угловые скобки и амперсанды НЕ экранируются: экранировать нечего, фронт кладёт их через textContent.
