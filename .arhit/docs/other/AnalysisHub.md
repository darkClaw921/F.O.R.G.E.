# AnalysisHub

plugins/chat-analysis/src/hub.rs (после выноса из plugins/vk/src/analysis/hub.rs, эпик forge-caport-1a-4fwj). Реестр активных анализов чата поверх forge_claude_runner::ClaudeRunner, общий для VK, Telegram и Bitrix. Конструктор new(cli_path, model, timeout_secs) + with_store(Arc<Mutex<PromptStore>>, path). Решает три задачи, которых нет у раннера: (1) дедуп по беседе — второй запуск для того же dialog_id возвращает StartOutcome::AlreadyRunning и НЕ порождает второго процесса Claude; (2) явный потолок MAX_PARALLEL_ANALYSIS=2 по разным беседам с мгновенным AnalysisError::Busy (семафор дал бы молчаливое ожидание — пустой попап без объяснений); (3) коалесцинг дельт в пампере (120 мс / 400 символов) — условие корректности, а не оптимизация. start(Arc<dyn AnalysisSink>, StartRequest) синхронно вещает кадр started, спавнит пампер и возвращает run_id; cancel/cancel_dialog взводят CancellationToken ДО abort'а (иначе пампер принял бы обрыв канала за нормальный конец и соврал бы ok:true) — финальный кадр после отмены шлёт РОУТ плагина; shutdown гасит все run'ы (иначе процесс claude пережил бы devforge). Сохранение результата — задача пампера и ТОЛЬКО при ok==true: analyze/refresh -> PersistTarget::Analysis (с last_message_id — точкой отсчёта следующего REFRESH), ask -> PersistTarget::Turn (пара в тред). В логи уходят только размеры, промпт не логируется никогда.
