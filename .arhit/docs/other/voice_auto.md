# voice_auto

Модули plugins/{vk,telegram,bitrix}/src/voice_auto.rs — воркеры автоматического разбора новых голосовых сообщений (Ф4 фичи голосовых).

ОБЩАЯ СХЕМА. Точка входа одна на плагин: on_new_message(state, msg) -> usize (число запущенных фоновых задач; ноль означает 'не произошло ничего'). Зовётся из потока событий плагина: VK — longpoll.rs на кадре new_message, Telegram — updates::handle_update, Bitrix — events::dispatch. Решение принимается СИНХРОННО и стоит разбора уже полученного DTO; докачка и движок уезжают в tokio::spawn, потому что поток событий держит ленту всего аккаунта. Решение — общее forge_voice::auto::decide, дедуп — forge_voice::auto::SeenKeys (поле voice_seen в состоянии плагина), запуск — общая с кнопкой функция routes::voice::begin(state, key, force), то есть та же лестница проверок и тот же реестр VoiceHub (общий потолок параллелизма: фоновая работа не отодвигает человека, нажавшего кнопку).

ГЕЙТ ФАЗЫ. При выключенном тумблере не происходит НИЧЕГО: ни докачки, ни запуска движка, ни записи в стор. Держится порядком (тумблер — первая ступень decide) и проверяется тестом the_gate_a_disabled_switch_writes_nothing_to_disk в каждом плагине: после события медиа-кэш пуст, стор пуст, hub.active() == 0, ключи не заняты.

РАЗЛИЧИЯ ПЛАТФОРМ.
- VK: вложений до десяти, у каждого свой index; вид и длительность есть прямо в MessageDto. Вид беседы для белого списка выводится из peer_id, но словарь ПЕРЕВОДИТСЯ: бэкенд говорит group, настройки — community (visibility_kind, есть тест).
- Telegram: одно вложение, index всегда 0. Автоматически берётся ТОЛЬКО kind == voice; обычное аудио (пересланный трек, подкаст) остаётся кнопке — час музыки в облаке стоит денег. Папку чата из dialog_id не вывести, поэтому при действующем фильтре разбирается лишь чат, отмеченный поимённо (как и во фронте).
- Bitrix: событие im.v2 НЕ несёт дескрипторы файлов — вид вложения в событии всегда file. Поэтому сначала дешёвые проверки, потом фоновая задача берёт ОДНУ страницу истории (load_page, LIMIT=1) ради дескрипторов и разбирает только kind == voice. Ключи занимаются ДО похода в портал, иначе повторная доставка сходила бы за страницей второй раз при бюджете 2 rps. Вид диалога выводится из DIALOG_ID (число = user, иначе chat); чат ЗАДАЧИ по одному id неотличим — белый список из одного вида task авторазбор в нём не включит, такие чаты отмечают поимённо.

ПОВТОРЫ. Список повторяемых кодов отказа ЯВНЫЙ в каждом плагине (not_connected, no_media, voice_busy, flood_wait у Bitrix, ...). Повторяемый отказ снимает пометку 'уже брали' — следующая доставка события попробует снова; незнакомый код считается окончательным, иначе получился бы бесконечный круг оплаченных прогонов.
