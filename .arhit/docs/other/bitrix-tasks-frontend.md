# bitrix-tasks-frontend

ФРОНТ ЗАДАЧ — tmux-web/static/js/bitrix/tasks.js (Ф10).

Карточка-шапка #b24-task-card НАД лентой. Это не вторая вкладка (Р2): чат задачи — обычный IM-чат, комментарии и сообщения один поток, поэтому «Задачи» здесь директория ~/tasks одного списка плюс обогащённая шапка над той же лентой.

ЭКСПОРТЫ:
* initTasks({onReloadFeed, onTasksLoaded}) — ДЕЛЕГИРОВАННЫЙ слушатель кнопок на самой карточке. Делегирование обязательно: карточка пересобирается после КАЖДОГО действия (матрица динамична), и слушатели на кнопках пришлось бы вешать заново каждый раз. Идемпотентна.
* showTaskFor(dialog) — вызывается при выборе строки колонки. Для обычного чата карточка ПРЯЧЕТСЯ и очищается: оставленная шапка чужой задачи над чужой лентой — самая дорогая ошибка модуля, потому что кнопки в ней рабочие. Известную карточку рисует сразу (шапка не мигает пустотой), свежую подставляет следом.
* refreshTask(taskId) — перечитывает карточку. Ошибка не гасит ленту: рисуется строка b24-task-error, лента задачи самодостаточна.
* runTaskAction(action) — POST /api/bitrix/tasks/:id/:action. После успеха: (1) карточка перерисовывается ответом сервера — матрица УЖЕ другая; (2) лента перезапрашивается через onReloadFeed(dialog_id) — портал написал в чат системное сообщение о смене статуса. Ждать realtime нельзя: событий задач вебхуку не приходит.
* applyTaskUpdate(task) — WS-кадр task_update (действие выполнили в другой вкладке). Кадр несёт карточку целиком, поэтому запроса не требует.
* loadTasks({filter,start}) — страница tasks.task.list в b24State.tasks. Нужна КОЛОНКЕ: строка чата задачи получает статус-точку и бейдж новых комментариев только когда карточка известна, а список диалогов такой информации не несёт вовсе (у него источник im.recent.get). Ошибка гасится молча — статус-точки украшение.
* resetTasks(), _debugTasksState().

КНОПКИ СТРОГО ПО task.actions. Сервер уже отфильтровал матрицу двумя ситами («портал разрешил ПРЯМО СЕЙЧАС» и «панель умеет выполнить»), фронт не добавляет своего сита и не подставляет ни одной кнопки от себя — иначе появилась бы кнопка, за которой нет действия. Подписи берутся из закрытого словаря format.js::TASK_ACTION_LABELS; НЕЗНАКОМЫЙ ключ рисуется как есть — спрятать кнопку, которую портал разрешил, хуже.

Р20 «ЗАДАЧА БЕЗ ЧАТА»: dialog_id пуст -> карточка показывается целиком, ниже идёт подпись «Обсуждение задачи ещё не начато», setPromptEnabled(false) блокирует #b24-input и #b24-send и вешает класс b24-prompt-locked. Действия при этом ДОСТУПНЫ — они не требуют переписки. Пустая лента без объяснения читается как поломка панели.

409 invalid_state — НЕ сбой, а признак устаревшей кнопки: статус мог поменяться в чужом браузере. Карточка тут же перечитывается, пользователь видит актуальный набор.

XSS-ИНВАРИАНТ: innerHTML запрещён полностью — заголовок и описание задачи пишут люди. Только createElement + textContent. Обход DOM идёт по data-b24-task, а не селекторами (как closestWithData в dialogs.js): тогда и фейковый DOM тестов остаётся простым, и опечатка в классе не даёт молча пустую выборку.

СМЕЖНЫЕ ПРАВКИ ФАЗЫ:
* format.js: TASK_ACTION_LABELS, taskActionLabel, taskDeadlineLabel (просрочку решает СЕРВЕР — второй экземпляр правила разъехался бы), taskOfDialog, taskNoChatNote, taskSummary — все чистые, покрыты node-тестом;
* dialogs.js: в строке задачи статус-точка (класс b24-task-dot-<status_key>, общий с карточкой — иначе два набора цветов разъехались бы), метка просрочки, бейдж newCommentsCount; колбэк onDir тянет карточки при входе в ~/tasks;
* api.js: getTasks/getTask/getTaskCounters/taskAction + PATHS (сверяется страж bitrix_contract.test.mjs);
* main.js: initTasks до initDialogs, showTaskFor при выборе строки, applyTaskUpdate из WS, resetTasks при logout и teardown, три новых поля счётчиков;
* state.js: b24State.counters += expired/new_comments/mentioned (второе семейство, не складывать с tasks);
* css/bitrix.css: карточка, статус-точки по семи статусам, ряд кнопок, метка просрочки, заблокированный prompt;
* sw.js: forge-pwa-v8 -> v9 (модули раздаются stale-while-revalidate, и без бампа первый reload выполнил бы старый main.js без импорта tasks.js).
