# MAX_FILE_BYTES

Потолок размера файла ~/.forge/vk-chat-prompts.json: 64 МиБ = 67 108 864 байт (plugins/vk/src/analysis/prompts.rs). Файл больше потолка читается как ПУСТОЙ, не разбираясь; проверка идёт по metadata ДО чтения в память, иначе подсунутый гигабайт съел бы RAM процесса ещё до парсинга.

Арифметика (актуальная, после появления треда вопросов):
одна запись беседы = MAX_PROMPT_CHARS + MAX_ANALYSIS_CHARS + MAX_THREAD_CHARS = 4 000 + 12 000 + 10 000 = 26 000 code points, каждый из которых в UTF-8 занимает до 4 байт; записей может быть MAX_CHATS = 500.
500 × 26 000 × 4 = 52 000 000 байт полезной нагрузки. Накладные расходы JSON (ключи, кавычки, экранирование, отступы to_vec_pretty) на текстах такого размера не превышают четверти: 52 000 000 × 1.25 = 65 000 000 <= 67 108 864.

Дальше потолок не растёт: вместо этого снижен MAX_THREAD_CHARS (12 000 -> 10 000). Файл читается в память ЦЕЛИКОМ, и обещать себе чтение сотни мегабайт ради худшего случая, которого в реальности не бывает, хуже, чем помнить чуть более короткий тред.

Это граница защиты, а не ожидаемый размер: реальный файл на два-три порядка меньше (живая проверка — сотни байт на две беседы). Арифметику держит тест the_file_cap_covers_the_worst_case: неверная цифра здесь означает ТИХУЮ потерю всех заметок, разборов и тредов пользователя без единой ошибки в UI.
