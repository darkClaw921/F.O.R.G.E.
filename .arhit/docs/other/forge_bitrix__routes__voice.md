# forge_bitrix::routes::voice

Файл `plugins/bitrix/src/routes/voice.rs` (627 строк) — HTTP-конверт расшифровки
голосовых для панели Битрикс24.

# ЧЕТЫРЕ РОУТА, ОДИН И ТОТ ЖЕ НАБОР В ТРЁХ ПЛАГИНАХ

| метод | путь | что делает |
|---|---|---|
| POST | `…/voice/:dialog/:mid/:index/transcribe` | запустить расшифровку (`?force=1` — заново) |
| GET  | `…/voice/:dialog/:mid/:index/transcript` | отдать готовый текст из стора |
| GET  | `…/voice/settings` | текущий движок + `cloud_key_set` + предупреждение |
| PUT  | `…/voice/settings` | переключить движок (`local` / `cloud`), запись в `voice.toml` |

# ОБЩАЯ `begin` — ГЛАВНОЕ АРХИТЕКТУРНОЕ РЕШЕНИЕ Ф4

Тело `post_transcribe` вынесено в `pub(crate) async fn begin(state, key, force)`.
Её же зовёт авторазбор (`voice_auto::run_one`). Поэтому лестница проверок
(`forge_voice::gate::check`), реестр идущих прогонов (`VoiceHub`), потолок
параллелизма, дедуп и запись в стор у КНОПКИ и у АВТОРАЗБОРА буквально одни и те же.
Скопированное второй раз тело разошлось бы с первым в первый же месяц.

# ЛЕСТНИЦА ОТВЕТОВ

`parse_key` — 400 на кривой адрес; вложение не звуковое — 400 `not_voice`;
файла нет в кэше — `obtain_media` пытается докачать, не вышло — 404;
прогон по этому ключу уже идёт — 409 (повторный клик безвреден);
нет ffmpeg / whisper / модели / ключа облака — 503 со своим кодом;
всё сошлось — 202 и `TranscribeResp` с ключом, по которому фронт ждёт кадры.
`force_requested` разбирает `?force=`.

# НАСТРОЙКИ И СЕКРЕТ

`VoiceSettingsResp` отдаёт выбранный движок, признак `cloud_key_set` и список
`VoiceWarningDto` (например «выбрано облако, а ключа нет»). САМ КЛЮЧ НЕ ОТДАЁТСЯ
НИКОГДА — `SecretKey` не сериализуется по построению. `SetVoiceSettingsReq`
принимает только `engine`; значение проверяется `forge_voice::settings::parse_engine`,
запись идёт в `voice.toml` через `forge_voice::settings::set_engine`.

# ГДЕ ЛЕЖИТ `voice.toml`

`forge_voice::config` ищет его РЯДОМ с конфигом самого плагина
(`config::paths_next_to`), а не по фиксированному пути и не через переменные
окружения. Благодаря этому тесты изолированы друг от друга без env — обход
известного флака `forge-oi1l`.

# ОСОБЕННОСТИ BITRIX24 — САМАЯ БЕДНАЯ ПЛАТФОРМА ИЗ ТРЁХ

1. **Длительности звука портал не отдаёт вовсе.** Значит ступень «слишком длинное»
   нельзя пройти по метаданным — потолок ловится уже по ДЕКОДИРОВАННОМУ звуку
   (`forge_voice::audio::probe_duration_ms`).
2. **Огибающей тоже нет.** Она целиком считается на бэкенде при `commit` докачки и
   ложится в сайдкар `<stem>.wave.json`.
3. **Ключ может не собраться:** `voice::voice_key` возвращает `Option`, и `dir_name(key)`
   выводит подкаталог кэша из диалога.
4. **Событие `im.v2` не несёт дескрипторы файлов** — вид вложения в нём всегда `file`,
   поэтому авторазбор вынужден догружать страницу истории.

Роутер подключается `.merge(voice::router())` в `plugins/bitrix/src/routes/mod.rs`.
