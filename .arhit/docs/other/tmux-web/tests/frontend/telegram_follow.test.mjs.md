# tmux-web/tests/frontend/telegram_follow.test.mjs

tmux-web/tests/frontend/telegram_follow.test.mjs (201 строка) — регресс-тест ЧИСТОЙ логики «следования» ленты Telegram за сообщением бота.

СТЕНД. Стенда нет и не должно быть: тест грузит РЕАЛЬНЫЙ static/js/telegram/follow.js через `await import()` (тот же приём, что у telegram_reply.test.mjs), потому что модуль намеренно без DOM и без сети. Решения «следовать ли», «докуда скроллить» и «не отменил ли пользователь следование прокруткой» проверяются здесь без единого фейкового узла. UI-половина (реальный доскролл в onEdited/onNewMessage, жизненный цикл ResizeObserver, prefers-reduced-motion) живёт в соседнем telegram_scroll_ui.test.mjs, краевые случаи — в telegram_scroll_edge.test.mjs.

ЧАСЫ ИНЪЕКТИРУЮТСЯ: `T0 = 1_700_000_000_000`, все функции получают nowMs параметром. Реальный Date.now() сделал бы тест зависимым от скорости машины, а окно следования измеряется секундами.

МИНИ-ФРЕЙМВОРК: `eq(actual, expected, label)` (сравнение по JSON.stringify) и `ok(cond, label)`; счётчики checks/failures; код возврата 0 — все ассерты прошли, 1 — есть [FAIL]. Запуск: `node tmux-web/tests/frontend/telegram_follow.test.mjs`.

ДЕВЯТЬ СЕКЦИЙ:
1. Константы контракта — FOLLOW_TTL_MS=12000, FOLLOW_SCROLL_PAD=8, FOLLOW_CANCEL_UP_PX=24 (значения зафиксированы: их молчаливое изменение меняет ощущение фичи);
2. Регистрация и срок жизни — noteFollow возвращает true/false, followTarget до/после истечения, граница ровно `now === untilMs` (ещё живо), часы, прыгнувшие назад, следование не рвут;
3. Адресность: чужой диалог и чужое сообщение — isFollowing/followsMessage на несовпадении, id как число и как строка, messageId===0 ⇒ следование за диалогом целиком;
4. Перецеливание, продление и отмена — второе нажатие перезаписывает цель и продлевает окно; clearFollow идемпотентен и возвращает «было ли»;
5. Решение «скроллить ли» — матрица scrollDecision по всем комбинациям atBottom/following плюс мусорные значения (truthy-строка не включает прокрутку: сравнения строгие);
6. Куда скроллить — scrollTargetForRow: доскролл на разницу, отсечение потолком maxTop, зазор pad, `row = null` ⇒ самый низ, и главное — НИКОГДА не тянет вверх (want <= scrollTop ⇒ null);
7. Отмена ручной прокруткой — cancelledByScroll: движение вниз не отменяет, ровно порог не отменяет, порог+1 отменяет;
8. prefers-reduced-motion — scrollBehavior(true)==='auto', иначе 'smooth';
9. Снимок для диагностики — _debugFollowState: нормализация пустых значений к null, untilMs как есть.

ЧТО СОЗНАТЕЛЬНО НЕ ПРОВЕРЯЕТСЯ ЗДЕСЬ: любое взаимодействие с DOM, порядок вызовов в chat.js, жизненный цикл наблюдателя — для этого есть два UI-файла.
