# notify_outcome

Разбор updateNotifySettings в плагине Telegram (plugins/telegram/src/updates.rs) — чистая функция.

Telegram шлёт ОДИН апдейт и для «заглушил конкретный чат», и для «заглушил все каналы»; отличаются они вариантом NotifyPeer (unit-варианты — глобальные, Peer(..) — адресные).

Варианты NotifyOutcome:
- Defaults(NotifyDefaults) — сменился глобальный дефолт категории; внутри готовое новое состояние всех трёх категорий;
- Dialog { peer, muted } — настройки конкретного диалога, muted уже разрешён с учётом наследования;
- Ignored — форумный топик (наш контракт их не адресует);
- Unknown — настройки унаследованы ЦЕЛИКОМ, а категория неизвестна.

Про Unknown. Параметр kind: Option<&str> — настоящая категория диалога из кэша TelegramState::dialog_kinds. Раньше её угадывали по тегу PeerId (NotifyDefaults::for_peer_id), а мегагруппа и broadcast-канал оба PeerKind::Channel: при заглушённых «всех группах» мегагруппа получала дефолт каналов (false) и звенела — причём это значение ещё и писалось в кэш (CacheEffect::DialogMuted), переживая сам апдейт. Теперь при неизвестной категории и полностью унаследованных настройках возвращается Unknown: ни события во фронт, ни записи в кэш. Правду добудет probe_dialog_flags на первом же сообщении. Явные настройки (silent или mute_until) категории не требуют вовсе — Unknown им не грозит.
