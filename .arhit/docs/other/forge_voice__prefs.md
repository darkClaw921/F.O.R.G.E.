# forge_voice::prefs

Модуль plugins/voice/src/prefs.rs — чтение пользовательских настроек панели из ~/.forge/user_settings.json (файл хоста tmux-web).

ЗАЧЕМ. У плагинов VK, Telegram и Bitrix нет host-api: хост знает про них ровно init -> register_routes -> spawn_workers, зависимости на AppState нет вовсе. Прокидывать через хост два булевых значения (тумблер авторазбора) значило бы сломать эту границу, поэтому плагин читает файл сам. Второй довод — 'без перезапуска': файл перечитывается на КАЖДОЕ входящее голосовое, и переключённый в браузере тумблер действует со следующего сообщения.

API:
- PrefsKeys { autotranscribe, filter_enabled, visible_kinds, visible_peers } — имена полей одной панели, ТАБЛИЦЕЙ, а не format!("{prefix}_..."): словарь у панелей разный (vk_visible_kinds против telegram_visible_folders), и собранное из префикса имя разошлось бы с хостом молча.
- Константы VK / TELEGRAM / BITRIX — три готовых набора ключей.
- Prefs { autotranscribe, filter_enabled, visible_kinds, visible_peers } с методами filter_active() и peer_visible(peer, kind).
- default_path() -> ~/.forge/user_settings.json (то же написание, что у хоста).
- read(path, keys) -> Prefs — НИКОГДА не падает: нет файла, битый JSON, чужие типы = Prefs::default (всё выключено).

БИЗНЕС-ПРАВИЛА. Флаг читается строго как булево true (как '=== true' во фронте). Включённый фильтр с ПУСТЫМ выбором фильтром не считается — как normalizeFilter().active во фронте. Неизвестная беседа при действующем фильтре считается НЕВИДИМОЙ: не разобрать голосовое — мелкая неприятность, а разобрать его в скрытой беседе — отправить чужую речь в облако вопреки настройке. Разбор идёт через serde_json::Value, а не строгую структуру: хост добавляет поля в этот файл постоянно, и строгость превратила бы каждое новое поле в молчаливое выключение фичи в трёх плагинах.

Читатели: plugins/{vk,telegram,bitrix}/src/voice_auto.rs. Путь файла лежит полем user_settings_path в конфиге каждого плагина (serde skip, как prompts_path) — тесты подставляют tempdir и не трогают настройки живого пользователя.
