# spawn_workers

Точка входа фоновых воркеров плагина VK (plugins/vk/src/lib.rs).

Состав по фазам: LongPoll-supervisor (Ф5, запускается ВСЕГДА — даже без токена, он сам ждёт авторизации на VkState::authorized_notify, поэтому вставка токена в работающем процессе поднимает realtime без рестарта), LRU-подчистка медиа-кэша (Ф7), GC незавершённых загрузок (Ф8) и ЧЕТВЁРТЫМ — стартовая проверка токена (Ф3), только если токен есть в конфиге.

Проверка запускается ОТДЕЛЬНОЙ задачей и регистрируется в VkState::workers: spawn_workers возвращается немедленно, поэтому медленная или отсутствующая сеть не задерживает биндинг порта хостом. Состояние при этом проходит Disconnected (из from_config) -> Checking (первое действие verify_token) -> результат, то есть UI на старте НЕ мигает «отключено».

Без токена сеть не трогается вовсе: запрос «расскажи о владельце пустого токена» гарантированно вернул бы код 5 и положил бы ошибку в лог у каждого, кто запустил devforge с --vk, но ещё не логинился.

Повторов НЕТ: одна проверка на старт. Протухший токен чинится только новым значением от пользователя, а цикл переверификаций лишь тратил бы бюджет 3 rps.
