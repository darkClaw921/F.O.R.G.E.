# sanitize_hotkeys

user_settings.rs — приводит карту переопределений хоткеев Telegram к безопасному виду. Проверяется только ФОРМА, не смысл: backend намеренно не знает ни списка действий, ни синтаксиса комбинаций (это реестр static/js/telegram/keys.js), иначе список пришлось бы держать синхронным в двух местах. Неизвестный id действия не ошибка — он останется лежать и будет проигнорирован фронтендом, что позволяет откатывать версии клиента без потери настроек. Отбрасываются: пустые после trim ключи и значения, ключи с символами вне [a-z0-9_.-], слишком длинные ключи/значения (>64), управляющие символы в комбинации. Лишние записи сверх MAX_TELEGRAM_HOTKEYS=64 отсекаются детерминированно (BTreeMap упорядочен). Лимит нужен не для красоты: мапа приезжает из браузера и сохраняется в файл, без потолка одна кривая отправка раздула бы user_settings.json неограниченно.
