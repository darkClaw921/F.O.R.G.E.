# for_portal

BitrixConfig::for_portal — ЕДИНСТВЕННАЯ точка, где дисковые пути разводятся по порталам (Ф6 мультипортальности Битрикса). plugins/bitrix/src/config.rs.

ЧТО ДЕЛАЕТ. Из общих настроек + личности портала (id, title, webhook) собирает пер-портальный BitrixConfig КОПИЕЙ. Разводит два пути: cache_dir => <общий кэш>/<portal_id>/ (медиа, staging загрузок, курсор событий, расшифровки голосовых) и prompts_path => <база>-<portal_id>.json (заметки, разборы, треды Q&A). НЕ разводит: config_path (файл секретов один на все порталы), user_settings_path (настройки хоста общие), voice.toml (настройка машины).

ПОЧЕМУ ЭТО ВАЖНО. Весь код под B24State остался нетронутым: media_cache, routes::upload и events по-прежнему строят путь от cfg.cache_dir и не знают, что порталов стало много. Изоляция достигнута подстановкой значения, а не правкой каждого места, где собирается путь.

ИДЕМПОТЕНТНОСТЬ. Корни запоминаются в двух #[serde(skip)]-полях: cache_root и prompts_root (пусто = «конфиг ещё не разведён, путь сам себе корень»). Без них повторное применение дало бы <кэш>/<портал>/<портал> — и портал после рестарта не нашёл бы ни медиа, ни курсора. Отсекать «последний компонент» вместо хранения корня нельзя: имя каталога кэша задаёт пользователь, и оно может совпасть с id портала. Повторное применение возможно реально: реестр, собранный from_states поверх готового состояния, отдаёт в add уже разведённый конфиг.

PATH TRAVERSAL. portal_id попадает в путь на ФС, поэтому компонент строит portal_dir_component: нормализует ЗАНОВО (остаётся только [a-z0-9-]) и отдельно проверяет результат на разделители и на ./.. . Пустой id (слот без портала) получает зарезервированное _vacant — у настоящего портала подчёркивания быть не может. Закреплено тестом a_hostile_portal_id_can_never_escape_the_cache_root.

FORGE_BITRIX_PROMPTS_PATH. Переопределение теперь ложится в prompts_root, то есть служит БАЗОЙ, в которую подставляется имя портала. Герметичность тестов сохранена при N порталах: без этого cargo test начал бы писать в живой ~/.forge разработчика.

Потребители: BitrixRootConfig::portal_configs, BitrixRootConfig::primary, registry::portal_cfg.
