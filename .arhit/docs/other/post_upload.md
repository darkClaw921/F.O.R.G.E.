# post_upload

Хендлер POST /api/vk/upload (plugins/vk/src/routes/upload.rs). Принимает сырые байты файла телом запроса и заголовок X-Forge-File-Name (percent-encoded), кладёт их в <cache_dir>/uploads/<upload_id>.part и регистрирует UploadEntry в state.uploads. К VK не обращается ВООБЩЕ. Порядок проверок дословный: авторизация (409) -> наличие Content-Length (411) -> лимит max_upload_bytes (413) -> имя файла (400) -> стриминг на диск; каждая ступень отвечает ДО чтения тела, поэтому клиент не заливает гигабайт впустую. Имя staging-файла определяется только upload_id (UUID v4), ни один байт клиентского ввода в путь не попадает. Перед регистрацией делается ленивая подчистка протухших записей (evict_stale), чтобы реестр не рос без предела даже без GC-воркера.
