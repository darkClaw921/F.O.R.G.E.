# api_client

Клиент API текущего токена: ОДИН экземпляр на токен.

Метод VkState (plugins/vk/src/state.rs, добавлен в Ф3). Кэширует пару (SecretToken, Arc<VkClient>) под RwLock и пересобирает клиент только при смене токена; во всех остальных случаях отдаёт тот же Arc, а значит и тот же троттлер.

Зачем: вместе с клиентом создаётся Throttle, и лимит 3 rps выдаётся VK НА ТОКЕН, а не на соединение. Второй экземпляр клиента означал бы второй бюджет запросов и код 6 у пользователя на ровном месте. Повторная проверка под write-lock обязательна: пока задача ждала блокировку, соседняя могла собрать клиент.

Пара хранится вместе с токеном, под который собрана, потому что VkState::set_token сбрасывает кэш: клиент держит копию секрета внутри, и оставленный после логина старый экземпляр продолжил бы ходить в VK с прошлым токеном (после logout — с уже стёртым).

Ошибка возможна только одна — невозможность собрать reqwest::Client (нерабочий TLS-бэкенд, исчерпание дескрипторов); роуты превращают её в 503 not_connected.
