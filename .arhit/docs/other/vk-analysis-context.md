# vk-analysis-context

plugins/vk/src/analysis/context.rs — транскрипт переписки VK для анализа через Claude (Фаза 2 плана «Анализ чата»).

ГЛАВНОЕ РЕШЕНИЕ: сеть и рендер разделены. fetch() ходит в VK и ничего не форматирует; render() — чистая функция над &[MessageDto], проверяемая на литеральных DTO без стенда и токена.

Константы: DEPTH_CHOICES=[50,200,500], DEFAULT_DEPTH=200 (2 запроса; 500 это 5 запросов ~1.7 с при лимите 3 rps), MAX_TRANSCRIPT_CHARS=60_000, MAX_MESSAGE_CHARS=1_500, MAX_PAGES=8 (страховка от бесконечной пагинации).

Transcript { text, messages_used, truncated, oldest_id } — текст плюс всё, что нужно шапке тега <transcript> в analysis/prompt.rs.

clamp_depth(i64)->i64 — приводит запрошенную глубину к БЛИЖАЙШЕМУ значению DEPTH_CHOICES (400 -> 500), а не к дефолту: клиент, попросивший больше, хотел больше.

fetch(&Arc<VkState>, &VkClient, peer, depth) -> Result<Vec<MessageDto>, ApiError> — цикл messages.getHistory по образцу routes::dialogs::get_messages. Курсор — МИНИМАЛЬНЫЙ id предыдущей страницы (start_message_id + offset=1). Обязательны peers.absorb_extended + routes::dialogs::resolve_names, иначе транскрипт вышел бы из голых числовых id. Выход: history исчерпана (страница короче запрошенной), набрана depth, MAX_PAGES, курсор не сдвинулся. Ошибки VK идут через routes::dialogs::map_vk_error, чтобы captcha_required дошла до фронта своим кодом. Результат сортируется по возрастанию id, дедуплицируется и режется спереди до depth.

render(&[MessageDto], budget) -> Transcript — одна строка на сообщение, порядок по возрастанию id:
  [07.08 12:31] Я: текст
  [07.08 12:33] Игорь Герасимов: ↳ Анна: «превью цитаты» | текст
  [07.08 12:40] Анна: [документ: смета.xlsx] [фото]
  [07.08 12:41] * событие: Анна пригласил участника
  [07.08 12:45] Анна: вот что прислал подрядчик | » переслано от Пётр (05.08): превью …ещё 4
out==true -> «Я», иначе VkUserDto::display_name(), пусто -> «—». Переводы строк внутри текста схлопываются (одно сообщение = одна строка). Текст режется по MAX_MESSAGE_CHARS через dto::truncate_chars (CODE POINTS, не байты — байтовый срез паникует на кириллице). Пересылки дают отступ »/»»/»»» по depth и «…ещё N» из FwdDto::omitted. Сообщение без текста, без вложений и без action ПРОПУСКАЕТСЯ.

ИНВАРИАНТ УТЕЧКИ: в транскрипте нет ни одного URL. Медиа берутся из attachments (НЕ из media — оно дубль первого) и превращаются в компактные метки: [фото], [видео: title], [аудио: title], [голосовое 0:14], [документ: file_name], [стикер], [граффити], [ссылка: title] (kind=other с link_url), [вложение: kind]. player_url/link_url не переносятся вовсе — это правило dto.rs:213, здесь строже, потому что промпт уезжает в ЧУЖОЙ процесс. Закреплено тестом rendered_text_never_contains_urls.

БЮДЖЕТ РЕЖЕТ СТАРЫЕ: строки набираются с конца (новые важнее — вопрос почти всегда о том, чем разговор кончился), при переполнении первой строкой идёт «[…опущено N более старых сообщений]» и truncated=true. Под маркер освобождается место за счёт самых старых уцелевших строк, поэтому текст никогда не вылезает за budget; если бюджет не вмещает даже маркер, его просто нет, а флаг truncated остаётся.

Даты форматируются в ЛОКАЛЬНОЙ зоне (%d.%m %H:%M): транскрипт читает модель, отвечающая человеку, и сдвиг на UTC ломал бы выводы вида «вчера вечером договорились».

Тесты (13, чистые, без сети): out/in, порядок по id, метка на каждый kind, отсутствие URL, action, reply_to, fwd с глубиной и omitted, пропуск пустых, бюджет + маркер + truncated, обрезка по code points на кириллице и emoji, кламп depth, крошечный бюджет, правдоподобная переписка целиком (печатается при --nocapture для осмотра глазами).
