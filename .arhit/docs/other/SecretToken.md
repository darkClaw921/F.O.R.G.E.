# SecretToken

plugins/vk/src/config.rs::SecretToken — обёртка над строкой access_token ВКонтакте.

ЗАЧЕМ. Токен VK это доступ ко всей переписке пользователя, поэтому утечка должна
быть невозможна по типам, а не по дисциплине:
- НЕ реализует Serialize (и не должен): положить его в любое DTO или в ответ
  роута — ошибка компиляции. Тест status_never_leaks_token_in_any_state
  фиксирует НАМЕРЕНИЕ и краснеет на мутации «добавить поле token_fingerprint».
- Debug вручную скрывает значение.
- Значение достаётся ровно одним методом expose(), и он зовётся в ЕДИНСТВЕННОМ
  месте — VkClient::post_once, где токен кладётся в форму запроса.

МЕТОДЫ. new(raw) — конструктор; expose() -> &str — значение (см. выше);
is_empty() — есть ли токен вообще (по нему строится стартовое состояние логина);
fingerprint() -> String — короткий отпечаток ДЛЯ ЛОГОВ. Отпечаток НИКОГДА не
уезжает в HTTP-ответ: /api/vk/status уходит в браузер, в devtools и в HAR-файл
поддержки, а часть секрета — это часть секрета.

СВЯЗИ. Живёт в VkConfig::access_token и в VkState::token (RwLock). VkState::
api_client() кэширует пару (SecretToken, Arc<VkClient>) — один клиент на токен,
значит один троттлер; set_token() ОБЯЗАН сбрасывать этот кэш, иначе после
перелогина запросы уходили бы со старым значением.

ХРАНЕНИЕ. Только локально: ~/.config/forge/vk.toml, права 0600, запись атомарная
(временный файл + rename), чужие ключи файла сохраняются. Файл с более широкими
правами чинится на месте с warn-логом: пользователь вполне мог создать его сам
командой echo и получить umask-овые 0644.
