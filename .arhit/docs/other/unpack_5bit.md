# unpack_5bit

forge_voice::waveform::unpack_5bit(packed: &[u8]) -> Vec<i32> — распаковка звуковой огибающей Telegram.

Telegram кладёт огибающую голосового в DocumentAttributeAudio.waveform СПЛОШНЫМ битовым потоком по 5 бит на отсчёт (значения 0..=31, TELEGRAM_MAX_VALUE). Границы отсчётов с границами байтов не совпадают: с третьего отсчёта каждый следующий разрезан между двумя байтами. Биты идут от МЛАДШЕГО к старшему внутри байта, байты — по порядку, то есть отсчёт i — это биты 5i..5i+5 сплошной битовой строки.

ХВОСТОВЫЕ БИТЫ ОТСЧЁТОМ НЕ СТАНОВЯТСЯ: длина результата считается делением нацело (len*8/5), огрызок в 1..4 бита отбрасывается — иначе у каждой записи появлялся бы хвостовой столбик случайной высоты. Пустой вход даёт пустой вектор (у обычного аудиофайла атрибута нет вовсе, и это не ошибка).

Рядом: fit(values, src_max, buckets) приводит чужую огибающую к общему виду (не длиннее buckets, диапазон 0..=WAVEFORM_MAX_VALUE=255) — лишние отсчёты УСРЕДНЯЮТСЯ по бакетам, а не прореживаются каждый N-й (прореживание теряет как раз пики). from_telegram(packed) — композиция обеих: готовое значение для MediaDto.waveform.

Потребитель: plugins/telegram/src/dto.rs::audio_waveform → MediaDto.waveform. Эталон в тестах: 0x20,0x7c → [0,1,31] → [0,8,255].
