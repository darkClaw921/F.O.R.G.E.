# replace_portal_webhook_in

config::replace_portal_webhook_in(path, id, webhook) -> anyhow::Result<bool> (plugins/bitrix/src/config.rs) — меняет СЕКРЕТ уже записанного портала, не трогая ни id, ни title, ни его место в списке. Возвращает true, если портал с таким id в файле нашёлся.

ЗАЧЕМ ОТДЕЛЬНЫЙ ПРИМИТИВ. Ровно один сценарий: вебхук отозвали на портале и выпустили заново — хост тот же, код другой, то есть это та же вкладка, а не новая. Пара remove_portal_from + add_portal_to дала бы тот же файл, но ценой двух записей (между ними портала на диске не существует) и потерянных title с позицией: add_portal_to дописывает в хвост.

Наследует все четыре инварианта save_portals_to: read-modify-write (чужие ключи и секреты соседей целы), 0600 в момент создания, tmp+fsync+rename, удаление tmp при ошибке. Идемпотентна: тот же вебхук не переписывает файл. Пустой вебхук — ошибка (отвязка — это remove_portal_from).

Зовётся из routes/login.rs::persist_webhook. Добавлена в Ф4 мультипортальности.
