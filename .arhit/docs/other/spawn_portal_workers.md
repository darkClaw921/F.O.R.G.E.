# spawn_portal_workers

plugins/bitrix/src/registry.rs. Запускает полный набор воркеров ОДНОГО портала Bitrix24: стартовая проверка вебхука (только если вебхук есть, Ф3), поток событий im.v2.Event.* (всегда, Ф7), фолбэк-синхронизация списка и счётчиков (всегда, Ф7), LRU-подчистка медиа-кэша (всегда, Ф8), GC незавершённых загрузок (всегда, Ф9). Возвращается немедленно: воркеры именно ЗАПУСКАЮТСЯ, а не выполняются, поэтому медленная или отсутствующая сеть не задерживает биндинг порта хостом. Набор ОДИН И ТОТ ЖЕ и для порталов из конфига, и для добавленного в рантайме через B24Registry::add — разойдись эти два пути, портал, подключённый без рестарта, молча остался бы, например, без подчистки кэша, и заметили бы это через неделю по забитому диску. Оба realtime-воркера стартуют ВСЕГДА, даже без вебхука: они ждут подключения на B24State::authorized_notify и до него не делают ни одного сетевого вызова — ровно это позволяет вставить вебхук в работающем процессе. Зовётся из B24Registry::spawn_all (все слоты), B24Registry::add (новый портал) и B24Registry::remove (восстановленный пустой слот).
