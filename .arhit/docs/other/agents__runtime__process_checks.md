# agents::runtime::process_checks

Build exact per-session process lifecycle observations from current/previous bindings and profile-scoped Claude registries. Interactive pane candidates require both pane ancestry and the same controlling TTY from bounded ps pid/ppid/tty/comm metadata; detached background descendants and Codex managed app-server services cannot claim the first launching terminal. For new Codex shared-daemon versions, unique ephemeral native terminal name plus exact SQLite threads.name/cwd/profile supplies identity for the TUI process, while journal events supply task state. Existing verified PID/start bindings survive temporary missing FD evidence; confirmed PID reuse or exit ends an epoch. Claude complete registries may close absent historical sessions, while incomplete/missing probes stay unknown. Runtime reads store.runtime_tasks so interrupted epochs preserve identity, and a live manual binding resumes on new activity. Never guess a pane by cwd, hash terminal output, log argv/env or expose titles.
