# dialog_groups

Разрешение папок чата для авторазбора голосовых Telegram (plugins/telegram/src/voice_auto.rs).

ПОЧЕМУ ПОЯВИЛОСЬ (баг). Раньше Telegram собирал Candidate с peer_kind: None — 'папку чата из id не вывести'. При этом форма настроек позволяет выбрать ПАПКИ в скоупе авторазбора (telegram_voice_scope_folders). Сочетание молча ломало фичу целиком: непустой скоуп по папкам + неизвестная группа = Prefs::peer_in_scope возвращает false для ЛЮБОГО чата, и ни одно голосовое не разбиралось, сколько бы папок человек ни отметил. Снаружи это выглядело как 'не работает чекбокс Автоматически разбирать новые аудиосообщения'.

ЧТО ДЕЛАЕТ. Возвращает ключи групп чата (dto::dialog_group_keys): папки аккаунта берутся из кэша TelegramState::folders (заполняется одним messages.getDialogFilters, сбрасывается по updateDialogFilter* через CacheEffect::FoldersChanged), сам чат — одним messages.getPeerDialogs через updates::fetch_peer_dialog (нужны kind, muted, archived, unread_count, bot, contact — их читают правила папок).

ЦЕНА. Запрос делается ТОЛЬКО когда действует хоть один белый список (prefs.filter_active() || prefs.scope_active()) и только для голосовых вложений — единицы раз в минуту в худшем случае. Сам чат спрашивается каждый раз (его mute/архив/непрочитанное меняются, а от них зависят exclude_*-правила), папки — один раз до ближайшей правки.

СТОРОНА ОТКАЗА. Нет подключения, нет peer'а в кэше, RPC не уложился в таймаут — возвращается пустой список, то есть 'группы неизвестны': при действующем белом списке разбирается лишь чат, отмеченный ПОИМЁННО. Не разобрать голосовое — мелкая неприятность (кнопка на месте), разобрать в исключённом чате — отправить чужую речь в облако вопреки настройке.
