# forge_voice::store

Модуль `plugins/voice/src/store.rs` (494 строки) — JSON-СТОР готовых расшифровок рядом с
медиа-кэшем плагина.

# ЗАЧЕМ

Требование пользователя: текст под голосовым должен пережить скролл, переключение беседы
и перезагрузку страницы. Значит расшифровка обязана лежать НА ДИСКЕ и переживать
перезапуск процесса, а базы данных у VK, Telegram и Bitrix для этого нет — у них есть
файловый медиа-кэш. Стор живёт там же и вытесняется вместе с медиа.

# КЛЮЧЕВЫЕ ЭЛЕМЕНТЫ

- `VoiceKey` — адрес вложения: беседа, сообщение, номер вложения. Один и тот же смысл во
  всех трёх плагинах, но собирается по-разному (у Bitrix ключ может не собраться вовсе —
  там `voice_key` возвращает `Option`).
- `Engine` — чем расшифровано (`local` / `cloud`); хранится вместе с текстом, чтобы
  человек видел, что именно дало этот результат.
- `Transcript` — текст, сегменты с таймингами, движок, модель, язык, время.
- `TranscriptStore` — чтение/запись/наличие по ключу; запись атомарная (`forge-atomic`).

# СВЯЗИ И ЛОВУШКИ

Пишется из `transcribe::run`, читается роутом `GET …/voice/:…/transcript` и дедупом
авторазбора. Дедупа `VoiceHub` НЕ ХВАТАЕТ: он держит только идущие прогоны, а стор — уже
готовые; прогон, кончившийся ОТКАЗОМ, не попадает никуда, и повторная доставка события
запускала бы его по кругу — поэтому в Ф4 добавлен `auto::SeenKeys`.
Атомарная запись важна вдвойне: `forge-atomic` именует временный файл по PID, и два
ПОТОКА одного процесса ломали друг другу `rename` (баг `forge-vcqz7`).
