# recovery_for

plugins/vk/src/longpoll.rs::recovery_for(f: &LpFailed) -> LpRecovery —
таблица «что делать при failed:N», дословно по протоколу VK.

  failed:1 (StaleTs)  -> UseTs(new_ts)       — взять ts из ответа, ключ прежний;
  failed:2 (ExpiredKey) -> RenewKeyKeepTs    — перезапросить getLongPollServer,
                                               но СВОЙ ts сохранить;
  failed:3 (InfoLost) -> RenewAll            — перезапросить всё и сбросить курсор.

САМОЕ ВАЖНОЕ РЕШЕНИЕ ФАЗЫ: при failed:2 ts из ответа НЕ БЕРЁТСЯ. Пока ключ
протухал, на сервере копились события, а свежий getLongPollServer отдаёт ts,
указывающий на «сейчас» — взяв его, мы молча потеряли бы всё, что пришло за
время отсутствия. Ошибка здесь видна ТОЛЬКО у пользователя (пропавшие
сообщения), поэтому она закрыта интеграционным тестом стенда, который следит за
последовательностью ts в query a_check.

При failed:3 new_ts из ответа тоже игнорируется: VK говорит «истории больше
нет», и единственный корректный курсор — тот, что придёт с новым ключом.
