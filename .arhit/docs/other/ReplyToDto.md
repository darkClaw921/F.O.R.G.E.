# ReplyToDto

plugins/telegram/src/dto.rs — проекция ОРИГИНАЛА, на который отвечает сообщение, в том виде, в
котором UI рисует приглушённую строку-цитату над текстом.

ЗАЧЕМ. До этого типа фронт получал только `MessageDto.reply_to_id` — голое число. Нарисовать по
нему цитату нельзя (нет ни автора, ни текста), а тянуть оригинал отдельным запросом на каждое
сообщение — гарантированный FLOOD_WAIT. Жалоба пользователя, закрытая этим типом: «не понятно, на
какое сообщение ответил собеседник».

ПОЛЯ (ровно 8, порядок фиксирован контрактом):
- message_id: Option<i32> — id оригинала В ЭТОМ ЖЕ диалоге. None ⇒ адресовать оригинал нечем:
  ответ на сторис либо ответ на сообщение ЧУЖОГО чата. Фронт по этому полю решает, кликабельна ли
  цитата: id чужого чата, подставленный в наш диалог, увёл бы на постороннее сообщение.
- sender: Option<String> — отображаемое имя автора оригинала (first_name, иначе username).
  None у постов от имени канала и у НАШИХ сообщений в личке (Telegram не присылает from_id там,
  где отправитель очевиден) — подпись фронт выводит из `out`.
- sender_id: Option<String> — id автора СТРОКОЙ Bot API-формата (инвариант №1 плагина).
- text: Option<String> — превью текста оригинала: одна строка, ≤ REPLY_PREVIEW_CHARS (140) code
  points, см. reply_preview_text. None у сообщений без текста (чистое медиа, сервисные).
- media_kind: Option<String> — photo | video | document | sticker | voice | audio | other.
  Словарь совпадает с MediaDto.kind, чтобы цитата называла вложение так же, как строка оригинала.
- quote: Option<String> — процитированный фрагмент, если отвечающий выделил кусок текста.
- out: Option<bool> — оригинал наш. None ⇒ обогащение ещё не делали (см. reply_needs_preview).
- unavailable: bool — оригинал показать нечем: удалён, недоступен либо это ответ на объект без
  сообщения (сторис). Фронт рисует «сообщение недоступно».

ЗАПОЛНЯЕТСЯ В ДВА ПРИЁМА:
1. reply_to_from_header — синхронно, из самого сообщения: message_id, quote, а для ответов в чужой
   чат ещё автор и вид медиа (Telegram кладёт их прямо в header);
2. enrich_reply_previews / enrich_reply_preview — из уже полученных оригиналов: sender, sender_id,
   text, media_kind, out.
Признак «второй приём ещё не делали» — `out == None` при `message_id.is_some()`; именно поэтому
первый приём НЕ ставит `out`, даже когда его можно угадать.

ОСОБЫЙ СЛУЧАЙ. При unavailable == true поле `quote` НЕ стирается: фрагмент приходит с самим
ответом, а не с оригиналом, и остаётся единственным, что можно показать при удалённом оригинале —
так же ведут себя официальные клиенты.

ИНВАРИАНТЫ. Деривы совпадают с MessageDto (Debug, Clone, Default, PartialEq, Eq, Serialize,
Deserialize). Ни одного `skip_serializing_if` — все ключи обязаны присутствовать в JSON (инвариант
№2 плагина: фронт различает «поля нет» и «значение null»).

СВЯЗИ: MessageDto.reply_to (владелец), reply_to_from_header, reply_needs_preview,
reply_ids_to_fetch, enrich_reply_previews, enrich_reply_preview, reply_originals_index;
на фронте — reply.js::normalizeReplyTo и chat.js::buildQuoteRow.
