# takeTrack

Берёт удалённый аудиотрек в работу (plugins/meet/src/bot/inject/capture.js). ИНДЕКС НЕ ПЕРЕИСПОЛЬЗУЕТСЯ: переиспользуй мы номер после ended, звук двух РАЗНЫХ людей склеился бы в один raw/track-N.wav. Тождество источника — MediaStreamTrack.id, а не объект-обёртка: один трек приходит и событием track, и обходом трансиверов, и присваиванием srcObject.

Ф13 добавила msid. id потока и есть msid из SDP; он кладётся в entry.msid и уезжает полем m ВМЕСТЕ с событием track_added, а не отдельным событием — потому что разбор журнала (pipeline::run::timeline_from_journal) заводит дорожку по первому упоминанию, и связь, приехавшая позже, к ней уже не привяжется. Потока нет (тап обхода приёмников его не видит, глухой слот LiveKit его не имеет) — поля просто не будет: выдуманный msid хуже отсутствующего.

Уточнение делает noteMsid из обработчика track: у SFU событие приходит на одну дорожку не единожды, и второй раз — при ренеготиации — уже с настоящим msid. Дорожку при этом заводить заново нельзя, а уточнить связь можно; уточнение уходит событием track_msid с прежним значением в поле was.
