# AnalysisSink

plugins/chat-analysis/src/sink.rs. Трейт, через который ядро анализа вещает кадры, ничего не зная о WS-протоколе плагина: started(run_id, dialog_id, kind, messages_used, truncated) / delta(run_id, dialog_id, text) / done(run_id, dialog_id, ok, reason, input_tokens, output_tokens) / error(run_id, dialog_id, message). Единственная развязка крейта от плагина: до выноса hub знал VkServerMsg, и вместе с ним в общий крейт переехали бы WS-протокол VK и его broadcast. Каждый плагин реализует трейт в четыре строки (VkAnalysisSink и будущие TgAnalysisSink/B24AnalysisSink). Методы СИНХРОННЫЕ намеренно: их зовёт пампер в горячем цикле дельт, и async разрешил бы реализации ждать внутри него. Порядок кадров: ровно один started (до первой дельты), 0+ уже коалесцированных delta, 0-1 error перед финалом, ровно один done — КРОМЕ отмены, где финальный кадр шлёт сам плагин. Тестовая реализация — testing::RecordingSink.
