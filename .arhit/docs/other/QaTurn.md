# QaTurn

Пара «вопрос пользователя — ответ модели» сохранённого треда Q&A беседы VK (plugins/vk/src/analysis/prompts.rs).

Поля:
- q: String — вопрос пользователя, прошедший sanitize_turn (нормализация переводов строк, вырезание управляющих символов, обрезка до MAX_TURN_CHARS = 5 000 code points);
- a: String — ответ модели, та же чистка;
- at: i64 — unix-время записи пары.

Где рождается: пампер analysis::hub по УСПЕШНО завершённому run'у kind == "ask" (PersistTarget::Turn). Оборванный отменой, таймаутом или ошибкой ответ парой не становится — тред уходит модели как контекст следующего вопроса, и огрызок отравил бы его так же, как отравил бы REFRESH огрызок разбора.

Где живёт: поле ChatPrompt.thread (Vec<QaTurn>) в ~/.forge/vk-chat-prompts.json, рядом с заметкой и разбором той же беседы. Сериализуется только непустым (skip_serializing_if = Vec::is_empty), поэтому файл, написанный до появления треда, после перезаписи остаётся байт-в-байт прежним.

Ограничения: не более MAX_THREAD_TURNS = 12 пар и MAX_THREAD_CHARS = 10 000 суммарных символов на беседу; при переполнении выбрасываются САМЫЕ СТАРЫЕ пары (PromptStore::push_turn -> clamp_thread). Каждое поле пары ограничено MAX_TURN_CHARS = MAX_THREAD_CHARS / 2, чтобы одна пара гарантированно влезала в бюджет и последняя (только что заданная) не выбрасывалась никогда.

На проводе: GET /api/vk/dialogs/:id/analysis отдаёт thread: [{q, a, at}] (пустой — как пустой массив); DELETE /api/vk/dialogs/:id/analysis/thread стирает весь тред.
