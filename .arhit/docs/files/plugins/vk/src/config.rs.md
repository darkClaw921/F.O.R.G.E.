# plugins/vk/src/config.rs

Конфигурация плагина VK и хранилище единственного секрета — пользовательского access-токена. ГЛАВНЫЙ ИНВАРИАНТ: newtype SecretToken реализует Deserialize, но НЕ реализует Serialize — и не будет; из-за этого DTO с токеном физически не собирается, то есть утечка секрета стала ошибкой компиляции, а не предметом дисциплины (у Telegram защита api_hash держалась на одном тесте). Debug у SecretToken печатает <redacted>, читать содержимое можно только через expose() — grep по expose() показывает ВСЕ места выхода секрета; fingerprint() даёт 'vk1.a…4f9c3f' ТОЛЬКО для логов (в HTTP-ответы отпечаток не кладётся). VkConfig: access_token, api_version (5.199), base_url (ОБЯЗАТЕЛЕН, дефолт https://api.vk.com/method — единственный способ подсунуть тестовый стенд и переехать на api.vk.ru без пересборки), cache_dir, max_upload_bytes, max_cache_bytes, rate_limit_rps (3), longpoll_wait_secs (25). Цепочка: default() -> load_from_file(config_path()) -> apply_env(FORGE_VK_*) -> validate_and_fix(); load() НИКОГДА не паникует — битый TOML, мусор в env и значения вне границ дают warn и дефолт. validate_and_fix дополнительно срезает хвостовой / у base_url (иначе {base}/{method} даёт двойной слэш и HTML-404 вместо JSON) и разворачивает ~ в cache_dir. Запись токена: save_token_to = read-modify-write TOML-таблицы (чужие ключи выживают) + write_secret_file (mode 0600 ДО первого write_all) + fsync + rename + set_owner_only; при любой ошибке tmp удаляется, целевой файл не меняется. clear_token_to — logout. ДОБАВЛЕНИЕ ПРОТИВ TELEGRAM: при КАЖДОЙ загрузке файл с правами шире 0600 чинится на 0600 с warn — токен пользователь вставляет руками и вполне может создать vk.toml через echo > с umask'овыми 0644.
