# plugins/vk/src/routes/error.rs

Единый контракт ошибок REST-поверхности VK: тело всегда {"error":{code,message,...}}. 16 кодов: invalid_input(400), unknown_dialog/unknown_message/no_media(404), not_authorized/invalid_state/captcha_required/no_messages_scope/send_forbidden/validation_required/unsupported_button(409), length_required(411), too_large(413), flood_wait(429), vk_error(502), not_connected(503). Против Telegram: 1:1 переносятся десять кодов, telegram_error переименован в vk_error, bot_timeout УДАЛЁН (у VK нечему таймаутиться — клиентской половины message_event в публичном API нет, поэтому нажатие либо превращается в обычную отправку, либо отвергается сразу как unsupported_button), добавлены пять новых. ApiErrorBody расширен тремя необязательными полями (captcha_sid, captcha_img, redirect_uri) — это НАДМНОЖЕСТВО телеграмного контракта: старый фронт-разбор (code+message+retry_after_secs) продолжает работать, потому что отсутствующие поля не сериализуются вовсе. Retry-After ставится только у flood_wait и зеркалит тело. Тест full_error_contract_table проверяет по каждому коду статус, код, непустой message И ТОЧНЫЙ состав полей тела (лишний retry_after_secs заставил бы фронт показать обратный отсчёт на ровном месте). Автоматических ретраев на уровне REST нет: коды 9 и 29 у VK — часовые и суточные лимиты, автоповтор только продлевает блокировку; единственное исключение (код 6 — промах нашего троттлера) живёт ниже, в транспорте Ф2.
