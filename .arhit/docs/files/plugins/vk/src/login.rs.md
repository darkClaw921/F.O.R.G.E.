# plugins/vk/src/login.rs

Чистая половина автомата логина VK: перечисление LoginFlow (NotConfigured, Checking, Disconnected{error}, InvalidToken{error}, NoMessagesScope{error}, CaptchaRequired{sid,img}, Authorized{user}), их машинные имена (kind()), предикаты is_authorized/is_configured, from_config и сериализуемая проекция to_dto -> LoginStateDto {state, error, user, captcha_sid, captcha_img}. Сетевые переходы (users.get -> messages.getConversations, разбор вставленного redirect-URL, captcha) приезжают в Ф3 за trait LoginBackend — граница проведена там же, где у Telegram, чтобы матрица переходов тестировалась без сети и без живого токена. Два состояния добавлены против Telegram, и оба не косметика: NoMessagesScope (VK код 15) — отдельный ЭКРАН, потому что токен исправен и предлагать 'вставьте новый' бессмысленно, нужен токен с другим scope, а без этого экрана пользователь вставляет один и тот же рабочий токен по кругу; Checking — иначе UI мигал бы 'отключено' на каждом старте, пока идёт фоновая проверка. VkUserDto {id (строкой), first_name, last_name, screen_name} + display_name() с предсказуемым откатом 'Имя Фамилия' -> '@screen_name' -> id; аватар намеренно не переносится — это ссылка на CDN VK, а прямым ссылкам VK в DOM делать нечего. Тест login_state_never_leaks_the_token фиксирует намерение (по типам токен сюда попасть не может).
