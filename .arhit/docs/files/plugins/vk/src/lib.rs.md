# plugins/vk/src/lib.rs

Точка входа плагина forge-vk (вкладка мессенджера ВКонтакте, opt-in --vk). Публичный API — РОВНО ЧЕТЫРЕ функции, буква в букву как у forge-telegram, host-параметра нет: init(VkConfig) -> Result<Arc<VkState>> (синхронный, сети НЕ трогает, ошибка = 'стартовать без плагина', а не фатальный сбой); register_routes(Router, Arc<VkState>) -> Router (мерджит /api/vk/* и /ws/vk, ОБЯЗАН вызываться ДО .fallback и .layer(auth) хоста — только так bearer_auth и csrf_guard покрывают роуты плагина); spawn_workers(&Arc<VkState>) (в Ф1 пуст; контракт на будущее — воркеры ЗАПУСКАЮТСЯ, а не выполняются, LongPoll-supervisor стартует всегда и сам ждёт авторизации на authorized_notify, поэтому вставка токена в работающем процессе поднимает realtime без рестарта); shutdown(&Arc<VkState>) (cancel токена + shutdown_workers, ИДЕМПОТЕНТНА — хост зовёт её из обработчика сигнала, который может сработать дважды). Модули: config (токен и цепочка загрузки), login (автомат из 7 состояний), dto (проводные структуры), state (разделяемое состояние), routes (HTTP), ws (WebSocket). Чего нет и не будет: session.rs и runtime.rs — у VK нет MTProto-сессии и постоянного сокета, единственный артефакт учётки это строка токена; отдельного crate vk-host-api тоже нет — плагину от хоста нужен только Router. Ограничение платформы, зашитое в дизайн: VK не выдаёт право messages обычным standalone-приложениям (error_code=15), поэтому у автомата логина есть отдельное состояние NoMessagesScope со своим экраном.
