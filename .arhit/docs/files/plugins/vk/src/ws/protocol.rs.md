# plugins/vk/src/ws/protocol.rs

Типизированный WS-протокол /ws/vk: внешний тег type в snake_case, id строками, message_id числом. VkServerMsg: login_state, new_message{message,muted,archived}, message_edited, message_deleted, typing, online, read, upload_progress, download_progress, notify_settings, unread_total, history_cleared, dialog_changed, resync, ping. VkClientMsg: только pong (вся мутация идёт по REST). Отличия от телеграмного набора: download_progress получает поле index (у сообщения VK до 10 вложений, и без индекса прогресс второго фото прилетал бы в карточку первого); notify_defaults_changed УДАЛЁН (у VK нет глобальных категорий mute — глушение только per-peer); folders_changed УДАЛЁН (папок нет); НОВЫЕ unread_total (событие LongPoll 80 отдаёт общий счётчик готовым, поэтому бейдж перестаёт быть суммой по загруженной странице), history_cleared (событие 13: VK не присылает id удалённых сообщений, только границу — message_deleted тут неприменим), dialog_changed (события 51/52: фронт перечитывает ОДНУ строку списка). muted/archived лежат на уровне КАДРА, а не внутри message: это свойство диалога, источник истины — сервер, иначе фронт судил бы по своей неполной странице списка и всплывал тостом от каждого заглушённого чата за её пределами; archived у VK всегда false и сохранён ради идентичности фронтового обработчика. Тесты: round-trip всех кадров, ПОБАЙТОВАЯ форма new_message (оба флага обязательны — кадр без них отвергается), уникальность snake_case-тегов, отвергание удалённых телеграмных кадров.
