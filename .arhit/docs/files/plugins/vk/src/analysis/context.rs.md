# plugins/vk/src/analysis/context.rs

Выгрузка истории беседы VK и рендер её в ТЕКСТОВЫЙ транскрипт для модели (фича «Анализ чата через Claude», АЧ-Ф2).

ЧТО ДЕЛАЕТ. Две половины: сетевая (постранично тянет messages.getHistory через общий rate-limiter плагина, до выбранной пользователем глубины) и чистая — render(), которая превращает список MessageDto в строки вида «Имя: текст». render() НЕ ходит в сеть и не логирует ничего: это гарантирует тест rendering_a_transcript_writes_nothing_to_the_logs.

ФОРМАТ СТРОК. Исходящее сообщение подписано «Я», входящее — отображаемым именем автора. Вложения превращаются в компактные метки ([фото], [видео: Заголовок], [файл: ...] — по метке на каждый из 9 видов kind). Служебные сообщения (action) рендерятся как события беседы. reply_to даёт префикс-цитату, пересылки несут глубину и хвост [...ещё N...]. Пустые сообщения пропускаются целиком. Порядок строк — строго по возрастанию id, независимо от порядка на входе.

НИ ОДНОГО URL. Отдельный явный инвариант (тест rendered_text_never_contains_urls): в транскрипт не попадает ни link_url, ни player_url, ни любая другая строка с '://'. Адрес во вложении — это трекинг-ссылка, отдавать её модели незачем, а печатать в интерфейс тем более.

БЮДЖЕТ. render(messages, budget) режет СТАРЫЕ сообщения (новые важнее), ставит маркер «[...опущено N...]» и выставляет truncated=true — этот флаг едет в атрибут <transcript truncated="true">, и SYSTEM_PROMPT прямо велит модели не делать выводов о начале разговора. Обрезка длинных сообщений идёт по code points, а не по байтам (кириллица и emoji рвались бы посреди символа). Крошечный бюджет (0, 1, 5 символов) деградирует без паники и без строки сверх лимита.

ГЛУБИНА. Значение из запроса клампится к закрытому списку DEPTH_CHOICES; DEFAULT_DEPTH дублируется во фронте (js/vk/analysis.js) намеренно, как страховка от старого index.html из кэша PWA.

СВЯЗИ. Потребитель — plugins/vk/src/analysis/prompt.rs (заворачивает Transcript в теги) и routes/analysis.rs (вызывает выгрузку до старта процесса). Возвращаемый Transcript несёт text, messages_used, truncated, oldest_id — первые два уезжают клиенту в ответе POST /analysis и в кадре analysis_started.
