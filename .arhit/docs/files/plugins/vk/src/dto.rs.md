# plugins/vk/src/dto.rs

Проводные структуры REST/WS-поверхности VK. В Ф1 объявлена только ФОРМА (поля, имена, сериализация) — наполнение приезжает в Ф4 (DialogDto/MessageDto), Ф6 (ReplyToDto), Ф7 (MediaDto из attach.rs) и Ф9 (ReplyMarkupDto). Форма нужна уже сейчас, потому что от неё зависит WS-протокол: кадры new_message/message_edited объявлены целиком в Ф1, чтобы фронтовый buildHandlers писался один раз по готовой таблице. Инвариант 'id — строки': dialog_id (peer_id) строкой (peer_id беседы = 2e9 + chat_id), message_id и cmid — i32. Отличия от телеграмной формы и их причины: pinned/archived/folder_id СОХРАНЕНЫ константами (VK не умеет ни закреплять диалоги, ни архивировать, ни папки) — идентичная форма важнее минимальной, каждое удалённое поле это if во фронте; attachments: Vec<MediaDto> с полем index у каждого (у сообщения VK до 10 вложений, и без индекса ключ медиа-кэша не различал бы два фото одного сообщения); cmid (conversation_message_id) едет рядом с id; fwd (рекурсивные пересылки, границы MAX_FWD_DEPTH=3 и MAX_FWD_PER_LEVEL=10, остаток в omitted — иначе один DTO раздуется на мегабайт); action (служебные сообщения, неизвестный kind сохраняется как есть); payload; important/can_write/can_write_reason у диалога. MediaDto несёт has_full=false и player_url для видео — вложение video у VK не содержит воспроизводимого файла. ReplyButtonDto.supported=false для callback/vkpay/open_app/location: это ограничение ПЛАТФОРМЫ (клиентской половины message_event в публичном API нет), и кнопка обязана рисоваться отключённой, а не исчезать. Сам payload кнопки в DTO не ездит — нажатие адресуется координатами {row,col}, что исключает подделку payload с фронта.

MediaDto.link_url (Ф7, добавлено при починке карточки ссылки). Адрес вложения link — тот, что прислал собеседник. Вместе с player_url это ЕДИНСТВЕННЫЕ поля-URL в MediaDto, и ни одно не адресует CDN вложений: player_url — страница-плеер VK (воспроизводимого файла у вложения video не существует), link_url — содержимое переписки. Оба пропущены через attach::http_url (белый список http/https) на сервере и через js/vk/format.js::webUrl в браузере. Утечку адресов ФАЙЛОВ по-прежнему стережёт attach::attachment_cdn_urls_never_leak, который вдобавок падает при появлении ТРЕТЬЕГО поля-URL.

MediaDto.has_thumb / has_full — не «мнение ветки разбора», а результат attach::url_for(att, Thumb|Full).is_some(). Обещание DTO и способность роута /api/vk/media его выполнить — одно знание, разъехаться нечему. См. док attach.rs и страницу vk-link-preview.
