# plugins/vk/src/state.rs

Разделяемое состояние плагина VK (VkState): создаётся один раз в init, живёт в Arc, раздаётся хендлерам через with_state, WS-соединениям и воркерам. Поля: config (неизменяемая часть), token: RwLock<SecretToken> (ЕДИНСТВЕННАЯ часть конфигурации, меняющаяся в рантайме — пользователь вставляет токен в UI; effective_config() отдаёт снапшот 'конфиг + свежий токен'), broadcast (ёмкость 1024, БЕЗ фильтрации по диалогу: бейдж и тосты обязаны работать с любой вкладки), login: Mutex<LoginFlow> (set_login делает запись и broadcast под ОДНИМ lock'ом, поэтому клиент не может увидеть переходы в обратном порядке), uploads (реестр незавершённых загрузок, TTL 30 мин, take_upload ПОТРЕБЛЯЕТ запись — это и есть защита от двойной отправки), lp_cursor (курсор LongPoll, наполняется в Ф5), health, workers + shutdown + authorized_notify, тайминги WS данными (чтобы тест закрытия по idle не ждал боевую минуту). ConnHealth Ok{at}/Down{since,reason} + HEALTH_GRACE_SECS=3 — это ответ на вопрос 'что значит 503 not_connected, если постоянного соединения нет вовсе': каждый успешный вызов ставит Ok, транспортный отказ — Down, а connected(now) возвращает false ТОЛЬКО внутри окна грейса. Грейс обязателен в обе стороны: без него один сетевой чих залипал бы навсегда (чинить здоровье нечем, если все запросы отвергаются на входе), а без окна вовсе 503 не возникал бы никогда и трёхступенчатая лестница проверок 409->503->404 стала бы фикцией. Повторный отказ НЕ сдвигает since — иначе череда сбоев продлевала бы окно бесконечно. Чего нет против Telegram: runtime, SessionLock, кэш PeerRef.
