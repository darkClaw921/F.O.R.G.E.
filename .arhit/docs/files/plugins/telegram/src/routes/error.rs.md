# plugins/telegram/src/routes/error.rs

# routes/error.rs — единый контракт ошибок REST-поверхности плагина

Тело ответа всегда одной формы, фронту не нужно угадывать:

  {\"error\":{\"code\":\"not_authorized\",\"message\":\"...\"}}
  {\"error\":{\"code\":\"flood_wait\",\"message\":\"...\",\"retry_after_secs\":42}}

## Таблица

| HTTP | code            | когда |
|------|-----------------|-------|
| 400  | invalid_input   | Telegram отверг введённые данные (код, пароль, телефон) |
| 409  | not_authorized  | аккаунт не привязан / сессия отозвана |
| 409  | invalid_state   | операция невозможна в текущем состоянии логина |
| 404  | unknown_dialog  | диалога нет или он недоступен |
| 404  | no_media        | у сообщения нет запрошенного медиа |
| 411  | length_required | POST /upload без Content-Length |
| 413  | too_large       | файл больше max_upload_bytes |
| 429  | flood_wait      | Telegram попросил подождать retry_after_secs |
| 503  | not_connected   | MTProto-соединение отсутствует |

## Почему решения принимаются по `code`, а не по статусу

409 бывает и `not_authorized`, и `invalid_state`, а реакция фронта на них
разная (показать форму входа против «сначала введите api_id»). Поэтому в
Фазе 6 добавлен тест `full_error_contract_table`: он прогоняет ВСЕ девять
конструкторов через настоящий `IntoResponse` и сверяет статус, Content-Type,
точный код, непустой message, наличие `retry_after_secs` РОВНО у flood_wait,
отсутствие полей сверх контракта и итоговый список кодов. Переименование кода
теперь валит тест, а не ломает вкладку молча.

## Маппинг ошибок логина

`impl From<LoginError> for ApiError` — единственное место, где ошибки MTProto
превращаются в HTTP; держится здесь, чтобы контракт нельзя было «разъехать»
между четырьмя роутами логина. Тест `every_login_error_variant_is_mapped`
содержит исчерпывающий `match` и ломает сборку, если у нового варианта
LoginError не назначен код.

## Политика FLOOD_WAIT

`429 flood_wait` НИКОГДА не ретраится автоматически: на логине блокировка
измеряется часами, повторные попытки её продлевают. UI обязан показать
обратный отсчёт.
