# plugins/tracker/tests/store.rs

Интеграционные тесты хранилища forge-tracker (21 тест; ещё 16 юнит-тестов лежат в модулях крейта).

ИЗОЛЯЦИЯ — условие гейта фазы, а не пожелание: каждый тест работает в tempfile::tempdir() и передаёт путь через TrackerConfig::with_store_path. Живой ~/.config/forge/tracker.json не открывается ни одним тестом, потому что там личные задачи пользователя и затереть их прогоном cargo test недопустимо.

ПОКРЫТЫЕ ИНВАРИАНТЫ:
- базовое: отсутствующий файл даёт пустой стор; данные переживают повторное открытие того же файла; файл создаётся с правами 0600; битый JSON не паникует и не мешает дальнейшей работе;
- CRUD: приоритет обрезается до 4, перевод в done ставит done_at и возврат снимает, повторное удаление даёт NotFound, reorder расставляет order по позиции;
- каскад: удаление задачи уносит её пункты и отрезки и не трогает чужие; вехи переживают удаление задачи; удаление списка сохраняет его задачи (list_id = None);
- чек-лист: порядок по order, toggle двигает done_at в обе стороны, прогресс 1/3 = 33 %, удаление пункта сохраняет его время за задачей;
- ТАЙМЕРЫ: два таймера по разным задачам идут параллельно; повторный start по той же задаче возвращает ТОТ ЖЕ id и не переставляет начало; стоп одной задачи не трогает активный отрезок другой; повторный стоп идемпотентен; таймер пункта чек-листа даёт entry с item_id и входит в сумму задачи ровно один раз (50 мин = 20 мин пункта + 30 мин задачи); незакрытый отрезок переживает перезагрузку стора; ручные отрезки валидируются, второй активный отбивается;
- агрегации: отчёт по day/task/list, Гантт помечает превышение (278 мин факта против 60 мин оценки) и терпит задачи без дат, суммы за сегодня учитывают идущий таймер.
