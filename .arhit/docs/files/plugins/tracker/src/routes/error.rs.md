# plugins/tracker/src/routes/error.rs

Единый контракт ошибок /api/tracker/*: тело всегда {"error":{"code","message"}}, как у forge-vk и forge-bitrix, чтобы фронт разбирал ошибку одним общим помощником. ApiError{status, code, message} с конструкторами bad_request (400), not_found (404), conflict (409), internal (500) и IntoResponse. From<TrackerError>: NotFound -> 404, Conflict -> 409, Io|Json -> 500 с ОБЩЕЙ формулировкой (путь к файлу пользователя и текст ошибки ФС уезжают только в tracing::error, наружу не отдаются). Граница 400/409 проходит по вопросу «изменится ли ответ, если состояние стора станет другим»: перевёрнутый отрезок (stopped_at <= started_at) не станет законным никогда — это 400, и роуты снимают его ДО обращения к стору; второй активный таймер той же задачи станет законным, стоит остановить первый — это 409. Стор разницы не знает и отдаёт Conflict в обоих случаях, поэтому маппинг в 409 остаётся страховкой на случай забытой проверки на роуте. ApiResult<T> — alias результата роутов.
