# plugins/tracker/src/routes/mod.rs

HTTP-поверхность плагина forge-tracker: сборка роутера и общие помощники. build_router(Arc<TrackerState>) -> Router вешает 24 маршрута — /api/tracker/{status,state,tasks(+reorder,+:id,+:id/status,+:id/timer/start|stop,+:id/items(+reorder,+:item_id,+toggle,+timer/start|stop)),entries(+:id),lists(+reorder,+:id),milestones(+:id),report,gantt} и /ws/tracker; зовётся из forge_tracker::register_routes ДО .fallback() и .layer(auth) хоста, чтобы Bearer-auth и csrf_guard хоста автоматически покрывали плагин в remote-mode. Таблица имён в шапке модуля ЗАМОРОЖЕНА — она источник истины для js/tracker/api.js (фаза 4), расхождение даёт молчаливый 404, а не ошибку сборки; сторожит её pub const ROUTE_PATHS + тест every_frozen_route_is_registered, который стучится по каждому пути четырьмя методами (признак «маршрута нет» отличается от «объект не найден» телом: наш 404 всегда несёт конверт error, 404 самого axum — пустое тело). status() отвечает 200 всегда, когда роуты зарегистрированы: выключенный плагин даёт 404 не телом, а ОТСУТСТВИЕМ роута (хост без --tracker не зовёт register_routes вовсе), поэтому гейт нельзя случайно включить правкой условия внутри плагина. state_snapshot() отдаёт StateDto. parse_body<T>(Value) переводит уже разобранный JSON в тело запроса и даёт 400 в общем конверте — прямой экстрактор Json<T> ответил бы на кривое тело кодом 422 мимо контракта ошибок. parse_status(&str) разбирает колонку канбана с перечислением допустимых значений в тексте ошибки. Три зафиксированных решения: ни одного path/root_path в запросах (задачи глобальные), перестановка это POST .../reorder, а не череда PATCH (порядок — свойство коллекции), тела через parse_body.
