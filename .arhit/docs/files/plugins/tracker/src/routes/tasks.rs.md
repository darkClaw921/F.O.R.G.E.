# plugins/tracker/src/routes/tasks.rs

Роуты задач: GET/POST /api/tracker/tasks, POST /tasks/reorder, GET/PATCH/DELETE /tasks/:id, PATCH /tasks/:id/status. create_task принимает CreateTaskReq (title обязателен и триммится, list_id, notes, status строкой, priority, tags, estimate_min, start, due) и отвечает 201 с созданной задачей. patch_task проверяет status ОТДЕЛЬНО и раньше общего разбора — иначе на неизвестной колонке сообщение было бы «unknown variant» без перечисления допустимых; дальше тело переводится в models::TaskPatch, где Option<Option<T>> различает три состояния (ключа нет — не трогаем, значение — ставим, null — сбрасываем). set_task_status — отдельный роут, а не частный случай патча: перетаскивание карточки самое частое действие канбана и не должно нести риск затереть соседние поля. reorder_tasks меняет order у произвольного числа задач и публикует reload (десяток task_upsert подряд гарантированно переполнял бы буфер канала на каждой сортировке). delete_task уносит вместе с задачей её пункты и отрезки (каскад в сторе): отрезок без задачи не имеет смысла ни в отчёте, ни на Гантте, а осиротевшие записи молча искажали бы суммы.
