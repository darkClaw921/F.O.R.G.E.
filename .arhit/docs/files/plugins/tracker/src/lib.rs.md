# plugins/tracker/src/lib.rs

Крейт forge-tracker — личный таск-трекер и тайм-трекер F.O.R.G.E. ЛИСТОВОЙ: не зависит ни от devforge, ни от других плагинов (перенос задачи в TODO делает фронт через существующий POST /api/todos, поэтому про TodoStore и AppState крейт не знает). Задачи ГЛОБАЛЬНЫЕ — root_path нет ни в одной структуре, стор один: ~/.config/forge/tracker.json. Контракт плагина — РОВНО ЧЕТЫРЕ функции, как у forge-vk: init(TrackerConfig) -> Result<Arc<TrackerState>> (синхронная, сети не трогает: у трекера нет ни токенов, ни внешних сервисов; битый tracker.json ошибкой не считается — пользователь получает работающий сервер и пустую вкладку); register_routes(Router, Arc<TrackerState>) -> Router (мерджит /api/tracker/* и /ws/tracker, host-параметра нет намеренно); spawn_workers(&Arc<TrackerState>) (возвращается немедленно, старт плагина не имеет права задерживать биндинг порта); shutdown(&Arc<TrackerState>) (cancel токена будит WS-циклы и сторожа, затем гасятся воркеры; идемпотентна). Воркер один — сторож забытых таймеров: раз в WATCHDOG_INTERVAL (15 минут) пишет warn про отрезки, идущие дольше STALE_TIMER_HOURS (12 часов). Он нужен именно из-за параллельных таймеров: несколько идущих отрезков норма, забытый со вчера не бросается в глаза среди законных соседей, зато молча дописывает часы в отчёт; останавливать сам он ничего не должен — сколько засчитать, решает человек. Периодического сохранения среди воркеров НЕТ и не будет: стор пишет файл в той же операции, что и мутацию, поэтому «сохранить по таймеру» было бы записью уже записанного. По той же причине shutdown не сохраняет стор: лишняя запись в момент остановки процесса — новый способ испортить данные, а не защита от потери. Модули: models, store, report, config, error (фаза 1), state, routes, ws, dto (фаза 2). Включение флагом --tracker — фаза 3, фронт — с фазы 4.
