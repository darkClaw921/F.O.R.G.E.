# plugins/tracker/src/dto.rs

StateDto — снимок состояния трекера, ОДИН на два канала: GET /api/tracker/state и первый кадр {kind:snapshot} в /ws/tracker. Общая структура не украшение: собирай каждый путь ответ сам, они разъехались бы, и расхождение проявилось бы не ошибкой сборки, а «после переподключения половина полей исчезла». Поля: lists, tasks, items, milestones, entries (сырые коллекции), active (идущие отрезки для блока // RUNNING — их может быть несколько, параллельные таймеры штатны), task_seconds (BTreeMap<task_id, i64>), progress (BTreeMap<task_id, ProgressDto{done,total,percent}>), totals (суммы за сегодня и неделю для статус-бара) и now — момент, НА КОТОРЫЙ посчитаны агрегаты. Поле now обязательно: без опорной точки фронт не может дотикивать идущий таймер, часы браузера и сервера расходятся и секундомер прыгал бы при каждом снимке. Агрегаты считает сервер, а не JS, потому что правила (время пункта чек-листа входит в сумму задачи ровно один раз, идущий таймер учитывается по now) уже написаны в report.rs и покрыты тестами. StateDto::from_store_at(store, now) — явный момент ради тестируемости; from_store(store) — то же на Utc::now().
