# plugins/tracker/src/state.rs

Разделяемое состояние плагина forge-tracker: TrackerState { store: TrackerStore, events: broadcast::Sender<TrackerEvent>, shutdown: CancellationToken, workers: Mutex<Vec<JoinHandle>> }. Создаётся один раз в forge_tracker::init и ходит по коду только как Arc<TrackerState> (образец — Arc<VkState> в forge-vk). TrackerState::new(&TrackerConfig) открывает стор и заводит broadcast-канал ёмкостью EVENT_BUFFER = 64 (как /ws/todos хоста): буфер обязан пережить пакетную операцию UI (перетащили десяток задач в канбане), но не превращаться в очередь, часами хранящую события для отвалившейся вкладки. emit(event) публикует событие и НАМЕРЕННО проглатывает ошибку: broadcast::send даёт Err при нуле подписчиков, а это штатное состояние сервера с закрытой вкладкой. register_worker/shutdown_workers ведут реестр фоновых задач; shutdown_workers сначала ЗАБИРАЕТ список из-под замка (std::mem::take), и только потом абортит ручки — иначе замок держался бы всё время ожидания и параллельный register_worker встал бы на нём намертво (беда, за которую уже платили в forge-vk). Стор синхронный (std::sync::RwLock), асинхронны только те части состояния, которые реально ждут: канал и реестр воркеров.
