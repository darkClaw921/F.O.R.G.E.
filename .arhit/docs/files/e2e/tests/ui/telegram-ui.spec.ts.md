## Почему мок, а не живой плагин

Сервер для e2e поднимается БЕЗ `--telegram` (e2e/playwright.config.ts), поэтому
`GET /api/telegram/status` отвечает 404 — и это ПЕРВЫЙ проверяемый сценарий:
кнопка ✈ обязана остаться скрытой. Всё остальное включает плагин через
`page.route('**/api/telegram/status')` с телом `{enabled:true,state:'disconnected'}`.
Перехват ставится ДО `goto`, потому что `initTelegramGate` спрашивает статус в
момент загрузки страницы. Реальный вход в Telegram не выполняется НИКОГДА —
учётных данных в CI нет и быть не должно.

## Сценарии

Гейт кнопки (без плагина / с плагином), открытие панели и скрытие остальных,
каркас панели, login-оверлей на шаге 1 (поля, ссылка на my.telegram.org,
api_hash как password), доступность баров поверх оверлея логина, тема
(атрибуты + переживание reload), цикл тумблера auto->dark->light->auto,
скриншоты обеих тем в test-results/telegram-{dark,light}.png, уход на другую
вкладку и возврат (консоль без ошибок), отсутствие горизонтального скролла,
отдача завендоренного шрифта с `font/woff2`, ОТСУТСТВИЕ запросов во внешние
домены (проверка запрета CDN).
