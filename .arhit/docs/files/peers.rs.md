# peers.rs

plugins/vk/src/peers.rs — кэш имён и присутствия собеседников (Ф4.3, НОВЫЙ).

ЗАЧЕМ. Одноимённый модуль Telegram решает другую задачу — добывает access_hash. У VK адресация тривиальна (peer_id самодостаточен), поэтому здесь остаётся ровно одно: превратить id в отображаемое имя, НЕ ПОТРАТИВ лимит 3 rps.

ГЛАВНОЕ ПРАВИЛО. Первый источник имён — блоки profiles/groups, которые VK кладёт в ответ при extended=1 (getConversations/getHistory/getLongPollHistory). PeerCache::absorb_extended(profiles, groups) забирает их из УЖЕ ПОЛУЧЕННОГО ответа и сети не касается вовсе. Отдельные users.get/groups.getById (resolve_uncached) идут только для промахов и ПАЧКАМИ по RESOLVE_BATCH=100: резолв по одному id при бюджете 3 rps означал бы, что беседа из тридцати участников открывается десять секунд.

СТРУКТУРЫ. PeerInfo{id,title,username,photo,is_friend,online,last_seen,deactivated,at} + to_user_dto() (у пользователя имя разбивается на first/last по первому пробелу, у сообщества название остаётся ЦЕЛЫМ в first_name — иначе «Тестовое сообщество» разъехалось бы). PeerCache{inner: std::sync::RwLock<HashMap>, ttl, capacity} — синхронный намеренно: проекция DTO зовётся на КАЖДОЙ строке ленты, и .await там был бы точкой отмены на горячем пути.

ГРАНИЦЫ. PEER_TTL_SECS=600 (имя и особенно присутствие протухают: ушедший офлайн не должен светиться зелёной точкой до перезапуска devforge), PEER_CACHE_CAPACITY=2000 с вытеснением самых старых (кэш наполняется ИЗ ОТВЕТОВ VK, то есть его ростом управляет не наш код).

ЗНАК СООБЩЕСТВА. В блоке groups id ПОЛОЖИТЕЛЬНЫЙ, в peer_id — со знаком минус. Минус ставится ровно в одном месте (absorb_extended_at) — это самая вероятная ошибка модуля; resolve_uncached, наоборот, снимает знак перед groups.getById, иначе VK отвечает кодом 100.

missing() отбрасывает беседы (>= CHAT_PEER_BASE), ноль и дубликаты — спрашивать о них users.get значит гарантированно потратить запрос впустую. Отказ ОДНОЙ пачки не отменяет остальные: имена — украшение, и терять из-за них страницу истории нельзя.

Реализует crate::dto::PeerNames; живёт в VkState.peers; logout чистит (state.peers.clear() в routes/login.rs).
