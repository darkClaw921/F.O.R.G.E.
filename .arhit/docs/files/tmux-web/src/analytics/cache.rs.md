# tmux-web/src/analytics/cache.rs

Снимок индекса аналитики в ~/.forge/analytics-cache.json.

## Зачем
Первый полный проход по архиву транскриптов стоит секунды (498 файлов / 1406 МБ / 4.5 с в debug). Без снимка каждый перезапуск devforge платил бы эту цену заново, и обещание «вкладка открывается мгновенно» не выполнялось бы. Снимок хранит ровно то, что нужно для инкрементальности: роллап каждого файла ВМЕСТЕ с его (file_len, file_mtime_ms, parse_offset) — то есть загруженный снимок сразу годится как аргумент prev для scan::scan_incremental, и неизменившиеся файлы после рестарта не читаются вовсе.

## API
* CACHE_VERSION: u32 = 1 — версия СХЕМЫ данных, не версия продукта.
* CACHE_MAX_KEPT: usize = 4096 — порог усечения точных сэмплов.
* CACHE_FILE_NAME = "analytics-cache.json".
* CacheSnapshot { version, updated_at_ms, files: BTreeMap<путь, SessionRollup> } + CacheSnapshot::new(files, updated_at_ms).
* default_cache_path() -> Option<PathBuf> — ~/.forge/analytics-cache.json; None при незаданном HOME (аналитика тогда работает без снимка, но не падает).
* load(&Path) -> Option<CacheSnapshot> — None при любом «неудобном» случае: файла нет, не читается, JSON битый или недочитанный, версия не совпала. Все эти случаи означают одно и то же — полный пересбор; паники нет ни в одном.
* save(&Path, &CacheSnapshot) -> anyhow::Result<()> — атомарная запись.
* trim_for_cache(&mut BTreeMap<String, SessionRollup>) — усечение перед сериализацией.

## Атомарность
Запись идёт через общий крейт forge-atomic (plugins/atomic): write_bytes_atomic = create_dir_all + временный файл рядом с правами 0600 ДО первого байта + fsync + rename + повторный chmod, с удалением tmp при любой ошибке. Своей реализации tmp+rename здесь нет НАМЕРЕННО: пятая копия этой последовательности неизбежно разъехалась бы с оригиналом по правам. Практический смысл — прерывание процесса посреди сохранения не оставляет полуфайла: на диске либо прежний снимок, либо новый целиком. Ради этого в tmux-web/Cargo.toml добавлена зависимость forge-atomic (самый листовой крейт workspace, единственная внешняя зависимость — anyhow, подключение бесплатно).

## Версия схемы
Любое изменение полей роллапа или правил разбора ОБЯЗАНО поднимать CACHE_VERSION: иначе старый снимок, собранный по прежним правилам, тихо смешался бы с новыми числами. При несовпадении версии снимок молча игнорируется (лог info) — это не ошибка, а сигнал «нужен полный пересбор».

## Размер снимка
rollup::Samples хранит до MAX_KEPT_SAMPLES (20 000) точных значений на день, чтобы считать точные перцентили. В снимок такие раздутые наборы не попадают: при превышении CACHE_MAX_KEPT точные сэмплы отбрасываются, и перцентили после загрузки считаются по логарифмической гистограмме (она сохраняется всегда и складывается при слиянии без потерь).

ВАЖНО: отбрасывать можно только ЦЕЛИКОМ. Samples::quantile переходит на гистограмму именно по признаку kept.len() != count, поэтому усечённый наполовину набор дал бы НЕВЕРНЫЙ ответ вместо приближённого. save() режет копию — исходный индекс в памяти не трогается, точность живого процесса не страдает.

Зависимости: forge_atomic, serde_json, analytics::rollup (SessionRollup, Samples), tracing.

## Фаза 7 — CACHE_VERSION = 3
Версия поднята дважды: новые поля дневного бакета (метрики разнообразия, HLL-регистры) и новые правила разбора (три роли записи `user`). Снимок прежней версии молча игнорируется — это и есть штатный путь миграции.
