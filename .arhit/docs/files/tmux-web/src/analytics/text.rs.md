# tmux-web/src/analytics/text.rs

Нормализация текста сообщений человека, роли записи `user` и признаки «автопилота». Новый модуль Фазы 7 фичи «Аналитика использования Claude Code».

## Зачем отдельный модуль
Метрики разнообразия (TTR, повторы промптов, доля слэш-команд, доля односложных подтверждений) считаются по одному и тому же тексту и все ломаются от малейшего расхождения в правилах нормализации: «Ок.» и «ок» обязаны быть одним промптом. Правила живут в одном месте, а не размазаны по `parse.rs` и `rollup.rs`.

## Три роли записи `user` (главное открытие живой приёмки)
Структурный фильтр `Record::is_human_message` (type==user, не isMeta, не isSidechain, в контенте нет tool_result) пропускает НЕ только реплики человека. В архиве из 498 живых файлов под него подпадают ещё три вида записей:
- `[Request interrupted by user]` / `… for tool use` — прерывание хода (91 запись). Поля `toolUseResult.interrupted`, на которое рассчитывал план, в архиве НЕТ ни разу.
- `<local-command-stdout>…` / `<local-command-stderr>` / `<command-stdout>` — вывод слэш-команды, подставленный CLI (148 записей).
- `<command-name>/clear</command-name><command-message>…` — слэш-команда (161 запись). Текстом «/clear» она в файле НЕ записывается.

Роль возвращает `classify_user_text(text) -> UserRecord::{Message(HumanText), Interruption, CliOutput}`. Прерывание учитывается как `on_interruption` и НЕ открывает ход (пауза меряется до следующей настоящей реплики), вывод команды игнорируется полностью, слэш-команда остаётся сообщением с `is_slash = true`, `is_ack = false` и словарём из одного слова — имени команды.

## Ключевые элементы
- `HumanText { len, word_hashes, word_count, prompt_hash, is_slash, is_ack }` — признаки одного сообщения. Собираются один раз при разборе строки и сразу схлопываются в счётчики дневного бакета; сам текст никуда не уезжает.
- `classify(text) -> HumanText` — базовый разбор реплики.
- `classify_user_text(text) -> UserRecord` — роль записи (см. выше). Точка входа для `parse::apply_record`.
- `word_tokens(text) -> Vec<String>` — слова: максимальные последовательности `char::is_alphanumeric` в нижнем регистре. Кириллица и цифры наравне с латиницей. Стоп-слова НЕ отбрасываются — список стоп-слов для смеси русского с английским и именами файлов был бы произволом.
- `is_slash_command(text)` — первый непробельный символ `/`.
- `hash64(s) -> u64` — FNV-1a + финализатор SplitMix64. Своя функция, а не `DefaultHasher`: значения уезжают в снимок кэша и обязаны совпадать между запусками и версиями компилятора. Финализатор нужен потому, что HLL (`rollup::Distinct`) берёт номер регистра из старших бит.
- `ACK_PHRASES` — закрытый белый список из 46 нормализованных фраз (рус + англ): только реплики без единой инструкции. Подтверждением считается сообщение не длиннее трёх слов, чей нормализованный текст целиком в списке, либо состоящее из одних плюсов («+», «++»).

## Ограничения
Полный текст сообщений не сохраняется и наружу не отдаётся: модуль возвращает только признаки и 64-битные хеши. Закреплено тестом `analytics_does_not_keep_message_text_anywhere_in_the_rollup`. Изменение правил нормализации обязано поднимать `cache::CACHE_VERSION` (сейчас 3).

## Зависимости
Используется из `analytics::parse::apply_record`; хеши слов уходят в `rollup::Distinct`, хеш промпта — в `DayBucket::prompt_hashes`. Собственных зависимостей у модуля нет.
