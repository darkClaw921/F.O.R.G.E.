# tmux-web/src/agents/opencode.rs

OpenCode SQLite source adapter shared by live agent activity and historical usage. Public read(path, profile, since_ms, previous) opens only regular files with rusqlite SQLITE_OPEN_READ_ONLY and a 500 ms busy timeout, then takes a read transaction so WAL commits are visible without writing the source. OpenCodeCursor serializes metadata-only per-message contributions, source identity, schema version, append boundary and 64 recent rowid/id pairs; prompts, replies, error text and tool output never enter the cursor. V2 is selected exclusively by session_v2, using session_message/session_v2; V1 uses message/session even if a v1 session_message table exists. New rowids are decoded while existing indexed rows are checked by id/update stamp, mutable rows additionally by length, and missing rows/sessions remove their contributions. Replacement, schema changes and rowid reuse cause safe reconstruction; errors such as SQLITE_BUSY return Err and leave previous immutable data intact. SQL extracts only model, project, parent, timestamps, role, token/cost counters and tool/compaction flags. Event reconstruction preserves a user task across tool iterations and compactions; v1 completed tool steps yield Settled for the stores 30-second grace, while v2 keeps Active until its explicit idle row or final response. Final replies/errors/idle emit Ended with original task duration; child session events carry parent identity and do not become independent root counts in the store. Reasoning is added once to OpenCode output, token/cost absence remains unknown, native message IDs make streaming updates replace earlier usage. decoded_rows is instrumentation for verifying append-only behavior. Synthetic unit tests cover both layouts, WAL updates, same-timestamp length changes, revert/rowid reuse, schema upgrades, out-of-order imported history, child linkage, cache privacy/roundtrip, malformed rows, non-regular files and locks.
