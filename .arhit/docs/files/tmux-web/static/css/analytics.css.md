# tmux-web/static/css/analytics.css

Стили полноэкранного дашборда аналитики (#analytics), Фаза 5. Подключён @import секцией «6b2» в tmux-web/static/style.css рядом с daily-summary.css — до mobile.css, который обязан оставаться последним.

СОСТАВ. .analytics — вью на всю площадь #main (position:absolute; inset:0; overflow-y:auto), фон --bg-elev как у «Сводки дня». Секции (.analytics-head, -hero, -progress, -error, -kpi, -grid) центрируются колонкой max-width 1400px: в отличие от читаемой колонки сводки (760px) дашборду нужна ширина, иначе 90 дневных столбцов становятся частоколом, а KPI — вертикальным списком из двадцати строк.

.analytics-kpi — grid auto-fill от 150px; .analytics-tile — плитка со значением, дельтой (.is-good / .is-bad окрашивают по смыслу метрики) и примечанием; .analytics-tile-hero занимает две колонки и крупнее — под медианную паузу и долю ответов < 10 с.

.analytics-grid — grid auto-fill от 420px; .analytics-card-wide растягивается на всю строку (чарты по дням читаются только широкими); .analytics-plot-pair кладёт два SVG рядом (модели, гистограмма + линия). .analytics-plot задаёт хост SVG: кит рисует в единицах viewBox и тянется на 100% ширины контейнера.

.analytics-progress — прогресс-бар первого скана (track + fill, ширина ставится из JS); .analytics-error — сообщение с кнопкой «Повторить»; .analytics-empty — объяснение пустого периода вместо сетки заглушек. Ниже 900px карточки становятся одноколоночными, панель фильтров распускается вертикально.

ОГРАНИЧЕНИЕ. Ни одного литерала цвета — только переменные темы из css/base.css; хардкод-хекс пережил бы смену темы ровно у того пользователя, который тему и настроил. Страж — регулярка в analytics_view.test.mjs.
