# tmux-web/static/js/vk/format.js

tmux-web/static/js/vk/format.js — чистые функции форматирования, сортировки и БЕЗОПАСНОСТИ ССЫЛОК панели VK. Не импортирует ни DOM, ни core/*: грузится как есть в Node и покрыт tmux-web/tests/frontend/vk_format.test.mjs.

БЕЛЫЙ СПИСОК СХЕМ — ТРИ ФУНКЦИИ, разные по назначению:
  * safeUrl(raw) -> ?string — схемы http/https/vk. Используют media.js (player_url — страница-плеера видео) и botkb.js (кнопка open_link сообщества). vk: оставлена намеренно: это deep-link в приложение VK, и он уместен там, где адрес построили МЫ. Порядок операций критичен: сначала вырезаются управляющие и невидимые символы (браузер их игнорирует при разборе схемы, и java\0script: для него javascript:), только потом разбирается схема. Обратный порядок даёт обход одним нулевым байтом. http/https без authority (https:evil) отвергаются.
  * webUrl(raw) -> ?string — safeUrl БЕЗ vk:, то есть строго http/https. Через неё проходит всё, что становится href карточки ссылки (MediaDto.link_url). Отдельная функция, а не параметр safeUrl: схему адреса вложения link выбирал СОБЕСЕДНИК, и vk:// из чужого сообщения — не «удобный переход в приложение», а повод разбираться, что откроет установленный клиент. Второй рубеж поверх серверного attach::http_url.
  * linkDomain(raw) -> ?string — домен для ПОДПИСИ на карточке (psph.bitrix24.ru). Полный адрес не показывается: у ссылок из CRM/маркетплейсов путь перерастает ширину панели и карточка либо расползается, либо обрезается посреди идентификатора. www. снимается; punycode НЕ разворачивается — иначе домен-омограф выдавал бы себя за настоящий прямо в подписи. Порт в подпись не идёт.

canShowThumb(media) -> boolean — «стоит ли просить превью». РОВНО has_thumb === true, БЕЗ собственного списка видов. Здесь был живой дефект: функция держала белый список ['photo','video','document','sticker','graffiti'], в который не попал вид 'other', поэтому карточка ссылки с превью 1200x630 не делала запрос ВООБЩЕ и вечно показывала значок-заглушку («не работают превью ссылок»). Второй список поверх серверного флага — это второй источник истины, и он разъехался. Бэкенд считает has_thumb как attach::url_for(att, Thumb).is_some(), тем же кодом, который потом ищет адрес, поэтому флагу можно верить. ДОБАВЛЯТЬ сюда «страховочный» перечень видов нельзя: он снова разойдётся с сервером, теперь в другую сторону (сервер сможет отдать превью, а браузер откажется просить).

ОСТАЛЬНОЕ: slugName/peerKind/dialogKind/dialogStatusLine/splitDialogs (колонка бесед; CHAT_PEER_BASE=2000000000 дублирует dto::CHAT_PEER_BASE сознательно — это константа протокола VK), mediaKey(dialogId, messageId, index, kind) — ключ медиа-кэша С ИНДЕКСОМ (телеграмный ключ без индекса не уникален: два фото одного сообщения получили бы один ключ), mediaKindLabel/mediaGlyph/mediaMetaLine/durationLabel/formatBytes/progressPercent/progressLabel, isImageKind/isPlayableKind, sanitizeDownloadName, captchaFromError/captchaRetryBody, vkErrorLabel, UPLOAD_LIMITS/uploadRejectReason (у VK лимит зависит от вида вложения, одно число дало бы либо ложный отказ на документе, либо пропущенный отказ на фото).

ИМЯ БЕСЕДЫ (правка после приёмки «ники второстепенны, показывайте имена»): slugName УДАЛЁН вместе с KIND_SUFFIX и SLUG_MAX (у VK папок нет, других потребителей константы не было). Его заменили displayName(d) и displayNick(d) — по смыслу копия телеграмных, две честные копии вместо общего слоя, как и весь остальной файл.
  * displayName — имя КАК ЕСТЬ: title -> '@'+username -> peer_id -> 'anon'. Кириллица не транслитерируется: у VK это било сильнее, чем у Telegram, — русские названия бесед норма, и «Тестовое сообщество» превращалось в 'anon@club'.
  * displayNick — '@screen_name' либо пустая строка (у бесед screen_name не бывает вовсе; проекция screen_name -> username живёт в plugins/vk/src/dto.rs).
  * sessionHeadParts -> {name, nick, tail}: шапка разобрана на части, чтобы chat.js покрасил ник приглушённым узлом; sessionHeadText склеивает их и остаётся единственным описанием формы шапки.
