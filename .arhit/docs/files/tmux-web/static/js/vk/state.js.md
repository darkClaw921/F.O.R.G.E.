# tmux-web/static/js/vk/state.js

Клиентское состояние вкладки VK (vkState) + ЗАМОРОЖЕННАЯ ТАБЛИЦА ЛЕКСИКИ в шапке файла (вторая половина контракта Ф1.1, первая — в plugins/vk/src/routes/mod.rs). Структурная лексика UI остаётся ТЕЛЕГРАМНОЙ (dialog, dialogId, dir), VK-лексика (peer_id, conversation_message_id, attachments) живёт только на границе API и в именах полей DTO: при дублировании кода главный инструмент сопровождения это diff двух панелей, и переименование ради красоты превратило бы осмысленный дифф в шум. Ключевые отличия от tgState: dialogs — ВСЕГДА список filter=all (источник бейджа и белого списка), а dirDialogs — транзиентный список выбранного серверного фильтра, потому что четыре «директории» VK это ПАРАМЕТР метода getConversations, то есть другой запрос, и один общий список заставил бы бейдж считаться по случайной выборке; mediaCache ключуется строкой 'peer/mid/idx/kind' — С ИНДЕКСОМ вложения; появляется captcha {sid,img,pending}; НЕТ folders и НЕТ notifyDefaults (папок у VK нет, глушение только per-peer). currentVisibilityFilter() читает настройки лениво через window.ForgeApp и кэширует результат ПО СОДЕРЖИМОМУ (JSON.stringify) — так сохранённые настройки действуют сразу, без перезагрузки; инвариант «включён ≠ действует» дословный: active = enabled И непустой выбор, иначе включённый фильтр с пустыми списками спрятал бы все беседы и выглядел бы как пропажа данных. clearVkAccountData обязательно revoke'ает objectURL'ы (иначе после отвязки токена данные прошлого аккаунта остаются доступны по ссылке). normalizeFilterFromSettings временно лежит здесь и переедет в js/vk/visibility.js в Ф10.

ДОПОЛНЕНО В Ф11-Ф12. Контракт клавиатуры: панель публикует window.ForgeApp.vkKeys
{owns, enabled, invalidate} тем же приёмом, что и телеграмная (модули грузятся
позже классического hotkeys.js, поэтому спрашивают через window, а не импортом);
имя vkKeys перечислено в hotkeys.js::PANEL_KEY_CONTRACTS. Владение снимается не
только скрытой панелью и оверлеем логина, но и оверлеем CAPTCHA — отличие VK от
Telegram: она всплывает на ЛЮБОЙ метод API, и пока пользователь набирает код,
клавиши принадлежат её полю.
