# tmux-web/static/js/vk/attachments.js

tmux-web/static/js/vk/attachments.js — нормализация вложений и пересланных сообщений панели VK. НОВЫЙ модуль, аналога в js/telegram/* нет: у Telegram вложение ОДНО на сообщение (msg.media), у VK их до десяти в массиве msg.attachments плюс рекурсивные fwd. DOM не трогает и в сеть не ходит — готовит МОДЕЛЬ для карточек (рендер живёт в js/vk/media.js), поэтому грузится в Node и покрыт tmux-web/tests/frontend/vk_attachments.test.mjs.

ЭКСПОРТ: MAX_INLINE_CARDS=6 (сколько карточек рисуется подряд, хвост — «…ещё N»), MAX_FWD_DEPTH=2 (МЕНЬШЕ серверного dto::MAX_FWD_DEPTH=3 намеренно: сервер отдаёт на уровень больше, чем UI показывает, чтобы «…ещё N пересланных» считалось по настоящим данным), FWD_PREVIEW_CHARS=140, attachmentKind(att), normalizeAttachments(msg, opts), primaryAttachment(list), attachmentsSummary(list), hasRenderableMedia(msg), flattenForwards(msg, maxDepth), forwardsTail(count), forwardPreview(fwd).

attachmentKind принимает MediaDto, СЫРОЕ вложение VK (кадр WS старой версии, fwd/reply_to) либо строку вида. Неизвестный вид -> 'unsupported', а не выброс: пропавшее вложение читается как потеря данных, отключённая карточка — как «этот тип мы не умеем». link/wall/wall_reply/market/market_album/poll/gift/call/story/podcast/article -> 'other'.

normalizeAttachments СОХРАНЯЕТ ПОРЯДОК И ИНДЕКСЫ ровно такими, какими их прислал сервер: index входит в ключ медиа-кэша и в маршрут /api/vk/media/:peer/:mid/:idx, поэтому ни сортировка, ни фильтрация «ненужных» видов невозможны — они показали бы пользователю не то вложение. Поля выдачи: index, kind, mime, size, width, height, durationSecs, fileName, title, url (ВСЕГДА null), playable, thumbable, playerUrl, linkUrl, raw. Поддерживается и старая форма (одиночное msg.media без массива).

ИНВАРИАНТ «url ВСЕГДА null». Прямые ссылки НА ФАЙЛЫ VK в DOM запрещены: они подписанные и протухающие, а запрос с Referer devforge на серверы VK неуместен для панели с личной перепиской. Поле url оставлено в модели ЯВНО и всегда null — рендер, который его нарушит, получит пустую ссылку и сломается заметно, а не тихо утечёт. Второй, независимый рубеж — бэкенд (plugins/vk/src/attach.rs), который адресов файлов не отдаёт вовсе.
ПОД ЭТО ПРАВИЛО НЕ ПОПАДАЮТ playerUrl и linkUrl: первый ведёт на СТРАНИЦУ-плеер VK (файла у вложения video не существует), второй — на адрес, который прислал собеседник (MediaDto.link_url, добавлен при починке карточки ссылки — см. страницу vk-link-preview). Ни тот, ни другой не адресуют CDN вложений, не подписаны и не протухают. Здесь оба только нормализуются до строки-или-null; белый список схем применяется на границе с DOM — media.js через safeUrl (плеер) и webUrl (ссылка).

thumbable = a.has_thumb === true — модель ТОЛЬКО переносит серверный флаг и не судит о нём по виду вложения; решение «просить ли превью» принимает format.js::canShowThumb, который тоже верит серверу. playable = (voice|audio) && has_full === true: у video false всегда.
