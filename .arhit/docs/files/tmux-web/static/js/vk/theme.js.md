# tmux-web/static/js/vk/theme.js

Собственная тема панели VK (тумблер ◐) поверх общего js/messenger/theme-core.js. Зачем отдельная тема: панель нарисована в терминальной палитре и НЕ наследует токены приложения (все цвета объявлены на #vk в css/vk.css), поэтому переключение темы devforge её не касается — правильно, пока пользователь в тёмной теме, но на светлой чёрная панель выглядит инородно. Три режима в localStorage 'forge.vkTheme': auto (светлота выводится из вычисленного --bg приложения — глобального флага «сейчас светлая тема» в devforge нет, applyTheme просто расставляет CSS-переменные на :root), dark, light. Смена темы приложения ловится MutationObserver'ом на атрибут style у <html> — единственная развязка, не тянущая плагин в модуль тем (обратный импорт замкнул бы граф модулей). Второй наблюдатель на <html> (первый у Telegram) приемлем: связать их означало бы править js/telegram/theme.js, а стоимость одного callback'а на действие пользователя нулевая. applyVkTheme идемпотентна и трогает DOM только при реальном изменении; режим дублируется в data-vk-theme-mode у кнопки, потому что в auto на тёмной теме приложения переход в 'dark' не меняет data-vk-theme и отличить их иначе нельзя. Экспорт: initVkTheme (идемпотентна), applyVkTheme, setVkThemeMode, cycleVkThemeMode, teardownVkTheme, _debugVkTheme.
