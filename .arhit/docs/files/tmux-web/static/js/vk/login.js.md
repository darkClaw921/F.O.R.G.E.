# tmux-web/static/js/vk/login.js

Экран логина панели VK (оверлей #vk-login, Ф3).

Сильно проще телеграмного: не wizard из трёх шагов, а ОДИН экран — у VK нет ни кода из SMS, ни пароля 2FA, есть готовый access-токен.

Автомат отображения (источник истины — поле state ответа сервера): not_configured -> форма; checking -> «проверяем…», форма заблокирована, ошибка НЕ рисуется; disconnected -> форма + «нет связи с api.vk.com»; invalid_token -> форма + «токен неверен или отозван (VK 5)»; no_messages_scope -> форма + «нет права messages (VK 15)» + объяснение про standalone-приложения; captcha_required -> форма + строка, картинку показывает ОТДЕЛЬНЫЙ оверлей js/vk/captcha.js; authorized -> оверлей скрыт, поле очищено.

Экспорт: initLogin({onAuthorized}), renderLoginState(dto), setLoginHint(hint), formatWait(secs), startCountdown(secs), stopCountdown(), resetLogin(), _debugLogin(), STATE_TEXT.

Два правила, которые легко потерять: (1) разбор вставленного значения живёт ТОЛЬКО на бэкенде — здесь нет ни одного split('#') и ни одной проверки «похоже на токен»; (2) секрет не задерживается в DOM: значение #vk-token очищается сразу после успеха.

renderLoginState ИДЕМПОТЕНТНА — её зовут из снапшота /status, из WS-кадра login_state и из ответа каждого POST'а логина. Ошибка показывается при СМЕНЕ состояния, иначе повторный снапшот затирал бы более свежий текст шага.

Подсказка «где взять токен» приходит с бэкенда (status.hint); пустое значение не затирает дефолт из разметки. Обратный отсчёт (коды VK 6/9/29) блокирует кнопку и НЕ уходит в автоповтор: автоматические попытки только продлевают лимит. Пустое поле в настроенном состоянии означает «повторить проверку» (verifyLogin), а не отправку пустого токена.
