# tmux-web/static/js/vk/keynav.js

КЛАВИАТУРНАЯ НАВИГАЦИЯ ПО ПАНЕЛИ VK (Ф11) — DOM, фокус и состояние курсора.

Задача: пройти путь 'выбрать беседу → прочитать → открыть вложение → ответить → отправить → нажать кнопку сообщества' не трогая мышь. Чистая логика (реестр, разбор комбинаций, конфликты) — в keys.js и messenger/hotkeys-core.js.

## Владение клавиатурой

vkOwnsKeyboard() = панель видима И оверлей логина закрыт И ОВЕРЛЕЙ CAPTCHA ЗАКРЫТ И тумблер включён И (фокус внутри #vk ИЛИ фокус нигде). Публикуется как window.ForgeApp.vkKeys = {owns, enabled, invalidate} — контракт для static/hotkeys.js (он классический скрипт и импортировать модуль не может; имя перечислено в его PANEL_KEY_CONTRACTS рядом с телеграмным).

Проверка CAPTCHA — отличие от Telegram, где такого оверлея нет вовсе: у VK он всплывает на ЛЮБОЙ метод API, и пока пользователь набирает код, клавиши принадлежат его полю.

Правило 'фокус внутри панели ИЛИ нигде' означает, что кликнув в сайдбар сессий, пользователь ВОЗВРАЩАЕТ СЕБЕ глобальный vim. Сосуществование с Telegram бесконфликтно по построению: switchTab держит непогашенным ровно один пейн, а panelVisible() каждой панели смотрит на СВОЙ #telegram/#vk; цена — один if на нажатие в каждом из двух document-слушателей.

hotkeysEnabled() читает vk_hotkeys_enabled строго как '!== false' — ДЕФОЛТ ВКЛЮЧЁН. Свод гейтов, который тут легко перепутать: cmd_hints_enabled === true (выкл), telegram_hotkeys_enabled !== false (вкл), vk_hotkeys_enabled !== false (вкл), vk_filter_enabled === true (выкл).

## Слушатель

Стоит в CAPTURE на document (должен опередить построчные слушатели ленты и делегаты списка бесед), но НЕ глушит события вслепую: preventDefault/stopPropagation зовутся ТОЛЬКО когда runAction вернул true. Ложное true съело бы клавишу у соседних обработчиков, ничего не выполнив. Ранние выходы: скрытая панель, выключенный тумблер, открытый лайтбокс (он листает галерею вложений сам), .modal-overlay (там записывают новые комбинации). Внутри полей ввода одиночные клавиши не перехватываются вовсе (hotkeys-core::comboAllowedIn) — иначе сообщение с буквой 'j' было бы не набрать.

## Курсор

Хранится ИДЕНТИФИКАТОРОМ, а не ссылкой на узел: колонка бесед и лента перерисовываются целиком при каждой подгрузке. Ключ ленты — conversation_message_id (cmidOf из format.js), а НЕ глобальный message_id: cmid адресует ответы и переживает переоткрытие беседы. Класс vk-kb-cursor навешивается на найденный по id узел; смена беседы зовёт resetKeynav() из main.js::openDialogById, потому что cmid нумеруется в КАЖДОЙ беседе с единицы и в новой ленте тот же номер принадлежит другому сообщению.

## Зоны и действия

activeZone() считается по реальному фокусу (мышь и Tab двигают его мимо нас): 'input' (#vk-prompt) → 'keyboard' (.vk-kb-bar) → 'media' (.vk-media-card) → 'log' (#vk-log) → 'dialogs' (#vk-contacts). Порядок от вложенного к внешнему: карточка вложения лежит ВНУТРИ #vk-log, и проверь мы ленту первой, зона вложений была бы недостижима.

ЗОНА ВЛОЖЕНИЙ — новое по сравнению с Telegram. focusAttachments() (v) ставит фокус на кнопку OPEN первой карточки, j/k ходят ПО ВЛОЖЕНИЯМ (mediaButtons берёт по одной кнопке на карточку — у карточки их две, OPEN и SAVE, и хождение по обеим означало бы два нажатия j на одно вложение), Enter активирует сфокусированную кнопку СИЛАМИ БРАУЗЕРА. Свой click рядом с нативным дал бы два открытия — тот же инвариант, что у кнопок сообществ.

activate() со СТРОКИ: первое НЕотключённое вложение (кнопкой OPEN, а не кликом по телу карточки — тело реагирует только у превью и проигрываемых видов, и на документе клик по нему был бы съеденной клавишей без следствия), затем кнопка сообщества, затем цитата.

## Кэш привязок

currentBindings() ключуется по JSON.stringify карты переопределений, а НЕ по ссылке на объект настроек: сохранённые настройки начинают действовать СРАЗУ, без перезагрузки страницы, независимо от того, положил ли user-settings-api новый объект или мутировал старый. invalidateBindings() — страховка и явная точка контракта для формы настроек.
