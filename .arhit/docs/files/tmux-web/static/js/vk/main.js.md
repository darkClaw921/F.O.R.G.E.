# tmux-web/static/js/vk/main.js

Точка сборки вкладки VK: гейт кнопки Ⓥ, постоянный WS, карта кадров, бейдж и тосты.

## Экспорты
initVkGate() — спрашивает GET /api/vk/status на старте страницы; 404 = плагин
выключен (кнопка скрыта, в консоль не шумим). При enabled поднимает ПОСТОЯННЫЙ WS
ещё до первого открытия вкладки — иначе бейдж и тосты появлялись бы ровно тогда,
когда уже не нужны.
initVk() — идемпотентная сборка панели при первом открытии вкладки.
buildHandlers() — карта кадров WS.
recomputeUnread() — ЕДИНСТВЕННЫЙ путь обновления бейджа.
maybeToast(msg, frame) — тост о входящем.
openDialogById(id) — общая точка входа для клика по списку и по тосту.
onTyping(evt), frameFlag(value, fallback), applyLoginState(dto), setMode(mode),
suspendVk/resumeVk/teardownVk/reloadData/_debugState.
Константы: TOAST_THROTTLE_MS = 5000, TOAST_PREFIX = 'VK · '.

## Карта кадров и её отличия от телеграмной
Полный набор VkServerMsg: login_state, new_message, message_edited,
message_deleted, typing, online, read, upload_progress, download_progress,
notify_settings, unread_total, history_cleared, dialog_changed, resync, ping.
НОВЫЕ относительно Telegram: unread_total (VK отдаёт общий счётчик готовым,
событие LongPoll 80), history_cleared (событие 13 не несёт id удалённых
сообщений, только границу), dialog_changed (события 51/52).
УДАЛЕНЫ: notify_defaults_changed (глобальных категорий mute у VK нет, глушение
только per-peer) и folders_changed (папок нет). upload_progress/download_progress
пока заглушки — модули медиа и загрузок приезжают в Ф7/Ф8; без обработчика ws.js
писал бы «no handler» на каждый кадр.

## recomputeUnread — инвариант единственного пути
Второй писатель бейджа неизбежно разъезжается с первым, и снять расхождение можно
будет только перезагрузкой страницы. setUnreadBadge приватна, наружу её нет.
Источников числа два, приоритет у серверного:
1) кадр unread_total (считает ВЕСЬ аккаунт) плюс поправка unreadSinceServer —
   множество БЕСЕД, в которых непрочитанное появилось уже после этого кадра.
   Поправка нужна потому, что событие 80 приходит следом, отдельным кадром, и без
   неё бейдж на доли секунды показывал бы прошлое значение при каждом сообщении.
   Считаются беседы, а не сообщения: что именно нумерует счётчик VK, из протокола
   не следует, и «+1 за беседу» — оценка, которая не может ошибиться в разы;
2) до первого серверного кадра — локальный расчёт: сумма по загруженной странице
   (без заглушённых) плюс pendingUnread для бесед, которых на странице нет вовсе
   (WS вещает по всему аккаунту, а GET /dialogs отдаёт верхушку).
Беседа, появившаяся в списке, вычищается из pendingUnread и flagsExtra здесь же:
список авторитетнее кадров, иначе одно сообщение считалось бы дважды.

## Гейт mute держится на полях КАДРА
frameFlag(value, fallback) с явной проверкой typeof === 'boolean': у кадра старого
сервера поля нет вовсе, и наивное !frame.muted превратило бы «не знаю» в «не
заглушена», то есть вернуло бы тосты от заглушённых бесед. Локальный Set muted
собран из ЗАГРУЖЕННОЙ страницы и один гейтом быть не может; flagsExtra хранит
решение сервера по беседам вне страницы.

## maybeToast — гейты
Не своё исходящее; беседа звенит (dialogRings по кадру, локальное знание —
фолбэк); беседа проходит белый список (dialogShown; у VK предикат ТОЧЕН даже вне
загруженного списка — тип выводится из самого peer_id); НЕ активная беседа при
открытой вкладке; троттлинг TOAST_THROTTLE_MS на беседу.
ЗАГОЛОВОК: 'VK · ' + имя. При двух включённых панелях тосты падают в ОДИН стек
#echo-toasts, и без префикса пользователь не поймёт, куда его зовут. Канал —
только echo/notifications.js::notify, третий стек уведомлений не заводится.
Клик по тосту переключает на вкладку VK и открывает беседу.

## «Печатает…»
onTyping ведёт карту dialogId|userId -> {label, voice, timer}. TTL обязателен:
VK НЕ присылает «перестал печатать», он просто перестаёт слать событие.
typingLabel сверяет id, иначе участник группы получал бы имя самой беседы.
Уход из беседы гасит индикаторы ИМЕННО покинутой; openDialogById перерисовывает
строку под новую ленту.

## Отметки о прочтении
scheduleRead с дебаунсом READ_DEBOUNCE_MS и памятью readSent; readAllowed требует
видимой вкладки И открытой панели. noteReadFromServer запоминает границу,
пришедшую с другого устройства (read/in), чтобы не слать свою отметку следом.

## Белый список видимости (Ф10) — ДВЕ из четырёх точек применения

dialogShown(id) = visibility.js::dialogIdVisible(id, currentVisibilityFilter(),
vkState.dialogs). Гейт стоит в maybeToast (скрытая беседа не звенит — открыть её
кликом по тосту всё равно некуда) и в noteUnknownUnread (скрытая беседа не копит
непрочитанное). Третья точка — сам recomputeUnread: при ДЕЙСТВУЮЩЕМ фильтре
серверный счётчик unread_total ИГНОРИРУЕТСЯ целиком, потому что VK считает его по
ВСЕМУ аккаунту, включая скрытые беседы, а расщепить готовое число нечем; бейдж
возвращается к сумме по видимому срезу загруженной страницы плюс pendingUnread
(тоже проверяемый на видимость в момент пересчёта — карта переживает сохранение
настроек). Цена названа сознательно: цифра, ведущая в беседу, которой в колонке
нет, читается как поломка, и это хуже занижения.

publishFilterContract() публикует window.ForgeApp.vkFilter = {refresh}. Зовётся и
из initVkGate (вкладку могли ни разу не открыть, а настройки уже сохранить), и из
initVk. refresh делает ТРИ обязательных действия: invalidateVisibilityFilter() +
vkDialogs.renderAll() + recomputeUnread(). Без последнего бейдж продолжал бы
считать только что скрытые беседы. Контракт через window, а не импортом: модалка
настроек открывается и без включённого плагина. Тесты:
vk_dialogs_filter.test.mjs, vk_toasts.test.mjs. См. [[vk-visibility-model]].

ДОПОЛНЕНО В Ф11-Ф12. initVk() дособирает панель в фиксированном порядке:
initCaptcha -> initLogin -> initDialogs -> initChat -> initMedia (лайтбокс ПОСЛЕ
ленты: его Esc обязан регистрироваться позже снятия полосы ответа) -> initUpload
-> initKeynav. Клавиатурная навигация показывает короткие ответы тем же тостом,
что и остальной VK, с обязательным префиксом «VK» — тосты обеих панелей падают в
один стек #echo-toasts. teardownVk() снимает keynav (слушатель в capture на
document переживает bfcache и стрелял бы по мёртвому DOM). Deep-link ?tab=vk
разрешён в js/pwa/bootstrap.js::routeTab (белый список имён вкладок).
