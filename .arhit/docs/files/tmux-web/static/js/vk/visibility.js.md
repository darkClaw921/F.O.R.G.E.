# tmux-web/static/js/vk/visibility.js

Белый список видимых бесед VK — ЧИСТЫЙ модуль (ни DOM, ни сети, ни состояния), зависит только от format.js::peerKind. Близнец js/telegram/visibility.js, но предикат другой. Покрыт node-тестом tmux-web/tests/frontend/vk_visibility.test.mjs (77 ассертов) без фейкового DOM.

## Экспорт

- VISIBLE_KINDS — [{key,label,hint}] для трёх типов в порядке показа формы: user (Личные сообщения), chat (Беседы), community (Сообщества). Живёт здесь, а не в форме настроек: значения ключей — часть контракта настроек (ложатся в vk_visible_kinds и сравниваются с peerKind).
- kindLabel(kind) — человеческое название типа, неизвестный ключ отдаётся как есть.
- normalizeFilter(settings) → {enabled, kinds, peers, kindSet, peerSet, active}. Читает vk_filter_enabled (строго === true, дефолт настройки ВЫКЛ), vk_visible_kinds, vk_visible_peers. Списки чистятся: trim, отброс пустых, схлопывание дублей, порядок сохраняется, числа приводятся к строкам.
- filterActive(filter) — включён И непусто.
- dialogVisible(d, filter) — peerSet.has(String(d.id)) || kindSet.has(peerKind(d.id)).
- visibleDialogs(dialogs, filter) — фильтрация списка с сохранением порядка сервера.
- dialogIdVisible(peerId, filter, dialogs) — точка входа для WS-кадров.
- filterSummary(filter) — сводка со склонениями для формы настроек.
- pruneMissingPeers(selected, dialogs) — чистка исчезнувших бесед, только по явной команде пользователя.

## Инвариант «включён не равно действует» (перенесён из Telegram ДОСЛОВНО)

active = enabled && (kinds.length || peers.length). Тумблер с пустым выбором показывает ВСЁ. Иначе первое же включение дало бы пустую панель, и пользователь прочитал бы это как поломку, а не как свою настройку. Форма обязана прямо писать «Ничего не выбрано — пока показаны все беседы».

## Улучшение относительно Telegram

peerKind вычисляется ИЗ САМОГО peer_id по диапазонам (< 0 сообщество, < 2e9 пользователь, >= 2e9 беседа), без обращения к загруженному списку. Поэтому неизвестная по WS беседа при фильтре ПО ТИПУ решается ТОЧНО, а не консервативно: у Telegram принадлежность чата папке из одного id не выводится, и неизвестный чат приходилось скрывать. Строгость сохраняется только в поимённом режиме. Тип беседы берётся из peerKind(id), а НЕ из DialogDto.kind, хотя DTO под рукой: два источника типа разошлись бы, и беседа осталась бы в колонке, перестав звенеть (или наоборот).

## Чего здесь нет

emptyDirKeys (приглушение пустых пунктов навигации) НЕ переносится: пустоту серверного фильтра клиент не знает, не сделав запрос, а четыре запроса ради подсветки — весь секундный бюджет при лимите 3 rps.

## Потребители

state.js::currentVisibilityFilter (кэш разбора по СОДЕРЖИМОМУ настроек), dialogs.js (renderAll, renderDirs), main.js (dialogShown → бейдж и тосты), settings/vk-visibility-tab.js (форма). См. [[vk-visibility-model]].
