# js/telegram/login.js — трёхэтапный терминальный wizard логина

Оверлей `#tg-login` поверх панели: шаг 1 — креды (api_id / api_hash / phone),
шаг 2 — код из Telegram, шаг 3 — пароль двухфакторной защиты. Шаг определяется
состоянием сервера (LoginStateDto.state), а не локальным счётчиком: страницу
могли перезагрузить посреди входа.

## Ключевые функции

- `initLoginWizard({onAuthorized})` — навешивает обработчики один раз.
- `renderLoginState(dto)` — единственная точка, которая решает, какой шаг
  показать: not_configured/disconnected -> шаг 1, code_sent -> шаг 2,
  password_required -> шаг 3, authorized -> оверлей скрыт. Идемпотентна:
  повторный вызов с тем же dto не сбрасывает введённые поля и не
  перезапускает countdown.
- `resetLoginWizard()` — очистка полей (после logout).
- `stopCountdown()` — гасит таймер FLOOD_WAIT (обязателен на beforeunload,
  иначе таймер тикает в фоне и держит ссылку на DOM).

## FLOOD_WAIT

Ответ `429 {code:'flood_wait', retry_after_secs}` НИКОГДА не ретраится
автоматически: на логине блокировка измеряется часами, и каждая повторная
попытка её продлевает. Показывается обратный отсчёт, кнопка шага заблокирована
до нуля.

## Безопасность

- api_hash вводится в `input[type=password]` и никогда не отображается обратно:
  сервер его в статусе не возвращает (проверено smoke-тестом).
- Пояснение со ссылкой на my.telegram.org обязательно: без него пользователь
  решает, что нужен бот-токен, и вводит не то.
- Оверлей закрывает тело панели, но НЕ бары: titlebar и statusbar лежат выше
  (z-index 6), чтобы тумблер темы и состояние связи оставались доступны.
