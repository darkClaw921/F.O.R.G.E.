# tmux-web/static/js/bitrix/dialogs.js

Колонка диалогов «Битрикс24»: загрузка, директории, рендер, realtime-патчи.

ОТЛИЧИЕ ОТ VK. Портал отдаёт ОДИН список (im.recent.get), а директории ~/all, ~/chats, ~/tasks, ~/unread выводятся из полей строки (Р2) — переключение директории ЛОКАЛЬНОЕ, сетевого запроса не стоит, второго списка нет.

ЗАГРУЗКА. loadDialogs({append}) — страница DIALOG_PAGE=40; директория на сервер НЕ уезжает (иначе счётчики соседних директорий показывали бы ноль). loadFilters() — директории и счётчики (после холодного старта сервер отвечает из снимка, Р3). Бесконечная прокрутка по SCROLL_TAIL_PX.

REALTIME (Ф7).
- applyDialogsPatch(dialogs, removed) — слияние тем же mergeDialogs, что и догрузка страницы; removed сервер сегодня не заполняет никогда (портал об исчезновении строк не сообщает), но обрабатывается ради будущего.
- bumpDialog(msg, counts) — подъём строки по пришедшему сообщению ЛОКАЛЬНО, без запроса к порталу: всё нужное лежит в кадре. Счётчик растёт только у чужого сообщения в неоткрытом диалоге. Возвращает false, если строки нет в загруженной странице — вызывающий перезапрашивает список.
- setUnread(id, count) — точечная установка счётчика строки.

РЕНДЕР. renderAll (полный: строк десятки, а не тысячи), renderDirs (счётчики директорий считаются ПО ВИДИМЫМ строкам — точка 2 белого списка), highlightActive, делегирование кликов (строки перерисовываются целиком).

Тесты: bitrix_format.test.mjs, bitrix_visibility.test.mjs, bitrix_realtime.test.mjs.

Ф10 (задачи): строка чата задачи получает СТАТУС-ТОЧКУ (класс b24-task-dot-<status_key>, общий с карточкой — два набора цветов разъехались бы), метку просрочки и бейдж непрочитанных КОММЕНТАРИЕВ (newCommentsCount — отдельное число портала, не совпадающее с непрочитанными сообщениями чата). Источник — b24State.tasks: im.recent.get про статусы задач не знает ничего, карточки тянет tasks.js при входе в ~/tasks. Пока карточки нет, точка нейтральна — честнее, чем угадать статус. initDialogs получил колбэк onDir, selectDir зовёт его: единственное, что директория догружает по сети, — карточки задач.

Ф11. initDialogs принимает четвёртый колбэк onCounters — сигнал «счётчики портала обновились», который loadFilters() посылает после успешного GET /api/bitrix/filters. Бейдж вкладки пишет ЕДИНСТВЕННЫЙ писатель (main.js::recomputeUnread), а счётчики приезжают сюда, поэтому связь колбэком: обратный импорт dialogs.js -> main.js замкнул бы граф модулей. До Ф11 бейдж обновлялся только кадром counters из WS и на свежей загрузке страницы оставался пустым, хотя число уже было получено по REST.

Две точки применения белого списка из четырёх живут здесь и в Ф11 покрыты тестом, который сверяется с ПЕРЕЧНЕМ ИЗ ШАПКИ visibility.js: visibleSource() (колонка) и renderDirs() (счётчики директорий по ВИДИМЫМ строкам). Мутация любой из них роняет tests/frontend/bitrix_visibility.test.mjs.
