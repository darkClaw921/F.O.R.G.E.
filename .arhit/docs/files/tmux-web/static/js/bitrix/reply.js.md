# tmux-web/static/js/bitrix/reply.js

Цитата ответа и поиск оригинала в панели «Битрикс24» (forge-92x6).

ЗАЧЕМ ОТДЕЛЬНЫЙ МОДУЛЬ. У VK и Telegram цитата адресуется идентификатором: сервер отдаёт reply_to, фронт находит строку и подсвечивает её (vk/chat.js::jumpToMessage). У Битрикс24 этого пути НЕТ: REPLY_ID при отправке уходит, но при ЧТЕНИИ портал его не отражает — params пустые, MessageDto.reply_to ВСЕГДА null (Р10, plugins/bitrix/src/dto.rs). Единственный след ответа, доживающий до чтения, — ТЕКСТОВАЯ цитата, которую приписывает сервер (routes/dialogs.rs::compose_reply):

    > Игорь Герасимов: текст оригинала, схлопнутый по пробелам и обрезанный
    сам ответ

Отсюда задача модуля: УЗНАТЬ цитату в тексте, отделить её от тела ответа и НАЙТИ оригинал среди загруженных сообщений сопоставлением автора и начала текста.

ЭКСПОРТЫ.
- QUOTE_MAX_CHARS = 200 — дословная копия crate::routes::dialogs::QUOTE_MAX_CHARS: сервер обрезает превью ровно здесь.
- QUOTE_AUTHOR_MAX_CHARS = 64 — копия truncate_chars(author, 64) в compose_reply; из-за обрезки автор сравнивается ПРЕФИКСОМ.
- normalizeQuoteText(value) → строка со схлопнутыми пробелами. Нужна на ОБЕИХ сторонах сравнения: цитата приходит уже схлопнутой (split_whitespace().join(" ")), а оригинал живёт с переводами строк.
- stripEllipsis(value) → снимает «…», которым truncate_chars помечает обрезку. Без неё длинная цитата не совпала бы с оригиналом никогда.
- parseQuoteBody(raw) → {author, text, raw} | null. Разделитель — ПЕРВОЕ «: », как его ставит compose_reply. Разбор приблизителен: «Внимание: смотри вложение» даст автора «Внимание» — это компенсируется запасным путём в findQuoteOrigin.
- splitQuote(segments) → {quote, body} | null. Разбирает ДВЕ формы: (1) «> Автор: текст\nответ» — своя отправка, ведущие строки ПЕРВОГО текстового сегмента (перевод строки живёт внутри сегмента: bbcode.rs превращает в br только тег [BR], обычный \n остаётся символом); (2) первый сегмент kind='quote' — [QUOTE]…[/QUOTE] веб-клиента портала. Сообщение, состоящее ИЗ ОДНОЙ цитаты, цитатой НЕ считается — иначе его текст исчез бы в узкой серой строке.
- findQuoteOrigin(list, msgId, quote) → сообщение-оригинал | null. Обход от БЛИЖАЙШЕГО к старому (отвечают почти всегда на недавнее, а одинаковых реплик «ок» сколько угодно). Совпадение — ПРЕФИКСНОЕ (сервер обрезал превью). Строго СТАРШЕ ответа: иначе цитата нашла бы саму себя, ведь текст ответа начинается ровно с неё. Строки pending/failed пропускаются: у них временный идентификатор. Запасной путь — совпадение по ЦЕЛОЙ строке цитаты, он спасает случай ложного автора.

ЧИСТОТА И ЗАВИСИМОСТИ. Ни одной ссылки на DOM — только импорт segmentsText/senderLabel из bitrix/format.js. Владелец ленты по-прежнему один — bitrix/chat.js. Покрытие: tests/frontend/bitrix_reply.test.mjs (чистая логика) и bitrix_reply_ui.test.mjs (UI на фейковом DOM).
