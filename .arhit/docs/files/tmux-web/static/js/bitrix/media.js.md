# tmux-web/static/js/bitrix/media.js

Поведение вложений панели «Битрикс24» (Ф8): ленивая загрузка, прогресс, лайтбокс-галерея, плеер в карточке, аватары. Разметку карточки строит attachments.js (чистые узлы, ни одного обработчика), этот модуль находит её по классам и оживляет.

ПЯТЬ ИНВАРИАНТОВ
1. Загрузка ТОЛЬКО через fetch -> blob -> objectURL. Атрибут src не несёт заголовков, а в remote-mode /api/* требует Authorization: Bearer — прямой src="/api/bitrix/media/…" работал бы локально и молча ломался бы у пользователя с токеном.
2. Внешних адресов в DOM нет ВООБЩЕ: и байты вложений, и аватары идут через прокси. У аватаров CDN публичен и работал бы напрямую — они всё равно через прокси (Р6), потому что инвариант проверяется одним грепом, а исключение превращает проверку в разбор каждого поля каждого DTO.
3. Лениво: превью запрашивается только когда карточка подъехала к вьюпорту (IntersectionObserver, запас 200px). Полный файл — только по явному действию. Отдельного thumb у портала нет, превью картинки это и есть её файл, поэтому ленивость здесь не оптимизация, а условие работоспособности.
4. objectURL освобождаются при смене диалога (revokeDialogMedia): браузер не собирает блоб, пока жив его URL. Аватары ПЕРЕЖИВАЮТ смену диалога — они общие для всей панели.
5. Всё содержимое — textContent/createElement; имена файлов пишет собеседник.

ЭКСПОРТ
  loadMedia(key, path, onNetProgress) — двухуровневый дедуп: готовый URL из b24State.mediaCache, незавершённая загрузка из local.loads (без второго уровня два клика по OPEN дали бы две параллельные загрузки).
  renderMediaGroup(msg) — контейнер карточек сообщения + wireCard на каждую.
  attachAvatar(img, userId) — подставляет blob-адрес в готовый <img>; 404 (нет фото) прячет картинку, остаются инициалы.
  revokeDialogMedia() / dropMessageMedia(dialogId, messageId) / resetMediaCards() / teardownMedia().
  onDownloadProgress(evt) — кадр WS по ключу <dialog>/<mid>/<index>.
  openMedia / saveMedia / playInCard / stopPlayer / isPlayerClick / resolveCardClick.
  initMedia / openLightbox / stepLightbox / closeLightbox / galleryOf.
  _debugMediaState().

ПРОГРЕСС ДВУНОГИЙ: кадр WS download_progress — «сервер тянет из портала» (подпись B24), чтение response.body — «сервер отдаёт вкладке» (подпись NET). Обе ноги пишут в одну полосу, но с разной подписью: иначе индикатор дважды бежал бы от нуля до ста без объяснений.

ЛАЙТБОКС — галерея по картиночным вложениям ОДНОГО сообщения (ходить по всей ленте нельзя: «следующее фото» значит следующее в этом сообщении). Esc, стрелки, клик по фону, ловушка фокуса. Границы НЕ зациклены: прыжок в начало читается как сбой, крайняя кнопка гасится.

ПЛЕЕР: играет ровно один; повторный клик по той же карточке переключает play/pause без потери позиции (resolveCardClick — чистая функция, единственная точка истины). Клики изнутри controls не считаются действием карточки.

walkNodes/pick/pickAll/on вместо querySelector и прямого addEventListener — модуль обязан работать под крошечным фейком документа во фронт-тестах, где из всего DOM есть createElement, appendChild и childNodes. Это дешевле jsdom и дешевле ветки «а если это тест».
