# tmux-web/static/js/settings/hotkeys-tab.js

Вкладка «Горячие клавиши» в модалке настроек devforge. Экспортирует buildHotkeysForm(settings, onSaved) — фабрику DOM-узла с тумблером telegram_hotkeys_enabled, таблицей всех действий с их текущими комбинациями, переназначением по нажатию и сбросом (одного действия и всех сразу).

ДЕФОЛТ ТУМБЛЕРА. Инициализация строго '!== false', а НЕ '=== true' как у соседей в interface-tab.js. У тех фич (cmd_hints_enabled, next_step_enabled) дефолт выключенный, у этой — включённый: копирование их идиомы показывало бы фичу выключенной всем, у кого настройка ещё ни разу не сохранялась.

ЧЕРНОВИК. Правки живут в локальной Map до нажатия Save — закрытая без сохранения модалка ничего не меняет.

ЗАПИСЬ КОМБИНАЦИИ. Клик по кнопке комбинации вешает keydown-слушатель в capture на document и снимает его при ПЕРВОМ же событии: оставленный висеть, он перехватывал бы клавиши всей страницы. Escape — отмена записи, а не назначение (иначе первая же ошибка отняла бы у пользователя выход). Одиночный модификатор запись не завершает. Назначение, совпавшее с дефолтом, хранится как «нет переопределения» — чтобы смена дефолта в будущей версии доехала до пользователя.

КОНФЛИКТЫ показываются прямо в строке («занято: <другое действие>»), а проигравшее действие рисуется без клавиши — см. keys.js::resolveBindings.

SAVE шлёт два поля: telegram_hotkeys_enabled и telegram_hotkeys (только отличия от дефолтов, keys.js::overridesFromBindings). Карта заменяется ЦЕЛИКОМ — см. PatchUserSettingsReq в user_settings.rs, иначе снять переопределение было бы нечем. После успеха дёргает window.ForgeApp.telegramKeys.invalidate() — через window, а не прямым импортом keynav.js: настройки открываются и без включённого плагина Telegram, статический импорт тянул бы всю панель в граф модалки.

Стили: .tg-hotkeys-* в static/css/settings-modal.css. Подключение: settings/modal.js (вкладка data-tab='hotkeys', ленивый рендер по первому показу).
