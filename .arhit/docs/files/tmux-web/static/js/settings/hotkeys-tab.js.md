# tmux-web/static/js/settings/hotkeys-tab.js

Форма «Горячие клавиши» в модалке настроек devforge. С Ф11 (VK) ОБЩАЯ на обе панели-мессенджера и параметризуется конфигом.

  buildHotkeysForm(settings, onSaved, config)
  config = {legend, hint, toggleLabel, actions, groups, bindingRows, overridesFromBindings, comboFromEvent, normalizeCombo, enabledKey, mapKey, invalidate}

Экспортируются два готовых конфига: TELEGRAM_HOTKEYS_CONFIG (TG_ACTIONS, поля telegram_hotkeys_enabled / telegram_hotkeys, сброс кэша ForgeApp.telegramKeys) и VK_HOTKEYS_CONFIG (VK_ACTIONS, vk_hotkeys_enabled / vk_hotkeys, ForgeApp.vkKeys). Пропуск третьего аргумента даёт ТЕЛЕГРАМНУЮ форму: единственный вызов до параметризации был телеграмным, и промолчавший вызывающий обязан получить прежнее поведение, а не пустую таблицу.

ПОЧЕМУ ПАРАМЕТРИЗАЦИЯ, А НЕ КОПИЯ. Для VK форма отличается ровно тремя вещами — источник реестра, имена двух полей настроек и текст легенды. Копия дала бы ТРЕТЬЮ точку правки при каждом изменении UX записи комбинаций. Это единственное место общего существующего кода, которое проект VK трогает намеренно.

ДЕФОЛТ ТУМБЛЕРА. Инициализация строго 's[cfg.enabledKey] !== false', а НЕ '=== true' как у соседей в interface-tab.js. У тех фич (cmd_hints_enabled, next_step_enabled) дефолт выключенный, у этих — включённый: копирование их идиомы показывало бы фичу выключенной всем, у кого настройка ещё ни разу не сохранялась.

ЧЕРНОВИК. Правки живут в локальной Map до нажатия Save — закрытая без сохранения модалка ничего не меняет.

ЗАПИСЬ КОМБИНАЦИИ. Клик по кнопке комбинации вешает keydown-слушатель в capture на document и снимает его при ПЕРВОМ же событии: оставленный висеть, он перехватывал бы клавиши всей страницы. Escape — отмена записи, а не назначение (иначе первая же ошибка отняла бы у пользователя выход). Одиночный модификатор запись не завершает. Назначение, совпавшее с дефолтом, хранится как «нет переопределения» — чтобы смена дефолта в будущей версии доехала до пользователя. Разбор идёт через cfg.comboFromEvent, то есть по event.code: на русской раскладке event.key вернул бы кириллицу.

ПОРЯДОК ГРУПП берётся из cfg.groups (orderedRows), а не из порядка реестра — иначе заголовок группы мог бы появиться дважды.

КОНФЛИКТЫ показываются прямо в строке («занято: <другое действие>») плюс общим предупреждением под таблицей, а проигравшее действие рисуется без клавиши — см. hotkeys-core::resolveBindings.

SAVE шлёт ровно два СВОИХ поля (cfg.enabledKey и cfg.mapKey, только отличия от дефолтов). Карта заменяется ЦЕЛИКОМ — см. PatchUserSettingsReq в user_settings.rs, иначе снять переопределение было бы нечем. После успеха дёргает cfg.invalidate() → window.ForgeApp.<contract>.invalidate(); через window, а не прямым импортом keynav.js: настройки открываются и без включённого плагина, статический импорт тянул бы всю панель в граф модалки, а отсутствие контракта — норма.

Стили: .tg-hotkeys-* в static/css/settings-modal.css — имена остались историческими, блок правил общий на обе вкладки. Подключение: settings/modal.js — вкладка Telegram (видимость чатов, затем хоткеи) и вкладка VK (видимость бесед, затем хоткеи), ленивый рендер по первому показу.

Тест: tmux-web/tests/frontend/settings_hotkeys_form.test.mjs. См. также [[vk-keyboard]], [[keyboard-owners]].
