# tmux-web/static/js/tracker/render-list.js

Режим list панели «Мои задачи»: лента задач по макету ~/Documents/ForgeTracker.pen.

Строка задачи — ряд колонок фиксированной ширины: [ ] P1 Название … [work] #forge ~4ч 08.09 2/5 0:42:19 [▸] [→ tasks/todo] [rm]. Невыполненные и сделанные разделены заголовком // DONE — 2 · 1:39:13.

Что чистое, а что трогает DOM. Чистые (покрыты node-тестом): fmtDuration(seconds) → 0:42:19; parseTs(raw) — голая дата YYYY-MM-DD читается как ЛОКАЛЬНАЯ полночь, ровно как parse_ts в plugins/tracker/src/report.rs (через new Date("2026-09-08") так нельзя: там дата читается как UTC и срок уезжал бы на день назад в положительных поясах); inDir(task, dir, ctx); filterTasks(tasks, ctx); sortTasks(tasks); splitDone(tasks). Отрисовку делает renderList(container, view), но она НИЧЕГО не решает — все действия уходят в колбэки из main.js.

Директории это ПРЕДИКАТЫ поверх одного снимка, а не серверные запросы:
- ~/today — колонка today или doing, либо срок не позже конца сегодняшнего дня, либо по задаче идёт таймер;
- ~/week — то же плюс waiting и сроки до конца текущей локальной недели (с понедельника, как в report.rs);
- ~/inbox — колонка inbox;
- ~/all — всё.
Выполненное попадает в ту директорию, к чьему окну относится done_at: «сделано сегодня» не должно исчезать из ~/today от того, что срок не стоял.

Порядок ленты задаёт РУЧНОЙ order, а не приоритет: в макете P0 стоит второй строкой, то есть порядок задаёт человек перетаскиванием, а приоритет — метка. Автосортировка обесценила бы drag'n'drop. Перетаскивание отдаёт наружу не «новый порядок видимого», а пару «кого» + «перед кем»: пересобрать полный глобальный порядок умеет только main.js, у которого есть все задачи снимка.

Никакого innerHTML: заголовок задачи попадает в DOM только через textContent.

Четыре пустых состояния (по одному на директорию) повторяют экран «Состояния и перенос» макета: подпись // ~/today — 0 NODES, строка приглашения, два примера синтаксиса и подсказка по токенам.

Тикающие часы и блок // RUNNING — фаза 5: время задачи берётся из снимка (task_seconds, посчитано сервером на момент now) и обновляется по событиям WS.
