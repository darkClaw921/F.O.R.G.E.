# tmux-web/static/js/tracker/parse.js

Разбор строки нижнего prompt'а tracker:~$ панели «Мои задачи». Чистый модуль: ни DOM, ни fetch, ни глобального состояния — целиком покрыт node-тестом tmux-web/tests/frontend/tracker_parse.test.mjs (26 проверок).

Грамматика из макета ~/Documents/ForgeTracker.pen:
  Свести дизайн трекера !1 #forge ~4ч @work due:18:00
  !N — приоритет 0..4 (0 самый высокий); #тег — теги, можно несколько; ~2ч — оценка, единицы ч/h/час, м/m/мин, д/d/день, дробные через точку или запятую, голое число это минуты; @список — TaskList; due: — HH:MM, YYYY-MM-DD, YYYY-MM-DDTHH:MM, today/tomorrow, сегодня/завтра, DD.MM[.YYYY]. Остаток строки — заголовок.

Четыре зафиксированных решения:
1. Неизвестный токен ОСТАЁТСЯ В ЗАГОЛОВКЕ (!7, ~абв, due:никогда) и попадает в поле unknown для превью. Молчаливая потеря куска фразы хуже любого «не понял».
2. Токен — целое слово: строка режется по пробелам, поэтому x!1 и C# в заголовке выживают.
3. Повтор побеждает последним: !2 … !0 даёт 0. Так ведёт себя правка уже набранной строки.
4. Список из @… СОЗДАЁТСЯ, если его нет (сам вызов делает main.js, здесь возвращается только имя). Альтернатива — молча положить задачу в inbox, то есть сделать не то, что написал человек; создание списка обратимо, потеря адресата нет.

Экспорт: parsePrompt(line, now) → {ok, title, priority, tags, estimate_min, list, due, unknown}; parseEstimate(body); parseDue(body, now) (голая дата остаётся датой, время суток даёт RFC 3339); toCreatePayload(parsed, listId, status) — незаданные поля НЕ кладутся в тело, чтобы сервер применил свои умолчания, а не принял null за сброс; previewOf(parsed); formatEstimate(minutes).
