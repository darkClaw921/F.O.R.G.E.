# tmux-web/static/js/tracker/fields.js

Чистые конверсии значений полей карточки трекера: строка модели <-> значение нативного пикера, плюс селектор оценки.

ЗАЧЕМ ОТДЕЛЬНЫЙ МОДУЛЬ. modals.js импортирует core/dom.js (getElementById на уровне модуля), поэтому неимпортируем в голом node и ничем не покрыт. Конверсии дат вынесены сюда — без DOM и сети — и покрыты tests/frontend/tracker_fields.test.mjs (18 проверок).

ЭКСПОРТЫ:
- toLocalInput(raw) / fromLocalInput(value) — datetime-local <-> RFC 3339 (UTC). Переехали из modals.js как есть; их продолжают использовать ручные отрезки времени (// TIME).
- toDateInput(raw) / fromDateInput(value) — для поля start (input type=date). Голая дата НЕ разбирается через Date: new Date('2026-09-08') это полночь UTC, то есть на день раньше в зонах западнее Гринвича.
- toDueInput(raw) / fromDueInput(value) — для поля due (input type=datetime-local). Голая дата открывается как ...T00:00 и возвращается ГОЛОЙ ДАТОЙ; момент со временем ходит через RFC 3339.
- ESTIMATE_PRESETS (15м/30м/1ч/2ч/4ч/8ч), ESTIMATE_CUSTOM, estimateChoice(minutes), estimateValue(mode, custom).

ГЛАВНЫЙ ИНВАРИАНТ — КРУГОВОЙ ПРОГОН НИЧЕГО НЕ МЕНЯЕТ. buildPatch в modals.js сравнивает СТРОКИ формы со строками задачи и шлёт только изменённое; если to* -> from* вернут другую строку, открытая и сразу сохранённая карточка молча переписала бы срок каждой задаче. Живьём проверено: открыть и нажать SAVE без правок -> updated_at не меняется.

СБРОС. Пустой пикер даёт null, а не пустую строку: модель различает 'не передали' и 'передали null' (Option<Option<String>> в plugins/tracker/src/models.rs).

ОЦЕНКА. Наружу всегда уходит estimate_min в минутах. Значение не из списка (~90м из prompt-строки, из br, из чужого клиента) открывается КАК ЕСТЬ в режиме 'своё', а не подменяется ближайшим типовым. 'Своё' без числа или с нулём — это сброс.

Зависимости: parseTs из ./render-list.js. Потребители: modals.js (поля карточки и ручные отрезки).
