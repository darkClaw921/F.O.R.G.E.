# tmux-web/static/js/tracker/modals.js

Карточка задачи трекера (NODE): шапка с таймером, // FIELDS, // NOTES, // CHECKLIST, // TIME, подвал DELETE / -> tasks/todo / MARK DONE / SAVE.

ЧАСТИЧНОЕ РЕДАКТИРОВАНИЕ НЕ ЗАТИРАЕТ НЕЗАДАННОЕ: в PATCH уходят только реально изменённые поля (buildPatch сравнивает форму со снимком задачи на момент открытия), а пустое поле уезжает как null (сброс), потому что модель различает 'не передали' и 'передали null'.

ПОЛЯ ДАТ И ОЦЕНКИ — СЕЛЕКТОРЫ, НЕ ТЕКСТ (forge-sipno):
- start — input type=date (без времени): Гантт рисует плановую полосу по дням, времени начала не показывает никто;
- due — input type=datetime-local (со временем): 'due:18:00' из prompt-строки и 'сегодня 18:00' из макета обязаны быть видны и правимы; голая дата открывается как ...T00:00 и возвращается голой датой;
- estimate — select с типовыми длительностями (15м/30м/1ч/2ч/4ч/8ч) плюс 'своё…' с числовым полем минут; поле показывается только в режиме 'своё', но существует всегда, поэтому значение не из списка (90 минут) открывается как есть, а не подменяется ближайшим часом. Наружу по-прежнему уходит estimate_min.
Конверсии живут в ./fields.js (там нет DOM => покрыты node-тестом) и ре-экспортируются отсюда; save() приводит значения пикеров к форме модели ДО вызова buildPatch, поэтому сама buildPatch не изменилась.

Синтаксис prompt-строки (due:18:00, ~2ч) остался ТЕКСТОВЫМ: это командная строка, а не форма (parse.js не тронут).

Esc снимает ровно один слой: карточка не закрывается, пока открыт диалог переноса (isPushOpen) или диалог вехи (isMilestoneOpen).

Живые блоки (// CHECKLIST и // TIME) перерисовываются отдельно от формы: кадр WS не должен стирать наполовину набранную правку. Ручные отрезки времени — эталонный datetime-local, конверсии у них те же самые.
