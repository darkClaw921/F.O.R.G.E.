# tmux-web/static/js/tracker/to-todo.js

Перенос задачи трекера в TODO вкладки Tasks — диалог «PUSH ▸ tasks/todo» и сам
перенос. Фаза 8 плагина forge-tracker.

ЧТО ЭТО ДЕЛАЕТ. Кнопка [→ tasks/todo] в строке ленты, [→] на карточке канбана
и «→ tasks/todo» в подвале карточки задачи открывают один и тот же диалог. В
нём человек выбирает корень проекта и подтверждает; модуль создаёт ОДНУ
TODO-карточку в колонке TODO вкладки Tasks.

ЭТО КОПИЯ, А НЕ ПЕРЕЕЗД. В трекере после переноса не меняется ничего: ни
статус, ни done_at, ни updated_at, ни отрезки, ни накопленное время, ни
чек-лист. Модуль физически не умеет писать в трекер — единственный запрос,
который он делает, это POST /api/todos хоста. Обратной ссылки «этот todo сделан
из той задачи» не заводится намеренно: связывать две сущности — решение
пользователя, а не побочный эффект кнопки.

ПОЧЕМУ ЕСТЬ ДИАЛОГ ВЫБОРА КОРНЯ. Задачи трекера ГЛОБАЛЬНЫЕ: в
plugins/tracker/src/models.rs нет никакого root_path, стор один на машину
(~/.config/forge/tracker.json). TODO, наоборот, живёт в корне проекта —
POST /api/todos обязателен к полю path, из которого сервер делает
paths::resolve_root. Взять корень автоматически неоткуда, и это единственная
причина существования диалога.

НОВЫХ СЕРВЕРНЫХ РОУТОВ ФАЗА НЕ ДОБАВЛЯЕТ. Перенос целиком делает фронт через
существующий createTodoForPath (tmux-web/static/js/tasks/crud.js). Крейт
forge-tracker про TodoStore не знает и знать не должен: иначе личный слой задач
начал бы зависеть от хранилища хоста и перестал бы быть отключаемым по флагу
--tracker.

ЧИСТЫЕ ФУНКЦИИ (покрыты tmux-web/tests/frontend/tracker_push.test.mjs):

- shortenPath(path) — /Users/<кто-то>/… и /home/<кто-то>/… → ~/…. Настоящего
  $HOME у браузера нет, поэтому сокращается только заведомо домашний префикс;
  всё прочее показывается как есть (длинный честный путь лучше красивого
  неверного).
- collectRoots(sessions, activePath) — список вариантов. Концепции «проект» в
  devforge нет (см. paths::resolve_root и js/ws/todos-ws.js::sessionPathOrNull),
  поэтому проекты — это РАЗНЫЕ session.path из state.sessions, без повторов и
  без сессий с пустым cwd, отсортированные по подписи. Последним ВСЕГДА идёт
  виртуальный вариант «корень активной сессии tmux»: если активной сессии нет,
  он остаётся в списке с path: null и не выбирается — пропав, он молча менял бы
  умолчание.
- pickRoot(roots, savedPath) — выбор при открытии. Правило двухступенчатое:
  запомненный прошлый выбор (localStorage forge.tracker.push.root), если он ещё
  есть среди проектов; иначе корень активной сессии (умолчание плана,
  currentTodosPath из js/tasks/render.js); иначе первый проект; иначе null.
- contextOf(snap, task) — имя списка, накопленные секунды и пункты чек-листа по
  порядку ИЗ СНИМКА /api/tracker/state. Отдельного запроса ради описания нет.
- buildDescription(task, ctx) — текст описания будущей карточки. ФОРМАТ
  ЗАФИКСИРОВАН: заметки задачи первыми и без заголовка (в карточке Tasks видно
  начало текста, и там должно быть содержание), пустая строка, блок
  «// TRACKER NODE <8 знаков id>» с полями приоритет / статус / список / теги /
  оценка / начало / срок / потрачено, затем «// CHECKLIST done/total» и пункты
  [x]/[ ]. Пустые поля строк не занимают.

DOM-ЧАСТЬ. initTrackerPush(deps) · openPushDialog(task) · closePushDialog() ·
isPushOpen() · teardownTrackerPush(). Узлы диалога и внешние сервисы приходят
СНАРУЖИ, из js/tracker/main.js: импорт ../core/dom.js дёргает
document.getElementById на уровне модуля и сделал бы файл неимпортируемым в
голом node — ровно так же обходятся render-list.js и timer.js. deps несёт dom
(узлы #trk-push*), snapshot(), sessions(), activePath(), create(),
note(text, action) и openTasks().

ПОВТОРНЫЙ ПЕРЕНОС ТОЙ ЖЕ ЗАДАЧИ РАЗРЕШЁН и создаёт вторую карточку — принятое
правило, а не недосмотр: связи между задачей и todo нет, проверять «уже
переносили» не по чему, а угадывать по заголовку значило бы запрещать
намеренную вторую копию (например, в другой корень). Защита есть только от
двойного клика — флаг busy.

ОШИБКИ. Отказ POST /api/todos показывается В ДИАЛОГЕ (#trk-push-error), диалог
не закрывается, выбранный корень сохраняется, повтор — один клик. Задача
трекера при этом не тронута ничем. Когда корней нет вовсе (не открыто ни одной
сессии tmux), кнопка PUSH погашена и рядом стоит объяснение — заведомый 400 от
сервера человеку показывать нечестно.

УСПЕХ. Диалог закрывается, выбранный корень запоминается, а в статус-баре
панели появляется сообщение со ссылкой [открыть Tasks] на 10 секунд: своего
тоста у панели нет, «тостом» служит строка статуса (note в main.js).

Esc. Диалог снимает РОВНО ОДИН слой: modals.js::onKeydown при открытом диалоге
уходит первым же условием (isPushOpen), иначе Esc закрывал бы и диалог, и
карточку задачи разом, теряя недописанную правку.
