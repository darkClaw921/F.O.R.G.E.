# tmux-web/static/js/tracker/timer.js

Живые часы панели трекера (forge-tracker, фаза 5).

НАЗНАЧЕНИЕ. Один общий тик на всю панель вместо таймера на строку. Идущих отрезков может быть сколько угодно — параллельные таймеры по разным задачам это штатный сценарий трекера, — и setInterval на каждую строку означал бы N таймеров, которые надо снимать по одному при каждой перерисовке ленты. Одна перерисовка, и половина таймеров осиротела бы, продолжая жить в фоне.

ОПОРА ВРЕМЕНИ. Значение никогда не накапливается шагами (seconds += 1 расходится с реальностью в первый же раз, когда вкладку скрыли или машину усыпили). Каждое число вычисляется заново как сейчас минус started_at, где сейчас восстанавливается из снимка: serverNow = snap.now + (Date.now() - момент получения снимка). Поле now кладёт в снимок сервер (plugins/tracker/src/dto.rs) именно ради этого: часы браузера и сервера расходятся, и без опорной точки секундомер прыгал бы при каждом снимке.

ЭКСПОРТЫ.
- clockFromSnapshot(snap, clientMs) — опора {snapNowMs, baseClientMs}; берётся один раз при применении снимка.
- serverNow(clock, clientMs) — серверное сейчас в миллисекундах.
- sinceSnapshot(clock, clientMs) — секунды, натикавшие после снимка (не бывает отрицательным).
- dayRolledOver(clock, clientMs) — сменились ли локальные сутки. true означает, что арифметика добавки для TODAY больше не действует и нужен свежий снимок; main.js по этому признаку зовёт refreshTracker ровно один раз.
- entryElapsed(entry, nowMs) — длительность отрезка; у закрытого берётся stopped_at, у перевёрнутого и неразбираемого ноль.
- liveTaskSeconds / liveItemSeconds(snap, clock, clientMs) — серверная база (task_seconds / item_seconds) плюс дельта на каждый идущий отрезок задачи или пункта. Возвращаются ТОЛЬКО те ключи, у которых есть добавка.
- liveTotals(snap, clock, clientMs) — суммы дня и недели: база плюс дельта, умноженная на число идущих отрезков.
- startTicker(onTick) / stopTicker() / isTicking() — сам интервал в 1 секунду; startTicker идемпотентна.
- renderRunning(container, view) — блок // RUNNING — N по макету: чип с точкой, названием задачи, названием пункта, started HH:MM, живым временем и кнопкой [stop]. Перерисовывается только при СМЕНЕ СОСТАВА идущих отрезков.
- tickRunning(container, entries, nowMs) — обновление одних лишь цифр блока: идёт от узлов [data-trk-run] к отрезкам, а не селектором по id (CSS.escape есть не везде).
- _debugTimerState() — для e2e.

СВЯЗИ. Импортирует fmtDuration и parseTs из render-list.js. Потребитель — main.js (функция tick) и modals.js (entryElapsed). Правила учёта времени НЕ дублируются: они живут в plugins/tracker/src/report.rs, а модуль лишь продолжает во времени уже посчитанное сервером значение.

ОГРАНИЧЕНИЯ. Тикер работает только когда есть хотя бы один активный отрезок И панель видна (вкладка открыта, окно не скрыто) — этим управляет syncTicker в main.js. Полночь не досчитывается арифметикой.
