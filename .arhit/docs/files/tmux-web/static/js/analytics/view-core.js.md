# tmux-web/static/js/analytics/view-core.js

Чистая логика дашборда аналитики (Фаза 5): арифметика и форматирование без DOM и сети.

ЗАЧЕМ ОТДЕЛЬНЫЙ ФАЙЛ. Импортировать analytics.js в Node нельзя — он тянет core/dom.js, а тот на первой строке зовёт document.getElementById. Всё, что в дашборде можно посчитать неправильно, вынесено сюда: файл без единого импорта, грузится в Node как есть и покрыт tmux-web/tests/frontend/analytics_view.test.mjs (68 проверок).

ЭКСПОРТЫ.
- RANGES / DEFAULT_RANGE / normalizeRange(range) — значения селектора периода ('7','30','90','all'); мусор из localStorage превращается в умолчание '30', а не роняет вью.
- dayKey(date) — Date → YYYY-MM-DD в ЛОКАЛЬНОЙ зоне: дни индекса календарные, не UTC.
- rangeToQuery(range, now?) — границы {from,to} для запроса. «7 дней» это сегодня и шесть предыдущих дат (ровно семь колонок), переход через месяц и год считается календарём. 'all' возвращает {} — сервер подставит весь диапазон индекса сам; подстановка искусственной нижней границы увела бы в бессмыслицу предыдущий период для дельт.
- bucketFor(range) — 'day' до 90 дней, 'week' для «всего времени» (иначе ось превращается в частокол из двухсот колонок).
- computeDelta(current, previous, better?) — дельта к предыдущему периоду: {ratio, percent, direction, tone, text} либо null. null при previous === 0 или нечисловых входах: «+∞%»/«NaN%» в плитке читаются как поломка цифр. tone задаётся смыслом метрики (better 'up' — расти хорошо, 'down' — падать хорошо, null — нейтрально), а НЕ знаком разницы.
- bucketLabels(edges, fmt?) / pauseBucketLabels(edges) / msgLenBucketLabels(edges) — N границ дают N+1 подпись. Границы приходят С СЕРВЕРА (pauseBucketEdgesMs, msgLenEdges) именно затем, чтобы подписи не разъезжались с расчётом при правке PAUSE_BUCKET_EDGES_MS / MSG_LEN_EDGES.
- ratioSeries(num, den) — поэлементное отношение 0..1; нулевой знаменатель даёт 0, а не NaN (дыра в линии читалась бы как потерянные данные). Используется для доли thinking в выводе (чарт 12).
- isEmptySummary(summary) — в ответе нечего показывать: ни корзин, ни инструментов, ни моделей, ни проектов, ни сообщений. Вью рисует объяснение вместо сетки заглушек.
- progressPercent(progress) — 0..100; total === 0 в начале прохода это 0%, а не «готово».
- viewMode(summary) — главная развилка вью: {mode:'progress'|'data', polling, refreshing}. state !== 'ready' → только прогресс (рисовать нули было бы враньём); 'ready' при progress.running → ДАННЫЕ плюс пометка о фоновом доборе, потому что индекс поднят из кэша и добираются лишь хвосты дописанных файлов. Поллинг нужен в обоих случаях.

## Фаза 7
`weekdayHourMatrix(hourXWeekday)` — разворот матрицы активности из формата бэкенда `[час][день недели]` (24×7, так дешевле копить в дневном бакете) в календарный формат чарта `[день недели][час]` (7×24). Пустой вход даёт матрицу нулей. `hasHeat(matrix)` — есть ли хоть одно ненулевое значение: ровная карта нулей валидна, но рисовать её как данные нельзя, иначе равномерный цвет читается как равномерная активность.
