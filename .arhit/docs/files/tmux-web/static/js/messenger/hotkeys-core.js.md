# tmux-web/static/js/messenger/hotkeys-core.js

ДВИЖОК КЛАВИАТУРНЫХ КОМБИНАЦИЙ — общий слой мессенджеров (Ф11 VK).

Чистый модуль: ни DOM, ни сети, ни реестра действий. Реестр передаётся ПЕРВЫМ аргументом (actions) и живёт в панели (js/vk/keys.js, js/telegram/keys.js). Форма реестра: массив {id, title, group, combo, hint?, fixed?}.

## Экспорты

keyFromEvent(e) — каноническая клавиша из event.code (KeyX→'x', DigitN→'N', NumpadN→'N', F1..F24, таблица CODE_MAP для пунктуации и навигационных); event.key используется ТОЛЬКО как фолбэк для окружений без code (экранные клавиатуры, синтетические события), символ с Shift ('?') приводится к базовой клавише.
comboFromEvent(e) — канонический вид '[Ctrl+][Alt+][Shift+][Meta+]<клавиша>'; null, если нажат один модификатор.
normalizeCombo(raw) — разбор записанной строки с синонимами (Cmd/Command/super/win→Meta, Control→Ctrl, Option/opt→Alt) и починкой порядка модификаторов; null на мусоре ('a+b', '+++', пустая, неизвестный модификатор).
modifierName(part) / canonKey(part) — атомы normalizeCombo (в telegram/keys.js они приватные; экспортированы здесь ради тестируемости).
formatCombo(combo) — подпись для UI: 'Shift+/'→'⇧?', 'Enter'→'⏎', 'Escape'→'Esc'.
findAction(actions, id), defaultBindings(actions).
sanitizeOverrides(raw, actions) — зеркало backend-санитайзера user_settings.rs::sanitize_hotkeys, но строже: известен список действий, поэтому чужие id и fixed-действия отсеиваются. Фильтрация ТОЛЬКО НА ЧТЕНИЕ — настройки не портятся, и запись новой версии клиента переживает откат на старую.
resolveBindings(actions, overrides) → {bindings, byCombo, conflicts, unbound}.
bindingRows(actions, overrides) — строки для таблицы настроек и шпаргалки (combo, label, isDefault, fixed, conflictWith).
overridesFromBindings(actions, bindings) — что слать на backend.
groupedRows(actions, groups, overrides) — группы в объявленном порядке + 'Прочее' для неизвестных.
isEditableTarget(el), comboAllowedIn(combo, ctx), actionForEvent(e, resolved, ctx).

## Три инварианта, ошибка в каждом видна только у пользователя

1. СОПОСТАВЛЕНИЕ ПО event.code, А НЕ event.key. На русской раскладке event.key для физической J вернёт 'о', и хоткей перестал бы работать ровно у той аудитории, ради которой фича делается.
2. resolveBindings В ДВА ПРОХОДА: сначала все переопределения, затем дефолты нетронутых. Один проход отдал бы дефолту РАННЕГО действия победу над переопределением ПОЗДНЕГО, и пользователь получил бы 'моя настройка не применилась'. Проигравший конфликт остаётся БЕЗ клавиши (unbound) и честно показывается таким в настройках: молча вернуть ему дефолт значило бы соврать тому, кто этот дефолт только что занял.
3. overridesFromBindings ПИШЕТ ТОЛЬКО ОТЛИЧИЯ от дефолта. Полная карта означала бы, что смена дефолта в новой версии не доедет до пользователей 'со всем как из коробки', а снять переопределение станет нечем (пустая карта перестанет означать 'всё по умолчанию').

## Отношение к js/telegram/keys.js

Telegram на это ядро НЕ мигрирован: панель работает, и её правка ради красоты графа импортов — чистый риск без пользовательской выгоды. Движок существует в ДВУХ копиях, и дрейф ловит СТРАЖ tmux-web/tests/frontend/messenger_shared_parity.test.mjs — он импортирует обе реализации и требует совпадения на таблице входов (2883 проверки). Правка одной копии без второй = красный тест, а не жалоба 'в Telegram Ctrl+Shift+X работает, а в VK нет', которую невозможно диагностировать по симптому. Миграция (telegram/keys.js → re-export-шим) — отдельная задача после стабилизации VK.
