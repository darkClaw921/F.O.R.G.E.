# tmux-web/static/js/messenger/ws-core.js

Ядро WebSocket-клиента общего слоя мессенджеров (создано в Ф3 VK).

Вынесено из js/telegram/ws.js; сам telegram/ws.js НЕ редактируется и живёт со своей копией — панель Telegram работает у пользователей прямо сейчас, и переводить её на общий слой ради красоты означало бы рисковать рабочей вкладкой. Общий слой импортирует только панель VK.

Экспорт: createWsClient({urlFor, backoffs, pingIntervalMs, onFrame, onLatency, onOpen, onClose, label, socketFactory}) -> {connect, disconnect, isOpen, socket, _debug}; latencyFromPingDrift(prevAt, nowAt, expectedMs); DEFAULT_BACKOFFS_MS; DEFAULT_PING_INTERVAL_MS.

ГЛАВНЫЙ ИНВАРИАНТ: disconnect() снимает onclose/onerror/onmessage/onopen ДО close(). Это конкретный исправленный дефект js/echo/ws.js, а не стилистика: без снятия обработчиков close() асинхронно дёргает onclose уже закрытого сокета, тот планирует реконнект, реконнект открывает новый сокет — и так по кругу, пока вкладка открыта. Покрыто тестом messenger_ws_core.test.mjs (фейковый WebSocket ведёт журнал операций); мутация «перенести close() выше» краснит две проверки.

Прочее: одна ступень backoff на все обрывы (второй onclose не планирует второй таймер), успешное открытие сбрасывает лестницу, connect идемпотентен при живом сокете, ошибка конструктора не вылетает наружу а планирует повтор, на серверный ping немедленно отвечается pong (сервер закрывает соединение по idle 60с при ping раз в 15с), задержка оценивается по дрейфу интервала между ping'ами (эха на pong сервер не шлёт, классический RTT недоступен), исключение обработчика панели не отменяет следующие кадры.

urlFor инжектируется функцией, а не собирается внутри: модуль не импортирует core/auth.js (у того побочки на верхнем уровне — localStorage и подмена window.fetch) и потому грузится в Node без стенда.
