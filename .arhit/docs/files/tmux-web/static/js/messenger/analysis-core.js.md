# tmux-web/static/js/messenger/analysis-core.js

ЯДРО попапа «Анализ чата» — общее на три мессенджера (VK, Telegram, Битрикс24). Фабрика createAnalysisPanel({prefix, refs, api, isBlockingOverlayOpen, onNotice, dialogLabel, activeDialogId, errorTexts, depthChoices, defaultDepth}), а не набор функций с глобальным состоянием: попапов в приложении три, и общее состояние склеило бы их.

Что живёт внутри: вкладки «Анализ»/«Контекст чата»; ленивый GET заметки и сохранённого разбора (по одному разу на чат); тред Q&A с выбором цели дельт по открытой строке; сворачивание разбора с запоминанием в localStorage; rAF-буфер дельт; фильтрация ЧУЖИХ кадров по паре (dialog_id, run_id); усыновление run_id из analysis_started (вкладка, потерявшая его при перезагрузке, снова берёт run под управление); перерисовка Markdown по analysis_done; разбор ошибок СТРОГО по err.code.

Инварианты, которые ядро держит за все три панели:
- только textContent/createElement, ни одного innerHTML; Markdown — через messenger/markdown.js;
- клиентская половина коалесцинга дельт (серверная — в крейте forge-chat-analysis, 120 мс / 400 символов). Без неё Lagged -> Resync -> цикл перезагрузок панели;
- статус «выгружаю переписку…» ставится В ТОТ ЖЕ КАДР, что и клик, ДО отправки POST — именно поэтому Битриксу не понадобился отдельный кадр прогресса выгрузки, хотя его страница ограничена 50 сообщениями.

Параметры глубины (depthChoices/defaultDepth) добавлены НАЗАД-СОВМЕСТИМО на этапе Битрикса: по умолчанию берутся модульные DEPTH_CHOICES/DEFAULT_DEPTH, поэтому VK и Telegram не изменились ни на строку. Рядом заведён pickDepthFrom(choices, value); одноаргументный pickDepth оставлен как есть — на нём висят тесты VK и Telegram.
