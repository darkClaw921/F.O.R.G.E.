# tmux-web/static/js/messenger/theme-core.js

ПЕРВЫЙ файл общего слоя мессенджеров js/messenger/*. Правило приёма в этот каталог жёсткое: сюда попадает ТОЛЬКО код с НУЛЕВОЙ связью с мессенджером (не «почти нулевой»); всё, что знает про диалоги, сообщения или конкретный API, остаётся в js/telegram/* и js/vk/* двумя честными копиями. Математика цвета — эталонный случай: она не знает даже слова «сообщение», зато в ней уже зашит опыт (oklch() и transparent не разбираются -> запасная ТЁМНАЯ тема), и вторая копия неизбежно отстала бы от третьего нераспознанного формата. Экспорт: parseCssColor (hex 3/4/6/8, rgb/rgba с запятыми, пробелами, слэшем альфы и процентами, горстка именованных цветов; всё остальное -> null), relativeLuminance (без гамма-коррекции: нужен не WCAG-коэффициент, а грубое «светлая тема или тёмная»), resolveTheme(mode, appBg) (в dark/light цвет приложения не смотрится вовсе, в auto решает яркость --bg по порогу L > 0.5), normalizeThemeMode, nextThemeMode (круг auto->dark->light), themeToggleTitle, THEME_MODES, THEME_FALLBACK='dark'. ВАЖНО: js/telegram/format.js при этом НЕ редактировался — его копия осталась на месте, общий слой импортирует только панель VK; миграция Telegram это отдельная задача после стабилизации VK. Модуль чистый (ни DOM, ни localStorage, ни импортов), покрыт tmux-web/tests/frontend/messenger_theme_core.test.mjs — 70 проверок, мутация THEME_FALLBACK на 'light' даёт 5 падений.
