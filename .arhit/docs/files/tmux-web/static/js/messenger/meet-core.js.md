# tmux-web/static/js/messenger/meet-core.js

ОБЩЕЕ ЯДРО ДЕТЕКТА ССЫЛОК НА ВИДЕОВСТРЕЧИ для трёх панелей мессенджеров (фронтовая Ф1 плагина forge-meet, переработано фронтовой Ф2). Чистый модуль: ни DOM, ни сети, ни таймеров — тестируется в голом Node. Живёт рядом с messenger/analysis-core.js по той же причине: один файл на три панели.

ЗАЧЕМ. Линкификации в проекте нет вообще — текст сообщения рисуется текстовыми узлами, а Битрикс намеренно рисует адрес как span.b24-seg-url, а не как <a href>. Поэтому найти в сообщении ссылку на встречу — отдельная работа, а не побочный эффект рендера.

БЕЗОПАСНОСТЬ. Совпадение платформы ищется ТОЛЬКО в URL.hostname — точное равенство либо суффикс от точки. Четыре обхода подстрочного поиска (поддомен-обманка, домен в query, домен во фрагменте, домен в userinfo) закрыты отрицательными тестами. Схема — существующим safeHref из markdown.js. Нормализация — БЕЛЫЙ список параметров (pwd у Zoom, context и p у Teams).

ЧТО ИЗМЕНИЛА ФРОНТОВАЯ Ф2 (эпик forge-meet-fe2-g9jw):

1. ОДНО НАПИСАНИЕ ПОЛЕЙ РЕЕСТРА. configureMeetPlatforms принимает РОВНО проводную форму Provider: platform, title, hosts, host_suffixes, paths, keep_params, key_case, link_regex, audio; обёртка одна — providers. Прежняя терпимость (id/key, domains, path_patterns, params, keyCase, обёртка platforms) снята: она маскировала бы молчаливый откат на встроенный набор при переименовании поля на бэкенде. Равенство встроенного набора и PROVIDERS держится тестом meet_contract.test.mjs поле в поле, в обе стороны.

2. КЛЮЧ ПЕРЕИМЕНОВАН key -> localKey, и в результат добавлено поле audio. Результат detectMeetUrl: {platform, title, id, localKey, url, raw, audio}. localKey — ЛОКАЛЬНАЯ МЕТКА, а не url_key: идентичность комнаты считает только бэкенд по canonical_url, и на сервер уезжает поле url. Решение по вопросу 'зеркала Телемоста — одна комната?' записано в шапке модуля (хост остаётся частью идентичности; живая проба — задача forge-87hum).

3. ВСТРОЕННЫЙ НАБОР СИНХРОНИЗИРОВАН с бэкендом: добавлены хост telemost.360.yandex.ru и форма пути Zoom /w/<id>, которых во фронте не хватало.

Полное описание фазы — страница meet-frontend-phase2. Тесты: messenger_meet_core.test.mjs (205 проверок), meet_contract.test.mjs (178).
