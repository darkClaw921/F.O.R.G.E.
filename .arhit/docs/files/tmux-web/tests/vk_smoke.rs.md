# tmux-web/tests/vk_smoke.rs

Смоук-тесты плагина VK ПО ПРОВОДУ — близнец tmux-web/tests/telegram_smoke.rs.
35 сценариев, ни один не требует ни сети, ни токена.

ЧЕМ ОТЛИЧАЕТСЯ ОТ ЮНИТ-ТЕСТОВ plugins/vk/src/**. Здесь поднимается НАСТОЯЩИЙ
axum-сервер на 127.0.0.1:0 и запросы идут реальным HTTP-клиентом: это ловит
класс дефектов, который oneshot пропускает — несмонтированный роут, конфликт
шаблонов путей, сломанный WS-апгрейд, порядок слоёв, отказ ДО чтения тела.

СТЕНД. start_harness_opts(Opts{token, base_url, ws}) — конфиг ЦЕЛИКОМ в tempdir
(cache_dir и config_path), поэтому живой ~/.config/forge/vk.toml разработчика не
читается и не перезаписывается. base_url по умолчанию — заведомо закрытый порт
127.0.0.1:1. Опция ws даёт укороченные heartbeat/idle (VkState::with_ws_timings),
иначе тест ждал бы боевую минуту.

start_stub() — крошечный локальный «api.vk.com»: POST /method/:name отдаёт
заранее положенный JSON и ведёт журнал вызовов, GET /captcha.png отдаёт байты
картинки. Нужен ровно там, где отказ рождается НА СТОРОНЕ VK и иначе недостижим
(коды 14/15/9, callback-кнопка, чужая беседа). Полноценный стенд транспорта живёт
в plugins/vk/tests/vk_stub.rs и здесь НЕ дублируется.

ГРУППЫ СЦЕНАРИЕВ:
- opt-in: test_routes_absent_without_the_plugin — весь /api/vk/* (GET и POST) и
  /ws/vk отвечают 404 без register_routes. Главный инвариант фичи: на этом 404
  держится гейт кнопки Ⓥ во фронте;
- статус и шесть состояний логина, «токен не уезжает наружу» на СЫРОМ теле;
- таблица метод × путь × тело → статус + code (23 строки) с проверкой, что
  retry_after_secs / captcha_sid / redirect_uri присутствуют ТОЛЬКО у своих кодов;
- лестница 409 → 503 → 404 → 400 и враждебные идентификаторы (path traversal,
  «+», переполнение i64, emoji, XSS-строка) — все дают тот же 409, иначе по
  различию кодов можно было бы прощупывать валидность чужих id;
- logout: идемпотентность + проверка, что токен исчез С ДИСКА;
- ответы VK на стенде: код 15 → no_messages_scope, код 14 → конверт с captcha_sid
  и проксирование картинки, код 9 → retry_after_secs + заголовок Retry-After,
  callback-кнопка → unsupported_button без единого messages.send;
- медиа: попадание в кэш обслуживается БЕЗ вызовов VK даже при погашенном
  здоровье; отсутствующее вложение → 404 no_media;
- загрузка: 409/411/413/400 — и все ДО чтения тела (сырой TCP заявляет 64 МиБ и
  не досылает их: буферизующий хендлер повесил бы тест по таймауту); happy-path
  staging с юникодным именем; upload_id тратится ровно один раз;
- WS: первый кадр login_state, idle-таймаут против клиента с pong, Lagged →
  resync без разрыва, мусорные кадры, несколько вкладок, закрытие по shutdown;
- конфиг: битый vk.toml не роняет init.

Запуск: cargo test -p devforge --test vk_smoke.
