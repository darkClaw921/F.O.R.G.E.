# tmux-web/tests/analytics_frontend_suite.rs

Прогон фронтовых (node) тестов аналитики из cargo test — по образцу meet_frontend_suite.rs.

ЗАЧЕМ. Кит графиков ломается молча: width="NaN" или height="-12" браузер игнорирует без строчки в консоли, пользователь видит пустую карточку. Ловит это tests/frontend/analytics_chart.test.mjs, но лишь пока его кто-то запускает; запуск руками из README держится на памяти разработчика.

КАК. analytics_frontend_tests(dir) собирает список ПО КАТАЛОГУ (read_dir, маска analytics_*.test.mjs плюс settings_analytics_tab.test.mjs Фазы 6), а не перечислением: перечисленный список протухает молча — новый тест просто не попал бы в прогон. the_analytics_frontend_tests_pass запускает каждый файл отдельным процессом node из корня крейта; ненулевой код возврата собирается в отчёт и роняет тест. the_analytics_chart_test_is_in_the_list держит ключевой файл в списке поимённо на случай переименования.

НЕТ NODE — ПРОПУСК, а не падение: node не входит в зависимости devforge, требовать его от каждой машины сборки было бы новым требованием к окружению (тот же компромисс, что в meet_frontend_suite.rs). Пустой список тестов трактуется как ошибка — иначе проверка снялась бы молча.

Проверено эмпирически: подброшенный в каталог падающий analytics_*.test.mjs роняет cargo test без правки списка.
