# meet-tab.js

Вкладка «Встречи» в модалке настроек devforge (tmux-web/static/js/settings/meet-tab.js, Ф7 forge-meet).

НАЗНАЧЕНИЕ. Единственное место, откуда пользователь управляет плагином записи встреч, не открывая ~/.config/forge/meet.toml руками. Экспортирует buildMeetSettings(host, deps) — асинхронную фабрику, которая рисует вкладку в переданный узел и возвращает ссылки на построенные элементы (для тестов).

ИНЪЕКЦИЯ СЕТИ. Все сетевые вызовы приходят объектом deps: getMeetConfig, putMeetConfig, getMeetStatus, getModels, downloadModel, recheckDeps (все — из js/meet/api.js). Своего fetch у модуля нет ВООБЩЕ, и на это есть проверка по исходнику: так вкладка грузится в голом Node, а тест видит ровно те запросы, которые она делает.

СОСТАВ ВКЛАДКИ, сверху вниз:
1. «Окружение» — бейдж вычислителя (deviceBadge) и состояние четырёх внешних бинарей (depLine + DEP_HINTS) плюс кнопка «Перепроверить» (POST /api/meet/deps/recheck).
2. «Модели whisper» — каталог, вес каждой модели, признак «на диске», кнопка «Скачать» ТОЛЬКО у нескачанных.
3. Настройки по разделам MEET_GROUPS: бот, расшифровка, саммари, автовыход, хранилище, и в конце помеченные data-meet-advanced лимиты параллелизма и пороги VAD.
4. «Пути и жёсткие ограничения» — только для чтения.
5. Кнопка «Сохранить» и строка результата.

ПЯТЬ ПРАВИЛ, РАДИ КОТОРЫХ МОДУЛЬ УСТРОЕН ИМЕННО ТАК:
• deviceBadge при gpu_metal === false даёт tone: 'warn' и текст «расшифровка НЕ ЗАПУСТИТСЯ». Это не «медленнее»: правило проекта разрешает локальные модели только на GPU, и пайплайн убивает прогон, не доказавший Metal (структурный гард по строке ggml_metal_init:). Бейдж стоит первым, до всех полей.
• Поле с env_locked === true блокируется (input.disabled) и подписывается именем переменной. Переменная окружения сильнее файла, поэтому редактируемое поле означало бы «сохранил, а работает старое».
• collect() отправляет ТОЛЬКО изменённые поля (сравнение с config.fields[].value). Отправка всей формы затирала бы правки файла, сделанные между открытием вкладки и нажатием.
• После сохранения строка результата прямо говорит: «Новые значения применятся при следующем запуске devforge; идущие записи не тронуты». Конфиг плагина неизменяем в работающем процессе (см. routes/config.rs), и молчание здесь было бы ложью.
• Загрузка модели идёт только по нажатию — при открытии вкладки downloadModel не зовётся ни разу. Прогресс приходит кадрами model_progress по /ws/meet, опроса нет.

ОТКАЗЫ. Провал загрузки конфига НЕ показывает форму с умолчаниями — рисуется ошибка и кнопка «Повторить»: «Сохранить» поверх умолчаний затёрло бы реальный конфиг. file_parses === false (битый TOML) блокирует кнопку сохранения и объясняет причину.

РАЗМЕТКА строится узлами, без innerHTML: значения (имя бота, пути, тексты ошибок бинарей) приходят с сервера. Классы те же, что у соседних вкладок (notify-fieldset, notify-hint, notify-error, notify-actions, modal-check) — своего CSS вкладка не требует.

ЭКСПОРТЫ: buildMeetSettings, MEET_GROUPS, MEET_LABELS, WINDOW_MODE_LABELS, DEP_HINTS, deviceBadge, depLine, formatBytes.

РЕГИСТРАЦИЯ. Вкладка захардкожена в settings/modal.js в шести местах (кнопка, панель, селектор контента, объект состояния, ветка showTab, whitelist initialTab), а кнопка рисуется УСЛОВНО через meetEnabled() — по образцу remoteTabBtn. Без флага --meet вкладки нет вовсе.

Тест: tmux-web/tests/frontend/settings_meet_tab.test.mjs (61 проверка, включая структурный страж регистрации в modal.js). Ф11: добавлены подписи pertrack_transcription и persist_profile — контрактный тест требует русскую подпись для КАЖДОГО поля белого списка config::EDITABLE.
