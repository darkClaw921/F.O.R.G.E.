# routes/dialogs.rs

plugins/vk/src/routes/dialogs.rs — роуты данных плагина VK (Ф4.4 + Ф4.5, НОВЫЙ).

РОУТЫ: GET /api/vk/filters (4 серверных фильтра — ЗАМЕНА телеграмного /folders), GET /api/vk/dialogs?limit&offset&filter, GET|POST /api/vk/dialogs/:id/messages, GET /api/vk/dialogs/:id/messages/:mid, POST /api/vk/dialogs/:id/read, POST /api/vk/dialogs/:id/typing.

ПОРЯДОК ПРОВЕРОК (дословно как у Telegram): авторизация 409 not_authorized -> соединение 503 not_connected (ConnHealth + грейс 3 с) -> резолв peer 404 unknown_dialog -> разбор параметров 400/404. Порядок не стилистика: разбор :id до авторизации превратил бы роут в оракул валидности идентификаторов. Ради буквального соблюдения query разбирается ВРУЧНУЮ внутри хендлера (RawQuery + query_i64), а тела POST принимаются как Option<Json<T>> — экстракторы axum отработали бы ДО тела хендлера и вернули 400 раньше авторизации.

/filters СТАТИЧЕН: 0 вызовов VK, авторизация нужна, соединение НЕ проверяется (503 на константный ответ был бы враньём). Счётчиков в ответе нет — каждый стоил бы отдельного вызова при бюджете 3 rps; общий бейдж закрывает кадр unread_total (Ф5).

404 unknown_message ПОРОЖДАЕМ МЫ: messages.getById на чужой/удалённый id возвращает не ошибку, а пустой items. Плюс сверка peer_id — без неё роут читал бы чужую беседу по подставленному в путь id.

ОТПРАВКА: random_id генерируется РОВНО ОДИН раз на логическую отправку (транспорт при повторе шлёт те же параметры, VK дедуплицирует по нему); после send идёт getById за полным DTO — фронту нужен объект той же формы, что в ленте, иначе optimistic-строка мигает; если добор не удался, отдаётся минимальный DTO с настоящим id, а НЕ 500 (сообщение уже у собеседника). upload_id/upload_ids объявлены в контракте, но до Ф8 отвергаются 400. MAX_MESSAGE_CHARS=4096 проверяется ДО обращения к VK.

Имена берутся из profiles/groups того же ответа (peers::PeerCache::absorb_extended), недостающие — одной пачкой; неудача резолва НЕ проваливает запрос. Ошибка VK 14 запоминает картинку captcha в VkState (map_vk_error) — иначе прокси /api/vk/captcha/:sid показывать нечего.

Модуль несёт документированный #![allow(clippy::result_large_err)]: ApiError крупнее телеграмного на три поля контракта captcha/валидации, а Box добавил бы аллокацию на каждый штатный отказ.
