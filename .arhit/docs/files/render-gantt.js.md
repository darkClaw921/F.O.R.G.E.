# render-gantt.js

tmux-web/static/js/tracker/render-gantt.js — режим gantt панели forge-tracker (фаза 7).

НАЗНАЧЕНИЕ. Рисует диаграмму Гантта по данным GET /api/tracker/gantt?from&to: плановые полосы задач, заливку по фактически отработанному времени, дорожку вех // MILESTONES, маркер сегодняшнего дня и легенду. Экран-образец — ~/Documents/ForgeTracker.pen, «Экран — GANTT».

КЛЮЧЕВОЕ АРХИТЕКТУРНОЕ РЕШЕНИЕ: СЕТКА ИЗ СИМВОЛОВ, А НЕ ИЗ ПИКСЕЛЕЙ. Один день = CELL (4) знаков моноширинного шрифта; полоса задачи строится как СТРОКА той же длины, что шапка дней, и режется на цветные прогоны. Пиксельная раскладка требовала бы, чтобы ширина ячейки шапки, left/width полосы и позиция ромба совпадали; символьная не требует ничего — выравнивание делает шрифт. Побочная выгода: расчёт полосы становится чистой функцией строки и покрыт node-тестом без DOM.

ЧИСТЫЕ ФУНКЦИИ (экспортируются, покрыты tests/frontend/tracker_gantt.test.mjs):
* CELL — знаков на день (4);
* dayKey(date) — локальный ключ YYYY-MM-DD;
* dayStart(date) / addDays(date, n) — локальная полночь и сдвиг по суткам (безопасен к переходу на летнее время);
* buildDays(from, span, today) — ось дней окна: ключ, метка 01..31, признаки today и weekend;
* windowFor(anchor, span) — границы окна; якорь это ПЕРВЫЙ день, а не центр, потому что окна листаются встык;
* dayOffset(days, raw) — смещение даты от начала окна в сутках, МОЖЕТ быть отрицательным (полоса, начавшаяся до окна, обязана обрезаться, а не пропасть);
* dayIndexOf(days, raw) — индекс внутри окна или -1;
* planSpan(bar, days) — плановый отрезок в индексах дней. Правила: start+due → ровно эти дни; только start → вперёд на длину оценки; только due → назад от срока; ни того, ни другого → null. Длина оценки = ceil(оценка / 8 ч), минимум сутки; HOURS_PER_DAY=8 это рабочий день, календарные 24 схлопнули бы часовую задачу в точку;
* isOver(bar, seconds) — превышена ли оценка. Копия правила build_gantt из plugins/tracker/src/report.rs: без оценки превышения не бывает НИКОГДА. Считается заново на фронте только затем, чтобы полоса идущего таймера краснела мгновенно, а не после следующего запроса;
* buildTrack(bar, days, {seconds, over}) — прогоны [{text, cls}] строки полосы. Заливка = доля факт/оценка от длины полосы; без оценки полоса заливается целиком при любом ненулевом факте; ненулевой факт всегда даёт минимум один знак █; превышение красит ВСЮ полосу и убирает плановый хвост; ромб срока ◆ ставится последним знаком клетки своего дня и перекрывает знак полосы;
* buildLane(milestones, days, today) — строка дорожки вех: ▼ на сегодня, ◆ на вехи; несколько меток в один день занимают соседние знаки той же клетки;
* groupBars(bars, tasksById, lists) — группы по спискам в порядке списков стора, безсписочные последней группой «без списка»; внутри группы порядок тот же, что в ленте и на доске (ручной order через sortTasks);
* shortDate(raw) — короткая дата 05.09 для подписей.

ОТРИСОВКА. renderGantt(container, view) строит одну CSS-сетку .trk-g-grid (строки объявлены display: contents, поэтому колонки est и факт не разъезжаются между строками), в ней: шапка // NODE + номера дней + est + факт; дорожка // MILESTONES и полоса чипов с подписями вех; заголовки групп-кнопок сворачивания; строки задач; ниже сетки — легенда. Колонка факта несёт data-trk-task-time — тот же атрибут, что в ленте и на доске, поэтому общий тикер панели (js/tracker/timer.js) обновляет её сам, и своего таймера Гантту не нужно.

ОСОЗНАННЫЕ РАСХОЖДЕНИЯ С МАКЕТОМ. 1) Подписи вех вынесены из дорожки в чипы под ней: на живых данных подпись длиннее клетки дня, и две вехи на соседних днях либо наезжали бы друг на друга, либо уводили метку от своего дня; чипы заодно стали кнопками правки вехи. 2) Задача без start и без due полосы НЕ получает и показывает «— без плана —»: в данных Гантта нет разбивки времени по дням, и нарисовать её «где-то по факту» значило бы соврать.

ЗАВИСИМОСТИ. Импортирует fmtDuration, parseTs и sortTasks из render-list.js (parseTs читает голую дату как ЛОКАЛЬНУЮ полночь — иначе срок уезжал бы на день назад). Вызывается из js/tracker/main.js. Никакого innerHTML: заголовок задачи и подпись вехи попадают в DOM только через textContent.
