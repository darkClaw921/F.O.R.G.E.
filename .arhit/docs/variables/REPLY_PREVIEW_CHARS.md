# REPLY_PREVIEW_CHARS

Потолок превью текста цитаты в CODE POINTS. ОДНА И ТА ЖЕ константа объявлена по обе стороны и
значения обязаны совпадать:

- `plugins/telegram/src/dto.rs` — `pub const REPLY_PREVIEW_CHARS: usize = 140;`
- `tmux-web/static/js/telegram/reply.js` — `export const REPLY_PREVIEW_CHARS = 140;`

Почему не байты: "🦀" — четыре байта, побайтовая обрезка разорвала бы символ. Значение подобрано
под одну-две строки цитаты в UI; многоточие ВХОДИТ в лимит, поэтому результат никогда не длиннее
140 code points.

Почему дублируется на фронте: сервер уже обрезал `ReplyToDto.text`, но фронт собирает превью и
локально — `mergeReplyFromMessage` берёт оригинал из уже загруженной ленты, где серверные
ограничения не действуют. Разъедутся значения — одно и то же сообщение будет выглядеть по-разному
в зависимости от того, откуда приехала цитата.

Применяется: dto::reply_preview_text (и к `text`, и к `quote`), reply.js::truncatePreview.
