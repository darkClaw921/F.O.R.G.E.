# VK_SCOPE_SOURCE

Источники данных для выбора бесед авторазбора (tmux-web/static/js/settings/voice-scope-sources.js): VK_SCOPE_SOURCE, TELEGRAM_SCOPE_SOURCE, B24_SCOPE_SOURCE.

Каждый — объект с двумя асинхронными методами: listScopeGroups() отдаёт группы площадки ([{key,label,hint}]), listScopePeers() — список бесед ([{id,title,marks}]). Их получает общая форма выбора (buildPeerPicker) через api секции голосовых; подключает всё modal.js.

## Почему отдельный модуль

Секция голосовых — ОДИН модуль на три панели, и статический импорт трёх панельных api.js в него тянул бы в граф модалки весь VK ради вкладки Битрикса. Здесь импорты собраны в одном месте, рядом с точкой подключения, и заменяются в тестах целиком.

## Словари площадок

VK — типы бесед (user/chat/community) из vk/visibility.js VISIBLE_KINDS; тип в пометке беседы показывается ТОТ, по которому судит фильтр (выводится из peer_id через peerKind), иначе подпись и поведение разошлись бы на первой же беседе с неожиданным kind. Telegram — ПАПКИ аккаунта: ~/inbox первым, папки из listFolders() в середине, ~/archive последним (inbox и archive — не папки Telegram, а пункты нашей навигации). Битрикс24 — виды диалогов (user/chat/task); семь видов портала сведены к трём через filterKind.

## Фоновый приоритет у VK

listScopePeers у VK идёт через общий планировщик js/vk/ratelimit.js с PRIORITY_BG: пользовательский токен ограничен тремя запросами в секунду НА ВЕСЬ КЛИЕНТ, и открытая модалка не имеет права отодвигать запросы самой панели. Запрос ровно один за показ формы, поллинга нет. Лимит списка — PEER_LIST_LIMIT = 200, тот же, что в форме видимости.
