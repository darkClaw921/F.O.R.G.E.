# FOLLOW_CANCEL_UP_PX

FOLLOW_CANCEL_UP_PX = 24 (tmux-web/static/js/telegram/follow.js) — на сколько пикселей нужно уехать ВВЕРХ, чтобы «следование» за сообщением бота отменилось.

ЗАЧЕМ ПОРОГ, А НЕ ЛЮБОЕ УМЕНЬШЕНИЕ scrollTop. Инерционная прокрутка (trackpad, мобильный momentum) и «подпрыгивание» ленты при смене высоты полосы reply-клавиатуры дают отскок в единицы пикселей. По правилу «любое уменьшение — отмена» следование гасло бы сразу после включения, ровно в момент, когда клавиатура бота перерисовывается, — то есть фича не работала бы никогда.

ПОЧЕМУ 24. Заметно больше дребезга (единицы px) и заметно меньше осмысленного жеста прокрутки (один «щелчок» колеса — порядка 100px, короткий свайп — сотни).

ПОЧЕМУ ПО НАПРАВЛЕНИЮ, А НЕ ПО ФЛАГУ «ЭТО СКРОЛЛИЛ Я». Присваивание scrollTop (и scrollTo) порождает событие `scroll` АСИНХРОННО, и синхронный флаг «сейчас скроллю сам» успел бы сброситься до его доставки — получилась бы гонка, которая гасит следование от собственного же доскролла. Собственные доскроллы всегда УВЕЛИЧИВАЮТ scrollTop (scrollTargetForRow не тянет вверх никогда), поэтому «уменьшилось сверх порога» однозначно означает руку пользователя.

ГДЕ ПРИМЕНЯЕТСЯ: follow.js::cancelledByScroll (значение threshold по умолчанию), вызывается из chat.js::bindScroll на каждом событии scroll с парой (local.lastScrollTop, текущий scrollTop).
