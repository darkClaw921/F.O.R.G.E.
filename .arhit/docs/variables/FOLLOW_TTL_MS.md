# FOLLOW_TTL_MS

FOLLOW_TTL_MS = 12000 (tmux-web/static/js/telegram/follow.js) — сколько миллисекунд живёт «следование» ленты Telegram за сообщением бота после нажатия кнопки.

ЗАЧЕМ ИМЕННО ОКНО, А НЕ ФЛАГ. Следование — это разрешение автоматике двигать ленту вопреки позиции чтения пользователя. Такое разрешение обязано быть срочным: бот отвечает за секунды, а вот через полминуты «оно само уехало вниз» читалось бы уже как самовольная прокрутка и баг.

ПОЧЕМУ 12с. Верхняя граница здравого смысла: покрывает и медленного бота (callback → правка сообщения), и догрузку картинки по слабой сети, но не переживает паузу, за которую пользователь успевает переключиться на чтение истории.

КТО ЧИТАЕТ:
 * follow.js::noteFollow — значение по умолчанию для ttlMs (перекрывается параметром только в тестах);
 * chat.js::armFollowTimer — длительность setTimeout, по которому снимается ResizeObserver.

ВАЖНО: сам срок проверяется ПО ЧАСАМ в followTarget, а не таймером. Таймер нужен только ради снятия наблюдателя размера — без него ResizeObserver висел бы на строке до следующей смены диалога. Поэтому расхождение таймера и часов (спящий ноутбук, throttling фоновой вкладки) не даёт «вечного следования»: followTarget всё равно вернёт null, а onFollowResize в этом случае сам зовёт stopFollow.

СВЯЗАННЫЕ КОНСТАНТЫ: FOLLOW_SCROLL_PAD (зазор под нижним краем блока), FOLLOW_CANCEL_UP_PX (порог отмены прокруткой вверх).
