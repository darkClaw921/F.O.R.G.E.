forge-sipno: все поля даты/времени панели трекера — селекторы, а не текстовый ввод.

ЧТО ЗАМЕНЕНО
1. Карточка задачи (js/tracker/modals.js):
   - start: текстовый input 'YYYY-MM-DD' -> input type=date. БЕЗ времени: Гантт рисует плановую полосу по дням (planSpan в render-gantt.js), времени начала не показывает никто, а лишний T00:00 в модели пришлось бы либо хранить, либо сбрасывать на каждом сохранении.
   - due: текстовый input 'YYYY-MM-DD или RFC 3339' -> input type=datetime-local. СО временем: срок со временем осмыслен ('due:18:00' в prompt-строке, 'сегодня 18:00' в макете) и модель разрешает RFC 3339.
   - estimate: число минут -> select (15м/30м/1ч/2ч/4ч/8ч + 'своё…') плюс числовое поле минут, видимое только в режиме 'своё'.
2. Вехи Гантта (js/tracker/main.js): два window.prompt -> диалог #trk-ms (js/tracker/milestone.js) в языке диалога PUSH: подпись, input type=date, CANCEL/OK и явная кнопка DELETE вместо 'пустая строка = удалить'.
3. Нативные пикеры стилизованы под обе палитры: color-scheme: dark на #tracker и color-scheme: light на #tracker[data-tracker-theme=light] — всплывающий календарь и стрелки рисует браузер, и никакой другой CSS до них не достаёт.
4. Синтаксис prompt-строки (due:18:00, ~2ч) остался ТЕКСТОВЫМ — это командная строка, а не форма; parse.js не тронут.

КАК СОХРАНЁН КОНТРАКТ ЧАСТИЧНОГО РЕДАКТИРОВАНИЯ
buildPatch не изменилась: она по-прежнему сравнивает СТРОКИ формы со строками задачи и шлёт только изменённое, а пустое значение уезжает как null (сброс; Option<Option<T>> в models.rs). Изменилось только то, что save() приводит значения пикеров к форме модели ДО сравнения — через чистые функции js/tracker/fields.js. Ключевой инвариант: круговой прогон to* -> from* возвращает ИСХОДНУЮ строку, иначе открытая и сразу сохранённая карточка переписывала бы срок каждой задаче. Поэтому голая дата в due показывается как ...T00:00, но возвращается голой датой.

НЕСТАНДАРТНАЯ ОЦЕНКА
estimateChoice(90) -> {mode: 'custom', custom: '90'}: значение не из списка открывается КАК ЕСТЬ в режиме 'своё' и не подменяется ближайшим типовым. estimateValue('custom', '') -> '' — это сброс (человек выбрал 'своё' и стёр число).
