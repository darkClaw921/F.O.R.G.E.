# forge-meet: архитектура плагина целиком

Плагин записи и расшифровки онлайн-встреч. Ссылка на встречу в переписке
(Telegram, VK, Битрикс24) → кнопка рядом с сообщением → бот в настоящем Chrome
входит во встречу и пишет звук → ffmpeg сводит → whisper на GPU расшифровывает
→ спикеры получают имена → Claude пишет саммари → карточка со всем этим
открывается прямо в ленте, на том же сообщении.

Эта страница — карта целиком. Частности живут в соседних страницах, ссылки в
конце.

## Из чего собран

| крейт / каталог | что делает |
|---|---|
| `plugins/meet` (`forge-meet`) | сам плагин: роуты, состояние, бот, ингест, пайплайн, саммари, ретенция |
| `plugins/forge-cdp` | свой клиент Chrome DevTools Protocol: запуск браузера, вкладка, инжект, биндинги, транспорт |
| `plugins/atomic` (`forge-atomic`) | `write_bytes_atomic` — запись файла через `tmp + rename`; манифест и транскрипт переживают обрыв |
| `tmux-web/static/js/meet/*` | клиент плагина во фронте: гейт, HTTP-обёртки, WS |
| `tmux-web/static/js/messenger/meet-*.js` | общее для трёх лент: детект ссылок, стор состояний, кнопка на строке, карточка встречи |
| `tmux-web/static/css/meet.css` | слой алиасов `--m-*`, объявленный по разу на `#telegram`, `#vk`, `#bitrix` |
| `tmux-web/static/js/settings/meet-tab.js` | вкладка настроек плагина |

## Пять решений, которые определяют всё остальное

### 1. Бот — НАСТОЯЩИЙ Chrome под своим CDP-клиентом

Не расширение и не headless-библиотека. Расширение отпадает структурно: у
площадок жёсткий CSP, и внедрённый код не может открыть сокет к нашему
серверу. Готовые обёртки (puppeteer, chromiumoxide) — это Node-сайдкар либо
чужая модель жизненного цикла; дистрибуция devforge при этом обязана остаться
ОДНИМ Rust-бинарём через brew.

Поэтому `forge-cdp`: запуск Chrome с `--remote-debugging-port`, свой WebSocket
к DevTools, `Page.addScriptToEvaluateOnNewDocument` для инжекта,
`Runtime.addBinding` для канала данных. Измерено в Ф1: биндинг доносит кадры
из OOPIF без усечения (проверено до 4 МиБ), а окно браузера не крадёт фокус
только при запуске с `--no-startup-window` и созданием цели в фоне.

### 2. Звук идёт через CDP-биндинг, а `/ws/meet/ingest` НЕ СОЗДАЁТСЯ НИКОГДА

Это не оптимизация, а граница безопасности. Между инжектированным скриптом и
нашим сервером стоят четыре барьера: `csrf_guard` на апгрейде `/ws/*`,
Bearer-auth, `connect-src` в CSP площадки и Private Network Access. Биндинг
убирает все четыре разом, потому что убирает сеть.

Обратный вариант — «сделать исключение в `csrf_guard` по одноразовому токену» —
не делать никогда: токен физически лежит в памяти страницы, которую
контролирует третья сторона (а мы ей ещё и CSP отключили ради инжекта). Скрипт
площадки прочитает токен и откроет WS к главному серверу, где живёт
`/ws/attach`, то есть терминал. Это превращает плагин записи встреч в
drive-by RCE. Строка про отсутствующий роут стоит в таблице
`routes/mod.rs` отдельным пунктом и проверяется контрактным тестом: отсутствие
роута — такое же решение, как его наличие.

### 3. Селекторы площадок — ДАННЫЕ, и запись от них не зависит

`bot/probes.toml` встроен в бинарь, но поэлементно перекрывается
пользовательским `~/.config/forge/meet.probes.toml`. Вёрстка площадок меняется
чаще, чем выходят релизы: `button.continueInBrowserButton_-wew`, снятый живой
пробой Телемоста, протух за ТРИ ДНЯ.

Держащий всё инвариант: **промахнулись все пробы разом — запись всё равно
идёт**. Пробы влияют на имена спикеров и на удобство входа; звук берут тапы
`capture.js`, которые про этот файл не знают вовсе, а конец встречи ловится
независимыми сигналами. На это есть два теста: деградация имён и «ни один
селектор не протёк в код захвата».

### 4. Одна ось времени, и каталог встречи самодостаточен

Ingest адресует каждый кадр АБСОЛЮТНЫМ СЭМПЛОВЫМ СМЕЩЕНИЕМ от `T0`, а не
дописывает в конец файла. Дорожка, появившаяся на пятнадцатой минуте,
начинается тишиной ровно нужной длины — то есть все `raw/track-N.wav` уже лежат
на общей оси, и `adelay` в фильтрографе им не нужен (в Ф5 это чуть не сдвинуло
дорожки второй раз).

`~/.forge/meet/<id>/` можно скопировать на другую машину и доработать там:
рядом лежат `manifest.json` (паспорт записи: режим SFU, тап, `T0`, дорожки,
след пост-обработки и каскада имён) и `events.ndjson` (журнал: VAD, активный
спикер, вход и выход). Пост-обработка читает каталог, а не память процесса, —
поэтому переживает перезапуск devforge.

Две оси всё-таки существуют, и путать их нельзя: сегменты whisper живут на оси
АУДИО, метки событий — на оси СТРАНИЦЫ (`performance.now`). Коррекция дрейфа
применяется к ИНТЕРВАЛАМ, а не к сегментам: поправь сегменты — и клик по
реплике в плеере попадёт мимо неё.

### 5. Локальные модели считаются ТОЛЬКО на GPU, и очередь у них одна

Правило проекта исполняется структурно, а не комментарием: `-ng`/`--no-gpu`
никогда не попадают в argv (тест на чистой `build_args`), а stderr парсится на
ТОЧНЫЙ префикс `ggml_metal_init:` — `contains("ggml_metal")` пропустил бы
CPU-прогон, потому что строки про устройство печатаются всегда. Цена нарушения
измерена: разрыв по энкоду пятнадцатикратный, час аудио на CPU — почти
полтора часа расчёта.

Слот whisper РОВНО ОДИН и поднять его нельзя: Metal занимается процессом
целиком, два прогона суммарно идут медленнее одного. И whisper не стартует,
пока идёт ЛЮБАЯ запись: Chrome рендерит встречу на том же GPU, и пострадала бы
именно та встреча, которая пишется прямо сейчас.

### Плюс к пяти: плагина нет, пока не попросили

Без флага `--meet` роутов нет вовсе, и `GET /api/meet/status` отвечает 404.
Ровно на этом 404 держится фронтовый гейт: `meetEnabled()` навсегда `false`,
кнопка не появляется, WS не открывается, батчей нет. Выключенный плагин стоит
фронту один GET за загрузку страницы.

## Дорога данных, этап за этапом

```text
ссылка в ленте ──► meet-core.js: детект по URL.hostname (не по подстроке!)
      │
      ▼
кнопка на строке ──► POST /api/meet/meetings ──► слот записи (2) ──► бот
      │                                                               │
      ▼                                                               ▼
   статус в сторе ◄── WS /ws/meet ◄── broadcast ◄──── Chrome + инжект (3 тапа)
                                                                      │
                                          Runtime.bindingCalled (PCM16 16 кГц)
                                                                      ▼
                                              raw/track-N.wav + events.ndjson
                                                                      │
   transcoding ──► work/mix.wav ──► audio.m4a (архив, 14,7 МБ/час) ◄───┘
      │
      ▼
   transcribing ──► ОДИН слот whisper ──► сегменты
      │                    (или пер-трековая нарезка по VAD — см. ниже)
      ▼
   атрибуция спикеров ──► transcript.json + transcript.md ──► база
      │
      ▼
   summarizing ──► claude -p (промпт через stdin, НЕ через argv) ──► summary.md
      │
      ▼
   ready ──► карточка в ленте: расшифровка, участники, плеер, саммари
```

## Что в этой картине НЕ проверено вживую

Раздел обязателен: без него документация выглядит как отчёт об успехе.

| что | состояние |
|---|---|
| Яндекс Телемост | адаптер прогнан на живой встрече ОДНИМ участником (Ф4). **Приёмка на настоящей встрече с людьми не пройдена** — задача `forge-meet-f4-8sa7.7` открыта |
| Google Meet, Microsoft Teams, Zoom | **вживую не проверялись вообще**: аккаунтов и встреч не было. Селекторы в `probes.toml` — ЧЕРНОВИК по документации и разметке, ни одна задача Ф8–Ф10 не закрыта |
| Пер-трековая расшифровка (Ф11) | работает только в режиме `PerParticipant`, а такого режима **не подтверждено ни у одной площадки**: Телемост измеренно работает в `Slots`. Путь проверен на мок-встрече и на живом whisper, но не на живой площадке |
| Пост-обработка, саммари, фронт | проверены на настоящих бинарях (whisper 1.9.2, ffmpeg 8.0, `claude -p`) и живым Chrome; встречи при этом синтезированные |
