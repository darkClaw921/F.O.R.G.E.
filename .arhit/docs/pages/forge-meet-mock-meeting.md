# Мок-встреча — главный тестовый актив плагина forge-meet

`plugins/meet/tests/fixtures/mock-meeting/` — страница, изображающая
видеовстречу настолько точно, насколько это нужно боту, и делающая это
ДЕТЕРМИНИРОВАННО.

## Зачем

Весь пайплайн записи — инжект, три тапа захвата, VAD, транспорт через
CDP-биндинг, писатель WAV, атрибуция — отлаживается здесь, ДО живой платформы.
Обратный порядок означал бы отладку двух неизвестных одновременно: своего кода
и чужой вёрстки, которая меняется без предупреждения и воспроизводится раз в
сутки. Здесь прогон занимает секунды и повторяется байт в байт.

## Файлы

- `index.html` — петлевой `RTCPeerConnection` (pcSend → pcRecv в одной вкладке),
  осцилляторы с расписанием, DOM с 13 селекторами, скрытый `<audio muted>` на
  каждую входящую дорожку, три сигнала конца встречи.
- `expected.json` — ЭТАЛОННЫЙ таймлайн: кто когда говорит, участки наложения,
  участки тишины, селекторы, допуски.
- `README.md` — как запускать, как добавлять сценарии.

## Три режима SFU

| `?mode=` | дорожек | собеседников | что проверяет |
|---|---|---|---|
| `per-track` | 3 | 3 | трек = человек, пер-трековая атрибуция работает |
| `slots` | 2 | 6 | КТО в дорожке меняется → трекам не верим, спикер только из DOM |
| `mixed` | 1 | 3 | звук смикширован сервером → атрибуция по трекам невозможна |

Прочие параметры: `autojoin=0` оставляет пре-джойн (интерстишал, поле имени,
кнопка входа — этим пользуется Ф4), `duration=<мс>`, `room=<строка>`.

## Откуда берётся детерминизм

Расписание задаётся АУДИОЧАСАМИ (`AudioContext.currentTime`): гейты
осцилляторов ставятся на абсолютные моменты `t0 + смещение`, сэмпл-точно.

Это не стилистика. Окно бота стоит свёрнутым либо за экраном, то есть
occluded, а Chrome троттлит таймеры рендерера occluded-окна ДО ОДНОЙ СЕКУНДЫ —
расписание на `setTimeout` разъехалось бы на этом первым, и «эталонный»
таймлайн стал бы случайным. DOM тоже обновляется опросом аудиочасов, а не
счётчиком тиков. На это есть тест: `setTimeout` в странице ЗАПРЕЩЁН, а
`setInterval` разрешён ровно один — тот, что опрашивает часы.

## Дублирование расписания — намеренное

`index.html` исполняет расписание, `expected.json` его проверяет. Эталон,
вычисленный тем же кодом, который проверяется, не проверяет ничего. На
расхождение есть тест `the_page_schedule_matches_the_expected_timeline`:
правка `SCHEDULES` без правки `expected.json` не проходит молча.

## `window.__mockMeeting` — только для тестов

Инжектируемый скрипт бота им не пользуется и пользоваться не имеет права: на
живой площадке ничего подобного нет, и тап, опершийся на такое поле, прошёл бы
мок и провалился бы на Телемосте. Поле объявлено ровно один раз и снабжено
предупреждением; на это тоже есть тест.

## Как прогнать

```bash
# полный e2e во всех трёх режимах (нужен Chrome)
FORGE_MEET_E2E=1 cargo test -p forge-meet --test e2e_mock -- --nocapture

# посмотреть глазами
cd plugins/meet/tests/fixtures/mock-meeting && python3 -m http.server 8765
open "http://127.0.0.1:8765/index.html?mode=slots&autojoin=0"
```

Без `FORGE_MEET_E2E=1` живые тесты полностью пропускаются: CI без браузера
обязан оставаться зелёным.

## Живая проверка (сделана)

3/2/1 удалённых дорожки по режимам, участников в DOM 4/7/4, два прогона
совпадают, встреча завершается сама и ставит маркер конца.

## Открытое ограничение окружения

В окружении, где `AudioContext.currentTime` замирает на первом кванте (см.
[[forge-meet-phase3-gate]]), страница физически не может произвести звук:
дорожки идут, но несут тишину. `e2e_mock` это состояние обнаруживает и
пропускает прогон с явным сообщением.
