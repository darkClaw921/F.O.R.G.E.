## 1. Имя бинаря: `whisper-cli`, и в `PATH` есть ЛОВУШКА

Формула 1.9.2 кладёт в `/opt/homebrew/bin` девять бинарей, среди них `whisper-cli`,
`whisper-bench`, `whisper-server`, `whisper-stream`, `whisper-vad-speech-segments`.
Бинаря `whisper-cpp` **нет**, бинаря `main` **нет** — апстримовское переименование
`main` → `whisper-cli` из 1.7.x доехало до формулы.

**Ловушка, из-за которой порядок кандидатов важен.** На этой машине в `PATH` уже лежит
`/Library/Frameworks/Python.framework/Versions/3.12/bin/whisper` — это **Python
openai-whisper 20250625**, а не whisper.cpp. У него другой CLI (`--model tiny`, `--output_format`),
другие модели (`.pt`, не GGML) и по умолчанию расчёт на CPU. Проба «есть ли `whisper` в PATH»
нашла бы именно его и увела бы весь пайплайн в нарушение правила «локальные модели только на GPU».

Порядок кандидатов для `deps.rs` (Ф5):

1. `whisper-cli` — фактическое имя в 1.7.x+;
2. `whisper-cpp` — как звалось до переименования формулы;
3. `main` — историческое имя апстрима, встречается при сборке из исходников;
4. `whisper` — **только последним и только с верификацией**: найденный кандидат обязан
   ответить на `--version` строкой вида `whisper.cpp version: X.Y.Z`. Не ответил — это не наш
   бинарь, идём дальше / считаем, что whisper не установлен.

Проверка `--version` дешёвая и обязательна: имя файла ничего не гарантирует.

## 2. Флаги: поддерживаются ВСЕ спорные, но с оговорками

Целевая команда плана
`whisper-cli -m <model> -f <wav> -l ru -p 1 -bs 5 -fa -ojf -pp -of <out>`
отработала **как есть**, exit 0.

| Флаг | Есть? | Что важно |
|---|---|---|
| `-p N` / `--processors` | да | по умолчанию `1` — то есть значение плана совпадает с дефолтом, но передавать явно всё равно нужно: дефолт не контракт |
| `-bs N` / `--beam-size` | да | дефолт тоже `5` |
| `-fa` / `--flash-attn` | да | **дефолт уже `true` в 1.9.2**. Флаг стал no-op, а выключается обратным `-nfa` / `--no-flash-attn`. В более старых сборках дефолт был `false` — поэтому передавать `-fa` явно всё-таки стоит, он безвреден и делает команду версионно-независимой |
| `-ojf` / `--output-json-full` | да | одного `-ojf` достаточно, дописывать `-oj` не нужно: файл `<out>.json` создался |
| `-pp` / `--print-progress` | да | прогресс идёт в stderr |
| `-of FNAME` | да | путь БЕЗ расширения, оно дописывается по формату |
| `--vad` | да, но | см. п. 5 — без модели VAD процесс **падает по SIGABRT** |
| `-ng` / `--no-gpu` | да | ровно то, что НИКОГДА не должно попадать в argv (инвариант теста Ф5) |
| `-dtw MODEL` | да | альтернативный источник токеновых таймкодов, точнее эвристики; требует указания типа модели. Кандидат на будущее, если атрибуция по границам сегментов окажется грубой |

### Что реально даёт `-ojf`

JSON `<out>.json`: `systeminfo`, `model`, `params`, `result.language`, `transcription[]`.
Каждый сегмент — `{timestamps, offsets:{from,to}, text, tokens[]}`, и **у каждого токена свой
`offsets:{from,to}` в миллисекундах** плюс вероятность `p`. Пример из прогона:

```
segment offsets: {'from': 0, 'to': 3160}   text: " Коллеги, начинаем еженедельную встречу команды."
  token ' Кол'  offsets {from: 20,  to: 200}  p=0.972
  token 'лег'   offsets {from: 200, to: 400}  p=0.999
  token 'и'     offsets {from: 400, to: 460}  p=0.999
```

Оговорка для Ф5: метки **потокенные, а не пословные** — токен это subword-кусок («Кол», «лег»,
«и»). Это даже мельче, чем нужно, но `speakers.rs` обязан склеивать токены в слова сам, а не
рассчитывать, что каждый элемент `tokens[]` — слово. Служебные токены (`[_BEG_]`) с нулевой
длительностью тоже лежат в массиве и должны отфильтровываться.

## 3. Metal: подтверждён, и опорная строка требует точности

В stderr успешного прогона строка **`ggml_metal_init:`** присутствует (6 вхождений:
`allocating`, `found device: Apple M1 Max`, `picking default device`, `use fusion`,
`use concurrency`, `use graph optimize`). Опора плана верна.

**НО опираться нужно на точный префикс `ggml_metal_init:` в начале строки, а не на подстроку
`ggml_metal`.** Проба показала, почему:

| Строка | GPU-прогон | Прогон с `-ng` | `--help` |
|---|---|---|---|
| `ggml_metal_device_init: GPU name: MTL0 (Apple M1 Max)` | есть | **есть** | **есть** |
| `ggml_metal_library_init: using embedded metal library` | есть | **есть** | **есть** |
| `ggml_metal_rsets_init: ...` | есть | **есть** | **есть** |
| `whisper_backend_init_gpu: using MTL0 backend` | есть | нет | — |
| `whisper_backend_init_gpu: no GPU found` | нет | **есть** | — |
| `whisper_backend_init: using BLAS backend` | нет | **есть** | — |
| **`ggml_metal_init: allocating`** | **есть** | **нет** | нет |

То есть ggml грузит Metal-бэкенд и печатает про устройство ВСЕГДА, даже когда считать на нём не
собирается. Небрежный гард `stderr.contains("ggml_metal")` пропустил бы CPU-прогон.

Рекомендация для Ф5: считать Metal подтверждённым, если stderr содержит строку, начинающуюся с
`ggml_metal_init:`; дополнительно логировать `whisper_backend_init_gpu: using MTL0 backend`, а
`whisper_backend_init_gpu: no GPU found` трактовать как явный признак отказа.

**JSON для гарда не годится.** Поле `systeminfo` в `<out>.json` у GPU- и CPU-прогона **побайтово
одинаково** (`MTL : EMBED_LIBRARY = 1 | ... | ACCELERATE = 1 | ...`) — это флаги сборки, а не
использованный бэкенд. Проверено сравнением двух файлов. Гард обязан читать stderr.

## 4. Скорость: 13–15× реального времени, ≈4,5 минуты на час аудио

Замер на **реальном файле известной длительности**, а не на синтетике: русская речь, надиктованная
`say -v Milena` по тексту планёрки, конвертированная `ffmpeg` в 16 кГц моно PCM16 —
ровно тот формат, который будет отдавать `build_mixdown_filtergraph` из Ф5.

Файл: **196,52 с** (3 мин 16 с), 6 288 592 Б.

| Прогон | wall | `whisper_print_timings: total` | × реального времени |
|---|---|---|---|
| 1 | 14,76 с | 14 564 мс | 13,3× |
| 2 | 14,62 с | 14 389 мс | 13,4× |
| 3 | 13,33 с | 13 176 мс | **14,7×** |

Разбивка лучшего прогона: `load 393 мс`, `mel 110 мс`, `encode 6353 мс / 9 runs (706 мс/run)`,
`batchd 4997 мс / 5403 runs`, `sample 1771 мс`, `fallbacks 0 p / 0 h`.

**Пересчёт на час аудио: ≈ 4 мин 5 с … 4 мин 30 с.** Это ЛУЧШЕ плановой оценки «5–9 мин»,
и цифру плана следует заменить на измеренную. Для планирования разумно оставить **5 мин на час**
как консервативную: проба шла на чистой синтезированной речи без шума, пауз и перекрытий, с
`fallbacks = 0`; на реальной встрече температурные фолбэки добавят времени.

`whisper-bench -m <model> -t 4`: `encode 833 мс / 1 run`, `decode 1,96 мс/run (256)`,
`batchd 0,56 мс/run (320)`, `prompt 0,11 мс/run (4096)`, total 1955 мс.

### Сколько стоит нарушить правило «только GPU»

Тот же бинарь с `-ng` на 20-секундном куске: `encode 10 941 мс / 1 run`, total 14 359 мс.
То есть **20 секунд аудио считаются 14 секунд**: 0,7× реального времени против 14×.
Один энкод на GPU — 0,7 с, на CPU — 10,9 с, разрыв ≈ **15×**. Час аудио на CPU — почти полтора
часа расчёта. Правило проекта не про эстетику: молчаливый откат на CPU превращает
пост-обработку часовой встречи из четырёх минут в полтора часа.

## 5. `--vad` есть, но без модели процесс ПАДАЕТ, а не ругается

`whisper-cli --vad -m <model> -f <wav>` без `-vm` завершается **exit 134 (SIGABRT)** со
стеком `ggml_abort`:

```
whisper_full: VAD is enabled, processing speech segments only
whisper_vad_init_from_file_with_params: loading VAD model from ''
whisper_vad_init_from_file_with_params: failed to open VAD model ''
whisper_vad: failed to initialize VAD context
whisper_full: failed to compute VAD
```

Полный набор VAD-опций 1.9.2: `--vad`, `-vm/--vad-model`, `-vt/--vad-threshold`,
`-vspd/--vad-min-speech-duration-ms`, `-vsd/--vad-min-silence-duration-ms`,
`-vmsd/--vad-max-speech-duration-s`, `-vp/--vad-speech-pad-ms`, `-vo/--vad-samples-overlap`.

Следствия для Ф5: если VAD у whisper вообще включается, то (а) нужна ОТДЕЛЬНАЯ модель silero в
`models.rs` рядом с моделью распознавания, (б) `--vad` без `-vm` не должен собираться в принципе —
это инвариант `build_args`, а не проверка в рантайме, потому что падение здесь не ошибка процесса,
а аварийный abort. Отдельно: у forge-meet свой VAD в AudioWorklet (Ф3), он про нарезку по времени
и к whisper отношения не имеет — путать эти два VAD нельзя.

## 6. Мелочи, полезные для `deps.rs`

- `--help` печатается в **stderr**, не в stdout, и перед ним идут строки загрузки бэкендов
  (`load_backend: loaded BLAS/MTL/CPU backend from ...`). Парсер флагов обязан читать stderr.
- **Первый в жизни запуск после установки медленный**: `ggml_metal_library_init: loaded in
  12.467 sec` (компиляция/прогрев встроенной metal-библиотеки). Все последующие — `0,014–0,031 sec`.
  Таймаут пробы в `deps.rs` обязан пережить холодный старт: минимум 30 с, а не 5.
- Поддерживаемые форматы входа: `flac, mp3, ogg, wav` — то есть WAV с ingest'а Ф3 идёт напрямую.
- Дефолт `-t` (threads) — `4 / 10`.
- `ffmpeg 8.0` в `/opt/homebrew/bin` — есть, конвертация AIFF → 16 кГц моно PCM16 отработала.
