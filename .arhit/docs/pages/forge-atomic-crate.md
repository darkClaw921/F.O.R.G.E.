Крейт plugins/atomic (package forge-atomic) — атомарная запись приватного файла. Создан в фазе 0 проекта forge-meet (задача forge-meet-f0-8bzq.4) выносом модуля atomic из forge-chat-analysis.

ЗАЧЕМ ОТДЕЛЬНЫЙ КРЕЙТ. Код родился внутри forge-chat-analysis и жил там, пока потребителями были только плагины-мессенджеры, которые ядро анализа и так тянут. forge-meet ядро анализа НЕ тянет (у него свой промпт встречи и свой вызов раннера), но четыре файла на диск пишет: manifest.json, transcript.json/md, summary.md, chrome.pid. Подключение forge-chat-analysis ради tmp+rename+chmod притащило бы tokio (features=full) + tokio-util + uuid + forge-claude-runner, поэтому реальным исходом была бы ЧЕТВЁРТАЯ копия последовательности — ровно та болезнь, ради лечения которой atomic и выносили из плагинов в этап 1a (эпик forge-caport-1a-4fwj).

ЛИСТОВОСТЬ — ГЛАВНОЕ СВОЙСТВО. cargo tree -p forge-atomic: ровно один узел — anyhow (плюс tempfile в dev-dependencies). Ни одной зависимости на другой член workspace, ни одной на runtime: ни tokio, ни serde, ни axum. Правило на будущее: в этот крейт не добавляется НИЧЕГО, кроме того, что уже есть в дереве каждого потребителя. Как только подключение перестанет быть бесплатным, следующий плагин снова напишет свою копию.

СОСТАВ (plugins/atomic/src/lib.rs, 4 публичные функции):
- write_bytes_atomic(path, bytes) -> anyhow::Result<()> — ЕДИНАЯ точка. Последовательность: create_dir_all родителя -> запись во временный файл рядом -> fsync -> rename на целевой путь -> ПОВТОРНЫЙ set_owner_only (rename сохраняет права tmp, но целевой файл мог существовать раньше с более широкими). При ЛЮБОЙ ошибке tmp удаляется, целевой остаётся ровно прежним.
- tmp_path_for(path) -> PathBuf — имя временного файла: .<имя>.<pid>.tmp рядом с целевым. PID в имени защищает от коллизии двух процессов: последний rename выигрывает, но обрезанного файла не видит никто.
- write_secret_file(path, bytes) — открытие с mode(0o600) ДО первого байта, явный set_owner_only (файл мог остаться с прошлого раза, тогда mode() при create не применяется), write_all, sync_all.
- set_owner_only(path) — chmod 0600; на не-Unix это no-op.

ИНВАРИАНТ, РАДИ КОТОРОГО ВСЁ СУЩЕСТВУЕТ: частичного состояния на диске не бывает. Либо целевой файл прежний, либо он новый целиком. Права 0600 не опциональны — файлы, которые пишутся отсюда, содержат либо секрет (токены VK/Telegram/Bitrix, webhook портала), либо заметки о конкретных людях (хранилище разборов чатов), либо расшифровку встречи.

ПОТРЕБИТЕЛИ. forge-chat-analysis (prompts::save), plugins/vk/src/config.rs (сохранение токена — через переэкспорт), дальше forge-meet (файлы записи встречи). Плагины telegram и bitrix пока пишут своими копиями внутри write_table / write_secret_file — кандидаты на переезд сюда.

СОВМЕСТИМОСТЬ. В forge-chat-analysis/src/lib.rs оставлена строка pub use forge_atomic as atomic; — путь forge_chat_analysis::atomic::* продолжает работать, ни одно место вызова не правилось. В корневом Cargo.toml крейт поднят в [workspace.dependencies] как forge-atomic = { path = "plugins/atomic" } — это ЕДИНСТВЕННЫЙ внутренний крейт там (forge-claude-runner, forge-chat-analysis, echo-host-api подключаются относительным путём из манифестов): у атомарной записи потребителей больше и они разнороднее, а промах мимо каталога кончился бы не ошибкой сборки, а новой копией tmp+rename+chmod с другими правами.

ПРОВЕРКА: cargo test -p forge-atomic — 5 тестов (успешная запись приватна и не оставляет tmp; перезапись ужимает унаследованные 0644 до 0600; мусорный tmp от упавшего процесса ужимается ДО записи секрета; неудача не оставляет ни tmp, ни повреждений — целевой путь непустой КАТАЛОГ, чтобы падал именно rename; имя tmp содержит pid и лежит рядом с целевым).
