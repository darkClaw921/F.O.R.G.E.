# Кнопки сообществ ВКонтакте: что достижимо под пользовательским токеном, а что нет

Страница фиксирует РЕШЕНИЕ ФАЗЫ 9 плагина forge-vk и причины, по которым часть кнопок принципиально нельзя нажать из стороннего клиента. Она нужна, чтобы через полгода никто не пытался «доделать callback».

## Таблица

| action.type | под пользовательским токеном | что делает devforge |
|---|---|---|
| text | ДА | POST /api/vk/dialogs/:id/messages/:mid/button -> messages.send(peer_id, message=label, payload=payload, random_id). Именно так работает официальный клиент |
| open_link | ДА, без API | фронт открывает URL через format.js::safeUrl (белый список http/https/vk); бэкенд не участвует |
| callback | НЕТ | 409 unsupported_button; кнопка нарисована отключённой с пояснением |
| vkpay | НЕТ | то же: требует официального приложения VK |
| open_app | НЕТ | то же: мини-приложения открываются только в клиенте VK |
| location | НЕТ | то же: отправка геопозиции доступна только в приложении VK |
| незнакомый вид | НЕТ | kind доезжает до UI строкой как есть, supported:false — сообщение остаётся читаемым |

## Почему callback нереализуем

messages.sendMessageEventAnswer — это метод СТОРОНЫ СООБЩЕСТВА: им бот ОТВЕЧАЕТ на уже полученный message_event, и он требует ключа доступа сообщества. Обратной, клиентской половины — «отправить message_event от имени пользователя» — в публичном API ВКонтакте нет ВОВСЕ: ни в документации, ни в клиентских библиотеках; в экосистеме этот сценарий закрывается только группами. Прямого аналога телеграмному messages.getBotCallbackAnswer у VK не существует.

Следствия, зафиксированные в коде:
- код ошибки bot_timeout (504) из телеграмного контракта в VK ОТСУТСТВУЕТ — таймаутиться нечему;
- ветки applyAnswer / describeAnswer / тоста-ответа телеграмного botkb.js в js/vk/botkb.js не переносятся;
- обходных путей (эмуляция message_event, group-токен, скрытые методы) не изобретаем: имитация нажатия — худший из возможных вариантов, потому что пользователь не узнает, что команда не дошла.

## Как это видно пользователю

Кнопка ВИДНА, но отключена (disabled + класс .vk-kb-btn-unsupported) и объясняет причину в title: «ВКонтакте не позволяет нажать кнопку этого типа из стороннего клиента: механика message_event доступна только самому сообществу». Прятать такие кнопки нельзя — пользователь сверяет экран с телефоном, и исчезнувшая кнопка читается как поломка бота, а не как ограничение платформы. Это единственная функция телеграмной вкладки, принципиально недостижимая в VK-близнеце.

## Почему нажатие адресуется КООРДИНАТАМИ

payload кнопки уходит сообществу как команда. Принимай роут payload из тела запроса — любая вкладка (или XSS в соседней панели) отправила бы боту произвольную команду от имени пользователя. Поэтому:
- ReplyButtonDto НЕ содержит payload вовсе (проверяется тестом по сериализованному JSON);
- тело нажатия — только {row, col};
- сервер перечитывает сообщение (messages.getById) и достаёт label + payload сам;
- координаты сырые: проекция не перенумеровывает кнопки, а фронт, выбрасывающий кнопки без подписи, несёт координаты из DTO, а не из позиции в массиве.

Побочная выгода: устаревшая клавиатура (сообщество успело переписать сообщение) даёт честный отказ 400 invalid_input вместо нажатия «не той» кнопки.
