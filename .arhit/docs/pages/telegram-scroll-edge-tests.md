Краевые тесты автопрокрутки ленты Telegram (tmux-web/tests/frontend/telegram_scroll_edge.test.mjs, 149 ассертов).

ЗАЧЕМ. Соседний telegram_scroll_ui.test.mjs проверяет основной путь фичи «следование» (follow.js + chat.js), а этот файл добивает углы, где фича обязана либо сработать, либо честно уступить прежнему правилу isAtBottom.

СТЕНД. Свой процесс и свой фейковый DOM (стабы стоят ДО первого импорта, потому что core/dom.js резолвит все ref'ы один раз на верхнем уровне; ?bust= запрещён — он породил бы второй экземпляр state.js). Отличия от стенда telegram_scroll_ui: (1) построчная модель высоты — getBoundingClientRect отчитывается RECT_TALL (bottom=5000) только для id из множества tallRows, поэтому одно сообщение может вырасти, соседнее остаться коротким, а выросшее — сжаться обратно; (2) window.open как журнал внешних переходов (без него клик по url-кнопке роняет файл на TypeError); (3) хелперы lastCall()/lastBehavior() вместо scrollCalls[0].behavior — при отсутствии доскролла тест обязан дать [FAIL] с меткой, а не стек; (4) liveRo() — «последний созданный наблюдатель», потому что teardownChat распускает наблюдатель насовсем и следующее нажатие заводит следующий; (5) pressFromReading(id) — встать в позицию чтения и ТОЛЬКО ПОТОМ нажать кнопку (доскролл уезжает вниз, и любое последующее scrollTo(READING) — это уже отмена следования).

КЛЮЧЕВЫЕ ЧИСЛА СТЕНДА: scrollHeight=1000, clientHeight=400 ⇒ MAX_TOP=600 (потолок прокрутки, куда приезжает следование) против scrollTop=1000, куда пишет прежний scrollToBottom — по значению видно, КАКОЙ веткой поехала лента. READING=120 — «читаю историю» (isAtBottom ложно), AT_BOTTOM=600 — у кромки, READING_MID=250 в секции подгрузки истории (ниже потолка, чтобы ассерт «лента не сдвинулась» не выродился, и выше порога 200 из shouldLoadOlder, чтобы событие scroll не запустило вторую loadOlder).

СЕКЦИИ (17): рост без нажатия; нажатие из середины истории; дребезг против настоящего ухода вверх; ответ НОВЫМ сообщением; ответ через 20 с (TTL истёк); две кнопки в разных сообщениях подряд; правка в НЕактивном диалоге и совпадение message_id между чатами; сообщение стало КОРОЧЕ; подгрузка истории вверх (якорь); prefers-reduced-motion; кнопка reply-клавиатуры; жизненный цикл наблюдателя; окружение без ResizeObserver и без scrollTo; open-url/inline-query следование не включают; гонка «правка обогнала ответ на callback» + ошибка flood_wait; запоздалое срабатывание наблюдателя после отмены + регресс-щит на send(); полный сброс.

ВЕРИФИКАЦИЯ МУТАЦИЯМИ. Каждый ассерт проверен на способность падать: снятие сверки dialog_id в onEdited, following=false в onEdited и onNewMessage, снятие гарда local.loading в scrollBlockIntoView, игнор prefers-reduced-motion, снятие unobserveFollowRow из clearLog, снятие cancelledByScroll из bindScroll, снятие re-observe из renderHistory, «scrollTargetForRow тянет вверх», снятие сверки followRow===row в onDeleted, снятие disconnect из teardownChat, снятие stopFollow из openDialog, вызов onButtonPress для любого действия в botkb::runAction — все 13 мутаций поймались. Две первые редакции ассертов были вырожденными и переписаны: (1) секция подгрузки истории замеряла позицию у самого потолка прокрутки, где двигать нечего, — пропавший гард local.loading не ловился; (2) снятие наблюдения в clearLog и в onDeleted перекрывалось перепривязкой в renderHistory / вызовом stopFollow — добавлены сценарии «окно истекло по часам, а таймер снятия ещё не выстрелил», где эти строки единственные, кто отпускает мёртвый узел.

ПРОДУКТОВЫЙ КОД НЕ МЕНЯЛСЯ: багов краевые тесты не вскрыли, chat.js / follow.js / botkb.js побайтово те же.
