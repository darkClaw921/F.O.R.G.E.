Повтор этапа из `cancelled`: правило по данным, а не по ярлыку (07.09.2026).

СИМПТОМ. `POST /api/meet/meetings/<id>/summary` для встречи Телемоста
(f61cfa7a-14c7-49d6-8bc0-926d15ca6ebc) отвечал 409
`invalid_state: переход cancelled → summarizing недопустим`, хотя в каталоге
встречи лежали звук (1.3 МБ), транскрипт и готовое саммари, а `summary_status`
был `ready`.

ПРИЧИНА. `status::can_transition` не давал из `cancelled` вообще ничего, кроме
`pruned`, по комментарию «у `cancelled` не осталось ничего». Предположение
неверно: журнал встречи показывает `recording_stopped { reason: user_stop }` —
запись остановили кнопкой, пост-обработка прошла до конца, а статус после этого
стал `cancelled/user_cancel`. Отмену жмут в ЛЮБОЙ момент, в том числе после
готовой обработки, и ярлык статуса о содержимом каталога ничего не говорит.

ЛЕЧЕНИЕ.
* `cancelled` получил тот же набор этапов повтора, что и `ready`
  (`transcoding`, `transcribing`, `summarizing`).
* `failed` НЕ тронут: транскрипта у него нет по построению — провал саммари
  даёт `ready` + `SummaryStatus::Failed`, а до `failed` доходят только отказы
  записи и расшифровки. Саммари оттуда по-прежнему закрыто.
* Наличие входа проверяет `routes::meetings::missing_input` — и только для
  повтора из `cancelled`, где ярлык ничего не гарантирует: саммари требует
  `transcript_path`, расшифровка и перекодирование — `audio_path`. Коды отказа
  `transcript_missing` / `audio_missing` вместо падения внутри пайплайна.
* Проверяется ПУТЬ, а не файл на диске: случай «файлы вычищены ретенцией»
  закрыт отдельным статусом `pruned`, из которого переходов нет вовсе. Проверка
  файла ломала восемь существующих тестов, чьи фикстуры путей не заполняют.

Тесты: `status::tests::a_cancelled_meeting_can_still_be_resummarised`,
обновлённые `terminal_statuses_accept_no_command_and_move_only_on_retry` и
матрица `EXPECTED` (строка `canc`), плюс два интеграционных в
`tests/routes_result.rs` — `a_cancelled_meeting_with_a_transcript_can_be_resummarised`
и `a_cancelled_meeting_without_a_transcript_refuses_with_a_named_code`. Оба
заводятся из `summarizing`: отмена из терминального `ready` запрещена, и это
правильно — в жизни отмена и пришла во время пост-обработки.

Проверки: `cargo test -p forge-meet` — 738 тестов, 0 падений. Живая приёмка:
пересчёт саммари той самой встречи прошёл штатно (`summarizing → ready`,
summary.md переписан), плагины после перезапуска отвечают 200.

ОТКРЫТЫЙ ВОПРОС. Почему остановка кнопкой (`user_stop`) закончилась статусом
`cancelled/user_cancel` — не выяснено. Пост-обработка при этом отработала
полностью, то есть отмена пришла в конце и перезаписала статус. Стоит проверить
путь `stop` → пост-обработка → финальный статус.
