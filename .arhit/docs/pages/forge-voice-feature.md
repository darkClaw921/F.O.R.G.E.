# Голосовые сообщения в чатах: волна, расшифровка, авторазбор

Фича целиком: VK, Telegram и Битрикс24. Реализована шестью фазами
(эпики `forge-cvoice-f1…f6`), ядро — крейт `plugins/voice` (`forge-voice`).

## 1. Зачем фича и три исходных требования

Голосовое сообщение — худший формат входящего в рабочем чате: его нельзя пролистать
глазами, нельзя найти поиском, нельзя прочитать в тишине. Панели F.O.R.G.E. показывали
их заглушкой-шумом и кнопкой воспроизведения — то есть ровно тем, чем и мессенджер, без
единого преимущества.

Три требования пользователя:

1. **Показывать настоящую звуковую дорожку**, а не одинаковый декоративный шум.
2. **Расшифровывать голосовое в текст по кнопке**, с видимым прогрессом.
3. **Разбирать новые голосовые автоматически**, если человек этого захотел.

## 2. Архитектура: ядро + три адаптера + общий фронт

Образец — `forge-chat-analysis` (перенос анализа чата в три мессенджера). Ядро не знает
ни про `AppState`, ни про `axum`, ни про WS-протоколы; наружу отдаёт чистые функции,
движки и закрытые списки отказов.

```
                   plugins/voice  (крейт forge-voice)
    proc → tools → audio → gate → transcribe → {whisper | cloud} → store
                              waveform   hub   sink   config   prefs   auto   settings
                                          ▲
        ┌─────────────────────────────────┼─────────────────────────────────┐
   plugins/vk                       plugins/telegram                  plugins/bitrix
   src/voice.rs                     src/voice.rs                      src/voice.rs
   src/voice_auto.rs                src/voice_auto.rs                 src/voice_auto.rs
   src/routes/voice.rs              src/routes/voice.rs               src/routes/voice.rs
        └─────────────────────────────────┼─────────────────────────────────┘
                                          ▼
        static/js/messenger/waveform-core.js        (волна — один рисовальщик)
        static/js/messenger/voice-transcript-core.js (текст — одна фабрика)
        static/js/settings/voice-tab.js              (настройки — одна секция)
```

Крейт появился не с нуля: движки (`whisper`, `cloud`, `proc`) были написаны и обкатаны в
`forge-meet` на живых встречах. В Ф1 они переехали в `forge-voice`, а в `forge-meet` на
прежних путях остались обратные `pub use` — ни одно место вызова и ни один тест плагина
встреч от переезда не изменились. Второй реализации Metal-гарда и второго разбора ответа
polza.ai в проекте нет.

Состав ядра — см. `forge-voice-crate`, `forge_voice::whisper`, `forge_voice::cloud`,
`forge_voice::cloud::stt`, `forge_voice::cloud::service`, `forge_voice::audio`,
`forge_voice::gate`, `forge_voice::tools`, `forge_voice::proc`, `forge_voice::waveform`,
`forge_voice::transcribe`, `forge_voice::store`, `forge_voice::prefs`,
`forge_voice::auto`, `forge_voice::settings`, `VoiceConfig`, `VoiceHub`, `VoiceSink`,
`VoiceError`, `TranscriptStore`.

## 3. Откуда берётся звуковая дорожка — у каждого мессенджера по-своему

| платформа | источник | кто считает |
|---|---|---|
| **VK** | массив приходит прямо в ответе API | никто, берём как есть |
| **Telegram** | `DocumentAttributeAudio.waveform`, упаковка по **5 бит** | `waveform::unpack_5bit` / `from_telegram`, без запуска процессов |
| **Telegram, аудиофайл** | атрибута нет | бэкенд, ffmpeg |
| **Битрикс24** | ничего | бэкенд, ffmpeg, при `commit` докачки |

**Правило приоритета: АТРИБУТ ПОБЕЖДАЕТ РАСЧЁТ.** Если Telegram прислал волну, ffmpeg не
запускается вовсе — платформа знает про свою запись больше, чем перекодированная копия.

Расчёт (`waveform::compute`): ffmpeg декодирует файл в сырой PCM на
`DECODE_SAMPLE_RATE = 8000`, `decode_s16le` разбирает байты, `rms_buckets` сворачивает их
в столбики по среднеквадратичному значению. Общая шкала для всех источников —
`WAVEFORM_MAX_VALUE = 255`, длина не больше `MAX_WAVEFORM = 200` (`fit` приводит любой
источник к ней), поэтому фронт не знает, откуда волна взялась.

**Кэш — отдельный сайдкар `<stem>.wave.json`** рядом с `<stem>.bin`, схема
`CACHE_SCHEMA_VERSION = 1`, API — `WaveformCache`. Почему не поле в `.meta.json`: мету
пишет `commit` докачки, который случается раньше расчёта, дописывать пришлось бы гонкой.
Эксплуатационная ловушка: сайдкар надо ВРУЧНУЮ добавлять в LRU-подчистку медиа-кэша
каждого плагина, иначе после вытеснения `.bin` остаются сироты.

Рисует всё это `messenger/waveform-core.js`: сорок столбиков (`WAVE_BARS`), высоты
8…32 px, нормализация по пику самого массива. Пустой массив означает
**детерминированный** шум-заглушку (xorshift32 от `noiseSeed`) — она не «дышит» при
перерисовке ленты и исчезает сама, как только доедет настоящая огибающая. Соль шума у VK
и Telegram РАЗНАЯ (у VK в неё входит номер вложения) — сводить их нельзя, изменился бы
рисунок всех уже нарисованных карточек.

## 4. Два движка расшифровки

### Стандарт — облако

По умолчанию расшифровка идёт через **облачного провайдера** (polza.ai): `VoiceConfig`
рождается с `engine = Engine::Cloud`, и селект в настройках показывает облако первым, с
подписью «по умолчанию».

Из этого следует единственное исключение в лестнице наследования настроек: **движок из
`meet.toml` не наследуется**. `stt_backend = "local"` во встречах не уводит чаты на
локальный whisper, хотя ключ, модель, язык и таймауты оттуда по-прежнему подхватываются.
Причина в разнице задач: час записи встречи локально и бесплатно — осмысленный выбор,
ждать её всё равно никто не будет; голосовое в чате живёт секунды, приходит в любой
момент и читается сразу, поэтому оно не должно ни стоять в очереди к GPU, ни требовать
574 МБ весов на машине. Наследуй мы `stt_backend`, настройка одной вкладки молча меняла
бы поведение другой — и заметить это можно было бы только по времени ответа.

Локальный движок никуда не делся, но включается ЯВНЫМ `engine = "local"` в `voice.toml`
(его же пишет селект). Инвариант закреплён тестом
`config::tests::the_meet_toml_backend_never_switches_chats_to_the_local_engine`.

### Локальный: whisper.cpp, ТОЛЬКО GPU

Правило проекта «локальные модели не считаются на CPU» здесь **структурное**, а не
декларативное, и держится двумя независимыми механизмами:

1. `-ng` / `--no-gpu` (`whisper::FORBIDDEN_ARGS`) не попадают в argv **по построению**:
   `build_args` — чистая функция под тестом-перебором, `sanitize_extra_args` вычищает
   запрещённое из пользовательских добавок конфига.
2. stderr живого прогона парсится на `METAL_NEEDLE = "ggml_metal_init:"`. Не увидели
   строку за `DEFAULT_METAL_GRACE_SECS = 60` секунд — процесс **убивается**, наружу идёт
   `metal_unavailable`. Встречный список `CPU_MARKERS` убивает прогон немедленно, если
   бэкенд явно объявил себя процессорным.

Молчаливого отката на процессор нет ни при каких настройках, включая `force`. Модель по
умолчанию — `DEFAULT_WHISPER_MODEL = "large-v3-turbo-q5_0"`, beam size 5.

### Облачный: polza.ai

OpenAI-совместимый API, модель **`openai/whisper-large-v3-turbo`** по умолчанию
(`DEFAULT_CHAT_STT_MODEL`), язык `ru`.

**Почему не `openai/whisper-1`, как у встреч.** Живой каталог (`GET /models`,
`top_provider.pricing.stt_per_minute`, август 2026) в рублях за минуту:

| модель | ₽/мин | таймкоды |
|---|---|---|
| `openai/whisper-1` — только по явной настройке | 0,432 | да |
| `openai/gpt-4o-mini-transcribe` | 0,344 | нет |
| `mistralai/voxtral-mini-transcribe` | 0,216 | нет |
| `nvidia/parakeet-tdt-0.6b-v3` | 0,108 | нет |
| **`openai/whisper-large-v3-turbo` — дефолт ЧАТОВ И ВСТРЕЧ** | **0,048** | нет |

Разница девятикратная, и платят у встреч ровно за таймкоды: на них построена
атрибуция спикеров. Под волной голосового показывается ТЕКСТ, таймлайна там нет
вовсе, поэтому чаты за таймкоды не платят. Выбранная модель — та же
`large-v3-turbo`, что стоит дефолтом у локального движка, так что облако и GPU
дают на чатах сопоставимый результат.

Цена этого выбора — один обязательный нюанс: turbo идёт через «OpenRouter Audio
API», который на `verbose_json` отвечает не молчаливым игнорированием, а
`BAD_REQUEST` («Допустимые значения: json, text»), то есть теряет расшифровку
целиком. Поэтому формат ответа выводится ИЗ МОДЕЛИ функцией
`cloud::stt_response_format` (`verbose_json` для моделей из
`TIMESTAMPED_STT_MODELS`, иначе `json`), а не задаётся полем конфига, которое
разъехалось бы с моделью на первой же смене дефолта. Ответ `{"text": "…"}`
разбирает та же `parse_verbose_json` — ветка «сегментов нет, но текст есть».

Как и движок, модель НЕ наследуется из `meet.toml`: `cloud_stt_model =
"openai/whisper-1"` во встречах не переводит чаты на дорогую модель. Своя строка
`cloud_stt_model` в `voice.toml` по-прежнему работает.

Прочее об облачном пути: язык `ru`. Длинное
голосовое режется на окна не длиннее **90 секунд** (`MAX_STT_WINDOW_SECS`), границы по
возможности сдвигаются в паузы (`plan_windows_at_silence` + `CUT_PAD_MS = 300`), каждое
окно уходит отдельным запросом в **mp3** (`WINDOW_BITRATE = "32k"`), тайминги
возвращаются в общую ось через `shift_segments`. Отказ одного окна не убивает
расшифровку — окно попадает в список `failed`.

**Ключ не светится нигде.** `SecretKey` — newtype без `Serialize`, с рукописными `Debug`
и `Display`, печатающими маску из `•`. В лог он попасть не может (`{:?}` даёт маску), в
ответ роута — тоже (структуру нельзя сериализовать). Наружу отдаётся лишь булев признак
`cloud_key_set`. Инвариант закреплён тестами `plugins/meet/tests/key_privacy.rs`.

## 5. Где живут настройки

### `voice.toml` — движок, ключ, пороги (ОДИН на все мессенджеры)

`VoiceConfig`, модуль `forge_voice::config`. **Дефолты наследуются из `meet.toml`**:

```
voice.toml (если поле есть и непусто) → meet.toml → встроенный дефолт
```

Кроме `engine` — он берётся только из `voice.toml`, стандарт чатов остаётся облачным
независимо от настроек встреч (раздел 4).

Ключ polza.ai пользователь уже ввёл в настройках плагина встреч, где облачная расшифровка
появилась первой. Требовать тот же ключ второй раз означало бы гарантированно получить
два разошедшихся ключа и вторую копию секрета на диске. Пустая строка в `voice.toml` —
это НЕ «выключить»: файл правят руками, и `polza_api_key = ""` чаще означает «не
заполнил». Явное выключение делается выбором движка.

Файл ищется РЯДОМ с конфигом самого плагина (`config::paths_next_to`) — благодаря этому
тесты изолированы без переменных окружения. Запись идёт через `toml_edit`, чтобы
сохранить комментарии, которые человек читает прямо в файле; права `0600`, запись
атомарная.

Ключевые пороги: `DEFAULT_MAX_DURATION_SECS = 900` (пятнадцать минут — длиннее голосовых
не бывает, лимит существует ради подменённых метаданных), `DEFAULT_CLOUD_TIMEOUT_SECS =
120`, `whisper::DEFAULT_TIMEOUT_SECS = 3600`.

### `user_settings.json` — тумблеры авторазбора (СВОЙ на каждую панель)

`vk_voice_autotranscribe`, `telegram_voice_autotranscribe`, `bitrix_voice_autotranscribe`
— дефолт ВЫКЛЮЧЕНО, читается строго как `=== true`. Три поля, а не одно: рабочий Битрикс
разбирать хочется, а личный Telegram — не обязательно. Подробности — `voice_user_settings`.

**Почему движок общий, а тумблеры раздельные, и как человек об этом узнаёт:** вкладок
настроек три (`settings/voice-tab.js` с тремя конфигами `*_VOICE_CONFIG`), и под селектом
движка стоит подпись `SHARED_HINT` — иначе переключивший движок на вкладке VK не понял бы,
почему изменилось поведение Битрикса.

Плагин читает `user_settings.json` САМ (`forge_voice::prefs`) на каждое входящее
голосовое: канала настроек от хоста к VK/Telegram/Bitrix не существует (у них нет своего
`*-host-api`), и заводить его ради двух булевых значений значило бы сломать границу
плагина. Побочная выгода: переключённый в браузере тумблер действует со следующего
сообщения, без перезапуска процесса.

## 6. Ручной и автоматический режим — одна и та же дорожка

Тело `post_transcribe` вынесено в `pub(crate) async fn begin(state, key, force)`, и её же
зовёт авторазбор. Поэтому лестница проверок, реестр идущих прогонов, потолок
параллелизма и запись в стор у КНОПКИ и у АВТОРАЗБОРА буквально одни и те же.

**Ручной**: кнопка «Расшифровать» под волной → POST → кадры прогресса → текст.
Текст переживает скролл, переключение беседы и перезагрузку, потому что лежит в
`TranscriptStore` на диске рядом с медиа-кэшем.

**Автоматический** (`voice_auto`): на входящее сообщение перечитываются `prefs`,
`auto::decide` возвращает либо `Ok`, либо причину `Skip` (выключен тумблер, беседа вне
белого списка видимости, своё исходящее, не голосовое, слишком длинное), `SeenKeys`
(FIFO на 512) отсекает повтор, дальше — та же `begin`.

`SeenKeys` нужен отдельно от `VoiceHub`: хаб знает только про ИДУЩИЕ прогоны, стор — про
УСПЕШНЫЕ, и прогон, кончившийся отказом, повторная доставка события гоняла бы по кругу.
Список кодов, которые имеет смысл повторить, задан явно (`retryable`).

**Выключенный тумблер = полное молчание**: ни докачки файла, ни запуска движка, ни записи
в стор. Решение принимается до любого обращения к сети и диску, причина пропуска пишется
в журнал (`log_skip`) — по нему это и проверяется, а не по глазам в интерфейсе.

## 7. Роуты (четыре на каждый плагин)

| метод | путь (`…` = `/api/{vk,telegram,bitrix}`) |
|---|---|
| POST | `…/voice/:dialog/:mid/:index/transcribe` (`?force=1` — заново) |
| GET | `…/voice/:dialog/:mid/:index/transcript` |
| GET | `…/voice/settings` |
| PUT | `…/voice/settings` |

Лестница ответов: 400 — кривой адрес либо не звук; 404 — файла нет и докачать не вышло;
409 — прогон по этому ключу уже идёт (повторный клик безвреден); 503 — нет ffmpeg /
whisper / модели / ключа; 202 — принято, ждите кадров.

Подробности — `forge_vk::routes::voice`, `forge_telegram::routes::voice`,
`forge_bitrix::routes::voice`.

## 8. WS-кадры

Четыре кадра: `voice_transcribe_started | delta | done | error`. Объявлены ТРИЖДЫ, в трёх
независимых enum'ах (`VkServerMsg`, `TgServerMsg`, `B24ServerMsg`) — плагины изолированы
по построению, общего типа между ними нет и быть не может. Читает их ОДИН фронт-модуль,
поэтому набор и имена полей обязаны совпадать дословно; сверяет это
`tmux-web/tests/frontend/voice_frames_contract.test.mjs` (81 проверка).

Каждый кадр несёт координаты вложения (`run_id`, `dialog_id`, `message_id`, `index`):
сервер вещает всем подписчикам без фильтрации, и подписчик обязан сам понять, его ли это
карточка. `delta` несёт ТОЛЬКО `percent` — текст приезжает целиком в `done`.
`error` несёт `code` ОТДЕЛЬНО от `message`. Полный контракт — `forge-voice-frames-contract`.

## 9. Требования к машине

- **ffmpeg** — обязателен всегда: подготовка звука для обоих движков, расчёт огибающей,
  нарезка окон. Нет — код `voice_no_ffmpeg`.
- **Локальный движок**: бинарь `whisper-cli` (или `whisper-cpp` / `main` / `whisper`),
  файл весов `ggml-<модель>.bin` в `models_dir`, **и работающий Metal** — без него прогон
  убивается, а не считается медленно на процессоре.
- **Облачный движок**: ключ polza.ai (свой в `voice.toml` либо унаследованный из
  `meet.toml`) и деньги на балансе.

## 10. Ограничения и известные отказы

**Ограничения платформ:**

- **Битрикс24 не отдаёт длительность звука вовсе** — ступень «слишком длинное» нельзя
  пройти по метаданным, потолок ловится по ДЕКОДИРОВАННОМУ звуку.
- **Битрикс24 не отдаёт огибающую** — она считается для каждого голосового.
- **Событие Битрикса `im.v2` не несёт дескрипторы файлов** — вид вложения в нём всегда
  `file`, поэтому авторазбор вынужден догружать страницу истории.
- **Чат ЗАДАЧИ у Битрикса по `DIALOG_ID` неотличим от обычного** — белый список из одного
  вида `task` авторазбор там не включит.
- **Telegram: атрибут волны побеждает расчёт** — если платформа прислала огибающую,
  ffmpeg не запускается; своей огибающей у аудиофайлов нет, им она считается.
- **Telegram: автоматически разбираются только голосовые** — пересланная музыка и
  подкасты доступны по кнопке (иначе час аудио съедал бы GPU без единого нажатия).
- **VK: словари видов беседы у бэкенда и фронта разные** (`group` против `community`) —
  перевод делает `visibility_kind`.

**Коды отказа, которые видит человек** (таблица текстов — `ERROR_TEXT`):
`voice_not_audio`, `voice_too_long`, `voice_no_ffmpeg`, `voice_no_whisper`,
`voice_no_model`, `voice_no_key`, `voice_busy`, `voice_config`, `metal_unavailable`,
`not_authorized`, `not_connected`, `no_media`. Текст показывается строго ПО КОДУ:
в `message` кадра лежит хвост stderr, пути до бинарей и обрывки конфигурации — человеку
это не нужно, а следы ключей показывать вредно.

## 11. Открытое: живая приёмка

Гейт `forge-cvoice-f6-jv35a.4`. Всё, что проверяется без живых аккаунтов (изолированные

## 12. Дешёвая модель и во встречах (21.08.2026)

`DEFAULT_STT_MODEL` (встречи) приравнен к `DEFAULT_CHAT_STT_MODEL`: обе дороги идут
в `openai/whisper-large-v3-turbo`, 0,048 ₽/мин вместо 0,432 ₽/мин.

**Проверено на записи настоящей встречи** (39 минут, платформа Телемост, эталон —
та же запись, уже расшифрованная `openai/whisper-1`: 343 сегмента с таймкодами и
спикерами). Шесть минут звука прогнаны боевым путём — окна по 90 с, mp3 32k mono
16 кГц:

| | whisper-1 (эталон) | turbo |
|---|---|---|
| слов на интервале 90–450 с | 692 | 733 |
| совпадение словаря | — | 233 из 268 общих слов |
| время на окно 90 с | — | 3–4 с |
| таймкоды | посегментные | нет (один сегмент на окно) |
| цена за 39 минут | 16,8 ₽ | 1,9 ₽ |

Текст сопоставим, местами точнее: turbo расставляет пунктуацию и заглавные, узнаёт
имена («Алексей, Алексей, мы не видим»), правильно склоняет («что делает каждая
кнопка, видите?» против «что делает каждый кнопки»). Встречаются и свои ошибки
(«Она нам отрадыщена» вместо «Она нам это зачем»).

**Тишину надо вырезать — это измерено, а не предположено.** На сыром миксе с паузами
turbo галлюцинирует классическим whisper-мусором («Продолжение следует…», «Спасибо.»)
— 28 мусорных слов из 733, то есть 4 %. Та же запись с удалённой тишиной — 1 %.
Пер-трековый путь (`pipeline::pertrack`) режет тишину сам, поэтому боевой прогон
встречи попадает в лучший случай; миксовый — в худший.

**Чем платим.** Посегментных таймкодов у модели нет вовсе, `parse_verbose_json` кладёт
ответ одним сегментом на окно. Пер-трековый путь подпись спикера НЕ теряет (дорожка =
микрофон одного человека), грубеет только раскладка реплик по времени внутри окна.
Миксовый путь теряет атрибуцию: класть сегменты на таймлайн не по чему. Кому нужен
точный таймлайн — ставит `cloud_stt_model = "openai/whisper-1"` в `meet.toml`; она
остаётся единственной моделью в `TIMESTAMPED_STT_MODELS`, и фронт помечает пригодность
флагом `timestamps` (`sttModelNote` в `settings/meet-tab.js`).
