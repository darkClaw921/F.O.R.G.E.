# forge-meet: тестовые активы

Чем плагин проверяется, когда живой встречи нет, — и как этим пользоваться.

## Мок-встреча: страница, которая ведёт себя как площадка

`plugins/meet/tests/fixtures/mock-meeting/` — статическая страница с настоящим
WebRTC-звуком по расписанию. Поднимается `testing::StaticServer` на свободном
порту, адрес собирается `mock_meeting_url(mode, extra)`.

| параметр | что делает |
|---|---|
| `mode=per-track` | у каждого «участника» своя дорожка — режим `PerParticipant` |
| `mode=slots` | фиксированный набор дорожек, как у Телемоста |
| `mode=mixed` | всё в одной дорожке |
| `duration=<мс>` | длительность встречи |
| `autojoin=0` | не входить автоматически: остаться на пре-join |
| `deny=1` | площадка ОТКАЗЫВАЕТ во входе — проверка `JoinStep::Denied` |
| `audiogate=1` | звука нет, пока не нажата кнопка «включить аудио» — механика Zoom |
| `hotkeys=1` | микрофон и камера переключаются сочетаниями клавиш |

Рядом лежит `expected.json` — эталонное расписание речи. Он тоже может врать:
пауза 500 мс в первой редакции равнялась `vad_hangover_ms`, то есть ровно тому,
что VAD обязан НЕ считать концом реплики; тест падал, а прав был код.

Мок-встречу можно и нужно растить под механизмы новых площадок: `deny`,
`audiogate` и `hotkeys` появились под Ф8–Ф10 и дали живую проверку в Chrome
того, что живой встречи не требует.

## Моки внешних бинарей

`testing::mocks` пишет исполняемые shell-скрипты во временный каталог — тесты
подставляют их путь прямо в отчёт проб (`state.deps`), а не в `PATH`: `PATH` —
состояние всего процесса, а тесты идут параллельно.

| мок | что умеет |
|---|---|
| `mock_whisper(WhisperMock)` | `--version`, `--help`, прогон с записью `<out>.json`; CPU-прогон (нет `ggml_metal_init:`), «молчащий про бэкенд», чужой CLI, падение, зависание, **ответ, зависящий от входного файла** (`per_input` — для пер-трековой расшифровки) |
| `mock_ffmpeg_*` | успех, падение с текстом в stderr, зависание |
| `mock_ffprobe` | заданная длительность (по ней проверяется коррекция дрейфа) |
| `mock_claude_*` | поток `stream-json`, падение, зависание |

Зависание пишется ТОЛЬКО через `exec sleep N`: без `exec` `kill` убивает
оболочку, `sleep` остаётся сиротой, держит pipe stderr, и тест таймаута висит
вечно.

## Живые прогоны и переменные

| команда | что проверяет |
|---|---|
| `cargo test -p forge-meet` | всё герметичное: 620+ тестов, ни одного внешнего бинаря, ни одной сети |
| `FORGE_MEET_E2E=1 cargo test -p forge-meet --test e2e_mock` | настоящий Chrome на мок-встрече: инжект, тапы, worklet, биндинг, файлы на диске |
| `cargo test -p forge-meet --test pipeline_live -- --ignored --nocapture` | настоящие ffmpeg, ffprobe и whisper на синтезированной речи (`say -v Milena`) |
| `cargo test -p forge-meet --test window_mode -- --ignored` | режим окна против `CGWindowList` (ground truth) |
| `cargo test -p devforge --test meet_frontend_suite` | фронтовые контрактные тесты через `node` |

Без `FORGE_MEET_E2E=1` живые тесты ПРОПУСКАЮТСЯ с сообщением: CI без браузера
обязан оставаться зелёным. Живой e2e при этом начинается с измерения
аудиочасов и пропускается при замерших — бывают окружения, где `AudioContext`
рапортует `running`, а `currentTime` стоит на первом кванте, и тест проверял бы
тишину, называя её успехом.

Живые прогоны браузера идут ПО ОДНОМУ (`testing::browser_guard()`): пять
Chrome разом отнимают друг у друга процессор, и короткий прогон получал ноль
кадров на исправном коде.

## Герметичность — не пожелание, а проверяемое свойство

Негерметичный тест молча открыл бы `~/.forge/meet` живого пользователя, где
лежат записи настоящих встреч. `plugins/meet/tests/invariants.rs` проверяет
это статически (каждый тестовый `MeetConfig` уводит `config_path`, `cache_dir`
и `db_path` во временный каталог; исключения перечислены с причинами и сами
проверяются на протухание), а факт подтверждён замером: снимок `~/.forge/meet`
до и после полного прогона крейта не изменился.

Помощник — `testing::hermetic_config(dir)`. Отдельный тест следит, чтобы он
уводил ВСЕ пути конфига, а не три из пяти.

## Свод инвариантов

Там же, в `tests/invariants.rs`, лежит таблица четырнадцати обещаний плагина
(«`init` не запускает процессов», «`status` не падает никогда», «слот whisper
строго один», «провал саммари сохраняет транскрипт», «транскрипта нет в
argv»…). Для каждого проверяется, что покрывающий тест существует, не помечен
`#[ignore]` и всё ещё содержит своё утверждение. Свод не дублирует проверки —
копия разошлась бы с оригиналом и одна из двух начала бы врать.

## Смежное

* `forge-meet-mock-meeting` — устройство страницы;
* `forge-meet-architecture` — картина целиком;
* `forge-meet-platform-probes` — как чинить селекторы, проверяя на моке.
