# forge-tracker: перенос задачи в tasks/todo (фаза 8)

Кнопка `[→ tasks/todo]` копирует задачу трекера в колонку TODO вкладки Tasks.

## Границы решения

- **Копия, а не переезд.** В трекере не меняется НИЧЕГО: статус, `done_at`,
  `updated_at`, отрезки, накопленное время и чек-лист остаются как были.
- **Обратной ссылки нет.** Ни в задаче, ни в созданном todo не сохраняется
  указателя друг на друга. Отсюда следует, что повторный перенос той же задачи
  законен и создаёт вторую карточку.
- **Серверных роутов не добавлено.** Всё делает фронт через существующий
  `POST /api/todos` (`createTodoForPath`, tmux-web/static/js/tasks/crud.js).
  Крейт `forge-tracker` про `TodoStore` не знает — проверяется тем, что во всём
  `plugins/tracker` слово `TodoStore` встречается только в комментариях о том,
  что зависимости нет.

## Почему спрашивается корень

Задачи трекера глобальные (в `models.rs` нет `root_path`, стор один —
`~/.config/forge/tracker.json`), а TODO привязан к корню проекта: `POST /api/todos`
обязателен к полю `path`, из которого сервер делает `paths::resolve_root`.
Автоматически корень взять неоткуда, поэтому он выбирается в момент переноса.

Список корней — это разные `path` открытых сессий tmux (`state.sessions`):
концепции «проект» в devforge нет, вкладка Tasks фильтруется ровно по этому же
признаку. Последним пунктом всегда стоит «корень активной сессии tmux»
(`currentTodosPath()`), он же значение по умолчанию для первого переноса;
дальше подставляется запомненный прошлый выбор (`forge.tracker.push.root`).

## Формат описания создаваемой карточки

```
<заметки задачи>

// TRACKER NODE 847b1c99
приоритет: P1
статус: doing
список: work
теги: #forge #design
оценка: ~4ч30м
начало: 2026-09-08
срок: 2026-09-10
потрачено: 0:42:19

// CHECKLIST 1/2
[x] свести палитру
[ ] отдать в реализацию
```

Пустые поля строк не занимают. Заметки идут первыми и без заголовка: в карточке
Tasks видно начало текста, и там должно быть содержание, а не метаданные.

## Что показал живой гейт

Стенд: свой tmux-сокет, временный HOME, свободный порт, headless Chrome по CDP.
Две сессии-«проекта» (`projA`, `projB`), одна задача с заметками, тегами,
оценкой, сроком, чек-листом 1/2 и закрытым отрезком 0:42:19.

41 проверка, все зелёные. Существенное:

- перенос в явно выбранный projB создал ровно одну карточку с тем же
  заголовком и ожидаемым описанием; в projA при этом пусто;
- задача в трекере не изменилась: `status`, `done_at`, `updated_at`,
  `task_seconds`, `entries`, `items` совпали побайтно, активных таймеров нет;
- повторный перенос создал ВТОРУЮ копию, и в диалоге подставился запомненный
  корень;
- отмена по Esc не создала ничего, а Esc над открытой карточкой задачи снял
  только диалог;
- перенос в «корень активной сессии tmux» после выбора сессии в сайдбаре попал
  в projA, и карточка видна в колонке TODO вкладки Tasks;
- копии пережили перезагрузку страницы.

## Расхождение с макетом

В макете список вариантов — это два проекта и строка «корень активной сессии
tmux» без пояснения. В реализации у этой строки справа показан РАЗРЕШЁННЫЙ путь
(или «сессия не выбрана», и тогда вариант не выбирается): иначе непонятно, куда
именно уедет карточка. Кнопки CANCEL и PUSH ⏎, заголовок, приписка про копию и
объяснение «почему спрашиваем» — как на макете.
