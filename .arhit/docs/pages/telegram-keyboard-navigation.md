# Клавиатурная навигация в Telegram (forge-nert)

Фича «взаимодействие только через клавиатуру» во вкладке Telegram: подсказки
открываются и в самой панели, и в настройках; хоткеи включаются, выключаются и
переназначаются.

## Из чего состоит

| Слой | Файл | Роль |
| --- | --- | --- |
| Чистая логика | `static/js/telegram/keys.js` | реестр 19 действий, разбор комбинаций, конфликты, что слать на backend |
| DOM | `static/js/telegram/keynav.js` | курсор, зоны фокуса, выполнение действий, оверлей шпаргалки |
| Настройки | `static/js/settings/hotkeys-tab.js` | тумблер, таблица действий, запись новой комбинации |
| Хранение | `src/user_settings.rs` | `telegram_hotkeys_enabled` (bool, default **true**), `telegram_hotkeys` (map) |
| Уступка | `static/hotkeys.js` | vim-навигация молчит, пока панель владеет клавиатурой |
| Стили | `css/telegram.css`, `css/settings-modal.css` | `.tg-kb-cursor`, `.tg-keys-help`, `.tg-hotkeys-*` |

## Действия по умолчанию

| Клавиша | Действие |
| --- | --- |
| `d` / `m` / `i` | фокус: список чатов / лента / поле ввода |
| `j` / `k` | вниз / вверх (по чатам, сообщениям или ряду кнопок бота — смотря где курсор) |
| `Enter` | открыть чат, открыть медиа, нажать кнопку бота, перейти по цитате |
| `u` | следующий непрочитанный чат (по кругу) |
| `[` / `]` | предыдущая / следующая папка |
| `r` / `o` / `y` / `b` | ответить / к оригиналу цитаты / скопировать текст / к кнопкам бота |
| `⇧G` / `g` | в конец ленты / подгрузить историю выше |
| `a` / `t` / `?` | вложение / тема панели / шпаргалка |
| `Esc` | отмена, выход из поля (**не переназначается**) |

## Пять решений, без которых фича не работала бы

### 1. Сопоставление по `event.code`, а не по `event.key`

В Telegram печатают по-русски. При русской раскладке `event.key` для клавиши J
вернёт `'о'`, и хоткей `j` не работал бы ровно у тех, ради кого фича делается.
`event.code` описывает физическую клавишу и от раскладки не зависит.

### 2. Уступка глобальной vim-навигации — по фокусу, а не по факту открытой вкладки

`static/hotkeys.js` занимает `j/k/h/l/g/1/2/3/?` глобально. Если бы панель
забирала клавиши всегда, пока она открыта, пользователь потерял бы навигацию по
сессиям в сайдбаре, который виден рядом. Поэтому `telegramOwnsKeyboard()`
требует, чтобы фокус был внутри `#telegram` (или нигде): клик в сайдбар
возвращает vim.

Контракт публикуется через `window.ForgeApp.telegramKeys` — `hotkeys.js`
классический скрипт и импортировать модуль не может.

### 3. В поле ввода одиночные клавиши не перехватываются

Иначе букву «j» было бы не набрать в сообщении. Проходят только
`Ctrl`/`Alt`/`Meta`-комбинации и `Escape`. `Shift+буква` — тоже обычный символ.

### 4. Курсор хранится идентификатором, а не ссылкой на узел

И колонка чатов, и лента перерисовываются целиком при каждой подгрузке. Ссылка
на узел протухла бы после первого же обновления; по `dialogId`/`message_id`
курсор находится заново.

При смене диалога курсор сбрасывается: в новой ленте тот же `message_id`
принадлежит другому сообщению — нумерация у каждого чата своя.

### 5. Enter по сфокусированной кнопке бота отдан браузеру

`<button>` активируется Enter'ом штатно. Свой `click()` рядом с нативным мог бы
отправить боту **два** callback'а на одно нажатие — а это бывает и «купить», и
«удалить». Поэтому если фокус уже на `.tg-kb-btn`, `nav.activate` возвращает
`false` и событие не гасится. Нажимаем кнопку сами только когда фокус на строке.

### 6. Конфликт переназначений оставляет проигравшего без клавиши

Переопределение сильнее дефолта; среди переопределений — то, что раньше в
реестре (иначе результат зависел бы от порядка ключей в JSON). Проигравшее
действие показывается в настройках прочерком и пометкой «занято: …». Молча
вернуть ему дефолт значило бы соврать пользователю, который этот дефолт только
что занял.

## Кто кому уступает клавишу

| Ситуация | Кто обрабатывает |
| --- | --- |
| Панель скрыта / открыт оверлей логина | vim-навигация `hotkeys.js` |
| Фокус вне `#telegram` | vim-навигация `hotkeys.js` |
| Настройка выключена | vim-навигация `hotkeys.js` |
| Открыт лайтбокс медиа | `media.js` (свои стрелки и Esc) |
| Открыта модалка настроек (`.modal-overlay`) | форма записи комбинации |
| Фокус в поле ввода, клавиша без Ctrl/Alt/Meta | само поле |
| `Escape` при выбранной цели ответа | `chat.js` (снимает полосу «отвечаю …») |
| Всё остальное внутри панели | `keynav.js` |

## Хранение и дефолт

`telegram_hotkeys_enabled` по умолчанию **true** — в отличие от
`cmd_hints_enabled` и `next_step_enabled`. Это не рассогласование: те фичи
глобальные и заметные, а эта живёт внутри уже opt-in вкладки Telegram
(флаг `--telegram`) и молчит в полях ввода. Пользователь просил тумблер, чтобы
фичу **выключать**, а не чтобы включать.

`telegram_hotkeys` хранит **только отличия от дефолтов** — иначе смена дефолта
в новой версии не доехала бы до пользователей, у которых «всё как из коробки».
Backend валидирует форму (`sanitize_hotkeys`), но не смысл: список действий
знает только фронтенд, и дублировать его в Rust значило бы держать две правды.
Неизвестный id не отбрасывается на входе — он просто игнорируется клиентом, что
позволяет откатить версию клиента без потери настроек.

## Известные ограничения

- Оверлей шпаргалки не листается клавиатурой — закрывается `Esc` или `?`.
- `b` фолбэчится на reply-клавиатуру бота, если у сообщения под курсором нет
  своих кнопок; выбрать конкретный ряд нельзя, только идти `j`/`k` по кнопкам.
- Порядок обхода чатов — DOM-порядок колонки (сначала узлы, потом каналы).
