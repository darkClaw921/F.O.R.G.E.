БАГФИКС forge-uo7b (2026-08-06): непрочитанное не сбрасывалось при живом сообщении в открытом диалоге.

## Жалоба пользователя

Пришло сообщение, открыл его в плагине (диалог уже был активной вкладкой), но прочтение на реальном портале засчиталось только когда пользователь отдельно открыл сам Битрикс24.

## Корень

main.js::message_new (кадр WS для нового сообщения) вызывал chat.appendMessage(msg.message) напрямую, когда диалог уже открыт — но НИ ОДНОГО явного вызова scheduleRead там не было. Комментарий рядом утверждал «открытую пользователь читает глазами — отметку шлёт сама лента» — но это было НЕПРАВДОЙ.

Единственным фактическим триггером scheduleRead при вставке сообщения был ПОБОЧНЫЙ ЭФФЕКТ: appendMessage->scrollToBottom() меняет $b24Log.scrollTop, браузер шлёт нативное событие scroll, его ловит onScroll в chat.js::initChat, и ТОЛЬКО ТАМ вызывается scheduleRead. Механизм ломается ровно тогда, когда лента КОРОТКАЯ (scrollHeight <= clientHeight, типично для только что открытого диалога с парой сообщений): новое сообщение не меняет scrollTop, событие scroll в браузере НЕ РОЖДАЕТСЯ вовсе, onScroll не зовётся никогда — отметка о прочтении молчит, а сообщение остаётся непрочитанным на портале до момента, пока пользователь не откроет его в официальном клиенте (тот использует другой путь чтения).

## Как было найдено

Диагноз через чтение кода (без воспроизведения на реальном сообщении — источник другого человека недоступен по требованию), затем СВЕРЕНО с уже рабочим telegram-плагином в этом же репозитории: telegram/main.js::new_message ИМЕННО ТАК и делает — if (isActive && drawn && !dto.out) scheduleRead(id, dto.id); с комментарием «Диалог открыт — ставим в очередь отметку о прочтении». У Bitrix эта строка отсутствовала целиком — единственная реальная причина расхождения поведения двух соседних плагинов.

## Фикс

main.js::message_new: добавлен явный if (open && !msg.message.out) scheduleRead(id, msg.message.id); — использует УЖЕ вычисленный в этом же обработчике флаг open (onB24Tab() && activeDialogId === id, тот же флаг, что решает считать ли сообщение непрочитанным для бейджа). scheduleRead импортирован из chat.js (уже существовал, использовался loadPage/onScroll, теперь третий вызывающий).

СОЗНАТЕЛЬНО НЕ трогали: chat.js::appendMessage остался БЕЗ знания про видимость вкладки (onB24Tab) — это осталось прерогативой main.js, у которого уже есть open. Первая версия фикса пыталась встроить отметку прямо в appendMessage по одному local.stickBottom — откачена, потому что stickBottom знает только про прокрутку, а НЕ про то, видна ли вкладка Битрикс24 среди вкладок devforge вообще: диалог, оставшийся 'загруженным' в фоне (currentDialogId()===id) при активной вкладке Terminal, отметился бы прочитанным, хотя пользователь его не видит — рассинхрон с бейджем (тот как раз ПРАВИЛЬНО считает такое сообщение непрочитанным через тот же open).
