# Жизненный цикл плагина VK в хосте: четыре точки входа

`plugins/vk/src/lib.rs`. Хост (`tmux-web/src/main.rs`) знает о плагине ровно
четыре функции. Host-адаптера (аналога `echo_host_api::HostApi`) НЕТ: плагину от
хоста нужен только `Router`.

## 1. `init(cfg: VkConfig) -> anyhow::Result<Arc<VkState>>`

Синхронная и СЕТИ НЕ ТРОГАЕТ — иначе биндинг порта ждал бы, пока ответит VK.
Порядок: `cfg.validate()?` → `ensure_dirs()` (ошибка НЕ фатальна: каталог нужен
только при записи кэша) → `VkState::new(cfg)`. Ошибка валидации трактуется
хостом как «стартовать без плагина»: VK — опциональная вкладка, и сломанный
`vk.toml` не должен мешать работать с терминалом. Битый TOML до `init` вообще не
доходит — `VkConfig::load_from_file` чинит его дефолтами с warn-логом (тест
`vk_smoke::test_broken_config_does_not_break_init`).

Стартовое состояние логина выводится из конфига: токен есть ⇒ `disconnected`
(проверять его будет `spawn_workers`), нет ⇒ `not_configured`. Именно
`disconnected`, а не `checking`: последнее означало бы «проверка уже идёт».

## 2. `register_routes(app: Router, state: Arc<VkState>) -> Router`

Мерджит `routes::build_router(state)`. **Вызывается ДО `.fallback(...)` и
`.layer(auth_middleware)`** — только так Bearer-auth и csrf_guard хоста
автоматически покрывают роуты плагина в remote-mode. Исключение из общего
правила «тело обязано быть JSON» сделано точечно: `tmux-web/src/auth.rs::
RAW_UPLOAD_PATHS` перечисляет `/api/vk/upload` ПОЛНЫМ путём (префиксное
исключение накрыло бы будущие мутирующие роуты плагина).

Если этой функции не вызвать (нет флага `--vk`) — плагина не существует:
404 на всём префиксе. Это главный opt-in-инвариант, и он проверяется по проводу.

## 3. `spawn_workers(&Arc<VkState>)`

Возвращается НЕМЕДЛЕННО: воркеры именно запускаются, а не выполняются.

| воркер | когда | зачем |
|---|---|---|
| LongPoll-супервизор | ВСЕГДА, даже без токена | ждёт `authorized_notify`; вставка токена в работающем процессе поднимает realtime БЕЗ рестарта |
| LRU-подчистка медиа-кэша | всегда | держит `max_cache_bytes` |
| GC незавершённых загрузок | всегда | staging-файлы старше TTL |
| проверка токена | только если токен есть | ОДНА проверка на старт, без повторов |

Без токена сеть не трогается вовсе: запрос «расскажи о владельце пустого токена»
гарантированно вернул бы код 5 и положил бы ошибку в лог у каждого, кто запустил
devforge с `--vk`, но ещё не логинился. Повторов проверки нет намеренно —
протухший токен чинится только новым значением от пользователя, а цикл
переверификаций лишь тратил бы бюджет 3 rps.

## 4. `shutdown(&Arc<VkState>)`

Идемпотентна и быстра (иначе Ctrl-C у devforge подвисал бы): отменяет
`CancellationToken`, будит воркеров, ждёт их с грацией `WORKER_STOP_GRACE`
(+2 c ради сохранения курсора LongPoll), закрывает WS-соединения. Второй вызов
(Ctrl-C + SIGTERM от systemd) не виснет и не паникует — проверено
`vk_smoke::test_workers_start_and_stop_cleanly`.
