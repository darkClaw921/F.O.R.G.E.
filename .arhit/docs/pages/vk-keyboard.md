КЛАВИАТУРА ВКЛАДКИ VK — как устроена фича целиком (Ф11).

## Файлы

js/messenger/hotkeys-core.js — движок комбинаций, общий на все панели-мессенджеры (реестр приходит аргументом).
js/vk/keys.js — реестр VK_ACTIONS (20 действий) + тонкие обёртки над движком.
js/vk/keynav.js — DOM, фокус, курсор, диспетчер, шпаргалка, контракт window.ForgeApp.vkKeys.
js/settings/hotkeys-tab.js — ОБЩАЯ форма настроек, VK_HOTKEYS_CONFIG.
static/hotkeys.js — глобальная vim-навигация, уступающая клавиши по списку PANEL_KEY_CONTRACTS.
src/user_settings.rs — поля vk_hotkeys_enabled (default TRUE) и vk_hotkeys (карта переопределений).
css/vk.css — .vk-kb-cursor (полоска слева, а не рамка: рамка сдвигала бы текст и лента дёргалась бы на каждом шаге) и .vk-keys-help (z-index 40, ВНУТРИ панели).

## Что умеет пользователь

d — фокус на список бесед, m — на ленту, i — в поле ввода; j/k — шаг вниз/вверх по текущей зоне; Enter — открыть/нажать; u — следующая непрочитанная беседа; ] и [ — серверные фильтры; r — ответить, o — к цитируемому оригиналу, y — скопировать текст, b — к кнопкам сообщества, v — к вложениям; Shift+G — в конец ленты, g — подгрузить историю выше; a — прикрепить файл, t — сменить тему панели, ? — шпаргалка, Escape — отмена (не переназначается).

## Сопоставление по event.code

На русской раскладке event.key для физической клавиши J вернёт 'о'. Вкладка мессенджера — место, где по-русски печатают чаще, чем по-английски, поэтому канон комбинации строится ИЗ КОДА физической клавиши; event.key остаётся фолбэком для экранных клавиатур. Живая проверка фичи обязана делаться НА РУССКОЙ РАСКЛАДКЕ — на латинице ошибка невидима.

## Настройки действуют сразу

Кэш разобранных привязок в keynav ключуется ПО СОДЕРЖИМОМУ карты (JSON.stringify), а не по ссылке на объект настроек: переназначение начинает работать сразу после Save, без перезагрузки страницы. Форма дополнительно зовёт ForgeApp.vkKeys.invalidate() — это делает контракт видимым, но не является необходимым условием.

## Гейт дефолта

vk_hotkeys_enabled читается '!== false' (ВКЛ по умолчанию) и в keynav, и в форме. Не путать с vk_filter_enabled рядом, который читается '=== true' (ВЫКЛ по умолчанию): белый список бесед — opt-in фича, а хоткеи живут внутри уже opt-in вкладки, и тумблер нужен для их ВЫКЛЮЧЕНИЯ.

## Тесты

vk_keys (реестр и чистая логика), vk_keynav (DOM, гейты, сосуществование панелей), messenger_shared_parity (страж дублирования движка), settings_hotkeys_form (общая форма), hotkeys_panel_owner (гейт vim-навигации) — все в tmux-web/tests/frontend/.

См. также: keyboard-owners (два владельца клавиатуры), vk-visibility-model (белый список бесед).
