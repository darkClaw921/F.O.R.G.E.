# Тосты от заглушённых чатов в Telegram — разбор и починка

## Симптом
Всплывающие уведомления (in-app тост, tmux-web/static/js/telegram/main.js::maybeToast) приходили от чатов, которые пользователь заглушил или убрал в архив.

## Где принимается решение
Фронт не решает сам: гейт dialogRings читает поля УРОВНЯ КАДРА new_message (muted/archived), которые считает сервер. Локальный Set из загруженной страницы — только фолбэк для старого сервера. Значит, все дефекты были на стороне плагина.

## Четыре причины
1. Промах кэша = «не заглушён». resolve_dialog_flags на промахе брал дефолт КАТЕГОРИИ. Кэш засевается листингами (стартовые 100 диалогов) и updateNotifySettings, поэтому точечно заглушённый чат вне этой сотни считался звенящим.
2. Архив не засевался вообще. iter_dialogs отдаёт основной список, строка «Архив» отбрасывается ⇒ про архивные чаты сервер не знал ничего, а промах кэша архива = false.
3. Мегагруппы получали дефолт каналов. notify_outcome угадывал категорию по тегу PeerId, где мегагруппа неотличима от broadcast. При заглушённых «всех группах» мегагруппа звенела — и ошибка закреплялась в кэше.
4. Не загрузились глобальные дефолты (три account.getNotifySettings упали или не уложились в NOTIFY_DEFAULTS_TIMEOUT) ⇒ на всю сессию дефолты остаются all-false, и звенит всё, что заглушено по категории. Видно в логе: 'global notification settings timed out'.

## Что сделано
- probe_dialog_flags — ленивый резолв флагов на промахе кэша: один messages.getPeerDialogs на диалог за сессию (claim_flags_probe), под таймаутом DIALOG_FLAGS_TIMEOUT = 3с, peer только из кэша peers. Кладёт в состояние muted, archived и настоящий kind.
- seed_archive_flags — досев архива (folder_id = 1, 100 диалогов) один раз за процесс, в supervisor до первого апдейта.
- updateFolderPeers → CacheEffect::DialogArchived: архивация с телефона правит серверный кэш немедленно (событий наружу нет, контракт WS про папки не знает; фронт узнаёт из полей ближайшего кадра).
- notify_outcome получил параметр kind и вариант Unknown: догадка о категории для унаследованных настроек запрещена.
- TelegramState::dialog_kinds — кэш категорий, засевается листингом (DialogDto.kind), резолвом и каждым входящим сообщением (msg.peer(), где мегагруппа = group).
- TelegramState::notify_defaults_loaded — гейт «дефолты реально спрошены»: пока их нет, ни резолв, ни досев ничего в кэш не пишут, иначе значение, посчитанное от заглушки, пережило бы её.

## Чего сознательно НЕ делали
- Не ходим в сеть за категорией/флагами по каждому апдейту: hot-path — единственный поток апдейтов на весь аккаунт.
- Не пересеваем архив на каждом реконнекте: у флапающего соединения это RPC каждые несколько секунд.
- Не трогали фронтовый гейт: он уже верен (кадр перебивает локальное знание в обе стороны).
