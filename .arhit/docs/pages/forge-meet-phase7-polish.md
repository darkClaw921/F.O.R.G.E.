# forge-meet, Фаза 7: Range, ретенция, настройки, переименование спикеров

Эпик forge-meet-f7-6xh25. Доводка после первого осмысленного релиза: то, что делает фичу пригодной для ежедневного использования, а не для демонстрации. Фаза закрыла три долга, которые фронт (ФФ4) оставил бэкенду: роутов Range, ?track= и PATCH /speakers на сервере не существовало вовсе — фронт их звал, а живая проба карточки шла на поддельных ответах.

## 1. Честный Range у GET /api/meet/meetings/:id/audio

Новый модуль plugins/meet/src/routes/audio.rs.

Фронт грузит запись через fetch + blob: (у элемента audio нет Bearer-токена, и в remote-mode прямой src ушёл бы без авторизации), поэтому перемотку обеспечивает blob, а не сервер. Range реализован всё равно: правильное поведение эндпоинта, отдающего медиафайл, не зависит от того, кто его дёргает. curl -r, ffprobe по HTTP и любой внешний плеер — законные клиенты.

* parse_range — чистая функция по RFC 9110 §14.1.1. Обычная форма, открытый хвост, суффикс. Синтаксически негодный или чужой Range (items=0-5, bytes=10-5, bytes=abc) ИГНОРИРУЕТСЯ, ответ 200: сервер, отвечающий 400 на непонятный ему Range, ломает клиента, которого целый файл устроил бы полностью.
* НЕСКОЛЬКО ДИАПАЗОНОВ игнорируются целиком. multipart/byteranges мы не собираем, а первый диапазон под видом всех — это молчаливая выдача неверных данных.
* 416 несёт Content-Range: bytes */LEN. Без длины клиент повторит тот же невыполнимый запрос.
* HEAD обслуживается ТЕМ ЖЕ хендлером, но отдельной веткой: у четырёхчасовой встречи пер-трековый WAV весит полтора гигабайта, и HEAD без этой ветки прочитал бы их с диска, чтобы отдать ноль байт.
* Тело отдаётся потоком кусками по 64 КиБ (futures_util::stream::unfold над tokio::fs::File), а не Vec<u8>: файл в память не читается.

Пер-трековое аудио — ПАРАМЕТР ?track=N, а не отдельный роут. Решение принято фронтом в ФФ4 и здесь исполнено дословно: таблица MEET_ROUTES в api.js и таблица в шапке routes/mod.rs сверяются контрактным тестом ДОСЛОВНО. Обход каталога невозможен структурно: N разбирается в u32, имя файла собирается format!("track-{n}.wav"), строка из URL в путь не конкатенируется.

## 2. Ретенция: plugins/meet/src/retention.rs

Переиспользован обкатанный образец plugins/bitrix/src/media_cache.rs::sweep_once (LRU по времени последнего обращения, подчистка до 90 % потолка с ГИСТЕРЕЗИСОМ, защита того, что используется прямо сейчас). Три отличия — свойства предметной области:

1. Единица — КАТАЛОГ ВСТРЕЧИ ЦЕЛИКОМ, а не файл. Удалить audio.m4a, оставив transcript.md, значит получить карточку с молча неработающим плеером.
2. Строка в базе ОСТАЁТСЯ, статус становится MeetStatus::Pruned (новый, тринадцатый). Удали мы строку — бейдж на старом сообщении превратился бы в «можно записать», то есть предложил бы войти ботом в давно прошедшую встречу.
3. retention_min_keep (новое поле конфига, по умолчанию 5) — последние N не удаляются никогда. Дисковый бюджет, выставленный слишком низко, иначе стирал бы вчерашнюю планёрку.

Что подметается: work/ у любой законченной встречи; chrome-profile/ сразу при чистом завершении и через сутки после failed (в нём единственные следы того, почему бот не вошёл); каталог встречи целиком — по возрасту (retention_days) либо по LRU при превышении max_cache_bytes.

ОБХОД ИДЁТ ПО СТРОКАМ БАЗЫ, а не по содержимому ~/.forge/meet: там лежат models/ с гигабайтами весов и meet.db. Отсюда же следствие — без базы подметание не работает вовсе и честно ничего не делает.

Запускается воркером sweeper_loop из spawn_workers (раз в 30 минут, прогон на старте) и после каждой встречи из pipeline::run::spawn_from: за полчаса до следующего тика успевают пройти ещё две записи.

## 3. Настройки: GET/PUT /api/meet/config плюс вкладка UI

Роуты — plugins/meet/src/routes/config.rs, реестр полей — config::EDITABLE.

БЕЛЫЙ СПИСОК, а не «всё, кроме опасного». В MeetConfig пять путей к исполняемым файлам (chrome_path, whisper_path, ffmpeg_path, ffprobe_path, claude_cli_path); роут, умеющий записать произвольный ключ, — это выполнение произвольного бинаря одним PUT. Чёрный список защищал бы ровно до появления шестого пути. Список NEVER_EDITABLE существует ради теста, который ломается, если такой ключ однажды попадёт в белый «заодно».

* Источник каждого значения виден: default / file / env. Значение из переменной окружения помечено env_locked и файлом не перезаписывается (иначе «сохранил в интерфейсе, а работает старое»).
* Файл ПРАВИТСЯ через toml_edit, а не пересобирается: комментарии и порядок ключей пользователя переживают сохранение. Новых узлов в дереве нет — toml 0.8 уже тянет toml_edit 0.22.
* В файл уходит ПОЧИНЕННОЕ значение (после validate_and_fix), а не присланное: иначе на диске осталось бы alone_timeout_secs = 0, при каждом старте молча превращалось бы в 5, и человек читал бы в файле одно, а видел другое.
* Битый TOML — единственный отказ PUT: молча перезаписать неразбираемый файл значило бы выбросить все остальные настройки разом.

РАСХОЖДЕНИЕ С ПЛАНОМ. Критерий «PUT применяет то, что применимо без перезапуска» НЕ ВЫПОЛНЕН и выполнен быть не может: MeetState::config неизменяем и раздан по всему плагину как state.config.поле — от таймаутов автовыхода в сеансе записи до пути модели в пайплайне. Горячий конфиг потребовал бы замка вокруг сотни мест чтения, а в награду дал бы запись, у которой таймаут поменялся посреди встречи, и расшифровку, начатую одной моделью и продолженную другой. Поэтому ответ несёт restart_required: true, вкладка говорит об этом прямо, и есть тест, сравнивающий state.config до и после запроса.

Вкладка — tmux-web/static/js/settings/meet-tab.js, подробности в её собственной записи документации.

## 4. Переименование спикеров: PATCH /api/meet/meetings/:id/speakers

plugins/meet/src/routes/speakers.rs.

Живая проба Ф0 доказала: Телемост работает в режиме Slots — дорожка не соответствует человеку, атрибуция строится корреляцией пер-трекового VAD с DOM-индикатором. Промахи неизбежны, значит ручное исправление — штатная последняя ступень каскада, а не украшение. Терпима она ровно потому, что есть пер-трековое аудио: человек жмёт «послушать» на «Участнике 2» (GET /:id/audio?track=1), за две секунды узнаёт голос и подписывает.

Переименование меняет ТРИ вещи разом:
* meeting_participants.display_name (source становится manual, confidence 1.0);
* meeting_segments.speaker_name — источник вкладки расшифровки;
* transcript.json и transcript.md — их читают человек и промпт саммари. Пропусти мы файлы, саммари после переименования всё равно говорило бы «Участник 2».

Файлы пересобираются ИЗ transcript.json (render::read_transcript + render::from_dto), а не из базы: в базе нет потокенных меток (words), и рендер из неё стёр бы их при первой же правке имени.

Связь «сегмент ↔ участник» двойная: по подписи (speaker_labels — display_name, «Дорожка N», «Участник N+1», participant_key) и по participant_id, который эта же операция проставляет при первом переименовании. Отсюда идемпотентность: повторный PATCH тем же значением находит те же строки уже по идентификатору и записывает то же самое, файлы не меняются ни на байт.

Пачка применяется ЦЕЛИКОМ или не применяется вовсе: половина применённых переименований хуже нуля, её не видно ни в ответе, ни в файле.

Долг фронта, найденный и закрытый здесь: appendSegments в meet-popup.js дедупил повторные дельты по id и молча выбрасывал их. PATCH вещает те же сегменты с новым именем, поэтому вкладка участников показывала бы «Борю», а расшифровка рядом — «Участника 2» до переоткрытия карточки. Теперь повтор обновляет подпись на месте (local.seen стал Map, индекс худеет вместе с потолком строк).

## Новый статус Pruned и его следы

MeetStatus::ALL стало 13. Переход в pruned разрешён ТОЛЬКО из ready / failed / cancelled и не ведёт никуда: повтор этапа оттуда невозможен не по правилу, а физически. is_terminal его включает, has_files() отвечает false. Во фронте: MEET_VIEWS.pruned (глиф ⌫, подпись «ВЫЧИЩЕНО», закреплён на строке) и TERMINAL_STATUSES += 'pruned'.

## Живая проверка (без Chrome — Ф4 ещё не закрыта)

Отдельный инстанс devforge --meet на свободном порту с HOME во временном каталоге. Проверено настоящим HTTP через curl, а не только tower::oneshot:
* полный GET побайтово равен файлу; 206 на bytes=10-19, bytes=70000-140000 (через границу куска чтения), bytes=199990-, суффикс -100 — каждый кусок сверен с файлом через dd + cmp;
* 416 с Content-Range: bytes */200000 и конвертом ошибки;
* HEAD отдаёт Content-Length: 200000 и НОЛЬ байт тела; HEAD с Range даёт 206 и правильный Content-Range;
* bytes=0-10,20-30 даёт 200 и весь файл;
* ?track=1 отдаёт дорожку побайтово с типом audio/wav; track=99 → 404, track=abc → 400, чужая встреча + битый параметр → 404 (лестница);
* PUT конфига сохранил починенное значение, оставил комментарий пользователя на месте, не оставил временных файлов; PUT claude_cli_path → 400;
* PATCH speakers переписал базу и оба файла, повтор не изменил файл ни на байт;
* ретенция на старте удалила каталог (210 389 байт), перевела встречу в pruned, стёрла пути, записала журнал, каталог models/ не тронула, GET audio после этого 404.
