# forge-meet, фаза 4: адаптер Яндекс Телемоста end-to-end

Дата: 2026-08-17. Первая живая платформа. Всё, что ниже, — про плагин `plugins/meet`.

## Что сделано

| файл | что |
|---|---|
| `src/bot/probes.toml` | встроенные пробы платформ (данные, не код) |
| `src/bot/platforms.rs` | книга проб, поэлементное переопределение, выражения для страницы |
| `src/bot/inject/observe.js` | чтение DOM по пробам; в инжект НЕ входит |
| `src/bot/observe.rs` | разбор снимка, «Участник N», ось времени |
| `src/bot/chrome.rs` | боевой `MeetBot` поверх `forge-cdp`: запуск, вход, насос, наблюдение |
| `src/bot/endgame.rs` | детект конца встречи и автовыход, чистая логика |
| `src/bot/attrib.rs` | каскад привязки дорожки к человеку, чистая логика |
| `src/pipeline/run.rs` | `timeline_from_journal`: выбор источника интервалов + след каскада в манифест |

## Держащий всё инвариант

**Запись не зависит ни от одной DOM-пробы.** Он не декларация: тест
`no_probe_selector_leaks_into_the_capture_sources` перебирает ВСЕ кандидаты ВСЕХ
платформ и требует, чтобы ни один не встречался в исходниках захвата
(`capture.js`, `transport.js`, `worklet.js`, `pcm.js`, `vad.js`). Мутация
«вписать селектор в capture.js» его красит.

Следствия: пустой набор проб даёт запись без имён («Участник N»), а конец
встречи ловится независимыми сигналами.

## Измерено на живом Телемосте 2026-08-17

**Селектор из пробы Ф0 УЖЕ ПРОТУХ.** Кнопка «Продолжить в браузере» больше не
`button.continueInBrowserButton_-wew`: сегодня это `Orb-Button` с
`data-testid="orb-button"`, причём тот же `data-testid` носят «Поддержка»,
«Частые вопросы» и «Скачать на телефон» — то есть по нему кликать НЕЛЬЗЯ.
Сработал второй кандидат — `text:Продолжить в браузере`. Это ровно тот случай,
ради которого пробы сделаны массивом кандидатов и живут в TOML; порядок
кандидатов у Телемоста поэтому переставлен: текст первым, класс вторым.

Комната пробы Ф0 (`/j/60497752704486`) больше не активна — вместо встречи
отдаётся посадочная страница с FAQ, поэтому дальше интерстишала живая проверка
входа в этот раз не пошла.

## Формат проб

```toml
[telemost]
continue_in_browser = ["text:Продолжить в браузере", "button.continueInBrowserButton_-wew"]
join_button = ["[data-testid=\"enter-conference-button\"]", "text:Подключиться"]
speaking_marker = ["[class*=\"rootStroke\"]"]
participant_key_attr = ["attr:data-participant-id"]
post_call_url = []
```

Три вида кандидата: CSS-селектор, `text:<подстрока>` (ищется среди кликабельных
элементов, регистр не важен) и `attr:<имя атрибута>` (только для
`participant_key_attr`). Проба `post_call_url` хранит подстроки адреса, а не
селекторы.

Пользовательский файл `~/.config/forge/meet.probes.toml` переопределяет
встроенный **поэлементно**: строка с одной пробой чинит одну пробу и не
обнуляет платформу. Битый TOML — `warn` и встроенные значения. Путь
переопределяется `FORGE_MEET_PROBES_PATH` (герметичность тестов).

### Чего в пробах намеренно НЕТ

Нет пробы «мы всё ещё во встрече». Сигнал по ОТСУТСТВИЮ элемента опасен именно
тем, чем ценен файл: протухший селектор перестаёт находиться навсегда, и бот
немедленно решил бы, что встреча кончилась. Все сигналы конца встречи —
положительные.

## Порядок команд CDP

`setBypassCSP` → `grantPermissions` → `addBinding` →
`addScriptToEvaluateOnNewDocument` → `setAutoAttach` → `navigate`, подписка на
биндинг — ДО навигации. Нарушение ломает инжект МОЛЧА: страница загрузится,
вход пройдёт, а звука не будет. Закреплено тестом через `RecordingTransport`
(`tests/chrome_bot.rs`), фейковый транспорт без сокета и браузера.

## Вход: две ветки pre-join и счётчики попыток

Решение вынесено чистой функцией `next_join_step(снимок, ход входа, лимит)`:
капча → мы внутри → интерстишал → имя → вход → лобби → ждать.

* **гостевая ветка** и **ветка залогиненного профиля** различаются НАЛИЧИЕМ ПОЛЯ
  ИМЕНИ, а не отдельной пробой «залогинен»: Ф0 измерила, что на залогиненном
  профиле поля нет вовсе, а протухший маркер отправлял бы бота не в ту ветку
  молча;
* **счётчики попыток на шаг** — лекарство от зацикливания, найденное живым
  прогоном: нажатая кнопка не обязана исчезать;
* лобби даёт `MeetEvent::WaitingAdmit` → статус `waiting_admit` (человек не
  нужен, нужно подождать), а невлезание в таймаут — `needs_human`, после чего
  подхватывает ассистированный вход.

## Микрофон и камера — два независимых барьера

1. флаги запуска: `--use-fake-device-for-media-stream` плюс
   `--use-file-for-fake-audio-capture=<тишина>` (без файла тишины фейковое
   устройство Chrome ПИКАЕТ в встречу);
2. кнопки по пробам, и они жмутся **повторно после входа** — ловушка Ф0:
   Телемост включает микрофон сам в момент подключения.

`DeviceState::Unknown` никогда не считается достигнутым состоянием: «не знаю» —
это не «выключено».

## Конец встречи: шесть независимых сигналов

`target упал` → `все дорожки ended` → `DOM-маркер либо пост-звонковый адрес` →
`потолок длительности` → `бот один` → `тишина при ≤1 собеседнике`. Все таймауты —
поля конфига в миллисекундах, поэтому табличный тест идёт доли секунды.

**Автовыходы слепы, пока пробы не сработали ни разу.** Пустой список участников
означает и «никого нет», и «селектор больше не находится»; перепутай их — и
протухшая вёрстка выкидывала бы бота с живой встречи через минуту после входа.

## Каскад имён и выбор источника интервалов

Пять ступеней: `msid` → `ssrc` → **корреляция VAD-таймлайна с DOM-индикатором**
(окно 90 с, порог 0.7, плюс обязательный зазор до второго претендента) → прямое
указание площадки → «Участник N». Назначение решается как задача о назначении
(перебор до семи дорожек), мера — IoU. Сработавшая ступень уезжает в
`manifest.speakers` и в `meeting_participants.source`.

**Расхождение с планом, найденное при сведении.** В журнале живой встречи лежат
ОБА таймлайна сразу — пер-трековый VAD и DOM-индикатор. Сложи их, и каждая
реплика попала бы в расшифровку дважды: под именем дорожки и под именем
человека. Поэтому источник теперь ВЫБИРАЕТСЯ:

| что есть | источник |
|---|---|
| каскад назвал хотя бы одну дорожку | VAD дорожек (видит наложение речи) |
| имён нет, но есть DOM | DOM (режим `Slots` Телемоста) |
| ни того, ни другого | VAD с «Дорожка N» |

## Живая приёмка на мок-встрече (Chrome 151, 2026-08-17)

`FORGE_MEET_E2E=1 cargo test -p forge-meet --test chrome_bot` — мок поднимается
с `autojoin=0`, то есть без кликов бота встречи не существует, и пришедший PCM
и есть доказательство входа:

* страница подтвердила клики `continue-in-browser`, `join` и имя `F.O.R.G.E.` в поле;
* `micEnabled=false`, `camEnabled=false` — оба барьера сработали;
* три дорожки, 1830 кадров, `capture_path=rtcpeerconnection`;
* участники из DOM совпали с фактическими (бот и трое), восемь смен активного
  спикера с метками на общей оси;
* бот вышел САМ с причиной `all_tracks_ended`, живых Chrome после выхода ноль;
* поток событий живого бота проходит `validate_order`.

Живой прогон нашёл три вещи мимо герметичных тестов: порядок `joined` и
`recording_started`, видимость элементов пре-join и зацикливание на
неисчезающей кнопке. Все три закрыты кодом и тестами.

## Чего НЕТ

Живой приёмки на НАСТОЯЩЕЙ встрече Телемоста с несколькими участниками (гейт
`forge-meet-f4-8sa7.7`): комната пробы Ф0 больше не активна, а создать встречу
можно только из залогиненного аккаунта. Требование перенесено на финальный гейт
проекта.
