## Решения, которые нельзя переиграть, не переделав фазу

**Три тапа, а не один, и работают они ПО ПРИОРИТЕТУ, а не аддитивно.**
Подробности и история дефекта — [[forge-meet-three-taps]]. Коротко: Zoom не
отдаёт медиа через WebRTC вовсе, поэтому тапов три; тождество источника — это
`MediaStreamTrack.id`; младший тап не заводит дорожку при работающем старшем;
старший, включившийся позже, вытесняет младший.

**Звук идёт через CDP-биндинг.** Роут `/ws/meet/ingest` НЕ СОЗДАЁТСЯ — есть
тест `the_ingest_socket_is_never_registered`. Отклонённый вариант «исключение в
csrf_guard по одноразовому токену» записан комментарием рядом с
`RAW_UPLOAD_PATHS` в `tmux-web/src/auth.rs`: токен лежит в памяти чужой
страницы, которой мы отключили CSP, а через главный сокет достижим
`/ws/attach`, то есть терминал.

**Адресация СЭМПЛОВЫМ СМЕЩЕНИЕМ.** Кадр не по порядку — кладём по смещению;
кадр потерян — остаётся тишина, таймлайн не сдвигается.

**Ось времени одна** — мс от T0 через `performance.now()`.

**Chrome целиком за `trait MeetBot`.** Ф4 подставит `ChromeBot` через
`BotFactory`, не тронув ни строки пайплайна.

Гейт фазы закрывался дважды: сначала без браузера (система не запускала ни один
Chromium), потом — по-настоящему.

```
[per-track] кадров 1227, дорожек 3, путь rtcpeerconnection, 8220 мс
[slots]     кадров  818, дорожек 2, путь rtcpeerconnection, 8222 мс
[mixed]     кадров  409, дорожек 1, путь rtcpeerconnection, 8215 мс
```

Первый же живой прогон нашёл то, чего не видел ни один герметичный тест:
**каждая дорожка захватывалась дважды** (6 вместо 3, 4 вместо 2, 2 вместо 1).
Разбор — в [[forge-meet-three-taps]].

## Три поломки, которые нашлись только на живом прогоне

1. **Двойная регистрация дорожек** (обход приёмников брал молчащие приёмники
   отправляющей стороны).
2. **Противоречие внутри эталона**: в режиме `mixed` пауза между репликами
   была 500 мс — ровно `vad_hangover_ms`, то есть ровно тот промежуток, который
   детект речи ОБЯЗАН не считать концом реплики. Интервалы сливались, и прав
   был код. Паузы разведены до 1200 мс.
3. **Две оси времени сравнивались как одна**: расписание страницы идёт от `t0`
   аудиочасов, запись — от первой захваченной дорожки, между ними стабильно
   160–170 мс. Допуск в 250 мс тратился на эту разницу вместо точности детекта.
   Страница отдаёт `mock.t0UnixMs`, тест вычитает сдвиг.

## ДВЕ НАСТОЯЩИЕ ПОЛОМКИ, найденные тестами VAD

1. **Пол, ползущий от -70 дБ по 3 дБ/с**, десятки секунд держит порог
   ВЫКЛЮЧЕНИЯ ниже уровня самой тишины. Речь, начавшись, не кончалась
   никогда — вся встреча становилась одной репликой. Лечится засевом пола
   ПЕРВЫМ замером.
2. **Пол подползал вверх в окне подтверждения** (0.6 дБ за реплику, десятки
   децибел за встречу — детект слепнет). Адаптация выключена по
   `aboveMs === 0`, а не по «не говорим».

## Измерения окружения (важно для Ф4)

**Web Audio может не рендериться вовсе.** Бывает окружение, где Chrome
стартует, страница грузится, `AudioContext.state === "running"`, а
`currentTime` ЗАМИРАЕТ на первом кванте (256/48000 = 0.00533 с). Поэтому e2e
НАЧИНАЕТСЯ с измерения аудиочасов и при замерших пропускается с явным
сообщением: молча зелёный тест здесь хуже красного. На здоровой машине часы
идут, и все проверки выполняются.

**Режим окна — `minimized`, решение по измерению.** Полностью:
[[forge-meet-window-mode]]. Коротко: пока бота не показывали, окна нет на
экране ни в одном режиме, но после показа человеком вернуть окно «за экран» на
macOS невозможно — координаты подрезаются, окно остаётся полосой 350 пикселей
на весь оставшийся час. Свернуть можно, и захват от этого не страдает: 149,9
кадра в секунду из 150 за пять минут, ноль дырок в PCM, снимок работает.

## Тесты

359 юнит-тестов крейта + интеграционные (`repo`, `routes_recording`,
`mock_fixture`, `js_suite`, `e2e_mock`, `window_mode`) + 32 JS-теста через
`node --test`, прогоняемых ИЗ `cargo test`. Живые прогоны за
`FORGE_MEET_E2E=1`, пятиминутный стенд окна — дополнительно за
`FORGE_MEET_WINDOW_BENCH=1`.

Стражи проверены поломкой: четыре мутации `capture.js` красят от одного до
четырёх JS-тестов, две мутации режима окна — по одному тесту `forge-cdp`,
возврат старого обхода приёмников красит живой e2e за шесть секунд прогона.
