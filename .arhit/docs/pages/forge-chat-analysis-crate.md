Крейт plugins/chat-analysis (package forge-chat-analysis) — общее бэкенд-ядро фичи «Анализ чата через Claude», вынесенное из plugins/vk (эпик forge-caport-1a-4fwj, этап 1a переноса фичи в Telegram и Bitrix). Образец выноса — forge-claude-runner.

ЗАЧЕМ. Фича сделана и принята в VK. Telegram и Bitrix — структурные близнецы VK, и вторая (третья) реализация тех же 3250 строк разъехалась бы с оригиналом на первом же исправлении. Крейт ЛИСТОВОЙ: ни одной зависимости на плагины и на devforge, ни axum, ни http — про HTTP он не знает вовсе.

СОСТАВ (plugins/chat-analysis/src/):
- atomic — НЕ модуль этого крейта, а ПЕРЕЭКСПОРТ листового крейта forge-atomic (plugins/atomic) строкой pub use forge_atomic as atomic;. Код уехал в фазе 0 проекта forge-meet (задача forge-meet-f0-8bzq.4): forge-meet пишет manifest.json, transcript.json/md, summary.md и chrome.pid, а ядро анализа чата ему не нужно — подключать ради tmp+rename+chmod весь крейт с tokio+tokio-util+uuid+forge-claude-runner значило бы получить четвёртую копию последовательности. Переэкспорт оставлен намеренно: forge_chat_analysis::atomic::* — сложившийся публичный путь (им пользуется plugins/vk/src/config.rs), и все места вызова остались нетронутыми. Содержимое: write_bytes_atomic + tmp_path_for/write_secret_file/set_owner_only, см. страницу forge-atomic-crate.
- prompts.rs — пер-чатовое хранилище: PromptStore (BTreeMap dialog_id(строка) -> ChatPrompt{prompt, updated_at, analysis: Option<ChatAnalysis>, thread: Vec<QaTurn>}), load/save (ПУТЬ — ПАРАМЕТР, не константа: у каждого плагина свой файл), sanitize/sanitize_analysis/sanitize_turn, set/set_analysis/clear_analysis/push_turn/clear_thread, evict/normalize. Константы: MAX_PROMPT_CHARS=4000, MAX_ANALYSIS_CHARS=12000, MAX_THREAD_TURNS=12, MAX_THREAD_CHARS=10000, MAX_TURN_CHARS=5000, MAX_CHATS=500, MAX_FILE_BYTES=64 МиБ (арифметику худшего случая держит тест the_file_cap_covers_the_worst_case). load НИКОГДА не возвращает ошибку: мусор -> warn + пустое хранилище. В tracing уходят только размеры, target chat_analysis.
- prompt.rs — SYSTEM_PROMPT (уезжает в --append-system-prompt, а не в тело), Task::{Analyze,Refresh{previous},Ask{question,history}}, build(chat_title, custom, &Transcript, &Task), escape (& первым), clamp_history (режет САМЫЕ старые пары). Теговая форма <chat>/<chat_context>/<previous_analysis>/<transcript>/<history>/<task> — митигация prompt injection первого уровня.
- transcript.rs — Transcript{text, messages_used, truncated, oldest_id, newest_id}. Собирает ПЛАГИН (у каждого свой API истории), потребляет ядро.
- hub.rs — AnalysisHub поверх forge-claude-runner: дедуп по dialog_id (второй запуск -> StartOutcome::AlreadyRunning), потолок MAX_PARALLEL_ANALYSIS=2 с мгновенным отказом, коалесцинг дельт (DELTA_FLUSH_MS=120 / DELTA_FLUSH_CHARS=400 — УСЛОВИЕ КОРРЕКТНОСТИ: без него broadcast плагина переполняется, Lagged -> resync -> цикл перезагрузок панели), аккумулятор полного ответа, PersistTarget::{Analysis,Turn}, сохранение ТОЛЬКО при ok==true, отмена (финальный кадр шлёт РОУТ отмены, пампер молчит по CancellationToken), таймаут, shutdown. Промпт уходит в CLI через stdin (prompt_via_stdin), не через argv.
- sink.rs — trait AnalysisSink{started,delta,done,error}: ЕДИНСТВЕННАЯ развязка с плагином. Методы синхронные намеренно (их зовёт пампер в горячем цикле).
- error.rs — AnalysisError{Busy(usize), CliUnavailable, NoPreviousAnalysis, Storage(String)}; Display без путей и секретов (тест). HTTP-код выбирает плагин.
- testing.rs — pub RecordingSink: накопитель кадров (Frame::{Started,Delta,Done,Error}) с wait_for по Notify. Им же тестируются роуты плагинов.
- text.rs — truncate_chars (по CODE POINTS: байтовый срез на кириллице паникует) и now_unix через SystemTime (chrono крейту не нужен).
