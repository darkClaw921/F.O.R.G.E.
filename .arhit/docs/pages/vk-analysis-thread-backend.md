# Сохраняемый тред вопросов: бэкенд (эпик forge-vkmd-a-zzz1)

## Зачем

История вопросов к беседе жила только в памяти вкладки (local.thread в js/vk/analysis.js) и пропадала на первой же перезагрузке страницы. Требование пользователя: тред живёт до ручной очистки кнопкой CLEAR Q&A. Решение — то же, что уже принято для разбора: тред хранится на бэкенде, в записи беседы файла ~/.forge/vk-chat-prompts.json.

## Формат

ChatPrompt получил поле thread: Vec<QaTurn>, где QaTurn = {q, a, at}. Поле опциональное (skip_serializing_if = Vec::is_empty), версия файла остаётся 1 — старый файл читается без потерь, а перезапись не добавляет ему пустого массива. Проверено и тестом (an_old_file_without_analysis_round_trips), и живой проверкой на изолированном инстансе.

## Почему хранимый тред больше отправляемого модели

Хранение: MAX_THREAD_TURNS = 12 пар, MAX_THREAD_CHARS = 10 000 символов суммарно (q + a по всем парам), обрезка со СТАРЫХ пар по обеим осям.
Промпт: clamp_history оставляет MAX_HISTORY_TURNS = 6 пар и MAX_HISTORY_CHARS = 8 000 символов.

Разница намеренная: тред на экране — история переписки пользователя с моделью, она обязана пережить F5 целиком; тред в промпте — расход контекстного окна и денег на каждом вопросе, и седьмая пара давности в нём только вытесняет транскрипт. Помним больше, чем отправляем — на обеих осях. Инвариант закреплён const-ассертами в тесте the_file_cap_covers_the_worst_case, чтобы правка одной константы не сделала оба числа равными молча.

## Потолок файла пересчитан

MAX_FILE_BYTES поднят 40 -> 64 МиБ, но не «молча»: сначала снижен MAX_THREAD_CHARS (12 000 -> 10 000 из плана), потому что файл читается в память целиком, и 72 МиБ худшего случая — это уже не граница защиты. Итоговая арифметика: 500 чатов × (4 000 + 12 000 + 10 000) символов × 4 байта = 52 000 000 байт, плюс четверть на накладные расходы JSON = 65 000 000 <= 67 108 864. Цена ошибки здесь — тихая потеря ВСЕХ пользовательских данных: файл больше потолка читается как пустой без единой ошибки в UI.

Дополнительный потолок MAX_TURN_CHARS = MAX_THREAD_CHARS / 2 держит инвариант «одна пара всегда влезает»: без него один гигантский ответ модели вытеснил бы весь тред, включая только что заданный вопрос.

## Кто пишет тред

analysis::hub, пампер, по успешно завершённому run'у kind == "ask". Симметрично тому, как analyze/refresh сохраняют разбор: PersistCtx получил PersistTarget::{Analysis, Turn} вместо пары полей — у разбора и у пары треда нет общих параметров, и Option на каждый допускал бы состояния «разбор без точки отсчёта» и «пара без вопроса», которых не бывает.

Сохраняется ТОЛЬКО при ok == true и только непустой ответ. Отмена, таймаут и ошибка CLI пары не оставляют: тред уходит модели как контекст следующего вопроса, и огрызок отравил бы его так же, как отравил бы REFRESH огрызок разбора. Вопрос берётся из уже разобранного Task::Ask (после trim и проверки на пустоту) — в тред попадает ровно то, что уехало модели.

## Контракт роутов

- GET /api/vk/dialogs/:id/analysis — ответ дополнен полем thread: [{q, a, at}]; пустой тред приезжает пустым МАССИВОМ, а не отсутствием поля (фронту проще безусловно перебрать).
- DELETE /api/vk/dialogs/:id/analysis/thread — новый путь, «CLEAR Q&A». Ступень авторизация + resolve_peer, без require_ready: тред в локальном файле, VK для его очистки не нужен. 200 {"cleared": bool}, идемпотентен.

Выбран отдельный путь, а НЕ DELETE /analysis?thread=1: query-параметры в плагине разбираются вручную через RawQuery, потому что экстрактор Query<T> отрабатывает до тела хендлера и отвечает 400 раньше проверки авторизации — то есть ломает auth-ladder. Отдельный маршрут не требует исключений и попадает в сторожевые тесты routes/mod.rs перебором: data_routes_are_mounted_and_demand_authorization и hostile_dialog_ids_hit_auth_before_any_parsing (по всем враждебным id, с проверкой, что файл заметок даже не создавался).

## Матрица независимости трёх полей записи

|                | prompt (заметка) | analysis (разбор) | thread (тред) |
|---|---|---|---|
| set() / PUT /prompt | меняет | НЕ трогает | НЕ трогает |
| set_analysis() | НЕ трогает | меняет | НЕ трогает |
| push_turn() | НЕ трогает | НЕ трогает | добавляет пару |
| clear_analysis() / DELETE /analysis | НЕ трогает | стирает | НЕ трогает |
| clear_thread() / DELETE /analysis/thread | НЕ трогает | НЕ трогает | стирает |

Запись живёт, пока жива хотя бы одна половина; когда пусты все три — удаляется. Матрица закрыта тестами на ДВУХ уровнях, и на HTTP-уровне проверка идёт после реального round-trip через файл (save + load), потому что молчаливая потеря происходит именно на записи.

## Живая проверка

Изолированный инстанс (свой HOME, свободный порт, мок api.vk.com, мок claude CLI): два вопроса -> перезапуск сервера -> обе пары на месте -> analyze -> CLEAR Q&A стёр тред, разбор остался -> CLEAR анализа стёр разбор. Отдельно: файл СТАРОГО формата без ключа thread прочитан без потерь (включая emoji в заметке), а после перезаписи в нём не появилось "thread": null.
