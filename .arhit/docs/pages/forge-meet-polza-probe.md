# polza.ai как облачный провайдер для forge-meet — живая проба API

Дата: 2026-08-19. Все цифры ниже сняты боевыми запросами с ключом пользователя, не из
документации. Потрачено на пробу около 12 ₽.

## Итог одной строкой

polza.ai — OpenAI-совместимый агрегатор: `chat/completions` со стримингом, `audio/speech`
и `audio/transcriptions` работают. Но **у облачного STT есть жёсткое ограничение, которое
определяет всю архитектуру: около 60 секунд на запрос по стене**, поэтому длинную запись
обязан резать НАШ код.

## База и аутентификация

```
POST https://api.polza.ai/api/v1/...        (тот же ответ отдают /v1/... и polza.ai/api/v1/...)
Authorization: Bearer pza_...
```

Служебные эндпоинты, полезные для `GET /api/meet/status`:

| Эндпоинт | Отдаёт |
|---|---|
| `GET /api/v1/models` | 388 моделей; `type` ∈ chat / stt / tts / image / video / embedding / music |
| `GET /api/v1/key` | лимиты ключа: `limit`, `limit_remaining`, `limit_reset: daily`, `usage` |
| `GET /api/v1/balance` | `amount`, `reservedAmount`, `spentAmount` — **в рублях** |

`/credits`, `/me`, `/auth/key` — 404, их нет.

Проверка ключа на живость дешевле всего делается через `/key`: он не тратит ни копейки и
сразу показывает, не исчерпан ли дневной лимит.

## Цены лежат в `top_provider.pricing`, а не в `pricing`

Поле верхнего уровня `pricing` у всех записей `null` — цена спрятана на уровень глубже, и
это ровно та ловушка, на которой парсер молча покажет «бесплатно»:

```json
"top_provider": {"context_length": 1048576, "max_completion_tokens": 65536,
  "pricing": {"prompt_per_million": "176.05", "completion_per_million": "1056.32",
              "currency": "RUB"}}
```

У STT-моделей форма другая — `{"stt_per_minute": "...", "currency": "RUB"}`.

## Облачный STT: единственная модель с таймкодами — `openai/whisper-1`

Замер на русской речи, сгенерированной их же TTS:

| Модель | `response_format` | Таймкоды | 2 мин аудио | 3 мин аудио |
|---|---|---|---|---|
| `openai/whisper-1` | `verbose_json` | **посегментные** | 200 за 35 с | **обрыв TCP на 62 с** |
| `openai/whisper-large-v3-turbo` | только `json` / `text` | нет вообще | 200 за 6 с | 200 за 16 с |

Развилка жёсткая и выбора не оставляет:

* `whisper-large-v3-turbo` быстрее в разы и втрое дешевле (0.048 ₽/мин против 0.432 ₽/мин),
  но идёт через «OpenRouter Audio API», который на `verbose_json` отвечает прямым отказом:
  «Допустимые значения: json, text». Без таймкодов расшифровка невозможно привязывается к
  таймлайну — а вся атрибуция спикеров у нас построена на пересечении интервалов;
* `whisper-1` таймкоды даёт, но только **посегментные**: параметр
  `timestamp_granularities[]=word` принимается без ошибки и молча игнорируется — поля
  `words` в ответе нет. Это регресс относительно локального whisper.cpp с `-ojf`, где
  пословные метки есть, и он бьёт ровно по той ветке плана, где сегмент с низкой
  уверенностью режется по границе слова.

Отсюда два следствия для реализации:

1. **Облачная расшифровка режется на окна.** Обрыв происходит по стене (2 мин ⇒ 35 с, 3 мин
   ⇒ смерть на 62 с), а не по размеру, поэтому безопасное окно — около 90 секунд аудио с
   запасом. Смещения возвращаются на общую ось уже существующей `remap_segment_times`.
2. **Пословного дробления сегмента в облаке нет.** Ветка «confidence < 0.6 ⇒ режем по
   словам» в облачном режиме обязана деградировать до пометки `overlapped`, а не молча
   выдавать неверные границы.

Формат файла: принимаются `flac, m4a, mp3, mp4, mpeg, mpga, oga, ogg, wav, webm`, но
**WAV на 193 КБ уронил шлюз** с `Maximum call stack size exceeded` (у них наивная
base64-обвязка), тогда как mp3 того же аудио прошёл. Значит на облако отдаём сжатый mp3,
а не сырой PCM — заодно это на порядок меньше трафика.

`response_format=diarized_json` существует и отвечает 200, но на нашей пробе вернул только
текст без спикеров. Как замену DOM-атрибуции не рассматриваем.

## Облачное саммари: `chat/completions`, стрим по SSE

Обычный OpenAI SSE: `data: {"choices":[{"delta":{"content":"…"}}]}`, поле `provider`
показывает, кто реально исполнил. Стриминг важен: ровно так живёт нынешний экранный вывод
саммари через `AnalysisSink::delta`, и облачный путь встаёт на то же место без переделки
фронта.

Кандидат по умолчанию — `google/gemini-3.5-flash`: контекст 1 048 576 токенов (часовая
встреча ≈ 30 тыс. токенов помещается целиком, map-reduce не нужен), 176 ₽/млн на входе и
1056 ₽/млн на выходе, то есть около **7 ₽ за саммари часовой встречи**. Каталог отдаёт
Claude, GPT-5.x, DeepSeek и YandexGPT — модель обязана быть полем конфига, а не константой.

## Что это значит для переключателя «локально / облако»

Стадии независимы и переключаются раздельно, потому что ограничения у них разные:

| Стадия | Локально | Облако | Замечание |
|---|---|---|---|
| Расшифровка | whisper.cpp + Metal | `openai/whisper-1`, окна ≤ 90 с | облако не даёт пословных меток |
| Саммари | Claude CLI | `chat/completions` со стримом | контекст 1M снимает вопрос длины |

Облако не требует ни модели на диске (1,6 ГБ), ни занятого Metal, ни установленного
`whisper-cli`, и не конкурирует с Chrome за GPU — то есть в облачном режиме исчезает и
семафор «whisper строго один», и запрет «не расшифровывать, пока идёт запись».
