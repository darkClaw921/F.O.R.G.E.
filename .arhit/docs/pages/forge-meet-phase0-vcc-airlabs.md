# forge-meet, живая проба площадки vcc.airlabs.pro (L.I.N.K.)

Дата: 2026-08-19. Проба снята на **реальной комнате**, созданной прямо на площадке, с
тремя участниками (бот + два «говоруна» с синтезированной речью), через CDP с патчем
`RTCPeerConnection` до навигации — то есть тем же механизмом, каким работает боевой бот.

## Итог одной строкой

**Площадка построена на LiveKit.** Это лучший из четырёх известных нам случаев: режим
**`PerParticipant`** (трек = человек), стабильные `data-lk-*` атрибуты вместо хешированных
CSS-модулей, и `data-testid` на ключевых кнопках. Ни одного селектора с хешем сборки.

## Что измерено

### 1. Адрес комнаты: `/r/<код>`

Код вида `6b2-m7e-g9z` — три группы по три символа через дефис. Комнату создаёт кто угодно
без входа: лендинг → выбор режима (`ONE_TO_ONE` / `CONFERENCE` / `WEBINAR` / `STREAMING`) →
кнопка «Создать встречу» → редирект на `/r/<код>`.

Несуществующая или закрытая комната отдаёт страницу с заголовком **«Встреча завершена»**
(`<title>` = `Встреча завершена — AirLabs Видеовстречи`) — готовый положительный маркер.

### 2. Это LiveKit — DOM-контракт вместо угадывания вёрстки

В разметке присутствуют: `lk-participant-tile`, `lk-participant-name`, `lk-grid-layout`,
`lk-room-container`, `lk-participant-media-audio`, а на плитке участника — набор атрибутов:

```
data-lk-speaking="true|false"        ← индикатор говорящего, per-participant
data-lk-audio-muted="true|false"
data-lk-video-muted="true|false"
data-lk-local-participant="true|false"  ← так отличается плитка самого бота
data-lk-source="camera"
```

Имя участника — `[data-lk-participant-name]` (значение дублируется и в атрибуте, и в тексте).

Это принципиально отличается от Телемоста: там классы плиток были CSS-модулями с хешами
сборки (`item_NZ2DW`), протухавшими за три дня. Здесь селекторы — часть публичного контракта
компонентов LiveKit.

### 3. Режим SFU — `PerParticipant`, трек = человек

При двух удалённых участниках бот получил **два отдельных удалённых аудиотрека**, каждый в
своём `<audio class="lk-participant-media-audio">`:

```
ba907a9d…  mid=0  label "remote audio"
52c56f5a…  mid=1  label "remote audio"
cefd03f3…  mid=2  (глухой слот про запас)
```

`getContributingSources()` пуст на обоих — микса нет. Пер-трековая нарезка по VAD и
пер-трековая расшифровка, бессмысленные для Телемоста, **для этой площадки работают**.

### 4. В msid лежит идентификатор участника

Событие `track` приходит ДВАЖДЫ. Первый раз — с общим потоком (`2e362d2c…`), второй, при
ренеготиации, — с настоящим msid LiveKit:

```
ba907a9d…  streams: ["PA_PEpGftC6osXZ|TR_AMYPfGyxhgvJQb"]
52c56f5a…  streams: ["PA_snV754Yxnoqb|TR_AMsHBUVaDUizsq"]
```

`PA_*` — SID участника, `TR_*` — SID дорожки. То есть **трек↔участник разрешается на уровне
WebRTC**, без корреляции по времени. Чего в этой связке НЕТ — человеческого имени: в DOM
`PA_*` нигде не выставлен, глобального объекта `Room` страница не публикует
(`Object.keys(window)` его не содержит). Поэтому имя всё равно берётся из
`data-lk-participant-name`, а msid остаётся дополнительной осью устойчивости.

### 5. Индикатор говорящего работает и различает участников

За 20 с наблюдения `data-lk-speaking` независимо переключался у обеих плиток, совпадая с
речью соответствующего «говоруна». Параллельный замер RMS по каждому треку дал ту же
картину раздельно:

```
ba907a9d=0.1490  52c56f5a=0.0000
ba907a9d=0.0059  52c56f5a=0.0526
```

То есть у этой площадки есть ДВА независимых источника атрибуции — DOM и пер-трековый VAD, —
и они друг друга проверяют.

### 6. `--mute-audio` не глушит данные для WebAudio

Замер сделан в браузере, запущенном с `--mute-audio`: RMS удалённых треков ненулевой и
меняется в такт речи. Вопрос №3 из плана Ф0 закрыт положительно.

### 7. `getSynchronizationSources().audioLevel` НЕ заполняется

`getSynchronizationSources()` возвращает записи, но в них есть только `source` (SSRC), поля
`audioLevel` нет вовсе. Вопрос №2 из плана закрыт **отрицательно**: рассчитывать на дешёвый
уровень от отправителя нельзя, VAD строится на собственном RMS/worklet.

### 9. Пре-джойн: две ветки, как у Телемоста

Гостю показывается модалка «Зарегистрируйтесь в CRM AirLabs» с кнопками «В другой раз» /
«ОК, зарегистрироваться» — её надо закрыть ДО работы с полем имени. Повторный вход в ту же
комнату из того же профиля пре-джойн **пропускает**: имя уже сохранено, бот оказывается
сразу во встрече.

### 10. Права на медиа нужно выдавать через CDP

`--use-fake-ui-for-media-stream` в живой пробе НЕ снял отказ: страница показала «Доступ к
камере/микрофону запрещён». Помог `Browser.grantPermissions` с `audioCapture`/`videoCapture`
на origin площадки — ровно то, что боевой лаунчер и делает.

## Побочный факт, важный для всего плагина

**`--use-file-for-fake-audio-capture` на этой сборке Chrome (151.0.7922.169, macOS) молчит.**
Замер: `getUserMedia({audio:true})` → RMS ровно `0.0000` на двенадцати отсчётах подряд, при
корректном WAV (48 кГц, моно, `pcm_s16le`), при коротком пути без спецсимволов и при
подтверждённом наличии флага в argv аудио-сервиса.

Хорошая новость в том же замере: **фейковое устройство при этом не пищит** — оно отдаёт
цифровую тишину, а не периодический бип, ради глушения которого файл тишины и заводился.
То есть `silence.wav` в боевом лаунчере из необходимой защиты превращается в страховку
второго эшелона: сегодня он ни на что не влияет, но и вреда не приносит, а на сборке, где
бип вернётся, сработает.

Для самой пробы источник речи пришлось делать патчем `getUserMedia` до навигации: страница
получает обычный `MediaStream`, внутри которого зациклённо играет настоящая речь. Приём
годится и для будущих e2e-прогонов на живых площадках.

## Чего проба НЕ дала

- **Лобби и отказ во входе** — комнату создавал сам бот, поэтому ветки «ждём допуска» и
  «хост не пустил» не наблюдались. Селекторы `join_denied_marker` остаются пустыми.
- **Режимы `WEBINAR` и `STREAMING`.** Проверен только `CONFERENCE`. У стрима, судя по
  описанию на лендинге, зрители смотрят HLS без WebRTC — то есть тапы захвата там,
  скорее всего, не сработают вовсе, и это отдельная задача.
- **Поведение при 10+ участниках**: сохранится ли `PerParticipant` или включится пагинация
  плиток (`data-lk-pagination` в разметке есть) и часть имён уедет на вторую страницу.
