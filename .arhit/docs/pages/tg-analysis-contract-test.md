telegram_contract.test.mjs — сверка серверных и клиентских контрактов плагина Telegram (задача forge-caport-tg-j1x4.17). У плагина такого теста не было вовсе; образцы — vk_contract.test.mjs и bitrix_contract.test.mjs.

ЗАЧЕМ. Три из четырёх осей ломаются МОЛЧА: расхождение путей даёт 404, на который панель просто «ничего не делает»; переставленные кадры WS дают console.debug вместо ошибки; ref без id даёт undefined, всплывающий где-то позже. Компилятор не видит ни одного из этих разъездов — граница между Rust и JS для него не существует.

ЧЕТЫРЕ ОСИ (60 ассертов).
1. WS-кадры (11). Имена вариантов enum TgServerMsg парсятся из plugins/telegram/src/ws/protocol.rs и переводятся в snake_case; сверка с SERVER_FRAMES из js/telegram/ws.js по СОСТАВУ И ПОРЯДКУ. Отдельно: тест падает громко, если у варианта появился явный serde(rename) — тогда вывод тега из имени врал бы. Плюс: четвёрка analysis_* стоит подряд между folders_changed и resync; у каждого кадра есть ключ в main.js::buildHandlers.
2. DOM (13). 75 ref'ов $tg* из core/dom.js <-> id в index.html В ОБЕ СТОРОНЫ. Правило преобразования ($tgAnalysisClearThread -> tg-analysis-clear-thread) выполняется на всех 75 без единого исключения и само проверяется ассертом. Набор $tgAnalysis* посимвольно зеркалит $vkAnalysis* — ядро попапа общее.
3. Пути (20). ТРИ отношения, а не два: markdown-таблица в шапке routes/mod.rs <-> реально зарегистрированные .route(...) <-> пути из api.js. У Telegram в api.js нет замороженной таблицы (в отличие от VK), поэтому пути извлекаются разбором call-сайтов: комментарии вырезаются, склейки шаблонных строк сшиваются, ${...} -> :, query отбрасывается, метод берётся из jsonInit в границах того же оператора.
4. CSS (11). telegram.css не задевает #vk-/.vk-/#b24-/.b24-/#bitrix; в блоке попапа ни одного захардкоженного hex, только токены --t-*.

ЗАКРЫТЫЕ ИСКЛЮЧЕНИЯ (каждое со своим ассертом «не протухло»): tg-body/tg-statusbar/tg-session — структурные якоря CSS без обращений из JS; GET /ws/telegram — не в таблице путей (у сокета другой контракт, это сказано в шапке таблицы, и его сверяет ось 1); POST /api/telegram/upload — не в api.js (сырое тело через XHR ради прогресса, живёт в upload.js как UPLOAD_PATH); rgba(0,0,0,…) в box-shadow — не цвет палитры, а затемнение, как во всех «коробках поверх» файла.

ПРОВЕРЕН НА РЕГРЕСС по каждой оси: перестановка двух кадров в SERVER_FRAMES, переименование id в index.html, удаление строки из таблицы путей, правило, задевающее #vk-, — все четыре пробы покраснели, после чего исходники восстановлены побайтово.

ФАКТЫ, которые стоит знать: таблица в routes/mod.rs содержит 22 строки == 22 зарегистрированных axum-роута (23-й, /ws/telegram, исключён явно). /api/telegram/media/:dialog_id/:message_id исключением НЕ понадобился: mediaUrl()/fetchMedia() живут в api.js, а прямой src на этот путь невозможен из-за заголовка Authorization.
