# Белый список чатов и папок (forge-c2dt)

Режим «показывать только выбранное» во вкладке Telegram: пользователь отмечает
в настройках папки и/или отдельные чаты, остальные исчезают из devforge. В самом
Telegram они остаются нетронутыми — фильтр целиком клиентский.

## Из чего состоит

| Слой | Файл | Роль |
| --- | --- | --- |
| Чистая логика | `static/js/telegram/visibility.js` | разбор настроек, видимость чата, пустые пункты, сводка |
| Кэш и доступ | `static/js/telegram/state.js` | `currentVisibilityFilter` / `invalidateVisibilityFilter` |
| Колонка | `static/js/telegram/dialogs.js` | `renderAll`, `renderDirs` |
| Уведомления | `static/js/telegram/main.js` | `badgeUnread`, `dialogShown` → тосты и `pendingUnread` |
| Настройки | `static/js/settings/telegram-visibility-tab.js` | тумблер, списки папок и чатов, поиск |
| Хранение | `src/user_settings.rs` | `telegram_filter_enabled`, `telegram_visible_folders`, `telegram_visible_dialogs` |
| Стили | `css/settings-modal.css`, `css/telegram.css` | `.tg-visibility-*`, `.tg-dir-filtered-out` |

## Где именно применяется фильтр

Точек четыре, и все обязательны — иначе фильтр «протекает»:

1. **Колонка чатов** (`renderAll`) — что видно в списке.
2. **Счётчики папок** (`renderDirs`) — считаются по видимому срезу, иначе
   цифра «(7)» вела бы в скрытый чат.
3. **Бейдж на ✈** (`badgeUnread`) — та же причина.
4. **Тосты и накопление непрочитанного** (`maybeToast`, `noteUnknownUnread`) —
   спрятанный чат не должен дёргать уведомлением, и открывать его кликом по
   тосту было бы некуда.

## Четыре решения

### 1. «Включён» и «действует» — разные вещи

Тумблер с пустым белым списком означал бы пустую панель, и пользователь
прочитал бы это как поломку, а не как свою настройку. Поэтому
`filterActive = enabled && (папки + чаты > 0)`, а форма настроек прямо
предупреждает: «Ничего не выбрано — пока показаны все чаты».

### 2. Неизвестный чат при действующем фильтре скрыт

WS вещает по всему аккаунту, а `/dialogs` отдаёт только верхушку. Про чат из
кадра `new_message` может быть неизвестно ничего, кроме id. Считать такой чат
видимым — значит пропускать уведомления ровно от тех чатов, ради которых фильтр
и включали.

**Цена:** чат из отмеченной папки, не попавший в загруженную страницу, тоже
промолчит, пока страница не догрузится. Поимённо отмеченный чат при этом
работает всегда — для него DTO не нужен.

### 3. Пустой пункт навигации приглушается, но не исчезает

Папка, из которой ничего не видно, получает `tg-dir-filtered-out`. Убирать её
из списка нельзя: это структура аккаунта пользователя, а не наша.

### 4. Выбранные, но не загруженные чаты не вычищаются молча

Открытие настроек не должно терять из белого списка чат, до которого полгода
не доходили руки. Форма показывает такие записи отдельной группой и даёт
кнопку «Убрать несуществующие» — нажимает её пользователь.

## Семантика хранения

- `telegram_filter_enabled` — default **false**: нулевая конфигурация
  показывает всё, как и до фичи.
- Оба списка заменяются **целиком** при PATCH — иначе снять галочку нечем.
- Выключение тумблера **не стирает** выбор: включив обратно, пользователь
  получает свой список.
- Backend валидирует только форму (`sanitize_visible_list`): смысл ключей
  (`inbox`, `archive`, `folder:<id>`, id чата) знает фронтенд. Неизвестная
  запись сохраняется и просто ни с чем не совпадает — так переживается откат
  версии клиента.

## Взаимодействие с остальными фильтрами

| Что | Кто сильнее |
| --- | --- |
| Заглушённый чат в белом списке | mute — чат не звенит |
| Архивный чат в белом списке | архив — в `~/inbox` его нет, виден в `~/archive` |
| Скрытый чат в активной папке | белый список — его нет нигде |
| Поимённый выбор против неотмеченной папки | поимённый выбор |

валит, и это правильно: фильтры коммутативны, разницы в результате нет.

## Известные ограничения

- Фильтр клиентский: сервер по-прежнему получает все апдейты, экономии трафика
  нет.
- Список чатов в настройках — верхушка на 300 записей плюс поиск по ней;
  чата, которого нет в этой выборке, через UI не отметить.
- Категорийные папки (боты, контакты) работают по тем же правилам, что и
  колонка: у чата без полей `bot`/`contact` (старый сервер) классификация
  невозможна, и он проходит в любую категорийную папку.
