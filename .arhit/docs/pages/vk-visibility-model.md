МОДЕЛЬ ВИДИМОСТИ БЕСЕД VK (белый список, Ф10 плагина VK)

Пользователь ограничивает, какие беседы VK видны в devforge. Остальные продолжают жить в аккаунте — панель просто перестаёт их показывать.

## Где что лежит

- tmux-web/static/js/vk/visibility.js — ЧИСТЫЙ предикат (normalizeFilter / filterActive / dialogVisible / visibleDialogs / dialogIdVisible / filterSummary / pruneMissingPeers / VISIBLE_KINDS / kindLabel).
- tmux-web/static/js/vk/state.js — currentVisibilityFilter (кэш разбора по СОДЕРЖИМОМУ настроек) + invalidateVisibilityFilter.
- tmux-web/static/js/vk/dialogs.js — точки применения 1 и 2 (колонка, счётчики).
- tmux-web/static/js/vk/main.js — точки применения 3 и 4 (бейдж, тосты) + publishFilterContract.
- tmux-web/static/js/settings/vk-visibility-tab.js + modal.js (вкладка VK) — форма.
- tmux-web/src/user_settings.rs — поля vk_filter_enabled / vk_visible_kinds / vk_visible_peers.

## Инвариант «включён не равно действует» (перенесён из Telegram ДОСЛОВНО)

filterActive = enabled && (kinds.length > 0 || peers.length > 0). Тумблер с пустым выбором показывает ВСЁ, и форма прямо пишет «Ничего не выбрано — пока показаны все беседы». Иначе первое же включение дало бы пустую панель, а это читается как поломка, а не как своя настройка.

## Словарь: типы peer'а, а НЕ четыре серверных фильтра

Единственное место, где настройки VK намеренно расходятся с телеграмными. У Telegram белый список строится из ПАПОК; папок у VK нет, а all/unread/important/unanswered — параметр запроса messages.getConversations, то есть свойство ЗАПРОСА, а не беседы. «Показывать только непрочитанные» как постоянная настройка означала бы, что беседа исчезает из панели в момент прочтения. Поэтому белый список = типы user | chat | community плюс поимённый выбор peer_id.

## Улучшение относительно Telegram

peerKind вычисляется из самого peer_id по диапазонам (< 0 сообщество, < 2e9 пользователь, >= 2e9 беседа), без обращения к загруженному списку. Значит беседа, о которой пришёл WS-кадр и которой нет в загруженной странице, при фильтре ПО ТИПУ решается ТОЧНО. У Telegram приходилось скрывать неизвестный чат консервативно: принадлежность папке из id не выводится. Строгость сохраняется только в поимённом режиме. Тип везде берётся из peerKind(id), а не из DialogDto.kind — один источник, иначе колонка и WS-путь разошлись бы.

## ЧЕТЫРЕ точки применения — пропуск любой = протечка

1. колонка бесед (dialogs.js::visibleSource, одна точка на обе ветки: постоянный vkState.dialogs и транзиентный vkState.dirDialogs);
2. счётчики серверных фильтров (dialogs.js::renderDirs — считать по всему списку значит показать цифру, ведущую в никуда);
3. бейдж на Ⓥ (main.js::recomputeUnread; при действующем фильтре серверный unread_total ИГНОРИРУЕТСЯ, потому что посчитан по всему аккаунту и расщепить его нечем — бейдж возвращается к сумме по видимому срезу плюс pendingUnread, тоже проверяемый на видимость);
4. тосты и накопление непрочитанного (main.js::maybeToast / noteUnknownUnread).

Скрыть беседу только в колонке — половина работы: она продолжит всплывать тостом и накручивать цифру, ведущую в беседу, которой в списке нет. Каждая точка закрыта отдельным ассертом в tmux-web/tests/frontend/vk_dialogs_filter.test.mjs; мутация «убрать фильтр из точки N» краснит именно свой ассерт (проверено).

## Чего в модели нет

emptyDirKeys (приглушение пустых пунктов навигации) не переносится: пустоту серверного фильтра клиент не знает, не сделав запрос, а четыре запроса ради подсветки — весь секундный бюджет при лимите 3 rps.

## Контракт применения

window.ForgeApp.vkFilter = { refresh } (main.js::publishFilterContract, зовётся из initVkGate и initVk). refresh делает ТРИ обязательных действия: invalidateVisibilityFilter() + dialogs.renderAll() + recomputeUnread(). Без последнего бейдж продолжил бы считать уже скрытые беседы. Форма зовёт контракт через window, а не импортом: модалка настроек открывается и без включённого плагина.

## Хранение

PATCH /api/user-settings заменяет списки ЦЕЛИКОМ (merge сделал бы снятие галочки невозможным), значения проходят через общий sanitize_visible_list (потолки MAX_TELEGRAM_VISIBLE = 512 записей и MAX_VISIBLE_ENTRY_LEN = 64 символа — константы общие для обеих панелей). Выключение тумблера НЕ стирает выбор. Форма шлёт только свои три поля, поэтому соседние настройки не затираются.

## Тесты

vk_visibility.test.mjs (чистый предикат, 77 ассертов), vk_dialogs_filter.test.mjs (четыре точки применения на фейковом DOM, 50 проверок), vk_toasts.test.mjs (белый список в тостах), Rust-тесты user_settings (дефолты, замена списка целиком, санитайзер, потолок). Живая проверка Ф10 прогонялась в настоящем браузере на изолированном инстансе с моком REST плагина VK и НАСТОЯЩИМ backend'ом user-settings.
