# armFollowTimer

armFollowTimer() (tmux-web/static/js/telegram/chat.js, внутренняя) — перезаводит таймер истечения «следования» за сообщением бота.

ПОВЕДЕНИЕ: гасит прежний setTimeout (если был), проверяет наличие самого setTimeout (`typeof setTimeout !== 'function'` ⇒ тихий выход — гард для экзотических стендов), ставит новый на FOLLOW_TTL_MS (12с); в колбэке обнуляет local.followTimer и зовёт stopFollow().

ЗАЧЕМ ТАЙМЕР, ЕСЛИ СРОК И ТАК ПРОВЕРЯЕТСЯ ПО ЧАСАМ. Сам срок стережёт follow.js::followTarget по Date.now() — «протухшее» следование не сработает и без таймера. Таймер нужен РАДИ СНЯТИЯ НАБЛЮДАТЕЛЯ: без него ResizeObserver висел бы на строке до следующей смены диалога, а это ровно та утечка, которую фича обязана не создавать (требование «наблюдение обязано сниматься... утечки наблюдателей недопустимы»).

ПОЧЕМУ ПЕРЕЗАВОДИТСЯ, А НЕ ПРОДЛЕВАЕТСЯ: noteFollow при повторном нажатии перезаписывает untilMs целиком (`now + ttl`), и таймер обязан ехать за ним — иначе после серии нажатий он выстрелил бы по первому окну и снял наблюдение с живого следования.

ХРАНИЛИЩЕ: local.followTimer в модульном объекте `local` chat.js. Гасится в stopFollow (а значит — во всех точках отмены следования: прокрутка вверх, смена диалога, удаление сообщения, jumpToMessage, resetChat, teardownChat).

ВАЖНО ДЛЯ ТЕСТОВ: живой таймер держит процесс Node — поэтому teardownChat и resetChat зовут stopFollow безусловно.
