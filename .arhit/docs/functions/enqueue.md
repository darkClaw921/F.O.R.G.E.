# enqueue

tmux-web/static/js/telegram/upload.js (private)

`enqueue(file, dialogId, caption, replyToId)` — ставит файл в последовательную очередь отправки.

`replyToId` ФИКСИРУЕТСЯ В САМОМ item'е, а не читается перед отправкой: очередь последовательная, и
пока до файла дойдёт ход, полоса ответа уже может показывать другое сообщение. Побочно это чинит
RETRY — повтор уходит туда же, куда собирался пользователь.

Отличие от подписи: `caption` достаётся только ПЕРВОМУ файлу пачки (подпись трижды — спам), а
`reply_to_id` получают ВСЕ файлы: ответ тремя файлами и должен выглядеть как три ответа.

Дальше runItem передаёт его в `sendMessage(..., {replyToId: item.replyToId})`; на optimistic-строке
проставляется `data-reply-to-id` — хук для отрисовки цитаты владельцем полосы.
