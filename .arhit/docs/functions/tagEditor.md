# tagEditor

Редактор тегов в карточке задачи трекера (tmux-web/static/js/tracker/modals.js).

ЧТО ДЕЛАЕТ. Заменил единственное текстовое поле '#тег #тег' на чипы вида '#forge ×' плюс поле ввода с выпадающим списком подсказок. Возвращает {node, getTags(), closeSuggest()}:
- node — контейнер .trk-tags-edit (чипы + .trk-tags-input-wrap с input и .trk-tags-suggest);
- getTags() — список тегов для buildPatch; ДОЗАБИРАЕТ недобавленный ввод (человек набрал тег и нажал SAVE — терять набранное нельзя);
- closeSuggest() — закрывает список подсказок, возвращает true, если он был открыт (используется слоем Esc).

ИСТОЧНИК ПОДСКАЗОК. knownTags(snapshot.tasks) — теги из снимка /api/tracker/state, те же, что показывает блок // TAGS в сайдбаре. Второго источника нет.

«СОЗДАНИЕ» ТЕГА. Пункт «создать новый: #имя» появляется, когда набранного тега нет ни среди известных, ни среди навешенных. Он НЕ ходит в сеть: отдельной сущности тега в модели нет, тег — строка в task.tags, и создание сводится к добавлению новой строки, уезжающей обычным PATCH {tags: [...]}.

КЛАВИАТУРА. Enter — добавить (выделенную подсказку либо набранное); пробел и запятая — разделители (добавляют и очищают поле); Backspace на пустом вводе снимает последний чип; ArrowUp/ArrowDown ходят по подсказкам по кольцу; Esc закрывает СПИСОК и гасит всплытие, поэтому карточка не закрывается — второй Esc закрывает уже карточку. Слой встроен в существующий порядок Esc (диалог переноса to-todo.js, диалог вехи milestone.js, затем карточка): обработчик поля срабатывает раньше document-слушателя onKeydown, а в самом onKeydown есть страховочная ветка local.fields.tags.closeSuggest() на случай ушедшего фокуса.

ДЕТАЛИ РЕАЛИЗАЦИИ. Логика без DOM вынесена в js/tracker/tags.js и покрыта tests/frontend/tracker_tags.test.mjs. mousedown на строке подсказки гасится, чтобы поле не потеряло фокус до click. При скрытии список ОЧИЩАЕТСЯ (menu.textContent = ''), иначе спрятанные, но живые узлы видит querySelector и не видит человек. blur закрывает только список: набранное остаётся в поле и доедет до PATCH.

СОХРАНЕНИЕ. save() передаёт в buildPatch массив f.tags.getTags(); buildPatch принимает и массив, и строку (старая форма, prompt-строка, e2e) и по-прежнему шлёт tags только при фактическом изменении, не трогая соседние поля.

СТИЛИ. .trk-tags-edit / .trk-chip / .trk-chip-x / .trk-tags-input / .trk-tags-suggest / .trk-suggest / .trk-suggest-new в static/css/tracker.css — терминальные прямоугольные чипы на токенах --t-*, проверены в обеих темах (data-tracker-theme).
