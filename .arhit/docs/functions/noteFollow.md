# noteFollow

noteFollow(dialogId, messageId, nowMs, ttlMs?) -> boolean (tmux-web/static/js/telegram/follow.js) — включает, продлевает и перецеливает «следование» ленты Telegram за сообщением бота.

ПАРАМЕТРЫ:
 * dialogId — id диалога, приводится к строке (`String`); null/undefined/'' ⇒ функция ничего не делает и возвращает false. Диалог обязателен: следование адресное, «следить вообще» смысла не имеет;
 * messageId — id сообщения с кнопкой. Не-число, 0 или отрицательное ⇒ записывается 0, что означает «следим за ДИАЛОГОМ целиком». Это штатный режим для кнопок reply-клавиатуры: они принадлежат чату, а не конкретному сообщению, и ответ на них приходит новым сообщением;
 * nowMs — Date.now() вызывающего. Часы инъектируются, чтобы тест окна в 12 секунд не зависел от скорости машины; не-число ⇒ 0;
 * ttlMs (необязательный) — своё окно жизни; не-число или ≤0 ⇒ FOLLOW_TTL_MS (12000). Продуктовый код параметр не передаёт, он существует ради тестов.

ВОЗВРАТ: true, если следование включилось; false — если dialogId пуст.

ПОВЕДЕНИЕ ПРИ ПОВТОРНОМ ВЫЗОВЕ. Второй вызов ПРОДЛЕВАЕТ окно (`untilMs = now + ttl`, а не max со старым) и ПЕРЕЦЕЛИВАЕТ его на новую пару (диалог, сообщение). Это осознанно: пользователь жмёт кнопки пачкой («меню → раздел → страница 2»), каждое нажатие — свежий интент, и актуально всегда последнее. Старая цель при этом теряется молча — очереди целей нет.

ПОБОЧНЫХ ЭФФЕКТОВ НЕТ: функция не трогает DOM и не ставит наблюдателей. Всё остальное делает вызывающий — chat.js::noteButtonPress: после успешного noteFollow он перезаводит таймер (armFollowTimer) и переставляет ResizeObserver на строку (observeFollowRow).

ЦЕПОЧКА ВЫЗОВА: клик по кнопке → botkb.js::runAction (только для действий 'callback' и 'send-text') → колбэк onButtonPress → chat.js::noteButtonPress → noteFollow.

СВЯЗАННЫЕ: clearFollow (снятие), followTarget/isFollowing/followsMessage (чтение), FOLLOW_TTL_MS.
