# onDeleted

onDeleted(evt) (tmux-web/static/js/telegram/chat.js, экспорт) — обработчик WS-кадра `message_deleted`: заменить строки заглушкой «<< message purged >>».

ВХОД: {dialog_id: string, message_ids: Array<number>}. dialog_id бывает ПУСТЫМ — для личных чатов Telegram не сообщает диалог (см. plugins/telegram/src/updates.rs::deleted_event). Тогда чистка идёт по id во всех загруженных диалогах: message_id в ЛС уникален в пределах аккаунта, промаха нет.

ЧТО ДЕЛАЕТ ДЛЯ КАЖДОГО id: dropFromList + dropMessageMedia (по конкретному диалогу либо по всем), cancelReplyTo (отвечать на удалённое нечем — Telegram отверг бы такой reply_to_id, а пользователь до последнего видел бы полосу «отвечаю Васе»), гашение подсветки при совпадении с flashId, ОТМЕНА СЛЕДОВАНИЯ, снятие наблюдения за размером, превращение строки в заглушку (className/textContent/_tg=null) и удаление из local.rows.

ДВЕ СТРОКИ, ДОБАВЛЕННЫЕ ПРИ ИСПРАВЛЕНИИ ДЕФЕКТА АВТОПРОКРУТКИ:
 1. `if (followsMessage(dialogId || tgState.activeDialogId, id, Date.now())) stopFollow();` — сообщение с кнопкой стёрли, следовать больше не за чем. Фолбэк `|| tgState.activeDialogId` нужен ровно из-за пустого dialog_id в ЛС: без него удаление сообщения-с-кнопкой в личке не гасило бы следование, и оно доживало бы свои 12 секунд, дёргая ленту на чужих событиях;
 2. `if (local.followRow === row) unobserveFollowRow();` — строка ПЕРЕИСПОЛЬЗУЕТСЯ как заглушка (узел не удаляется из DOM, у него меняется класс и текст), наблюдать её размер незачем: смена содержимого на короткую системную строку сама по себе даёт resize-событие. Сверка именно с узлом (`=== row`), а не с id, — потому что наблюдение хранит УЗЕЛ.

ПОРЯДОК ВАЖЕН: обе строки стоят ДО превращения строки в заглушку и до `local.rows.delete(id)` — после удаления из индекса узел уже не найти.

ТЕСТОВОЕ ПОКРЫТИЕ: telegram_scroll_edge.test.mjs — мутация «снятие сверки followRow===row в onDeleted» ловится сценарием, где окно следования истекло по часам, а таймер снятия ещё не выстрелил.
