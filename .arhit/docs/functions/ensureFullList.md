# ensureFullList

tmux-web/static/js/telegram/dialogs.js — ленивая одноразовая догрузка расширенного списка
диалогов под пользовательскую папку (вторая половина D3). Приватная.

Сигнатура: ensureFullList() -> ?Promise<void>; null означает «уже сделано или идёт».

Что делает: один запрос getDialogs(FOLDER_LIST_LIMIT = 300, 'all') + format.js::mergeDialogs +
renderAll. Вызывается из selectDir для ключей вида 'folder:<id>' — то есть при ПЕРВОМ входе в
пользовательскую папку.

ПОЧЕМУ ЛЕНИВО, А НЕ НА СТАРТЕ: стартовый loadDialogs() оставлен как был (100 диалогов) —
первая отрисовка колонки после логина не должна замедляться. Расширенная выборка стоит нескольких
RPC к Telegram, а refreshAll дёргается на КАЖДОМ реконнекте WS: делать её на старте значило бы
поменять один дефект на другой — задержку старта и риск FLOOD_WAIT.

Страховки: флаг «догружено» (сбрасывается в loadDialogs), отдельный флаг «в полёте» против гонки
кликов, ошибка запроса молча оставляет стартовую выборку (ретрая нет). Состояние видно в
_debugDialogsState().fullListLoaded.

ЗАМЕЧАНИЕ: ?folder=all — это PEER-папка Telegram (main|archive|all), а НЕ id пользовательской
папки-dialogFilter. Пользовательские папки фильтруются на фронте (dialogInFolder).
