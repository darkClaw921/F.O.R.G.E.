# dialogRings

tmux-web/static/js/telegram/main.js — «звенит» ли диалог: показывать тост и учитывать сообщение
в бейдже. Единственная точка решения (D1).

Сигнатура: dialogRings(frame, localMuted, localArchived) -> boolean.

ИСТОЧНИК ИСТИНЫ — ПОЛЯ УРОВНЯ КАДРА new_message ({"type":"new_message","message":{…},
"muted":bool,"archived":bool}), а не локальный Set. Кадр перебивает локальное знание В ОБЕ
СТОРОНЫ: muted:false означает «mute сняли с телефона», и старое локальное «заглушён» обязано
уступить.

Фолбэк на localMuted/localArchived включается ТОЛЬКО когда поля в кадре НЕТ — проверка
frameFlag(value, fallback) смотрит typeof value === 'boolean', а НЕ !frame.muted. Разница
принципиальна: «не знаю» старого сервера при наивной проверке превратилось бы в «не заглушён»,
то есть в регресс ровно в сторону жалобы пользователя.

ПОЧЕМУ ЭТО ЛЕЧИТ НЕИЗВЕСТНЫЙ ДИАЛОГ: local.muted собирается из mutedIds(tgState.dialogs), то
есть из ЗАГРУЖЕННОЙ страницы /dialogs (верхняя сотня), а WS вещает по ВСЕМУ аккаунту. Чат вне
страницы — заглушённый лично, заглушённый глобально по категории или архивный — был фронту
неотличим от незаглушённого. Сервер это уже посчитал (с наследованием глобальных настроек), кадр
несёт готовое решение.

АРХИВ теперь тоже гасит тост — раньше maybeToast про него не знал вовсе.

Смежное состояние: local.flagsExtra (dialog_id → {muted, archived}) — знание о диалогах ВНЕ
загруженной страницы; заполняется кадрами new_message и notify_settings, снимается, как только
диалог появится в списке (список авторитетнее).
