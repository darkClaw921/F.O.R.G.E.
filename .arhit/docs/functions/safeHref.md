# safeHref

js/messenger/markdown.js — проверка допустимости URL ссылки. P0-функция эпика forge-vkmd-b-4fyj (задача .5).

ЭТО ЕДИНСТВЕННОЕ МЕСТО, где недоверенный текст становится КЛИКАБЕЛЬНЫМ элементом. Всё остальное в модуле — текстовые узлы; ссылка — узел с атрибутом href, который браузер выполнит.

Контракт: safeHref(raw) -> нормализованный абсолютный URL, если схема входит в белый список [http:, https:], иначе null. Не-строка, пустая строка и мусор дают null.

ПОЧЕМУ new URL, А НЕ РЕГЕКСП. Префиксный регексп по началу строки обходится ведущими пробелами, табами, переводами строк, управляющими символами и регистром: " javascript:", "java\\nscript:", "javascript\\t:", "JaVaScRiPt:". Конструктор WHATWG-URL выполняет ровно ту же нормализацию, что и браузер при переходе по ссылке — вырезает табы и переводы строк ВНУТРИ URL, обрезает пробелы по краям, приводит схему к нижнему регистру. Сравнивать после этого нужно уже не с текстом, а с url.protocol — и все перечисленные обходы схлопываются в одно и то же "javascript:". Конструктор обёрнут в try/catch: выброс = ссылка невалидна.

ОТНОСИТЕЛЬНЫЕ ССЫЛКИ ЗАПРЕЩЕНЫ (решение явное). Базы нет, а подставлять location.href панели значило бы позволить ответу модели сделать кликабельной ссылку на собственный API devforge (/api/vk/...) с куками пользователя. new URL(raw) без базы бросает на относительном пути — такая ссылка становится текстом.

ПОСЛЕДСТВИЕ В РЕНДЕРЕРЕ (renderLink): при null элемент <a> не создаётся ВОВСЕ — текст ссылки отдаётся обычным узлом в span.md-link-blocked, и пользователь видит всё, что написала модель, просто без клика. Пустой href или <a> без адреса были бы хуже: ссылка выглядела бы рабочей. Разрешённая ссылка получает через setAttribute target="_blank" и rel="noopener noreferrer" (без rel новая вкладка получает window.opener и может увести исходную страницу на фишинг).

Блокируются, в частности: javascript:, data: (можно спрятать целый HTML-документ), vbscript:, file:, about:, blob:, URL-кодированные и HTML-сущностные схемы. Все векторы перечислены поимённо в секции 3 теста tmux-web/tests/frontend/messenger_markdown.test.mjs и проверяются дважды — решением функции и последствием в DOM.
