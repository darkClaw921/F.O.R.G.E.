# stopFollow

stopFollow() -> boolean (tmux-web/static/js/telegram/chat.js, внутренняя) — ПОЛНОЕ снятие «следования» ленты Telegram за сообщением бота: состояние + таймер + наблюдение за размером строки.

ПОРЯДОК: гасит local.followTimer (clearTimeout + обнуление), зовёт unobserveFollowRow() (снимает ResizeObserver с узла, сам наблюдатель сохраняется для следующего нажатия), возвращает результат follow.js::clearFollow() — было ли следование живо.

ЕДИНСТВЕННЫЙ ПРАВИЛЬНЫЙ СПОСОБ ОТМЕНЫ. Прямой вызов clearFollow() из follow.js оставил бы висеть и таймер, и наблюдателя на detached-узле — поэтому продуктовый код зовёт только stopFollow.

ВСЕ ТОЧКИ ВЫЗОВА (семь):
 * armFollowTimer, колбэк таймера — истёк TTL (12с);
 * bindScroll — пользователь прокрутил ленту ВВЕРХ сверх FOLLOW_CANCEL_UP_PX (его прокрутка важнее автоматики);
 * openDialog — сменился диалог: следование принадлежит ПОКИНУТОМУ чату, тянуть новую ленту вниз из-за кнопки, нажатой в другом чате, — самодеятельность. Повторное открытие ТОГО ЖЕ диалога (кнопка [retry]) следование сохраняет;
 * onDeleted — сообщение с кнопкой удалили, следовать не за чем;
 * jumpToMessage — переход к оригиналу по цитате уезжает ВВЕРХ, прямо против следования; живое следование вернуло бы ленту вниз, и клик по цитате выглядел бы как «ничего не произошло»;
 * onFollowResize — самопроверка: наблюдатель мог пережить истечение окна на кадр;
 * resetChat (logout/смена аккаунта) и teardownChat (уход страницы) — иначе таймер тикал бы в ленту, которой больше нет.

ВОЗВРАТ используется тестами (идемпотентность: второй подряд вызов даёт false).
