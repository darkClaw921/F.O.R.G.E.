# createVoiceTranscript

Фабрика карточки расшифровки голосового — ОДНА на три панели (tmux-web/static/js/messenger/voice-transcript-core.js, ГС-Ф5).

НАЗНАЧЕНИЕ. Под волной голосового сообщения рисует блок расшифровки: подпись, строку состояния, полосу прогресса, сам текст и две кнопки. Панель (VK, Telegram, Bitrix24) отдаёт сюда ровно три вещи — транспорт (`{transcribe, transcript}` из своего api.js), имя своего DOM-события с кадрами и префикс классов; ни одной строки про конкретный мессенджер в модуле нет (проверяется тестом по исходнику).

ЧЕТЫРЕ СОСТОЯНИЯ: idle (кнопка «Расшифровать»), running (кнопка заблокирована, полоса живёт кадрами delta), ready (текст; длинный свёрнут кнопкой «Показать полностью»), error (человеческая причина по коду + «Повторить»). Отдельный флажок fetching — это «GET готового текста в полёте»; он ничего не показывает и ничего не запрещает.

API инстанса: attach({dialogId, messageId, index, kind, doc}) → узел или null для не-звука; onFrame(detail) — кадр панели; start(...) — ручной запуск; peek(...) — снимок состояния; configure({api, frameEvent, eagerBudget, observe}); reset(); stats.

СОСТОЯНИЕ ЖИВЁТ В МОДУЛЕ (Map по ключу plugin/dialog/message/index), узлы лишь отображают его: лента перерисовывается целиком, и текст, хранимый только в DOM, исчезал бы при каждом скролле. Отсюда же — перерисовка посреди прогона не начинает второй прогон.

ЗАПРОСЫ. Ключ, про который уже всё известно, не спрашивается второй раз; пока карточки не видно, её не спрашивают (IntersectionObserver), а там где наблюдателя нет — жёсткий потолок EAGER_FETCH_BUDGET=12 запросов на пачку отрисовки. Сама расшифровка (POST) запускается ТОЛЬКО нажатием человека.

⚠ ОТЦЕПЛЕННЫЙ УЗЕЛ — НЕ МУСОР. Панель зовёт attach при СБОРКЕ карточки, то есть до вставки в документ. Первая версия чистила представления по root.isConnected === false прямо в рендере и выбрасывала свежее — расшифровка не появлялась на экране никогда. Правило теперь: последнее представление ключа не выбрасывается, предыдущие — только когда отцеплены.

XSS: тексты попадают в DOM только через textContent; хвост stderr движка (пути, следы ключей) на экран не выводится вовсе — причина берётся из таблицы ERROR_TEXT по коду.

Тесты: tests/frontend/messenger_voice_transcript_core.test.mjs (173 проверки), voice_transcript_panels.test.mjs (три панели, три процесса), voice_transcript_live.test.mjs (66 проверок в headless Chrome).
