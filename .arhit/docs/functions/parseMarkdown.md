# parseMarkdown

js/messenger/markdown.js — блочный парсер Markdown. ЧИСТАЯ функция: не читает document, window, время или сеть, поэтому целиком покрывается тестами в Node без фейкового DOM (в этом и смысл разделения парсера и рендерера).

Вход: строка ответа модели. Выход: массив блоков AST; на пустом входе или не-строке — пустой массив.

Работа: нормализует переводы строк (\r\n и одиночный \r -> \n; ответ по WebSocket и файл из Windows приходят с разными окончаниями, а весь парсер построчный), делит на строки и построчно опознаёт блоки в фиксированном порядке приоритета: ограждение кода -> hr -> заголовок -> цитата -> таблица -> пункт списка -> абзац. Порядок не случаен: hr проверяется РАНЬШЕ списка, иначе «---» стал бы пунктом.

Абзац копится до пустой строки ИЛИ до начала другого блока (startsNewBlock): список сразу после текста без пустой строки обязан разбираться как список — модель пустых строк перед списками часто не ставит.

Ключевые правила: 7 решёток заголовком не являются (уровня 7 в HTML нет) и уходят в абзац вместе с решётками; цитата из подряд идущих строк с > даёт ОДИН блок, содержимое разбирается рекурсивно (поэтому «> > текст» — вложенная цитата, «> # x» — заголовок внутри цитаты); списки вкладываются по отступу, смена маркера (- -> *) или типа (- -> 1.) начинает НОВЫЙ список; таблица опознаётся только по паре «строка заголовка + строка-разделитель», иначе любая ASCII-схема в ответе превращалась бы в таблицу; строки таблицы с чужим числом ячеек добиваются пустыми или обрезаются; экранированная \| не режет ячейку; незакрытое ограждение кода считается закрытым в конце текста.

Глубина вложенности ограничена MAX_NESTING = 12.

Вызывает: parseInline для содержимого абзацев, заголовков, пунктов списка, цитат и ячеек таблицы (содержимое блока кода инлайн НЕ проходит — звёздочки и ссылки внутри кода остаются символами).
