# observeFollowRow

observeFollowRow(row) (tmux-web/static/js/telegram/chat.js, внутренняя) — переставляет наблюдение за размером на другую строку ленты. `null` ⇒ просто снять наблюдение.

ПОВЕДЕНИЕ: сначала unobserveFollowRow() (снять со старого узла — иначе наблюдений накапливалось бы по одному на каждое нажатие), затем запись local.followRow = row, затем ensureFollowObserver() и `ro.observe(row)` в try/catch (узел мог уже уехать из документа). Обратите внимание: local.followRow ставится ДАЖЕ ЕСЛИ наблюдателя нет (окружение без ResizeObserver) — по этому полю строится диагностическое поле followObserving и решение в onDeleted.

ЗАЧЕМ ХРАНИТЬ УЗЕЛ, А НЕ ID (в отличие от подсветки flashId). Наблюдателю размера нужен КОНКРЕТНЫЙ элемент. Плата за это — все точки, где узел умирает, обязаны переставить наблюдение, иначе оно молча слушает detached-узел и фича «замолкает навсегда».

ВСЕ ТОЧКИ, ГДЕ НАБЛЮДЕНИЕ ПЕРЕСТАВЛЯЕТСЯ ИЛИ СНИМАЕТСЯ:
 * noteButtonPress — поставить на строку с кнопкой сразу при нажатии;
 * afterRowChanged (ветка 'follow') — переезд на актуальный узел: после `row.replaceWith(fresh)` в onEdited старый узел уже вне документа, а рост (медиа, клавиатура) ещё впереди;
 * renderHistory — перепривязка после полной перерисовки ленты (подгрузка истории вверх пересоздаёт ВСЕ строки); сделано по образцу восстановления подсветки flashId, стоящего строкой выше;
 * clearLog — единственная точка, через которую проходят все снесения ленты; само следование остаётся живым (его цель — id, а не узел), а наблюдаемый узел вот-вот станет detached;
 * onDeleted — строка переиспользуется как заглушка «<< message purged >>», наблюдать её размер незачем;
 * stopFollow / teardownChat — снятие насовсем.

СВЯЗАННЫЕ: unobserveFollowRow, ensureFollowObserver, onFollowResize, local.followRow.
