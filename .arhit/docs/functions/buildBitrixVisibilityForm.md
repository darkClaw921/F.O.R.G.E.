# buildBitrixVisibilityForm

Форма «Видимость диалогов» вкладки «Битрикс24» (tmux-web/static/js/settings/bitrix-visibility-tab.js) — с Ф7.5 ПЕР-ПОРТАЛЬНАЯ.

СИГНАТУРА: buildBitrixVisibilityForm(settings, onSaved, onPortalChange). Третий аргумент — просьба вкладке настроек перерисовать СОСЕДНИЕ формы: скоуп авторазбора голосовых тоже пер-портальный, а второго переключателя заводить не нужно (modal.js::paint).

ПЕРЕКЛЮЧАТЕЛЬ ПОРТАЛА в шапке: select из GET /api/bitrix/portals, пустой title показывается как id (хост портала бэкенд наружу не отдаёт — то же правило, что в строке вкладок панели). Ряд рисуется ВСЕГДА, даже при одном портале: он отвечает на вопрос «чьи это настройки», и при подключении второго портала ответ не должен появляться задним числом; при одном портале select disabled. Портал, исчезнувший из реестра (отвязали в соседней вкладке браузера), заменяется первым уцелевшим.

ТРИ СЛЕДСТВИЯ ПЕР-ПОРТАЛЬНОСТИ:
  • список диалогов тянется с ЯВНЫМ порталом getDialogs({limit, portal}) — иначе пикер на портале B показывал бы чаты портала A и человек отметил бы чужие чаты;
  • сохранение уходит ТОЛЬКО в запись выбранного портала (visibility.js::portalPrefsPatch); слияние делает бэкенд, записи остальных порталов не трогаются; плоские ключи форма НЕ переписывает — они заморожены ради отката;
  • смена портала перечитывает выбор, ТУМБЛЕР и список: черновик предыдущего портала не переносится (в нём его DIALOG_ID, то есть чужие чаты).
