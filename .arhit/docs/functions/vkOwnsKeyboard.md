# vkOwnsKeyboard

tmux-web/static/js/vk/keynav.js::vkOwnsKeyboard() -> boolean —
половина контракта window.ForgeApp.vkKeys, который читает static/hotkeys.js.

Возвращает true, только когда ВСЁ верно одновременно: пейн #vk видим, тумблер
vk_hotkeys_enabled не выключен (гейт строго !== false — дефолт «включено»), и
фокус находится ВНУТРИ панели или нигде (document.body). Отдельно снимается
владение при открытом оверлее логина и при открытом оверлее CAPTCHA — второе
отличает VK от Telegram: captcha всплывает на ЛЮБОЙ метод API, и пока
пользователь набирает код, j/k принадлежат её полю.

ЗАЧЕМ. hotkeys.js занимает j/k/h/l/g/1/2/3/? глобально (навигация по сессиям
tmux). Пока панель-мессенджер владеет клавишами, vim обязан молчать, иначе одно
нажатие j и листало бы ленту, и уводило фокус на сессию в сайдбаре. Кликнув в
сайдбар, пользователь возвращает vim себе — это проверяется и node-тестом
vk_keynav, и e2e-спекой vk-ui.spec.ts.

Две панели ответить true одновременно не могут по построению: switchTab держит
непогашенным ровно один пейн.
