# createMeetPopup

Фабрика карточки встречи (попапа) для одной панели — tmux-web/static/js/messenger/meet-popup.js.

ПОЧЕМУ ФАБРИКА, А НЕ ЕДИНЫЙ ОВЕРЛЕЙ. Токены палитры объявлены НА панелях (#telegram, #vk, #bitrix). За пределами этих поддеревьев var(--t-grn) не резолвится ни во что — не «выглядит иначе», а именно теряется: текст без цвета, рамки без рамок. Попап в body был бы бесцветным в любой теме. Поэтому создаётся ПО ЭКЗЕМПЛЯРУ НА ПАНЕЛЬ, последним потомком своей панели, а красится слоем алиасов --m-* из css/meet.css (объявлен трижды).

cfg: {panel, host, doc, api, onNotice, urls, timers, raf, caf}. doc приходит ПАРАМЕТРОМ (как renderSegments(segments, doc) в bitrix/format.js) — только так модуль проверяется на фейковом документе в голом Node. Сеть инъектируется: сам модуль js/meet/api.js не импортирует.

Возвращает {root, refs, open(detail), close(), teardown(), isOpen(), setTab(name), debugState()}.

СОДЕРЖИМОЕ: шапка (название, платформа, статус с тоном из meetViewFor), мета (начало, длительность, участники, этап/очередь), плеер, скриншот бота, три вкладки (саммари / расшифровка / участники), строка ошибки, полоса действий (record, stop, cancel, confirm, window, shot, retry) с видимостью по таблице ACTS_BY_STATUS.

ИНВАРИАНТЫ:
- Разметка строится УЗЛАМИ. innerHTML/outerHTML/insertAdjacentHTML запрещены и проверяются по исходнику (в карточку попадают названия встреч из чужих чатов, имена участников из DOM чужой страницы и текст расшифровки).
- z-index 6 и ПОСЛЕДНИЙ потомок панели: при равном z-index побеждает порядок в DOM, поэтому карточка ложится поверх оставленного открытым попапа анализа.
- position: absolute, не fixed — fixed вырвал бы её из панели в область просмотра.
- Esc — порт из analysis-core.js вместе со stopPropagation (одно нажатие закрывает ровно одно окно) и снятием слушателя в teardown (переживший bfcache, он стреляет по мёртвому DOM).
- Клик по подложке закрывает, клик по карточке — нет (сравнение e.target === root).
- Клик по кнопке в ленте ВСЕГДА открывает карточку и никогда не стартует запись: бот входит в чужую встречу и его видят все участники. Запись стартует явным нажатием ЗАПИСАТЬ, после ответа обязателен linkMeeting (кадр meeting_update несёт MeetingRow, в которой источника нет).
- Своих интервалов НЕТ: живой таймер записи один на документ и живёт в meet-store; карточка слушает его кадры tick.
- Подписка на стор живёт ровно пока попап открыт; кадры фильтруются по meeting_id (соединение одно на вкладку).
- Все выданные blob:-ссылки отзываются в close() и teardown().

Тесты: tests/frontend/meet_popup.test.mjs, meet_popup_tabs.test.mjs, meet_popup_player.test.mjs. Ф11: набор кнопок статуса берётся из экспортированной ACTS_BY_STATUS, в которой теперь есть строка pruned.
