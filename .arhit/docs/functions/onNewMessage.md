# onNewMessage

onNewMessage(msg) -> boolean (tmux-web/static/js/telegram/chat.js, экспорт) — обработчик WS-кадра `new_message`: вставить сообщение в модель и, если его диалог открыт, дорисовать строку в ленту. Возвращает, дорисовано ли в активную ленту.

ПОРЯДОК: гард на msg/msg.id → insertMessage(list, msg) (дедуп по id + вставка по возрастанию) → сохранение списка → если !inserted (дубль после catch_up) выход → noteReplyMarkup(msg) ДО проверки «диалог открыт» (клавиатура могла прийти в чат вне экрана и обязана быть актуальной при возврате туда) → если диалог не активен или нет $tgLog, выход → ЗАМЕРЫ → построение строки → вставка (в конец либо перед следующей по id, если сообщение пришло «из середины») → local.rows.set → updateHead → afterRowChanged.

ЗАМЕРЫ ДО ВСТАВКИ (обязательно ДО appendChild — после него высота ленты уже другая):
 * `const stick = isAtBottom($tgLog)` — прежнее прилипание к низу, было и раньше;
 * `const following = isFollowing(id, Date.now())` — ДОБАВЛЕНО при исправлении дефекта.

ЗАЧЕМ ДОБАВЛЕНО `following`. Бот может ответить на нажатие кнопки не правкой старого сообщения, а НОВЫМ (карточка товара, следующая страница списка, результат команды). Для пользователя это тот же результат его нажатия, и уехать к нему он должен так же — даже если чуть отлистал вверх. Это требование «бот в ответ на кнопку может прислать НОВОЕ сообщение вместо правки старого».

ПОЧЕМУ ЗДЕСЬ isFollowing, А НЕ followsMessage: у нового сообщения свой id, сверять его с id сообщения-с-кнопкой не с чем — достаточно совпадения ДИАЛОГА. Обратная сторона: пока следование живо (12с), любое новое сообщение в этом диалоге притянет ленту вниз, включая сообщение от человека. Осознанный размен — окно короткое и открывается только собственным нажатием пользователя.

ЧУЖОЙ ДИАЛОГ ленту не дёргает даже при живом следовании: проверка `String(tgState.activeDialogId) !== id` стоит выше замеров и просто выходит (тест telegram_scroll_ui.test.mjs секция 4).

ВСТАВКА «ИЗ СЕРЕДИНЫ»: если index !== list.length - 1 (сообщение пришло вне порядка после catch_up), строка вставляется перед следующей по id — иначе лента разъехалась бы с моделью. Разделители дат (needsDateSep/buildDateSep) добавляются только при вставке в конец.

СВЯЗАННЫЕ: afterRowChanged, follow.js::isFollowing, format.js::isAtBottom / insertMessage / needsDateSep.
