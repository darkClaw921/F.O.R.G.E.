# bindScroll

bindScroll() (tmux-web/static/js/telegram/chat.js, экспорт) — единственная подписка на событие `scroll` ленты #tg-log. Три обязанности, по порядку внутри обработчика.

ИНИЦИАЛИЗАЦИЯ: гард `if (!$tgLog || local.bound) return` (идемпотентность — зовётся из initChat), затем `local.lastScrollTop = Number($tgLog.scrollTop) || 0` — стартовая точка отсчёта направления.

ОБРАБОТЧИК:
 1. `const top = Number($tgLog.scrollTop) || 0`;
 2. ОТМЕНА СЛЕДОВАНИЯ (добавлено при исправлении дефекта автопрокрутки): `if (cancelledByScroll(local.lastScrollTop, top)) stopFollow();` — своя прокрутка вверх важнее автоматики: пользователь передумал ждать ответ бота и ушёл читать историю. Решение принимается ПО НАПРАВЛЕНИЮ движения (порог FOLLOW_CANCEL_UP_PX = 24px), а не по флагу «это скроллил я»: присваивание scrollTop порождает событие асинхронно, и флаг успел бы сброситься до его доставки. Собственные доскроллы идут ВНИЗ (scrollTargetForRow не тянет вверх никогда) и под порог не попадают;
 3. `local.lastScrollTop = top` — обновляется БЕЗУСЛОВНО, иначе одно резкое движение вверх гасило бы следование многократно;
 4. `if (isAtBottom($tgLog)) noteReachedBottom()` — «докрутил до низа» законный триггер прочтения: пользователь дочитал ленту глазами. Лишних запросов не плодит — решение принимает scheduleRead в main.js (debounce + память о последнем отмеченном id);
 5. `shouldLoadOlder(...)` ⇒ loadOlder(currentDialog()) — подгрузка истории вверх (scrollTop < 200 && hasMore && !loading).

СОСЕДСТВО ТРЁХ МЕХАНИЗМОВ В ОДНОМ ОБРАБОТЧИКЕ БЕЗОПАСНО, потому что они смотрят в разные стороны: отмена следования срабатывает на движение ВВЕРХ, отметка о прочтении — у нижней кромки, подгрузка истории — у верхней. Пересечение возможно только у «прокрутил вверх до самого верха» — там честно происходит и отмена следования, и загрузка истории, что и требуется.

СВЯЗАННЫЕ: follow.js::cancelledByScroll, stopFollow, format.js::isAtBottom / shouldLoadOlder, local.lastScrollTop (обнуляется в resetChat).
