# registerEscLayer

Регистрирует окно панели как СЛОЙ Esc в общем реестре tmux-web/static/js/messenger/esc-stack.js.

ЗАЧЕМ (дефект forge-o0sdg). Карточка встречи (messenger/meet-popup.js), попап анализа чата (messenger/analysis-core.js) и полоса цитаты ответа (vk/chat.js, telegram/chat.js) вешали СВОИ слушатели keydown на ОДИН И ТОТ ЖЕ document и каждый защищался вызовом stopPropagation(). Это не работает: между слушателями одного узла stopPropagation() не действует вовсе — он останавливает всплытие ВЫШЕ по дереву, а остальных слушателей ЭТОГО узла не отменяет (для них есть stopImmediatePropagation). Одно нажатие Esc закрывало ДВА окна — карточку встречи и попап анализа, либо карточку и поднятую цитату ответа — во всех трёх панелях (Telegram, VK, Битрикс24), каждый раз. Комментарии в обоих файлах прямо утверждали обратное, поэтому дефект пережил юнит-тесты.

ПОЧЕМУ НЕ stopImmediatePropagation. Он отменяет только тех слушателей, кто зарегистрирован ПОЗЖЕ, то есть делает поведение заложником порядка загрузки модулей: смена порядка импортов в bootstrap.js молча переключила бы Esc на другое окно, и тест на это не покраснел бы.

КАК УСТРОЕНО. Слои объявляют СТАТИЧЕСКУЮ глубину ESC_DEPTH, повторяющую реальный визуальный порядок наслоения: REPLY_BAR=10 (полоса цитаты), ANALYSIS_POPUP=20 (попап анализа), MEET_CARD=30 (карточка встречи — вставляется последним потомком панели и при равном z-index ложится поверх). Единственный слушатель keydown на документе закрывает САМЫЙ ГЛУБОКИЙ из ОТКРЫТЫХ слоёв. Ни порядок регистрации, ни порядок открытия ни на что не влияют; третий и четвёртый слой добавляются одной строкой.

API:
- registerEscLayer({name, depth, isOpen, close, doc?}) -> функция снятия слоя (идемпотентная). doc по умолчанию глобальный document; реестры хранятся по документам (у тестов свой фейковый документ на файл). Слушатель заводится ЛЕНИВО при первом слое и снимается, когда снят последний — переживший выгрузку страницы в bfcache слушатель стреляет по мёртвому DOM.
- topEscLayer(doc?) -> {name, depth} | null — верхний открытый слой. Нужен обработчикам, которые слоем стать не могут: Esc режима ответа/правки в Битриксе живёт на ПОЛЕ ВВОДА, срабатывает только при фокусе в нём и всплывает до документа раньше любого окна, поэтому он сам спрашивает реестр и молчит, пока сверху есть окно (bitrix/chat.js).
- ESC_DEPTH — замороженная таблица глубин.
- _debugEscStack(doc?) — снимок для тестов.

ГРАНИЦЫ. Реестр — власть над ОКНАМИ ПАНЕЛИ. Лайтбокс, плеер, мобильная колонка бесед и блокирующий оверлей панели слушают Esc сами и остаются со своими гардами, поэтому общий слушатель НЕ зовёт stopImmediatePropagation: только preventDefault() и stopPropagation() (последнее было и в карточке — без него Esc всплыл бы до window и закрыл заодно мобильную боковую колонку). Слой, обязанный уступить не-реестровому окну, говорит об этом своим isOpen(): так делает полоса ответа при открытом лайтбоксе, а попап анализа — при открытом блокирующем оверлее панели. Если ни один слой не открыт, реестр не гасит событие и не останавливает его — Esc достаётся соседям.

ТЕСТЫ. tests/frontend/messenger_esc_layers.test.mjs поднимает ОБА реальных модуля на ОДНОМ документе (именно этой связки не было ни в одном тесте — каждый поднимал свой документ и свой модуль) и требует, чтобы одно нажатие закрывало ровно одно окно, а одиночное окно закрывалось. Там же зафиксировано, что фейковый документ ведёт себя как браузер: вызывает ВСЕХ слушателей узла, stopPropagation их не отменяет, stopImmediatePropagation — отменяет. Сценарий с цитатой ответа проверяется на живых модулях панелей: vk_reply_ui.test.mjs, telegram_reply_ui.test.mjs, bitrix_send.test.mjs.
